# AD Coin Sponsored: '기타 모든 나라(GLOBAL)' 판매 설계 (2026-11-12)

PM 지시(사용자 결정 11-12 "둘 다 진행")에 따른 **설계 문서**다. 안정성 관문을 통과하기 전에는 이 설계의 코드를 운영에 넣지 않는다(`docs`·시험 계획까지만).
- 안정성 관문: user_slo 7일, 공개 전수 점검 실패 0 3일, 실제 과제 27/30, 설명 안 되는 오류 하루 0
- 결제 지갑의 제재 주소 대조(`paid_bookings.Sanctions`)는 그대로 둔다.

## 1. 지금 상태

| 항목 | 지금 |
|---|---|
| 판매 지역 | US, KR, JP, GB, DE 5개(`live_service.DEFAULT_REGIONS`) |
| 지역 판정 | `sponsored_http`가 `region` 쿼리 값을 먼저 쓰고, 없으면 `CF-IPCountry` 앞 2글자를 쓴다 |
| 5개국 밖 방문자 | 카드 0장(팔지 않음) |
| 칸·가격 | 하루·분야·지역마다 2칸, 1칸 5 USDC 또는 50 coins |

**지금 구조의 빈틈:** 쿼리의 `region`이 국가 헤더보다 앞선다. 그래서 어느 나라 방문자든 `?region=US`를 붙이면 US 카드를 볼 수 있다.
- 지금은 돈·개인정보와 무관한 표시 문제다.
- 하지만 제재 지역 차단을 넣는 순간 우회 경로가 된다. 이 설계에서 함께 닫는다(3절).

## 2. 지역 값 규칙 (판정 함수 하나로)

`region_of(headers, query_region) -> 'US'|'KR'|'JP'|'GB'|'DE'|'GLOBAL'|'BLOCKED'|'NONE'`

| `CF-IPCountry` | 결과 | 카드 | 노출 집계 | 판매 대상 |
|---|---|---|---|---|
| US, KR, JP, GB, DE | 그대로 | 그 나라 예약 | 셈 | 그 나라 칸 |
| CU, IR, KP, SY | `BLOCKED` | 0장 | 세지 않음 | 없음 |
| 제재 지역(크림·도네츠크·루한스크, 4절) | `BLOCKED` | 0장 | 세지 않음 | 없음 |
| XX(알 수 없음) | `NONE` | 0장 | 세지 않음 | 없음 |
| T1(Tor) | `NONE` | 0장 | 세지 않음 | 없음 |
| 그 밖의 ISO 3166-1 두 글자 | `GLOBAL` | GLOBAL 예약 | 셈 | GLOBAL 칸 |
| 헤더 없음(내부·직접 접속) | `NONE` | 0장 | 세지 않음 | 없음 |

**XX·T1을 GLOBAL로 보내지 않는 이유**
- 출처를 모르는 요청은 제재 지역에서 왔을 수도 있다. 보수적으로 막는다.
- 광고주에게 "어디서 보였는지 모르는 노출"을 팔지 않는다.
- XX·T1 트래픽은 많지 않을 것으로 본다. 출시 전에 엣지 집계로 비율을 확인한다(시험 계획 T9).

**판정은 한 곳에서만 한다.** 카드 응답, 노출 집계, 예약 화면의 지역 목록이 모두 같은 함수를 쓴다.

## 3. 쿼리 `region` 처리

- `CF-IPCountry` 헤더가 있으면 쿼리 `region`은 **무시한다**. 운영의 모든 공개 요청에는 이 헤더가 붙는다.
- 헤더가 없을 때(내부 시험, 127.0.0.1)만 쿼리 값을 쓴다. 이때도 같은 판정 표를 거친다.
  - 쿼리로 `BLOCKED`나 `NONE`을 우회할 수 없다.
  - 쿼리로 GLOBAL을 직접 고를 수도 없다(두 글자 나라 코드만 받음).
- 메인 화면(`experience.js`)은 지금 `region`을 보내지 않는다. 그래서 바뀌는 것이 없다.

## 4. 제재 대상 지역

OFAC 포괄 제재 대상은 다음과 같다(2026-11 기준, 재무부 공개 목록. 연 1회 이상 다시 확인).
- 나라: 쿠바(CU), 이란(IR), 북한(KP), 시리아(SY)
- 지역: 크림(EO 13685), 이른바 도네츠크·루한스크 인민공화국 지역(EO 14065)

**나라 코드로 가를 수 없는 지역(크림·도네츠크·루한스크)**
- 이 지역의 방문자는 `CF-IPCountry`에서 UA나 RU로 온다.
- 처리 순서는 다음과 같다.
  1. **우선안:** Cloudflare 관리형 변환 "Add visitor location headers"를 켜서 `cf-region-code`(ISO 3166-2)를 받는다. 다음 값이면 `BLOCKED`로 한다.
     - UA-43(크림), UA-40(세바스토폴)
     - UA-14(도네츠크), UA-09(루한스크)
     - 이 헤더는 판정에만 쓰고 저장·기록하지 않는다(개인정보 최소화 원칙 그대로).
     - Cloudflare 설정 변경이라 PM을 거쳐 **사용자 확인**이 필요하다.
     - 무료 플랜에서 되는지 먼저 읽기로 확인한다(값을 바꾸기 전에 지금 상태를 읽는다).
  2. **대안:** 그 헤더를 받을 수 없으면 UA와 RU를 GLOBAL에서 빼고 `BLOCKED`로 둔다(판매·노출 없음).
     - 손해는 두 나라의 노출이다.
     - 대신 제재 지역 노출이 0임을 보장할 수 있다.
- **목록 관리:** 제재 나라·지역 코드는 코드 상수 하나(`SANCTIONED_COUNTRIES`, `SANCTIONED_REGIONS`)에 둔다. 바꿀 때는 시험과 문서를 같이 고친다.

**판매 쪽(광고주)**
- 결제 지갑의 OFAC 주소 대조는 그대로 둔다. 걸리면 사람이 검토한다.
- 추가: 광고주 신청을 받을 때 그 요청의 지역 판정이 `BLOCKED`이면 신청을 받지 않는다.
  - 판정에만 쓰고 저장하지 않는다.
  - 신청 화면에는 "지원하지 않는 지역"이라고만 표시한다.

## 5. 칸·가격·겹침

- **칸:** GLOBAL도 하루·분야마다 2칸이다(`PLACEMENTS_PER_DAY` 그대로).
- **가격:** 출시 때는 같은 가격(5 USDC 또는 50 coins)을 제안한다.
  - GLOBAL은 여러 나라에 흩어진 노출이다. 자사 광고로 2주 노출을 잰 뒤 가격 조정을 PM에 올린다(결정은 사용자).
  - 가격 표는 USDC와 coins만 보인다. 원화 환산은 내부 기록(세무)에만 쓴다(PLAT-27의 "정산 자산과 혼동 금지").
- **겹침 없음:** 판정이 서로 배타적이다. 5개국 방문자는 자기 나라 카드만 보고, GLOBAL 카드는 5개국 밖 방문자에게만 간다.
  - 5개국 칸의 예약·노출 수는 바뀌지 않는다.
  - 기존 예약 데이터도 옮길 필요가 없다.
- **DB:** 지역은 `TEXT` 열이라 표 구조 변경이 없다(리허설 대상 아님).
  - 다만 `sponsored_http`의 `[:2]` 자르기는 바꾼다(판정 함수가 대신함).

## 6. PLAT-27을 채우는 방법

| PLAT-27 요구 | 채우는 방법 |
|---|---|
| 지원 국가 명시 | 약관 Sponsored 항과 `/ad-coin/v2/advertise`에 "US, KR, JP, GB, DE, and other countries (GLOBAL), except sanctioned regions"와 제외 목록을 공개한다(공개 게시는 PM을 거쳐 사용자 승인) |
| 상품 | Sponsored 1일 칸 하나(분야·지역) |
| 체인·자산 | Base 메인넷의 공식 USDC(컨트랙트 주소 공개). 또는 무상 coins |
| 제공자 | 없음. 받는 지갑은 사용자 소유이고, 서버는 받기만 한다 |
| 미지원 지역에 집행 안 함 | `BLOCKED`·`NONE`은 카드 0장·노출 0·판매 0. 시험 T2~T5와 운영 점검으로 확인 |
| 가격 표시 | USDC·coins만, 시점별 원화는 내부 기록. 결제 화면은 지금처럼 정확한 금액·만료 시각만 표시 |
| 결제 검증 | USDC 켜기 점검표(조건 0~7) 그대로. GLOBAL 결제는 US 결제와 같은 경로라 새 결제 코드가 없다 |
| 운영 검증 | 자사 광고 GLOBAL 1주(무상), 노출·오류·속도 영향 0 확인 뒤 판매를 연다 |
| 법적 적합성 | 사용자 결정대로 자문은 수익이 커진 뒤에 한다. 그 전에는 제재 지역 0노출과 지갑 대조를 최소선으로 지킨다 |

## 7. 바꿀 곳 (관문 통과 뒤 한 커밋, `AD_COIN_GLOBAL_ENABLED` 스위치는 기본 꺼짐)

- `sponsored_http.py`: 판정 함수와 쿼리 무시 규칙. 스위치가 꺼져 있으면 GLOBAL은 `NONE`으로 둔다.
- `sponsored.py`: regions에 GLOBAL 추가. `SITE_CATEGORIES` 대응은 그대로다.
- `live_service.DEFAULT_REGIONS`, `paid_bookings` 지역 집합: 스위치가 켜졌을 때만 GLOBAL 포함
- 광고주 화면(`web/index.html`·`app.js`): 지역 선택에 "Other countries (GLOBAL)"
- `web/advertise.html`, 약관: 지원 지역 문구(게시는 승인 뒤)
- `advertiser_applications.py`: `BLOCKED` 판정이면 신청 거부
- 설정: `gateway-data/sponsored.env`의 `AD_COIN_GLOBAL_ENABLED`(agentcon.env 아님, 11-11 f7cd7a83)
- 문서: `docs/AD_COIN_SPONSORED_CONTRACT.md`의 region 절

## 8. 시험 계획

| # | 시험 | 확인 |
|---|---|---|
| T1 | 판정 표 단위 시험 | 2절 표의 모든 행(5개국, CU·IR·KP·SY, XX, T1, 헤더 없음, FR·BR 같은 일반 국가) |
| T2 | 제재 국가 | 카드 0장, 노출 집계 0, `Cache-Control: private`, 응답 모양은 같음(차단 여부를 드러내지 않음) |
| T3 | 제재 지역 헤더 | UA + `cf-region-code: UA-43`/UA-40/UA-14/UA-09는 BLOCKED, UA + UA-30(키이우)은 GLOBAL. 대안 모드에서는 UA·RU 모두 BLOCKED |
| T4 | 쿼리 우회 | `CF-IPCountry: IR` + `?region=US`이면 카드 0. 헤더가 없을 때만 쿼리를 쓰고, `?region=GLOBAL`은 거부 |
| T5 | 겹침 없음 | 같은 날 US와 GLOBAL을 각각 예약하면 US 방문자는 US 카드만, FR 방문자는 GLOBAL 카드만 받는다 |
| T6 | 스위치 꺼짐 | GLOBAL 판매·노출 없음. 지금 동작과 같다(회귀) |
| T7 | 예약·결제 | GLOBAL 칸 코인 예약, USDC 견적·확정(가짜 RPC), 칸 2개 한도, 취소 |
| T8 | 원장 보존 | 위 흐름 뒤 `ad_coin_daily_ledger_check`가 clean |
| T9 | 운영 읽기 점검(출시 전) | 엣지 집계에서 XX·T1·제재 코드 요청 비율. 판정에만 쓰고 저장하지 않는다 |
| T10 | 광고주 신청 | BLOCKED 판정 요청의 신청 거부, 문구에 판정 근거·지역명이 드러나지 않음 |
| T11 | 화면 | 지역 선택·랜딩 문구. `scripts.ui_quality_audit` 0, 브라우저 광고주 흐름 완주 |
| T12 | 속도 | GLOBAL 판정 추가 뒤 Sponsored API·탐색·Chat에 지연 증가 없음(공개 주소·새 연결, `user_slo`) |

## 9. 출시 순서

1. 안정성 관문 통과(PM 판정)
2. Cloudflare 위치 헤더를 받을 수 있는지 읽기로 확인한다. 켜야 하면 PM을 거쳐 사용자 확인을 받는다.
3. 코드를 배포한다(스위치 꺼짐). 그 상태로 T1~T12를 운영 사본·공개 주소에서 확인한다.
4. 자사 광고를 GLOBAL research에 1주 둔다(무상). 노출·오류·속도를 본다.
5. 약관·랜딩 지원 지역 문구를 게시한다(사용자 승인).
6. 스위치를 켜 판매를 연다. USDC는 USDC 켜기 점검표를 따로 따른다.
