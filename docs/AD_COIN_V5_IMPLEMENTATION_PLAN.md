# AI AD Coin v5 구현 순서와 검수 계획

2026-11-06 · 상태는 정책과 설계 완료 후 구현 대기

> 2026-11-07 [광고주 플랫폼 정책 v6.1](AD_COIN_PLATFORM_POLICY.md)와 [확장 실행 기획](AD_COIN_PLATFORM_ROADMAP.md)을 추가했다. 본 계획의 자산·권한 기반과 43개 검수는 유지하고, 광고주 전체 업무·효과·통계·성장에 대한 GROW-01~28을 출시 범위별로 함께 적용한다. 문서 연결은 제품 검수 통과를 뜻하지 않는다.

구체 개발 작업은 [v6.2 개발 작업 WP-01~12](AD_COIN_PLATFORM_IMPLEMENTATION_PLAN.md)로 연결한다. WP-01~02가 본 단계 A, WP-06이 단계 B~C, WP-04~05가 단계 D~E, WP-12가 단계 F를 확장한다. v5 검수 43개는 폐기하지 않는다. [최신 보강 DES-01~10](AD_COIN_PLATFORM_DESIGN_UPGRADE.md)의 권한·보고·비용·복구 검수도 출시 범위별로 추가한다.

## 1 목표와 이번에 완료한 일

목표는 광고주 실제 입금으로만 발행되는 USDC 담보형 AI AD Coin을 사용자 승인 광고 보상, 에이전트 지갑, 유료 AI 작업, 외부 가맹점·지갑·상환에 연결하는 것이다. 우선순위는 보안, 품질 100%, 속도다.

이번 산출물은 [정책 POL-01~24](AD_COIN_POLICY.md), [기술 설계와 불변식 INV-01~06](AD_COIN_ARCHITECTURE.md), [기계 판독 설계 명세](ad_coin_v5_spec.json), 본 검수 계획과 설명용 Canvas다. 제품 코드·기능 공개·운영 DB·배포·실제 자금·지갑·체인 거래는 변경하지 않았다. 기존 v4 소스 해시와 시험 증거는 그대로이며 v5 완료 증거로 전용하지 않는다.

## 2 구현할 작업과 순서

### 단계 A 권한과 단위 경계

- 기존 `api.py`, `people.py`, `service.py`의 인증 주체를 사람·에이전트·가맹점·운영 역할로 분리한다. 사람 전용 동의·위임 확대·재인증은 에이전트 키를 거부하고 `spend`는 서버의 인증 주체로 actor를 정한다.
- `config.py`, `ledger.py`, `upgrade.py`를 참조해 v2의 자산 ID·6자리 정수 단위·USDC 견적을 별도 구현한다. 원화 시험 단위·환율 1,380·10원 반올림을 정식 자산에 사용하지 않는다.
- 정책·견적·동의·배분 버전을 고정하고, 멱등 키와 정규화 본문 해시를 결속한다.
- 완료 조건은 SEC-01~04, ECON-01, OPS-01이다. 기존 시험 회귀와 새 부정 시험을 함께 통과한다.

### 단계 B 준비금과 토큰 계약

- 새 계약 패키지에 최소 ERC-20, CollateralVault, CustodyVault, 비상 제어·관리 권한을 구현한다. 배포 시 공급량 0·고정 담보·발행 경로·초기 권한·주소 결속을 검증한다.
- 예치와 발행, 소각과 USDC 상환의 원자성·정수·단회 nonce·발행 한도·지급 실패 되돌림을 구현한다. 무담보 mint·관리자 USDC 인출·임의 권한 확장을 막는다.
- 완료 조건은 SEC-05~08, ECON-02~06이다. 로컬 체인에서 적대적 담보·전송 실패·재진입·권한·경쟁·성질 기반 시험과 독립 검토를 수행한다. 이 단계만으로 메인넷을 열지 않는다.

### 단계 C 이벤트와 수탁 원장

- 새 체인 어댑터·이벤트 인덱서·최종성 프로필·체크포인트·출고 작업자·서명 서비스·대사기를 구현한다. `db.py`와 등록 SQL 경계를 잇되 새 스키마를 명시적으로 추가한다.
- 입금 발행과 기존 토큰 재입금을 구분하고, 확정 전 크레딧 금지·이벤트 재생 멱등·고립 블록 처리·결과 불명 상태·DB와 outbox 원자성을 구현한다.
- 완료 조건은 SEC-09~11, ECON-07~10, OPS-02~04다. 동일 블록 기준 R/S/C/B 대사와 복구 후 지급 차단을 증명한다.

### 단계 D 광고와 사용자 지갑

- 기존 `service.py`, `screening.py`, `page.py`, `advertisers.py`를 바탕으로 P1 순수 승인 노출 코인 보상을 추가한다. P2·클릭·재생·체험·가입·구독·구매는 별도 보상 단계로 구현한다.
- 사람 승인 증명·전달 세션·위험 평가·단계 유일 키·최대 보상 사전 잠금을 구현한다. 사용자 코인 지급과 S1의 특정 작업 실행 승인을 분리한다.
- 관리형 에이전트 지갑·권한별 사용·내부 이전·외부 출고·철회·휴면 회수를 연결한다. 외부 자기보관 지갑의 임의 회수를 약속하지 않는다.
- 완료 조건은 SEC-12~14, AD-01~05, PAY-01이다. 실제 사람 화면·접근성·거절·부분 참여·서명·출고 권한의 통합 검수가 필요하다.

### 단계 E AI 작업과 외부 가맹점

- 기존 `private_workflows.py`, `run_results.py`, `test_products.py`의 권한·견적을 재사용하되 결제 작업 정의 해시와 실제 run의 강한 결속을 추가한다. 실행 성공·금전 지급·최종 정산 상태를 분리한다.
- 가맹점 등록·payment intent·수납 확인·capture·부분 수행·환불·분쟁·서명 webhook·USDC 정산을 구현한다.
- 완료 조건은 PAY-02~05와 ECON-11이다. 실제 제공자 샌드박스의 수행·실패·미실행·반복 콜백·정산·환불을 검증하고 제휴 계약과 환불 재원을 확인한다.

### 단계 F 활성화와 성능

- 보안 차단 항목 해결·필수 검수 전체 통과·독립 계약 감사·복구 리허설·키 운영·관할 검토를 완료한다.
- 체인·준비금·고객 자격·법적 주체·주소·서명자·한도·상환 조건이 채워진 활성화 명세를 고정한다. 메인넷·거래소 신청·실제 자금 수납은 해당 작업 범위와 승인을 별도로 확인한다.
- 내부 지연과 원장 처리량을 동일 구간에서 측정하고 외부 최종성·다지역 왕복·실제 사용자 완료 시간을 별도로 보고한다. 성능 개선 때문에 이전 단계 검증·권한·담보 검사를 끄지 않는다.
- 완료 조건은 OPS-05, PERF-01~03이다. 현재 프로젝트 서버를 경쟁 서버로 대체하지 않고 격리 앱·DB·포트로 검증한다. 실제 배포 시 활성 릴리스 기반의 리뷰된 오버레이 원칙을 따른다.

## 3 필수 검수 시나리오

모든 항목은 **앞으로 구현할 검수**다. 아래 목록을 썼다는 사실을 통과로 계산하지 않는다.

- SEC-01: 에이전트 키로 사람 동의·위임 생성·확대·재인증을 호출하면 거부한다.
- SEC-02: 에이전트가 mandate_id를 생략·변조하거나 다른 agent_ref를 보내도 위임 없는 지출을 거부한다.
- SEC-03: 소유자·가맹점·광고주 간 BOLA, 세션·CSRF·Origin·초대 철회·키 철회 우회를 거부한다.
- SEC-04: 같은 키의 다른 본문은 409, 같은 증명·nonce 재전송은 추가 금전 효과가 없다.
- SEC-05: 임의 계정·관리자가 담보 없이 발행하거나 준비금을 인출할 수 없다.
- SEC-06: 다른 체인·토큰·가짜 USDC·변조 주소·잘못된 소수점·음수·float·오버플로를 거부한다.
- SEC-07: 담보 지급 실패·동결·재진입·비표준 전송 반환값에도 소각·발행·준비금이 부분 반영되지 않는다.
- SEC-08: 권한 교체·Guardian·중지·지연·정족수·서명 키 분리와 재개를 검증한다.
- SEC-09: 위조 웹훅·RPC 불일치·이벤트 순서 역전·확정 전 재구성에 사용 가능한 잔액을 만들지 않는다.
- SEC-10: 출고 시간 초과·서버 재시작·대체 거래 때 새 지급을 만들거나 잠금을 조기 해제하지 않는다.
- SEC-11: 체크포인트·동의·원장·서명 nonce가 오래된 백업으로 되돌아가도 재지급·재민팅하지 않는다.
- SEC-12: displayed_ms·foreground·클라이언트 완료만으로 사람 노출 확정을 위조할 수 없다. 보완 신호의 한계와 외부 게시자 위험도 검수한다.
- SEC-13: 광고 자료의 송금·키 요구·프롬프트 주입이 에이전트 지출 권한을 확장하지 못한다.
- SEC-14: 외부 자기보관·계약 지갑 서명과 새 수취인 재인증, 무제한 승인 차단, 철회 이후 작업 차단을 검증한다.
- ECON-01: 기존 시험 잔액을 담보 없이 승계·환산하거나 v1 금액을 v2로 읽지 않는다.
- ECON-02: 시작 공급은 0이며 입금 순액만 한 번 발행한다.
- ECON-03: 광고·지갑 이전·AI 결제·시장 거래는 새 발행을 만들지 않는다.
- ECON-04: 모든 확정 단계에서 INV-01~06과 정수·비음수·분개 균형을 지킨다.
- ECON-05: 준비금·플랫폼 수익·가스·프로모션 재원·수탁 토큰을 구분한다.
- ECON-06: 소각과 상환은 원자적이고 실제 USDC 지급 없이는 소각 성공이 없다.
- ECON-07: 동일 블록의 수탁 토큰과 내부 가용·예약·출고 잠금의 합계를 대사한다.
- ECON-08: 같은 입금·노출·실행·이벤트를 다른 ID로 중복 귀속할 수 없다.
- ECON-09: 이중 결제·예산 소진·동시 출고·철회·상환 경쟁에서 음수·이중 지급이 없다.
- ECON-10: 미집행 환불과 이미 사용자에게 확정된 토큰을 동시에 같은 재원으로 지급하지 않는다.
- ECON-11: 부분 수행·미실행·작업 실패·확정 후 분쟁의 환불을 약정 재원으로 한 번만 지급한다.
- AD-01: 승인 전 소재 노출 없음, 거절·만료 시 보상 예약 해제, 기존 답변 유지.
- AD-02: P1 노출 보상은 추가 답변·클릭·구매 없이 조건 충족 시 지급한다.
- AD-03: P2 피드백의 정답·긍정 여부와 무관한 약정 지급, 기본·추가 보상 분리.
- AD-04: 사용자별·캠페인별 빈도·시간·최대 보상과 선택–재원 분리를 검증한다.
- AD-05: 기계 수신(B1)·사람 노출·브랜드 대화·실제 전환을 분리해 보고한다.
- PAY-01: 사용자 소유권·관리형 임시 보관·내부 이전·외부 출고·철회·회수의 의미를 실제 화면에서 확인한다.
- PAY-02: 주문·자산·수취인·금액·기한·실행 정의 해시가 결제와 일치해야 한다.
- PAY-03: 외부 결제는 요구 최종성 전 유료 작업을 완료 결제로 처리하지 않는다.
- PAY-04: 가맹점 webhook 위조·반복·역순·누락에서 상태 조회로 일관성을 회복한다.
- PAY-05: 실제 제공자 샌드박스 결과와 근거·품질·부분 지급·환불·상환이 일치한다.
- OPS-01: 정책·역할·자산·계정·외부 통신·보존·감사 로그의 개인정보 최소화를 검증한다.
- OPS-02: 처리 중 강제 종료·키 교체·RPC 장애·DB 장애·담보 동결 때 권리·준비금을 보존한다.
- OPS-03: 사람의 실제 로그인과 고객·광고주·가맹점·운영 경계, 보안 헤더와 브라우저 흐름을 확인한다.
- OPS-04: 대사 불일치 경보·중지·재개·백업 복구·고객 이의 제기의 운영 리허설을 수행한다.
- OPS-05: 활성화 필수값·관할 검토·주체·계약·독립 감사·복구 증거가 없으면 mainnet 시작을 거부한다.
- PERF-01: 읽기 20ms·금전 쓰기 50ms·정산 200ms p99와 원장 200건/초를 같은 구간에서 검증한다.
- PERF-02: seed 제외 실제 분개 차이·표본·일정 지연·거부·오류·꼬리 지연·정합성을 함께 보고한다.
- PERF-03: 다지역 왕복·화면·서명·최종성·실제 작업 완료 시간을 내부 지연과 분리한다. 동일 조건 비교 전 세계 최고라고 표시하지 않는다.

## 4 완료 증거와 남은 결정

각 검수에는 정책 ID·대상 커밋/소스 해시·환경·기대 결과·실제 결과·건너뜀 사유·원자료·검토자를 남긴다. 실패·미실행·미해결 건너뜀을 분모에서 빼서 100%로 만들지 않는다. 보안·경제 불변식은 임의 시퀀스·동시성·장애 주입으로도 검사한다.

설계 단계에서 남은 결정은 메인넷과 공식 주소, 상환·수탁 법적 주체·관할, 발행·출고 한도, 서명자, 수수료·최소 금액, 실제 가맹점·제공자·환불 계약이다. 이는 지금 정책·설계 작성을 멈출 이유가 아니며 활성화 명세에서 비워 둔 채 실제 자금을 받지 못하게 한다.

이번 완료 기준은 정책·아키텍처·전환·구현 순서·검수 추적의 문서화와 설계 정합성 검증이다. 스마트 계약 구현·감사·테스트넷·메인넷·상장 신청을 완료했다고 보고하지 않는다.

## 5 설계 검증 원자료

[설계 검증 결과](../reports/ad-coin-design-v5-2026-11-06/validation.json)와 [검증 코드](../reports/ad-coin-design-v5-2026-11-06/validate_design.py)는 문서 연결·정책 추적·정수 배분·단순 회계 모형을 검사한다. 가상 순환의 중복 요청·초과 사용·무담보 발행·미집행 환불과 임의 시퀀스의 불변식을 다룬다. 실제 계약·체인·사람 신원·API·법적 적격성을 검증하지 않으며 예정된 43개 제품 검수의 통과 수는 0으로 남긴다.

Canvas는 같은 자금 순환을 설명하는 모형이다. [Canvas 검증 기록](../reports/ad-coin-design-v5-2026-11-06/canvas-validation.json)은 문법·모형·대체 컴포넌트 실행 검사이며 실자산 UI·실제 브라우저 보안 시험이 아니다.
