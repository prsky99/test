## 4. 공통 화면 뼈대와 디자인 규칙

### 배치

- 데스크톱: 240px 업무 탐색 / 유연한 본문 / 필요할 때만 400~560px 상세 패널. 지원 대화·흐름 편집은 좁은 패널이 아닌 넓은 상세 페이지를 사용합니다.
- 상단: 서비스명, 통합 검색, 내 업무·알림, 사용자·역할, 로그아웃. 본문에는 경로·업무 제목·주요 버튼 하나를 둡니다.
- 제목 아래: 짧은 목적 설명 최대 1~2줄. 핵심 수치 4~6개. 그 아래 필터와 실제 업무 목록. 긴 운영 설명은 “도움말” 또는 “고급 정보”로 접습니다.
- 목록: 한 화면 50건 기본. 25/50/100 선택은 읽기 계약이 지원할 때 제공. 전체 건수·조건 결과 건수·현재 표시 범위를 구분. 정렬은 현재 50건 내부가 아니라 서버 조건으로 처리합니다.
- 상세 닫기·뒤로: 검색어·정렬·필터·페이지·스크롤을 보존합니다. 검토/저장/실행 버튼의 위치를 업무마다 바꾸지 않습니다.
- 1280px 이상은 기본 목록 6~8열. 태블릿은 우선순위 열과 상세 패널. 모바일은 핵심 3~4필드의 읽기 목록과 전체 화면 상세. 가로 스크롤이 필요하면 표 내부에만 생깁니다.
- 본문 가로 넘침, 문자가 한 글자씩 세로로 쌓임, 카드 한 개만 놓인 빈 열, 페이지 중앙 전체 스피너로 장시간 가리는 상태를 금지합니다.

### 글자·색·진주 컨셉

- 운영 어드민은 한국어 업무 문구, 공개 서비스·공개 게시물은 기존 영어 정책을 유지합니다.
- 본문 14px/22px, 표 13~14px/20px, 제목 22~24px, 보조 문구 최소 12px. 중요 상태를 보조 문구 색으로만 표시하지 않습니다. 숫자는 tabular numerals, 단위와 시각을 함께 표시합니다.
- 실제 구현은 현재 pearl-tokens의 공통 토큰을 기준으로 검토하되 다크·라이트에서 대비를 확인합니다. 본문 4.5:1, 큰 글자·비텍스트 경계 3:1을 검증 대상으로 삼습니다. 이 문서는 접근성 인증이 아닙니다.
- 진주는 장식용 카드마다 반복하지 않습니다. **에이전트 하나가 진주 하나**, 연결은 실제 입력·출력 관계, 테두리·상태 글자는 실제 점검/실행 결과입니다. 미확인을 성공 색으로 표시하지 않습니다. 10개 초과는 확대·축소/줄 바꿈으로 처리하며 개수를 임의의 진주 3개로 축약하지 않습니다.
- Lucide 아이콘은 위치 찾기 보조로만 사용합니다. 조회·실행·삭제 아이콘만 놓지 말고 글자 이름을 붙입니다.

### 상태 설계: 모든 화면의 필수 계약

1. **첫 조회**: 제목·필터·도구는 즉시 보이고 데이터 영역에 스켈레톤/짧은 조회 안내. 로그인·권한 확정 전 비공개 내용은 보이지 않습니다.
2. **정상 데이터**: 핵심 수치·첫 페이지를 자동 조회. “현재 상태 조회”를 눌러야 처음 보이는 화면 금지.
3. **실제 데이터 없음**: 무엇이 없고 왜 없는지, 최초 업무를 어떻게 시작하는지 안내. 빈 프레임이나 설명 한 줄만 남기지 않습니다.
4. **검색 결과 없음**: 기존 필터를 보존하고 조건 초기화. 전체 데이터 0건으로 표현하지 않습니다.
5. **조회 실패**: 실패 패널과 범위를 표시. 같은 조회만 재시도 가능. 마지막 성공 자료가 있으면 시각과 함께 유지합니다. 오류를 0건으로 바꾸지 않습니다.
6. **연결 미설정/접근 제한**: 필요한 연결·멤버십·역할을 구체적으로 설명. 권한이 없는데 실행 버튼을 활성화해 놓지 않습니다.
7. **명령 진행**: 누른 버튼과 관련 작업 행에 진행 표시·중복 클릭 차단. 작업이 길면 접수 → 대기 → 실행 중 → 완료/실패/결과 미확인을 구분합니다.
8. **부분 실패/오래된 데이터**: 정상 패널은 유지, 실패 패널만 오류. “10:20 기준 · 갱신 실패”처럼 마지막 확인 상태를 표시합니다.
9. **세션 만료**: 비공개 DOM·임시 응답·상세창 숨김 → 로그인 → 권한 재확인 → 유효한 이전 경로. 비밀값·미전송 외부 입력은 자동 재전송하지 않습니다.

조회와 명령은 타임아웃 정책이 다릅니다. 조회는 다시 조회할 수 있지만, 실행·전송·정정의 응답을 놓치면 명령 ID로 결과부터 확인합니다. 성공을 추정하거나 새 명령으로 재시도하지 않습니다. 작업 총량을 알 수 없으면 가짜 진행률을 만들지 않고 처리 건수·최근 갱신을 보여 줍니다.

자동 갱신은 집계·상태 패널에 한정합니다. 편집 중 폼·선택한 에이전트·스크롤·대화는 유지합니다. 숨김 탭은 주기를 멈추고 다시 보일 때 가벼운 상태 조회만 합니다. 자동 작업에는 중앙 로딩을 띄우지 않습니다. 사용자가 명령을 눌렀을 때 버튼 피드백을 우선하고, 세션 확인처럼 페이지 자체를 사용할 수 없는 동안만 중앙 안내를 씁니다.

## 5. 주요 업무 흐름

### 수집 현황: 문구와 화면을 실제 업무로 교체

기존: “수집 진행은 현재 원본 집계입니다. 실행 버튼은 수집·검색 요청을 등록하며 백그라운드 완료를 의미하지 않습니다.”

새 기본 안내: **“제공자별 수집 상태와 최근 결과입니다.”**

- 상단 상태: “수집 작업자 연결됨 · 마지막 확인 10:20:05” 또는 “수집 작업자 응답을 확인할 수 없습니다 · 마지막 확인 …”. 저장된 진행 정보만 보고 연결됨으로 단정하지 않습니다.
- 제공자 행: “MCP Registry / 수집 중 / 확인한 항목 1,240 / 신규 18 / 변경 32 / 마지막 갱신 10:20”. 숫자는 실제 관측값만 표시합니다. 처리 건수는 중복 제거 후 최종 에이전트 수와 다를 수 있으므로 툴팁에 정의합니다.
- 주요 버튼: “새 에이전트 수집”. 눌렀을 때 변경분 수집을 기본값으로 제안하고, 전체 다시 가져오기는 고급 선택으로 분리합니다. 제공자 개별 실행은 API 지원 전에는 약속하지 않습니다.
- 요청 직후: “수집 요청을 접수했습니다. 대기 중입니다.” + 해당 작업 행.
- 작업 시작: “수집 중 · MCP Registry · 새로 등록 18개”.
- 완료: “수집 완료 · 새로 등록 18개 · 변경 반영 32개 · 완료 10:24”. 완료는 실제 완료 기록이 있을 때만 표시합니다.
- 실패: “MCP Registry에 연결하지 못했습니다. 마지막 성공 09:15.” + 실패 상세 + 재실행 검토. 제공자 실패로 이미 관리 중인 에이전트를 자동 삭제·비활성화하지 않습니다.
- 수집 버튼이 비활성이라면 “수집 작업자 연결 확인 필요”처럼 이유를 바로 표시합니다. 미실행·대기·실행·중단·완료·실패·결과 미확인을 구분합니다.

### 에이전트 테스트

에이전트 이름 검색 → 검증된 도구/동작 선택 → 필수 입력 폼과 샘플 적용 → 외부 공유 대상·입력 검토 → 1회 실행 → 결과·실패 이유 → 동일 보고서 열기. 샘플 적용은 입력만 채우고 실행하지 않습니다. 보고서가 이미 있으면 또 만들지 않고 최신 상태와 원본을 확인합니다. 실패·거부·취소 시 보고서/크레딧을 임의로 생성·차감하지 않습니다.

### 워크플로·직원 도구

작업공간 선택 → 워크플로/저장 버전 선택 → 진주로 단계·입출력 연결 확인 → 실행 또는 배포 업무 선택. 에이전트 검색 결과에는 이름·프로토콜·최근 검증·기능을 보여 줍니다. API 키/제공자 인증이 필요하면 그 단계에 연결 안내를 표시합니다. 외부 실행·권한 발급·릴리스·다운로드는 각각의 기존 권한과 승인을 보존합니다.

### 고객 지원·승인

미배정/내 담당 케이스 → 대화·공유 범위 확인 → 답변/내부 메모 선택 → 전송 확인 → 저장된 결과 확인. 크레딧·계정 제한은 변경 전후가 보이는 승인 요청으로 이동합니다. 단일 “완료” 배지는 접수/승인/반영을 대신하지 않습니다. 전역 승인과 고객 승인은 하나의 큐에서 찾게 하되 서명·정정·실제 실행은 각 원장으로 분리합니다.

### 신규 가입 100크레딧

지급 정책은 신규 무료 플랜 가입 100개 1회입니다. 기존 고객 잔액을 100으로 덮어쓰거나 97개를 추가하지 않습니다. 재가입은 지급을 반복하지 않습니다. 관리자 화면에 잔액·지급 원장·사용 원장·가입 동의 버전을 구분하고 불일치/복원 제한 상태를 보입니다. 정정은 서명 원장·revision 검사·독립 검토를 거칩니다.

## 6. AI는 업무 보조로 배치

이 절은 제안 기능이며 현재 동작한다고 표시하지 않습니다.

- 실패 수집/실행 요약: 관련 오류 코드·발생 시각·대상·근거 링크를 함께 보여 주고 사람이 다시 읽을 수 있게 합니다. 관측이 없으면 “원인 확인 필요”입니다.
- 지원 답변 초안: 현재 케이스의 허용된 자료만 별도 동의로 사용. 내부 메모·비밀값·다른 고객의 자료를 자동 공유하지 않습니다. 초안/수정/전송을 분리합니다.
- 워크플로 초안: 사용자 목적에 맞는 최근 검증 에이전트와 단계별 입력·출력을 제안. 실제 도구·기능·연결을 계약 검증한 뒤 저장하며 이름만 그럴듯한 에이전트를 만들지 않습니다.
- 중복 보고서 검토: 같은 대상·버전·입력·검증 범위 기준의 후보만 표시. 자동 삭제나 성공 보고서로 바꾸는 기능은 추가하지 않습니다.
- 조회 조건 제안: “지난 24시간 실패한 MCP”를 보이는 필터로 변환한 뒤 목록을 조회. 자연어가 운영 명령을 바로 실행하지 않습니다.
- AI 모델 지연·실패는 목록·로그인·수집 상태 확인을 막지 않습니다. 관리자 명령과 에이전트 본문은 신뢰 경계를 분리하고, 프롬프트 인젝션 입력으로 권한·정책·도구를 변경하지 않습니다.

## 7. 구현 구조와 데이터 계약

화면은 Shell → 업무 목록/폼 → 대상 상세 → 승인/진행 상태의 네 계층으로 분리합니다. 업무 모듈마다 `조회·필터·페이지·선택 대상·편집 중 입력·진행 중 명령`을 별도 상태로 관리합니다. URL은 화면/대상/필터를 나타내며 비밀값·고객 본문은 넣지 않습니다.

읽기 모델: 화면별 최소 데이터·서버 페이지/정렬·확인 시각·전체/조건 건수 정의. 목록·집계·상세를 각각 조회하며 무거운 전역 overview 성공을 다른 화면의 선행 조건으로 만들지 않습니다. 초기 인증은 공통이지만 특정 집계 실패가 전체 메뉴를 가로막으면 안 됩니다.

- 수집: worker heartbeat + 현재 crawl_pass + 최근 crawl_runs + 명령 ID/실제 상태. 전용 bounded GET 설계. 기존 전체 overview의 벡터·평가·방문·헬스 전체 쿼리를 호출하지 않습니다.
- 목록: 50개 커서 페이지, 필요한 열만 조회, 인덱스와 PostgreSQL EXPLAIN 확인. 전체 COUNT가 비싸면 캐시 시각을 명시하고 목록 표시를 막지 않습니다.
- 캐시: 집계·일반 목록은 짧은 수명, 민감 고객 본문·원장·승인·키는 별도 no-store. 캐시 키에는 세션·권한·필터 포함. 로그아웃/역할 변경/권한 철회 시 이전 응답 폐기.
- 명령: 요청 ID·예상 revision·사유·승인 범위·명령 결과 조회 계약. 승인 여부나 완료 기록이 없다면 성공으로 표시하지 않습니다.
- 관측: 화면별 첫 유효 데이터 시간·조회 실패율·타임아웃·업무 완료 경로를 개인정보 없이 기록. 로그는 필요한 오류·경계 사건과 집계 중심으로 보관합니다.

새 API 또는 추가 확인이 필요한 화면: 작업 큐 통합, 제공자별 수집 실행·일정 변경, 최근 워크플로 목록, 평가/검색 반영 큐, 통합 서비스 상태, 통합 검색·알림, 기존 결제·설정의 새 UI 계약. 구현 전 응답·권한·상태 전이를 검증하며, 시안의 버튼이 있다는 이유로 기능 지원을 단정하지 않습니다. 전체 대상 정의는 screens.json의 source 항목을 참조합니다.

성능 목표는 실측 결과가 아닌 수용 기준입니다: 대표 운영 데이터와 지정 네트워크에서 인증 후 주요 목록 첫 유효 데이터 p95 2초 이내, 클릭 피드백 100ms 이내, 500ms 이상 조회는 국소 진행 안내, 부분 오류에서 나머지 화면 사용 가능. 측정 환경·표본 수·동시 사용자 수를 기록하고 기준 초과 시 인덱스·쿼리·캐시를 검토합니다. 단순 가짜 데이터 5행의 렌더 속도를 운영 성능으로 보고하지 않습니다.

## 8. 화면별 명세

각 화면은 첫 진입, 주요 행동, 기본 열, 검색 조건, 상세 영역, 빈 상태와 연동 범위를 정의했습니다. 공통 9개 상태와 역할 경계는 모든 화면에 추가 적용합니다.

### H01 · 운영 요약

- 목적: 현재 서비스가 정상인지, 무엇부터 처리할지 판단
- 기본 화면: 서비스 상태 / 현재 카탈로그 / 오늘 점검 / 처리할 일. 핵심 지표는 4~6개만.
- 주요 행동: **처리할 일 보기**. 위험/검토: 조회.
- 기본 항목: 우선순위 / 처리할 일 / 발생 시각 / 영향 / 담당자.
- 검색·필터: 오늘 / 최근 24시간 / 전체 서비스.
- 상세/다음 단계: 수집 상태 / 실행 실패 / 고객 문의 / 승인 대기.
- 기록이 없을 때: 현재 처리 대기 업무가 없습니다. 최근 변경과 정상 상태는 계속 표시합니다.
- 연동·추가 개발 범위: 기존 home/bootstrap + home/work. 일부 패널 실패 시 각각 표시.
- 우선순위: P0. 공통 상태·입력 보존·서버 권한 검사를 포함합니다.

### H02 · 내가 처리할 일

- 목적: 실패·문의·승인을 담당자가 누락 없이 처리
- 기본 화면: 우선순위별 작업 목록을 기본 표시. 클릭하면 해당 업무의 새 상세 화면으로 이동.
- 주요 행동: **우선 업무 열기**. 위험/검토: 조회.
- 기본 항목: 우선순위 / 종류 / 제목 / 담당자 / 기한.
- 검색·필터: 내 담당 / 미배정 / 종류 / 기한.
- 상세/다음 단계: 발생 근거 / 처리 이력 / 연결 화면.
- 기록이 없을 때: 내 담당 업무가 없습니다. 미배정 업무를 확인할 수 있습니다.
- 연동·추가 개발 범위: home/work, 고객 케이스·승인 메타데이터 통합 읽기 모델 추가. 권한은 원본별 유지.
- 우선순위: P0. 공통 상태·입력 보존·서버 권한 검사를 포함합니다.

### A01 · 전체 에이전트

- 목적: 찾고, 비교하고, 상태를 확인
- 기본 화면: 검색·프로토콜·상태 필터와 첫 50개 에이전트. 전체 수와 필터 결과 수를 구분.
- 주요 행동: **에이전트 등록**. 위험/검토: 조회.
- 기본 항목: 에이전트 이름 / 프로토콜 / 현재 상태 / 최근 확인 / 검증 결과 / 제공자.
- 검색·필터: 검색 / 프로토콜 / 상태 / 등급 / 제공자.
- 상세/다음 단계: 기본 정보 / 연결 / 헬스 이력 / 테스트 보고서 / 내부 메모.
- 기록이 없을 때: 등록된 에이전트가 없습니다. 에이전트를 직접 등록하거나 수집을 시작하세요.
- 연동·추가 개발 범위: 기존 /admin/api/v2/catalog/agents. 기본 집계·페이지 각각 독립 조회.
- 우선순위: P0. 공통 상태·입력 보존·서버 권한 검사를 포함합니다.

### A02 · 에이전트 상세

- 목적: 이 에이전트를 추천·테스트해도 되는지 판단
- 기본 화면: 이름·프로토콜·주소·현재 상태·마지막 확인을 헤더에 표시.
- 주요 행동: **이 에이전트 테스트**. 위험/검토: 단일 점검은 확인 후 실행.
- 기본 항목: 확인 시각 / 결과 / 응답 시간 / 오류 요약.
- 검색·필터: 최근 24시간 / 7일 / 30일.
- 상세/다음 단계: 개요 / 연결·인증 / 점검 이력 / 보고서 / 메모.

## 10. 권장 구현·전환 순서

1. **공통 기반과 조회 계약**: 최초 데이터 자동 조회, 오류/권한/빈 결과 구분, URL 상태, 역할별 메뉴, 목록·상세·폼, 중복 명령 방지. 기존 스타일만 덧씌우는 방식 종료.
2. **수집·자동 운영**: C01~C03, 홈 H01~H02. 전용 경량 조회와 실제 작업 상태. 화면 완성 전에 워커 기능을 자동 실행하지 않습니다.
3. **에이전트 관리**: A01~A08. 목록→선택형 테스트→결과→보고서, 키 목록 자동 조회·키 교체.
4. **고객 지원·크레딧·승인**: U01~U08/S01. 공개 답변·내부 메모·정정 원장·역할을 검증.
5. **워크플로·릴리스·전문 기능**: W01~W07/E01~E18. 대상 선택과 진주 흐름, 단계별 입력·출력·외부 실행 검토.
6. **공개 서비스·보안**: P01~P06/S02~S05. 목적별 연락 동의와 게시·알림 승인 유지.
7. **시스템·남은 기능 동등 이관**: T01~T05/U09/C04~C05. 로그·DB·백업·설정·기존 결제 세부 기능 누락 검증.
8. **전체 업무 검수와 운영 전환**: 대표 운영량 성능, 역할별 브라우저·API·보안 검사, 실제 업무 캡처·엑셀 증적. 검증된 메뉴 단위로 전환하고 기존 메뉴별 URL은 새 경로로 매핑. 운영 프로세스 교체는 저장소 운영 지침에 따라 사용자 지시 후 수행.

각 단계의 완료 조건은 시안과 유사한 색·간격이 아니라 “실제 데이터로 업무를 끝내고 결과를 다시 확인할 수 있음”입니다. 이 문서는 설계 산출물이며 위 8단계를 모두 구현 완료한 결과가 아닙니다.
