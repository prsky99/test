# AI AD Coin v2 공개 Sponsored 영역

- **결정:** 11-05 사용자 결정과 11-09 운영 헌장. 광고는 추천 순위와 섞지 않고 별도 영역에 "Sponsored" 표시를 붙여 보인다.
- **구현:** 2026-11-10, AI AD Coin 팀
  - 코드: `agent_market/ad_coin/v2/sponsored.py`, `sponsored_http.py`
  - 시험: `tests/test_ad_coin_v2_sponsored.py`

## 1. 동작

- **경로:** `GET /api/ad-coin/v2/sponsored?category=<작업 분류>&region=<넓은 지역>`
  - v2를 켰을 때만 연결된다(`AD_COIN_V2_ENABLED`).
- **응답:** `{"label": "Sponsored", "disclosure": ..., "reward": null, "cards": [...]}`
  - 카드는 최대 2개다. 카드에는 `id`, `label`, `advertiser`, `text`만 담는다.
- **추천과의 분리:** 이 경로는 추천 결과를 받지도 돌려주지도 않는다. 추천 순위 계산과 연결된 코드가 없다.
- **개인정보:** 로그인, 쿠키, 개인 식별 정보를 쓰지 않는다. 입력은 작업 분류와 넓은 지역뿐이다.
- **보상:** 없다(`reward: null`). 포인트는 따로 동의하고 15초를 보는 흐름에서만 준다.
- **노출 대상:** 활성 상태이고, 심사를 통과했고, 예산이 들어 있고, 광고주가 활성인 캠페인만 보인다. 초안과 심사 전 캠페인은 나오지 않는다.
- **공정성:** 같은 분류·지역의 캠페인을 1분마다 돌아가며 보인다. 사람마다 다르게 고르지 않는다.
- **캐시:** `Cache-Control: public, max-age=60`, `X-Robots-Tag: noindex`

## 2. 속도 (데이터가 늘어도 빠르게)

- 활성 캠페인을 최대 5,000개까지 메모리 스냅샷으로 읽는다. 스냅샷은 60초마다 다시 만든다.
- 요청은 (분류, 지역) 색인에서 찾고, 필요한 카드 2개만 훑는다.

**측정** (2026-11-10, 합성 캠페인 5,000개, 기계 부하 약 15):

| 항목 | 결과 |
|---|---|
| 스냅샷 만들기 | 중앙값 9.2ms |
| 요청 1건 조회 | 85.7µs(목록 전체 걸러내기) → **1.2µs**(필요한 2개만 확인) |

## 3. 함께 고친 결함 (제안 선택)

- **결함:** 사람이 제안을 요청하면(`requestOffer`) 활성 캠페인을 id 순으로 **처음 20개만** 읽고, 그 뒤에 분류·지역으로 걸렀다. 캠페인이 20개를 넘으면 조건이 맞는 캠페인이 제안되지 않을 수 있었다.
- **수정:** 분류·지역 조건을 SQL로 옮겼다(`campaigns_active_candidates_for_target`, `jsonb_exists`). 광고주 권한 잠금도 같은 후보 목록을 쓴다.
- **시험:** `test_offer_candidates_are_filtered_by_target_in_sql`

## 4. 남은 일

- Chat·Explore 화면에 이 영역을 붙이는 일. 공용 프론트 파일이므로 총괄 PM과 다른 팀에 먼저 알린다.
  - 추천 목록 밖에 따로 둔다.
  - 맨 위 줄에 "Sponsored"를 표시한다.
  - 텍스트로만 넣는다(`textContent`).
- 캠페인이 아주 많아지면 쓸 `payload_json` 대상 열의 표현식 색인. 운영 DB 변경이라 승인이 필요하다.
