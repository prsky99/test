# Bounded evaluation, private trust previews and routing recommendations

This source profile implements a finite, private portion of P2-02, P2-03 and P2-04. The concrete MCP evaluation adapter and bounded worker are available but disabled by default. It does not launch public trust pages, qualify production operation, activate a provider, or change the current public recommendation order. All HTTP routes are under the individual administrator session and current workspace authority boundary.

`ReliabilityEvaluation(access, runtime)` stores signed immutable corpus versions, signed owner plans and signed job states in new private tables. Corpus input is explicitly authorized synthetic or licensed data without personal data, validated against the existing documentation/news read contracts. Holdout/evaluation overlap and declared training hash overlap are rejected. A new question is never copied from visitor or customer history. Plans pin the existing current stateless MCP version, exact schemas, approved read tool, owner session and workspace/member revisions. Plan lifetime is at most one day.

Reservations use fixed time windows, deterministic jitter, overlapping per-host reservation budgets, global host serialization and logical deduplication. There are at most 20 corpus cases, 10 plan targets, 16 returned reservations per operation and 500 retained jobs per workspace. Exhaustion is visible coverage debt. This scheduler deliberately uses fixed rules; usage-adaptive prioritization and production acceptance remain future work. No six-hour health or ten-minute quality guarantee is asserted.

The states are `reserved`, `prepared`, `dispatched`, `completed`, `failed`, `unknown` and `expired`. Preparation and reservation are offline. Actual evaluation requires both a trusted read evaluator and a trusted purpose authorizer returning exactly `True`. Neither is configured by browser input. The envelope contains the exact approved case, existing pin and deadline. A scheduler completion is not an independent quality verdict. Adapter exceptions, malformed receipts, expired results and changed authority/control leave `unknown`. The durable dispatched boundary is never invoked twice. An uncertain result cannot replay the same logical job. Cancellation expires undispatched jobs; cancellation after dispatch leaves uncertainty.

`McpReadEvaluator(evaluation, enabled=False, max_seconds=12)` supplies the concrete gateway adapter. It uses the existing `McpProxy` with a shared absolute outbound budget and the exact approved `news.search.v1` or `docs.search.v1` input. It has no credential/payment path, alternative, retry or generic protocol adapter. The engine rechecks the owner session, workspace/member revision, corpus, plan/control revision, existing execution kill switches, restore tombstones, current schema/tool approval and deadline before starting discovery and again immediately before `tools/call`. Output must satisfy the pinned semantic contract and a 64 KiB bound. Only technical outcome/time/reference are retained; no result source or independent quality verdict is fabricated. The existing retained-source/independent-evaluator evidence plane remains separate.

`EvaluationWorker(evaluation, enabled=False)` uses one explicitly started daemon thread, a 1–60 second poll interval and at most 1–8 jobs per tick (default 2). It accepts at most eight explicitly activated workspaces. Activation requires a current named owner and exact current approved plan revision; a configured adapter alone never activates a workspace. Existing control/host budgets and coverage are reused. Only the concrete adapter can power this worker; arbitrary legacy injection cannot silently become background execution. Sessions are held only in process memory and each use is revalidated. Restart requires fresh activation. A prepared job can continue under that current activation; dispatched, unknown and terminal jobs never replay. Stop/deactivate fences the final packet and converts an in-flight result to uncertainty. `close()` fences immediately, joins for at most one second and reports whether the bounded transport has actually drained. No automatic public or operating activation occurs.

The adapter receipt is exactly `outcome`, `observed_at` and `evidence_ref`. The observation time must lie between durable dispatch and receipt. Coverage reads never manufacture an observation or refresh a test date. `evaluation_dispatches` measures durable adapter admissions, not an inferred number of provider network calls. New calendar windows are separate approved evaluation jobs, not reconciliation or replays of an uncertain job.

`ReliabilityTrust(access, evidence_source=plane.get_agent_projection)` reads the actual retained-evidence interface with the current named actor. A writer fence covers source read and final projection. No raw input, output, secret, host, user, stack or runtime field enters the DTO. Positive private `Last verified` requires exact current resource version/schema/contract, a current trusted independent evaluation, verified retained source, a nonempty denominator, an actual observation time, a future expiry and the explicit `approved_external` environment. Synthetic/isolated fixtures remain `Evidence pending`. Operating qualification and public activation remain false.

The SVG uses a fixed local template, fixed colors and escaped bounded text. It accepts no markup, external resource, URL, image, style or event-handler input. JSON and SVG have separate strong ETags. Each conditional request re-reads current evidence, authority, version, revocation and expiry before 304. Responses use `no-store`, including errors, so no positive stale cache policy exists. A copied badge is explicitly described as insufficient to establish current evidence or execution authority.

`ReliabilityRouting(access, runtime, evidence_source=plane.get_agent_projection)` implements only `offline` and `decision_shadow`. Owner configuration explicitly fixes candidates, exact existing read pins, prospective input-sharing scope, workflow graph, current session and expiry. Current execution kill switches, authority, contracts, pins, sharing, evidence qualification/expiry and the absence of an active R-06 fallback policy are rechecked. Open and half-open evidence circuits cannot become a user probe. An open circuit also excludes otherwise healthy candidates on the same host. Operator/dependency correlation beyond a known host requires a future explicitly sourced profile.

The fixed rule ranks qualified equivalent candidates by observed failure/unknown ratio, actual freshness, then the available gateway interval p95 and resource reference. Missing latency is not fabricated. Each signed decision records eligible/excluded candidates, reason codes, rule/policy hash, current evidence hashes, sample count, deterministic propensity and safe feature snapshots. Both modes make zero primary/alternative business calls. The recorded future profile limits are one business call and zero later replacements; these values are not an execution capability and cannot enlarge R-06's budget.

Historical replay repeats the rule against signed snapshots and reports deterministic matches and separate baseline/selected retained-history metrics. Repeated decisions do not multiply the same agent history. It explicitly does not establish paired-corpus success, a causal improvement, live latency or a provider SLA. Online learning and automatic model promotion are absent. A policy can be paused even after its old provider contract has become invalid.

The desktop dialog uses existing theme variables, a local Lucide shield/check path, semantic controls, text-only rendering, unchecked purpose authorizations and a current session/workspace fence. The browser exposes no raw response viewer, token, source bundle or invocation example. New controls are private; the public Workspace release gate remains independent.

Restore integration preserves unknown and dedupe history without rewriting signed payloads. `reliability_controls_restore_blocks` permanently fences old control, plan, job and routing policy authority. A blocked control/policy projects as paused, a plan as quarantined, `reserved`/`prepared` jobs as expired and dispatched jobs as unknown. Expiry recovery skips these signed rows. Fresh explicit owner revisions cannot replay blocked old jobs, and restoring an older valid signature cannot remove its tombstone. A restored corpus is data and does not reactivate its old plan. The shared restore owner populates these tombstones from the restored authority rows before releasing the restored store.
