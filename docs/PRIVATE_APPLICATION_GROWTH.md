# Reviewed private app composition and support observations

2026-10-19. These source profiles are private administrator tools. Public Workspace access remains closed. They do not establish operating readiness, provider quality, legal assent, customer retention or commercial authorization.

## Purpose to a reviewed contract graph

`workspace_app_factory.AppFactory` reuses the existing private typed workflow engine. It offers three fixed two-node read templates: documentation cross-check, news plus documentation, and normalized product evidence plus documentation. Automatic choice is a bounded English keyword rule, not an AI quality verdict. Current approved contract/schema/binding pins are checked independently for each selected agent; the preview presents every exact input and destination. Prior output sharing and execution are never inferred from a task description.

A five-minute signed review binds the current workspace, staff session, membership and resource versions. Saving requires fresh purpose-specific consent. The typed flow and commit receipt share one writer transaction, so a lost acknowledgement can be reconciled by its original review without creating another flow. Saving does not invoke providers, test an agent, issue a deployment grant or publish an app. Actual testing and private SDK2 release continue through their existing separate approval paths.

## SDK compatibility and lifecycle

The source-supported private versions are `workspace-sdk-v2` 2.0.0 and `workspace-typed-sdk-v2` 2.1.0. A current workspace owner may configure a signed revision of admission and sunset policy for either profile. Unknown versions, stale owner authority, restore tombstones and expired policies block new admission and execution. Default absence preserves existing private compatibility; it does not enable public access.

Retained status and history continue to require current customer authority and may remain readable when a compatibility policy blocks new tasks. Deployment origin, expiry, withdrawal and workflow review checks remain independent. Catalog MACs are private integrity evidence, not public signatures or deployment authority. Existing public SDK1 exports are outside this private policy.

## Support evidence and honest outcomes

`workspace_support_outcomes.SupportOutcomes` accepts a structured support category, staff-reported resolution and iteration count only for an actual retained terminal private run. It validates the signed original run and source identity. Single-tool metadata reads deliberately avoid decrypting stored outputs. Raw inputs, outputs, contacts, free-text notes and visitor profiles are not copied into support cases.

Logical run counts deduplicate support categories and revisions. A separately authorized permanent withdrawal excludes a case; deleted or changed original sources and restored cases do not qualify. A count of workflows observed again after 28 days describes retained workflow history, not customer retention. Staff resolution never becomes business success or provider quality. All business outcome qualification stays unassessed; marketing and model-training permission remain absent.

## Private interface and restore

The desktop administrator workspace includes **App factory and SDK**, with composition, lifecycle and support tabs. Native modal dialogs, text-only rendering, fresh unchecked approvals, expiring reviews, no automatic command retry, and session/workspace cleanup preserve the existing security boundaries. Transport uses named staff authentication, current membership, same-origin checks, bounded exact bodies and no-store responses.

Restoration retains signed history unchanged and permanently blocks old reviews, policy revisions and support cases. It never re-signs prior approvals for a new session. A current owner must establish new authority through the normal review paths. Actual Google/GitHub hosting, external provider qualification, production deployment, notification reception, storage load/DR and real payment acceptance still require designated environments and evidence.
