# Agent Concierge 운영 총괄 체계 (2026-11-09 확정)

사용자가 운영 전반을 Claude에게 맡기기로 했다(11-09). 이 문서는 총괄 PM 세션과 팀 세션이 함께 따르는 기준이며, 같은 날 사용자가 "이대로 시작"으로 확정했다.

## 0. 정체성과 경영전략 (2026-11-14 사용자 정의, 상세: `reports/agentcon-strategy-2026-11-14/README.md`)
- **브랜드와 역할:** AgentValCon — 에이전트 밸류 게이트웨이(Agent Value Gateway)
  - 공개 표기(11-14 사용자 결정, 같은 날 변경): 이름은 AgentValCon(Agent Value Concierge·Connector 등 여러 뜻), 부제는 "Agent Value Gateway"다. "Agent Concierge"는 alternateName에만 둔다. 도메인, MCP Registry 이름, 연락 메일은 그대로 둔다.
- **핵심:** "진정한 가치를 찾아서 그 가치를 연결해 새로운 가치를 만들어내는 것"(사용자)
  - 흐름: 수집 → 품질 등급 → 시험 보고서 → **진주 인증** → **진주 목걸이**(진주 2개 이상을 연결한 워크플로우 = 새 에이전트) → 공급(MCP·A2A·웹) → 매일 다시 시험
- **홍보:** 개별 에이전트가 아니라 우리가 만든 목걸이를 홍보한다.
- **품질 원칙:** 목걸이는 같은 정답 세트에서 가장 좋은 단일 진주보다 성공률이 높을 때만 공급한다(Δ > 0). 진주가 고장 나거나 도구 정의가 바뀌면 자동으로 교체하거나 보류한다.
- **대체 원칙(11-14 사용자 추가):**
  - 목걸이의 진주 자리마다 대체 에이전트를 여러 개 준비한다. 순서는 주 진주 → 외부 대체 진주 여럿 → AgentValCon이 직접 만든 대체 에이전트 최대 2개다.
  - 목걸이가 끝까지 실행되게 만드는 것이 우리의 역할이다. 지표는 목걸이 완주율, 단계별 대체 발생률, AgentValCon 대체 사용률이다.
  - 기반: docs/WORKFLOW_FALLBACK.md(지금은 꺼져 있고 범위가 좁음)
- **목걸이 출시 흐름(11-14 사용자 지시):**
  1. 워크플로우 팀: 생산체계(reports/necklace-production-2026-11-14)로 진주 목걸이(새 워크플로우 = 새 에이전트)를 만든다.
  2. 운영·SRE 팀: **품질 95% 이상**을 통과해야 한다(출시 관문). 정답 세트 종단 성공률 95% 이상, 최고 단일 진주 대비 Δ > 0, 완주율, 5초 지연, 보안 시험을 본다. 통과하면 운영·SRE가 프론트엔드 **워크플로우 메뉴**에 적용한다.
  3. 성장·유통 팀: 워크플로우 메뉴에 적용된 새 진주 목걸이(새 워크플로우, 새 에이전트)를 홍보한다.
  - 관문을 통과하지 못하면 워크플로우 팀으로 돌려보낸다. 공개 뒤 매일 재시험에서 95% 아래로 떨어지면 운영·SRE가 보류하고 워크플로우 팀이 고친다.
  - **상시 감시·점검(11-14 사용자 지시: "우리가 만든 진주 목걸이인 워크플로우는 상시 감시와 점검대상")**: 워크플로우 팀이 공개 목걸이와 시험 중인 목걸이 전부를 계속 관리한다.
    - 감시: 매시간 자리별 멤버 헬스와 도구 지문, 매일 정답 세트 종단 재시험(완주율·Δ·p95 지연·대체 발생률), 외부 실행 성공·실패
    - 자동 조치: 주 진주가 실패하면 대체 사슬 순서를 바꾸고, 즉시 보류 조건(보안·지문 변경·성공률 80% 미만·실행·결제 도구)에 걸리면 held로 바꾼다
    - 점검: 매일 현황판에 목걸이별 상태 한 줄, 주 1회 멤버 교체·대체 보강·은퇴 검토, 문제는 생긴 날 고친다
    - 운영·SRE는 관문과 보류 판정을 그대로 맡고, 워크플로우 팀은 감시·수리·멤버 교체를 맡는다
- **목걸이 단계별 대응(11-14 사용자 지시)**: 목걸이의 진주 자리마다 아래 단계로 판정하고 대응한다.
  1. **1단계 정상**: 모든 자리의 주 진주가 문제없이 연결·실행된다.
  2. **2단계 외부 대체 가동**: 어느 자리에서 주 진주 대신 외부 대체 에이전트가 실제로 실행됐다.
     - 워크플로우 팀이 그날 PM에 보고하고, PM은 **에이전트 팀**(자체 대체 에이전트 개발 전담 세션)에 그 자리의 자체 대체 에이전트 개발을 지시한다.
     - 이미 자체 대체가 있으면 그것을 다시 시험해 준비 상태를 확인한다.
  3. **3단계 자체 대체 실행**: 외부 대체까지 모두 실패하면 에이전트 팀이 만든 AgentValCon 자체 대체 에이전트로 그 자리를 실행해 목걸이를 끝까지 완주시킨다.
     - 자체 대체는 운영·SRE 관문(읽기 전용, 출처·라이선스 표기, 정답 세트 통과)을 거친 것만 쓴다.
  4. **4단계 서비스 정지와 대체**: 자체 대체까지 실패하면 목걸이를 정지한다(retired).
     - 워크플로우 팀이 같은 과제를 하는 새 목걸이를 만들어 관문을 거쳐 대체한다.
     - 그 목걸이를 썼던 사용자와 에이전트가 알 수 있게 공지한다: 목걸이 페이지와 워크플로우 메뉴의 정지 안내, MCP 도구·API·A2A 응답의 정지·대체 안내(새 목걸이 이름 포함), 공개 변경 피드, 로그인 사용자 화면 알림.
     - 메일 같은 외부 발송은 사용자 승인 뒤에만 한다.
- **경쟁 원칙:** Glama가 하는 일(목록·헬스·도구 점수)에는 뒤처지지 않는다. 차별화는 "검증된 진주로 만든, 계속 돌아가는 목걸이"에 둔다.
- **북극성(11-14부터):** 외부 클라이언트의 진주 목걸이 실행 성공 건수(하루). 이전의 "외부 실행 성공 쌍"은 보조 지표다.
- **목표(11-28 / 12-26):**
  - 진주: 200 / 1,000
  - 목걸이: 5 / 20
  - 목걸이 종단 성공률: 출시 관문 95% 이상(11-14 사용자 지시, 운영·SRE 검수), Δ > 0 전부 / 평균 Δ +10%p 이상
  - 목걸이 외부 실행 성공: 하루 3 / 20
- **속도·품질 목표:** 차선(3/5/3초, 품질 90%)과 최종(2/2/1초, 품질 100%)은 그대로다. 목걸이 실행에는 "복잡한 답변 5초"를 적용한다.

## 1. 원칙
- **성장 우선, 합법 범위 안에서 공격적으로 (11-09 사용자 결정으로 바꿈):**
  - 속도를 최우선으로 한다. 허용된 모든 채널에 한꺼번에 들어가고, 정해진 관행보다 빠른 방법을 고른다.
  - 다음은 불법이거나 사용자·서비스에 직접 피해를 주므로 하지 않는다.
    - 가짜 리뷰·후기·트래픽·계정
    - 동의 없는 광고성 메시지(정보통신망법)
    - 사실과 다른 성능·순위 주장
    - 광고를 추천인 것처럼 숨기기(표시광고법)
    - 남의 서버에 대한 무단 부하나 자격 증명 사용
    - 파괴적 호출 (시험 호출은 읽기 전용만 한다)
- **변호사 없이 빠르게 가는 경로:**
  - 법률 의견이 필요한 규제 영역(돈을 받고 파는 코인, 현금화·이전되는 포인트, 선불충전, 가상자산 발행·거래)에는 들어가지 않는다.
  - 대신 규제가 필요 없는 수익 모델로 먼저 성장한다.
    - 표시를 붙인 스폰서·광고
    - 일반 SaaS 유료 API·구독
    - 현금화·이전·구매가 안 되는 무상 활동 포인트
  - 실제 가치 코인은 자금과 법률 검토가 준비된 뒤로 미룬다. v1은 시험 전용으로 동결되어 있다(11-09 결정).
- **사람의 결정:** 돈, 계약, 계정, 외부 게시, 법적 약속은 사용자가 결정한다. Claude는 준비·분석·초안·실행 대기 목록까지 맡는다.
- **지출 0 (11-10 사용자 결정):** 수익이 생기기 전에는 돈을 쓰지 않는다. 유료 등록·광고·플랜·가스비·유료 API는 쓰지 않고 무료 경로만 쓴다.
- **코인 기반 수익·지출 (11-10 사용자 결정):**
  - 달러·원화 거래는 아직 하지 않고, 수익과 지출은 코인(AD Coin)으로 한다.
  - 코인으로 생긴 수익은 성장을 위해 언제든 쓸 수 있다. 예: 활동 보상, 제공자·기여자 보상, 노출 지원.
  - 코인 판매, 현금화, 법정화폐 교환 경로는 만들지 않는다(위 규제 회피 원칙).
- **USDC 광고 매출 (11-11 사용자 결정):**
  - 운영비를 위해 수익을 먼저 낸다. 광고 상품(Sponsored 하루 예약)값을 USDC on Base로 예약할 때마다 받는다(출시 가격 5 USDC).
  - 선충전 잔액, AD Coin 판매·전환, 고객 자산 보관, 환전, 송금 대행, 다른 코인으로의 전환은 하지 않는다. 서버는 받기만 하고 개인키를 두지 않는다.
  - AD Coin은 무상 크레딧이자 내부 관리 단위로 남기고, USDC 장부와 섞지 않는다.
  - 제재 주소 대조, 원화 환산·거래 해시 기록은 처음부터 남긴다. 법률·세무 자문과 신고는 수익이 커진 뒤 사용자가 정한다.
- **오류 즉시 처리 (11-10):**
  - 로그 오류와 엣지 게이트웨이의 실패는 생기는 즉시 고친다.
  - 직접 안 되면 논문과 SNS를 검색해 해결한다.
- **품질 100%, 속도는 계속 개선 (11-10):** 모든 품질 목표는 100%다. 데이터가 계속 늘기 때문에 속도는 목표 안이어도 매주 개선한다.
- **멈추지 않는 진행 (11-10):** 느려도 지속한다. 팀은 과제를 끝내면 다음 과제를 스스로 골라 계속한다.
- **기록:** 모든 결정과 결과는 `WORKLOG.md`와 `reports/`에 남긴다.

## 4. 운영 주기
- **매일:** 예약 점검(상태·오류·백업·속도·트래픽 요약). 이상이 있으면 원인을 조사하고, 위임 범위 안이면 고친 뒤 보고한다.
- **매주 월요일:** 주간 보고(지표, 한 일, 다음 주 계획, 승인 대기 목록). 사용자는 승인 대기 목록만 보면 된다.
- **매월:** 목표·지표 재검토, 비용 점검.

## 5. 장기 목표와 단계
"에이전트를 찾을 때 떠올리는 이름(에이전트의 구글)"이 장기 목표다. 순서는 다음과 같다.

1. **쓸모 증명 (지금~3개월):** 외부 에이전트와 개발자가 실제로 쓴다. 지표: 외부 에이전트 세션, MCP 클라이언트 수, 재방문, 추천 정확도 100%(11-10 사용자 결정: 모든 품질 목표 100%).
2. **기본 경로 되기 (3~12개월):** MCP·A2A 생태계의 기본 검색처가 된다(Registry·SDK·클라이언트 연동, 근거 데이터 공개). 이 단계에서 AD Coin 법률 검토를 마치고 결제 없는 광고 시험을 한다.
3. **수익화 (법률 확인 뒤):** 공정한 광고·스폰서 표시와 유료 API를 시작한다. 광고는 추천 순위에 섞지 않고 별도 영역에 표시한다(11-05 결정).
4. **인프라 확장 (수익이 정당화할 때):** 처음에는 클라우드·엣지 지역 확장, 다음에 지역 거점 임대(코로케이션), 자체 데이터센터는 마지막이다.
   - 나라마다 데이터센터를 짓는 일은 한 곳에 수천억~수조 원이 드는 사업이다.
   - 실제 수익과 수요 지표가 근거가 될 때 단계별로 사용자에게 사업 계획을 올린다.
