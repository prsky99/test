# AI AD Coin v6.2 개발 작업과 인수 기준

> 최신 조사에 따른 [v6.2 보강 설계](AD_COIN_PLATFORM_DESIGN_UPGRADE.md)의 DEC-08~13·DES-01~10을 함께 적용한다. 최상위 사업 정책은 v6.1을 유지하며 이전 기계 계약은 역사본으로 보존한다.

2026-11-07 · 기준: [개발 설계](AD_COIN_PLATFORM_ARCHITECTURE.md), [데이터·API](AD_COIN_PLATFORM_DATA_API.md), [최종 정책](AD_COIN_PLATFORM_POLICY.md)

2026-11-08 [상세 설계](AD_COIN_V6_2_DETAILED_DESIGN.md)·DTL-01~20을 추가하고 사용자 승인에 따라 R0 개발을 착수했다. 현재 구현/검증은 [개발 기록](../reports/ad-coin-v6.2-development-2026-11-08/PROGRESS.md)에서 따로 관리한다. 아래 계획 전체를 구현 완료로 바꾸지 않는다.

2026-11-09 WP-03/04 화면 구현을 추가했다. 명시적으로 등록하는 `/ad-coin/v2`에서 사용자 선택→조건 검토→승인→가시 신호→서버 검증 보상과 광고주 작성→심사 요청→예산 승인→활성화→중지/재개→보고 조회를 연결했다. 실제 심사자는 별도 인증 경계를 유지한다. PostgreSQL schema 4 인덱스와 고정 도착률 측정을 추가했으며 [최신 증거](../reports/ad-coin-v6.2-ui-performance-2026-11-09/README.md)를 기준으로 한다. 아래의 11-08 ‘UI 미완료’는 당시 상태이며, 운영 IdP/mTLS·role/RLS·복구·전지역 부하 인수는 계속 남아 있다.

## 1 개발 순서와 완료의 의미

첫 개발 단위는 **격리된 모형 환경에서 광고주 P1 캠페인→심사·승인→사용자 동의→플랫폼 노출→단회 코인 보상→영수증·잔액 확인**이다. 실제 발행·체인 출고 없이도 이 업무를 끝까지 검증할 수 있다. model 자산은 상환 가능한 코인이라고 표시하지 않는다. 실제 AI 작업 결제·발행·상환은 후속 단위와 v5 관문을 통과해야 한다.

각 작업은 PR 등으로 독립 검토 가능한 크기로 구현한다. 아래 파일 경로는 예정 위치이며 이번 작업에서 제품 파일을 생성한 것은 아니다. 완료는 문서 작성이 아니라 지정된 자동·통합·경쟁·복구·브라우저 검증과 리뷰의 증거로 판정한다.

## 2 작업 묶음

**WP-01 · 인증 주체와 v1 위험 경계.** 선행 없음. 현재 `api.py`·`people.py`·`service.py`를 수정해 agent key와 사람 전용 동의·위임 확대·재인증을 분리한다. `/spends`의 actor는 인증된 종류로 고정하고 명세·기한 없는 에이전트 지출을 거부한다. step-up 미구현 경로는 실제 고위험 실행을 허용하지 않는다. 신규 `v2/identity.py`, `v2/policy.py`는 타입화한 Principal을 반환한다. 인수: 다른 owner·에이전트·광고주 BOLA, 키 철회, 인증 혼합, CSRF, mandate 생략·변조, stale authorization의 부정 시험. SEC-01~04·14, GROW-04·07·12·26.

**WP-02 · 자산·스키마·원장·작업 기반.** 선행 WP-01. `v2/db.py`, `v2/accounts.py`, `v2/ledger.py`, `v2/operations.py`, `v2/outbox.py`, 명시적 schema migration과 SQL 허용 목록을 만든다. 모형/실자산 ID·uint256 정수·유일 경제 사건·원장 균형·계정 권리·lease·inbox를 구현한다. 인수: PG의 동시 조건부 잔액·이중 지급·자산 혼합·경계·교착 재시도·commit 직후 종료·outbox 중복. ECON-01·03~05·08~10, OPS-01~04, GROW-06·14·18. v6.2 신규 구현과 모든 DB 시험은 PostgreSQL만 사용한다. SQLite 구현·fallback·시험 경로는 만들지 않는다.

**WP-03 · 광고주·계획·심사·계약 예산.** 선행 WP-02. `v2/commercial.py`, `v2/review.py`, `v2/budgets.py`와 광고주 전용 v2 화면을 만든다. 기존 advertisers의 역할·CSV·심사 UI는 재사용하되 새 revision·editor/approver·다계정 위임·정수 예산을 적용한다. 초기에는 텍스트 P1·UTC 예산 창으로 제한한다. 인수: 미심사·미승인·미충전 활성화 거부, 소재 변경 후 재승인, 다른 광고주 접근, 캠페인 일/총 예산 경합, 지원 지역·형식 제한. GROW-01~03·06·07·11·19·28.

WP-03 구현 진행(2026-11-08): `v2/access.py`·`commercial_schema.py`·`commercial.py`·`http.py`에 저장 권한·불변 revision·심사 근거·fresh 예산 승인·단회 배정/중지/재개와 9개 부분 API를 구현했다. 모델 schema 1→2 명시적 업그레이드이며 DB는 PostgreSQL 전용이다. 검증된 credential resolver·세션 binding·명시적 fresh HMAC key를 주입해야 한다. 기존 앱에는 mount하지 않았고 전체 계약/자동 OpenAPI로 미완성 기능을 게시하지 않는다. 광고주 UI·실제 SSO/reviewer token+mTLS 연결·조직 온보딩은 남아 있으므로 WP-03 전체 완료로 계산하지 않는다. [증거/남은 작업](../reports/ad-coin-v6.2-development-2026-11-08/PROGRESS.md)을 따른다.

**WP-04 · 제안·사람 승인·P1 보상.** 선행 WP-03. `v2/offers.py`, `v2/human_actions.py`, `v2/exposures.py`, `v2/rewards.py`, `v2/receipts.py`와 전용 보상 화면을 구현한다. [첫 OpenAPI 계약](ad_coin_platform_p1_v6_2.openapi.json)을 따른다. 첫 버전은 플랫폼 렌더러만 지원한다. 인수: 승인 전 소재/추적 없음, 빈 답변·무클릭·무구매 P1 지급, 중복 완료·만료 정리·철회 경쟁·검토 중 hold 보존, 서버 검증을 통과하지 않은 클라이언트 시간 거부, 정확한 배분·영수증 지연 처리. AD-01~05, SEC-12~13, GROW-04~06·08·11·20·23·24. 실제 사람이 집중했다는 완전 증명을 주장하지 않는다.

WP-04 재검수(2026-11-08): 모델 29개 handler와 서명/보고/worker를 추가한 뒤 실제 결함을 재현하여 수정했다. 서버 시각 경과·양 끝 visibility·원본 evidence 독립 검증, 최신 안전 정지/승인/한도, nonce 재시도 일관성, lease 만료 rollback, 늦은 지급 보고·private manifest·공개 digest를 보강했다. PostgreSQL schema 3에서 이전 principal 제약과 manifest 열을 명시적으로 이전한다. “전체 완료” 표기는 철회하며 UI·실제 인증/인증서·RLS/role·복구·성능·운영 인수는 계속 필요하다. [재검수 결과](../reports/ad-coin-v6.2-development-2026-11-08/wp04-review/README.md)를 최신 근거로 사용한다.

**WP-05 · 사용자 지갑과 실제 AI 작업.** 선행 WP-02·04. `v2/mandates.py`, `v2/payments.py`, `v2/execution_bindings.py`를 만들고 현재 private_workflows·run_results를 보강한다. 실행 정의·버전·제공자·주문·호출·run을 결속하고 미실행/실패·부분 수행을 별도 정산한다. 인수: 범위 밖·철회 뒤 지출 차단, 실제 제공자 샌드박스 수행과 금전 정산 일치, 고유 run 재사용 거부, 위임 없이 광고 후 자동 작업 실행 금지. PAY-01~05, ECON-11, GROW-13·28.

**WP-06 · 발행·수탁·체인·상환.** 선행 WP-01·02. v5 단계 B~C의 계약·서명 분리·인덱서·동일 체크포인트 대사·unknown 출고·원자 상환을 구현한다. v5 계약과 공식 주소를 임의로 생성해 운영하지 않는다. 인수: v5 SEC-05~11·14, ECON-02~10, OPS-02~05·PERF-01~03. GROW-14·17·27. 독립 계약 감사·실가치 활성화 명세·지역별 적격성은 실제 가치 출시 전 필수다. WP-03~05의 model 업무 개발과 병행할 수 있다.

**WP-07 · 외부 배포와 매체 시장.** 선행 WP-04, 실제 지급은 WP-06도 필요. `v2/inventory.py`, `v2/envelopes.py`, `v2/relay.py`, `adapters/a2a.py`, `adapters/mcp.py`를 검증한 버전별로 추가한다. 일반 탐색·추천은 광고 없는 경우도 유지한다. 인수: 판매 권한·audience·hop 루프·만료·계약/후원 표시·중계 대가 보존, B1과 사람 노출 분리. GROW-02·03·08·19·20·26. 외부 렌더러 적합성 검증 전에는 제안 전달과 플랫폼 화면 연결만 제공한다.

**WP-08 · 브랜드 대화와 추가 단계.** 선행 WP-04·07. `v2/brand_sessions.py`, `v2/stages.py`를 만든다. 승인된 상품 팩, 사용자 선택 공유, 별도 상담·도구 비용 상한, 단계별 기간·중립적 피드백을 연결한다. 인수: 무단 대화 이력 이전 없음, 대화 종료·부정 평가가 기본 보상을 취소하지 않음, 호출 비용 폭주·자동 구매/구독·보상 복제 차단. GROW-05·11·19~21·24·28.

**WP-09 · CRM·전환·귀속·실험.** 선행 WP-04, 서비스 효과 결속은 WP-05. `v2/measurement.py`, `v2/attribution.py`, `v2/experiments.py`, 지원할 CRM/주문 adapter를 추가한다. 첫 외부 연동은 광고주가 실제 사용하는 하나를 계약과 테스트 가능성으로 선정한다. 인수: source/order 중복, 서명 위조·회전·지연·역순·취소, 귀속 재계산과 보상 분리, 관찰 완료 코호트, 대조군 보상 권리 보존, 광고주·독립 측정 대사. GROW-08~10·15·22·28.

**WP-10 · 최적화와 광고주 재집행.** 선행 WP-03·09. `v2/optimization.py`에서 권고→정책 검사→승인→제한 자율 적용을 구현한다. 인수: 예산/지역/소재 범위 확대 시 새 승인, 철회·중지와 경쟁, 사용자 역할·언어·후원·가격 대안 편향 회귀, 통계적 근거 없는 성과 보장 거부. GROW-01·12·15·16·23·26·28.

**WP-11 · 시장 정보·대행사·글로벌 지원.** 선행 WP-03·09. `v2/intelligence.py`, `v2/query_policy.py`, 통계 MCP adapter와 다계정 보고를 추가한다. 인수: 작은 집단·차분 질의·자료 사용권·타 광고주의 기밀·권한 회전·캐시 무효화, 단위·시점·관측 범위·미정의 분모, 미지원 국가 제한. GROW-07·10·15·17·24·25·27.

**WP-12 · 출시·복구·부하·운영 인수.** 각 출시 범위의 선행 작업과 v5 관문을 충족한다. 실제 범위의 GROW-01~28, 보안·브라우저/API 회귀·복구·대사·경제 불변식을 검증한다. 고정 도착률·다지역·표본·실패율·p99·실제 사용자 완료를 측정한다. 최초 200원장 명령/초 관문·1,000/초 도전은 분개 행 수와 구분해 새로 측정하며 과거 seed 포함 행 수를 재사용하지 않는다. 보안·정합성을 꺼서 성능을 맞추지 않는다. 배포 시 실제 활성 릴리스 위에 리뷰한 파일만 overlay하고 사용자 서버를 경쟁 서버로 바꾸지 않는다.

## 3 출시 단위

- **R0 model_p1:** WP-01~04·12의 격리 시험. 가상 재원, 텍스트 P1, 플랫폼 렌더러, 영어 전용 보상/광고주 화면, 사람·agent 역할. 온체인·외부 출고·가입/구매 보상·외부 렌더러·브랜드 상담은 비활성.
- **R1 agent_utility:** R0 + WP-05. 실제 제공자 샌드박스·작업 결속·부분 정산과 실패 환불을 확인한다. 모형 잔액을 실제 제공자 매출로 표현하지 않는다.
- **R2 collateral_backed_p1:** 해당 R0/R1 기능 + WP-06 + 지역·법적·독립 감사·키·수탁·상환·복구 관문. 실제 광고주 재원과 보상을 연결한다. R0 또는 배포 성공만으로 R2를 켤 수 없다.
- **R3 open_network:** 검증한 WP-07~10 범위만 순차 개방. 지원 상품·매체·프로토콜·CRM별 capability를 선언한다.
- **R4 intelligence_global:** WP-11의 자료 품질·권한·지역 검증을 통과한 기능만 판매한다.

연결 프로토콜, 실제 CRM, 체인·주소·발행 주체 등 미정 항목은 각각의 작업에서 검증·결정한다. 미정이어도 R0를 진행할 수 있다. 날짜·일정·인력 수는 가용 자원과 실제 구현 결과 없이 확정 약속하지 않는다.

## 4 개발자가 사용할 검증 기준

v6.2의 DES-01~10을 [보강 설계](AD_COIN_PLATFORM_DESIGN_UPGRADE.md)의 WP 매핑에 따라 추가한다. R0에는 WP-02/04의 사용자 전체 attention quota, fresh/멱등 계약 버전 고정, 검증 가능한 영수증, P1 사실의 UTC 기본 보고 의무·revision·수신 상태를 포함한다. CRM·외부 매출 귀속은 WP-09 후속 범위로 유지한다. 외부 어댑터·모델 호출을 켜지 않아도 이 기본 업무를 검증할 수 있다.

WP-01/02/06/12는 dispatch epoch·lease generation·unknown 결과 복구를, WP-03/08/10은 주장 근거와 외부 검색을 이용한 판단 유도를 검수한다. WP-07은 exact protocol/schema/auth profile을 확정하기 전 신규 프로토콜 버전이나 beta를 활성화하지 않는다. API의 확정 계약 변경은 v6.2 OpenAPI를 기준으로 리뷰하며 이전 명세·증거를 덮어쓰지 않는다.

기계 명세에 38개 정책의 담당 모듈·작업 묶음과 28개 GROW 검수를 연결했다. 기존 v5 검수 43개는 별도 목록을 그대로 유지한다. 필수 검수 범위는 출시 manifest로 고정하고 실패·미실행·건너뜀을 모두 보이게 한다. 범위를 줄여 전체 플랫폼 품질 100%라고 부르지 않는다.

현재 설계 검증은 OpenAPI 구조·JSON Schema·로컬 참조·정책/작업/검수 연결과 순수 상태/정수 예시만 확인한다. 실제 권한·원장·브라우저·계약·동시성·성능을 구현해 통과했다는 뜻이 아니다. 최신 도구와 결과는 [v6.2 설계 검증 기록](../reports/ad-coin-design-upgrade-v6.2-2026-11-07/README.md), 이전 범위는 [v6.1 기록](../reports/ad-coin-development-design-v6.1-2026-11-07/README.md)에 둔다.

각 PR은 정책 ID, contract/schema 변경, migration·SQL 허용 목록, tenant/actor/자산 경계, 장애·재시도, 영향받는 UI/API, 실제 검증과 미검증을 적는다. 기능 공개·실가치 활성화·운영 배포는 해당 단계의 구체 증거와 범위에 맞춰 별도로 수행한다.
