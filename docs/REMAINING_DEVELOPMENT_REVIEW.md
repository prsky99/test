# 남은 개발 작업 — 최신 소스·수용 증거 대조

> 2026-10-20 사용자 범위 결정: 실제 고객을 가상 고객으로 대체하고 별도 로컬 PostgreSQL에서 검증했다. ChatGPT는 보류, Gemini/Claude 구독 로그인은 제외하고 기록만 유지, 결제·hosted CI·동료 승인은 보류한다. [현재 범위와 결과](DEVELOPMENT_REMAINING_AFTER_RESTART.md)를 우선하며, 아래 원래 42개 요구와 과거 실제 수용 조건은 추적 이력이다. 이번 가상 검증을 운영 실검증으로 승격하거나 보류 항목을 자동 재개하지 않는다.

> 최종 코드 검증: [고정 후보 320개 모듈·5,796건 통합 통과 및 운영 버전 차이](../reports/final-frozen-validation-2026-10-19/README.md). 이전의 소스 확정 대기는 해제됐으며, 고정 후보 검증은 완료됐다. 실제 연동·배포 수용은 별도다.

> 이후 실행: [최신 보완·검증 및 남은 조건](../reports/restart-closeout-2026-10-19/README.md). 이 문서의 314개 선택 수와 미실행 설명은 당시 대조 기록이며, 최신 선택은 319개다. 이전 회귀 실패 재검증과 빌드/검사 누락 보완은 최신 보고서를 우선한다.

> 최신 실행: [9단계 개발·검증 및 제공자 조사 기록](../reports/final-nine-execution-2026-10-19/README.md). 다른 수정이 진행 중이라는 사용자 답변에 따라 최종 소스 확정과 전체 완료 판정만 대기한다. 현재 전체 회귀는 진단용이며, 과거/부분 통과 수를 최신 전체 통과로 합산하지 않는다. 원래 42개 요구와 실제 연동 수용 조건을 유지한다.

2026-10-19 · 기존 최종 계획 9단계/42개 요구 유지 · 새 기능 범위 추가 없음

현재는 **지원 범위의 구현·격리 검증이 상당 부분 완료됐지만, 전체 설계의 실제 연동 검증과 최종 인계는 끝나지 않은 상태**다. 남은 항목을 모두 미개발로 보거나, 반대로 소스 파일이 있다는 이유로 완료 처리하지 않는다. 이 문서는 기존 요구 ID를 유지하는 최신 실행 안내다. 원래의 필수 수용 조건을 차기로 옮기지 않는다.

근거: [정적 대조 기록](../reports/remaining-development-audit-2026-10-19/audit.json), [소스 지문](../reports/remaining-development-audit-2026-10-19/source-manifest.json), [원래 마감 계획](DEVELOPMENT_COMPLETION_PLAN.md), [요구별 실행 기록](development-completion-execution.json).

## 이번 확인 범위와 한계

- 기존 42개 요구가 참조하는 고유 증거 경로 107개는 모두 존재한다. 파일 존재 확인은 해당 요구의 기능 완성을 증명하지 않는다.
- 회귀 선택기는 현재 314개 모듈을 선택하고 필수 모듈 누락 방지 검사를 통과한다. AI 제공자·로컬 모델·10단계 브라우저 검사도 선택에 포함된다. 이번에 314개 모듈의 시험을 실행한 것은 아니다.
- 과거 전체 회귀 5,570건 통과의 1,019개 파일 지문과 비교해 30개 변경, 이번 소스 목록에서 14개 추가 경로를 확인했다. 기존 목록의 삭제 파일은 없다. 따라서 과거 전체 통과를 최신 전체 소스의 통과로 표시할 수 없다. 최신 좁은 범위 회귀 증거는 각각 별도로 유지한다.
- 이번 점검은 문서·지정 소스·시험 선택·기존 실제 계정 증거의 대조다. 전체 소스의 모든 실행 경로 재감사, 새 동적 보안검사, 운영 DB 접근, 실제 모델 호출, 서버 재시작은 하지 않았다. 새 보안 취약점이 없다는 인증이 아니다.
- 종료 대조 중 `tests/test_pearl_frontend.py`가 수집 지문 이후 변경된 것을 확인했다. 이 작업에서는 해당 파일을 수정하지 않았으며 변경분을 보존했다. 이번 기록은 고정 릴리스 후보의 전체 검증 결과가 아니다. [문서/지문 대조 결과](../reports/remaining-development-audit-2026-10-19/documentation-check.json).

## 이미 완료해 다시 개발하지 않을 항목

1. **Google/GitHub 기본 가입·로그인·서비스 로그아웃:** 실제 계정으로 확인됐다. 공개 Workspace 링크는 숨기고 직접 주소로 시험하는 설정도 확인됐다. 두 공급자의 계정은 이메일만으로 합쳐지지 않는다. [실제 로그인 증거](../reports/workspace-social-launch-2026-10-19/README.md).
2. **계정에 저장한 샘플 10개:** 실제 64단계 실행, 이전 결과 연결 54개, 두 개의 10단계 체인이 성공했다. 같은 승인된 Paper Finder 한 곳을 재사용한 결과이며, 서로 다른 10개 제공자 검증이 아니다. [샘플 증거](../reports/workspace-account-samples-2026-10-19/README.md).
3. **로컬 Ollama 기반 AI 생성 3개:** 제안→검토→저장→실제 에이전트 실행이 성공했다. 승인된 검색 계약으로 순차 체인을 만드는 제한된 생성기이며 임의의 업무·그래프를 자동 구현하는 기능은 아니다. [AI 생성 증거](../reports/workspace-ai-providers-2026-10-19/README.md).
4. **ChatGPT 로컬 계정 연결·모델 목록 조회:** 연결은 확인됐다. 실제 생성은 주간 한도 오류로 완료되지 않았으며 사용자가 재시험을 보류했다. 자동 재시도나 결제 설정 변경은 없다. [현재 상태](../reports/chatgpt-model-selection-2026-10-19/README.md).

기존 문서의 ‘최대 6노드’, ‘Google/GitHub 미시험’, ‘로컬 모델 응답 미통과’는 해당 시점의 기록이다. 현재 고객 typed 실행기는 최대 10노드/전체 60초/노드 12초이며, 로컬 AI 경로는 제한된 계획을 실제 생성했다. 공개/기존 관리자 실행기의 별도 제한까지 모두 10노드라고 확장 해석하지 않는다.

## 확인된 부분 누락과 남은 연결

- **완료 상태의 문서 동기화:** 기존 실행 기록의 하위 요구와 외부 의존 상태가 일부 서로 다르다. 최신 로그인·샘플·로컬 AI 증거를 요구별로 연결해야 같은 일을 다시 요청하지 않게 된다. 이번에 최신 대조와 해당 상태 설명을 추가한다.
- **ChatGPT의 제품 연결:** `workflow_chatgpt.py`는 명시적인 로컬 평가용이다. 서버 시작은 `OllamaGraphProposer`만 연결하며, 고객별 ChatGPT 연결·전환·철회 UI와 hosted 자격증명 격리 경로는 아직 제공하지 않는다. 로컬 계정 연결 성공만으로 워크스페이스 ChatGPT 기능 완료라고 할 수 없다. 공개 연동은 승인된 hosted 설정을 선행조건으로 유지한다.
- **설계 범위와 실제 시험 범위 차이:** 제한 MCP 검색 체인의 성공은 장기 A2A·다른 계약/제공자·외부 SDK 배포·Push·독립 평가·DB/DR·금융 sandbox 검증을 대신하지 않는다. 이 영역은 구현/격리 시험이 존재하는 부분과 지정 대상의 실제 통합 시험을 나눠 닫아야 한다.

확인하지 않은 일반화 기능을 새로운 필수 개발로 편입하지 않는다. 예를 들어 임의 API 합성, 10개의 서로 다른 에이전트, 모든 LLM 모델 선택, A2A 장기 작업의 typed DAG 내장, 다른 결제사·체인 추가는 현재 지원 profile의 검증과 구분한다.

## 권장 실행 순서 — 한 개의 마감 목록

### 1. 완료표·지원 범위·시험 기준을 최신화

대상: FINAL-01, FINAL-02, FINAL-09.01.

이번 대조 결과를 단일 마감표에 연결한다. 기본 로그인·10개 샘플·로컬 AI 생성·ChatGPT 계정 연결은 재개발 목록에서 제거하고, 실제 생성/외부 수용/공개 활성화의 상태를 각각 기록한다. 현재 10노드와 제한 검색 생성 범위를 명시한다. 요구별 코딩, 실제 통합 시험, 외부 조건, 완료 증거를 같은 ID로 관리한다.

**완료 조건:** 42개 요구의 최신 상태에 서로 모순되는 설명이 없고, 미완료는 아래 2~8번 또는 9번의 인계 조건에 연결된다. 과거 증거는 덮어쓰지 않는다.

### 2. 고객 작성→릴리스→배포·SDK와 검증 알림·신원 복구를 왕복 확인

대상: FINAL-06, EXT-CUSTOMER. 기본 로그인은 재사용한다.

고객 역할로 작성·시험·불변 릴리스·ZIP/외부 배포·게이트웨이 실행·철회/rollback을 실제 보호된 HTTPS에서 확인한다. webhook/A2A inbox는 별도 승인 수신처로 인증·서명·재생 방지·철회를 확인하고, 브라우저 알림은 실제 PushSubscription과 전달된 시험 알림 클릭까지 검증한다. 단독 소유자 복구는 독립 보관 키와 기존 권한 철회까지 시험한다.

**완료 조건:** 조직 간 격리, 오래된 권한 거부, 수신처 검증/철회, 실제 Push 클릭, 복구 시 세션·배포 권한 폐기가 증거로 남는다. 수신처/기기/키 보관자가 없는 항목은 명시된 외부 대기로 둔다. 마케팅 발송은 활성화하지 않는다.

### 3. 승인된 실제 제공자로 A2A·계약·분기 실행 범위를 검증

대상: FINAL-05.01~05.04, EXT-A2A의 장기 작업 부분.

현재 구현된 A2A 세션/stream/resume/cancel profile을 승인된 실제 endpoint로 확인한다. 지원 계약과 typed 분기는 해당 범위의 제공자·검증 가능한 출력으로 시험한다. 입력/이전 출력 연결, 빈 결과, 스키마 변경, 취소·응답 유실·복구 시 unknown 경계를 확인한다. 실패가 재현되는 경우 해당 adapter/권한/입출력 처리만 수정한다.

**완료 조건:** 지원 profile의 실제 왕복 기록과 실패/취소/유실 처리가 연결된다. 별도 비동기 A2A 이력을 typed MCP 노드나 장기 SDK 지원으로 표시하지 않는다. 제공자 10곳을 새로 연결하는 확장 개발은 요구하지 않는다.

### 4. 독립 품질평가→자격→운영 제어·신뢰 경로를 연결

대상: FINAL-04, FINAL-05.05~05.06, FINAL-07, EXT-EVAL, EXT-TRUST.

고정 corpus/rubric/holdout과 독립 평가자·qualifier로 실제 결과를 판정하고, 현재 버전·목적·만료·철회에 묶인 증거가 추천/라우팅/circuit에 소비되는지 확인한다. 지원하는 조기 종료·취소·짝 비교와 자체 문서검색 agent도 같은 평가 기준으로 검증한다. 공개 신뢰 표시는 별도 공개 승인 전 숨긴다.

**완료 조건:** 데이터 형식 통과, 외부 수락, 실제 업무 품질을 구분한 독립 결과와 제어 경계가 남는다. 독립 평가자·corpus·키 보관자가 준비되지 않은 상태를 설정 하나로 완료 처리하지 않는다. 4주 실고객 성과는 수집·분석 코드의 완료와 분리해 관측한다.

### 5. 지정 DB 환경의 부하·전환·백업 복구 시험을 마감

대상: FINAL-03, EXT-DB.

기존 backend 선택·writer fence·보존·restore quarantine을 재사용해 지정된 PostgreSQL/HA 시험 환경에서 대표 동시 부하, writer 전환/rollback, 복원 후 권한 무효화, RPO/RTO를 측정한다. 로컬 임시 PostgreSQL 성공은 재사용하되 운영 대상 검증으로 대신하지 않는다.

**완료 조건:** 목표 workload와 RPO/RTO 기준을 먼저 고정하고 그 기준의 실행 결과·복구 책임자·rollback 절차가 남는다. 운영 DB 전환 자체는 별도 승인 사항이다.

### 6. ChatGPT는 한도 회복 후 로컬 실제 생성부터 마감

대상: FINAL-05.02, 후속 사용자 요청의 계정 기반 AI 연동.

지금은 사용자 지시대로 실제 호출을 보류한다. 재개 요청 후 계정 허용 모델을 다시 확인하고, 승인된 공개 목적을 사용해 완성된 typed 제안과 실행 결과를 확인한다. 로컬 재연결 시 기존 issued client의 재사용·철회/재인증·안전한 오류 안내도 검토한다. 현재 고정 모델 실패 시 다른 모델이나 결제 방식으로 자동 전환하지 않는다.

그 다음 고객 서비스 연결을 진행하려면 승인된 hosted client/HTTPS callback과 고객별 토큰 저장·갱신·철회·provider 선택/권한 재검증을 구현·검증해야 한다. 개인 테스트 토큰을 고객 공용으로 사용하는 방식은 적용하지 않는다. 이것은 로컬 시험 완료와 별개의 남은 제품 연결이다.

**완료 조건:** 로컬은 completed 응답·검증된 그래프·실제 결과를 얻었을 때 닫는다. hosted는 승인 설정, 고객별 격리와 연결/철회 사용자 여정까지 통과해야 닫는다. 한도 회복·승인 대기를 다른 작업 전체의 대기 조건으로 만들지 않는다.

### 7. 결제 sandbox는 계정 자격·사업 결정을 먼저 해결

대상: FINAL-08, EXT-PSP.

기존 Stripe Connect TEST adapter·7:3 원장·환불·이체 취소·중복 event 처리는 다시 만들지 않는다. 현재 확인된 가입 자격으로는 실제 TEST 계정/수신 계정을 확보하지 못했으므로, 적격 계정 또는 명시적인 제공자/설계 변경 결정이 필요하다. 준비된 계정이 생기면 정상/유실/중복/부분 환불/대사를 실제 sandbox에서 시험하고 확인된 차이만 수정한다.

**완료 조건:** 적법하게 사용할 수 있는 선정 sandbox의 실제 수용 증거가 있다. 가입 국가·사업체를 꾸미거나 합성 결과로 닫지 않는다. 이 기능을 이번 완료 범위에서 제외하려면 사용자가 범위 변경을 명시적으로 결정해야 하며, 자동으로 차기로 넘기지 않는다. 실거래·은행 지급은 계속 비활성이다.

### 8. 최종 후보 한 버전으로 기능·보안·CI를 한 번 통합

대상: FINAL-09.01~09.04, EXT-RELEASE.

필요한 수정이 모이면 소스 지문을 고정하고 최신 선택 전체 회귀, 시큐어코딩, 동적 API/브라우저 보안, 콘텐츠/HTML mirror/SQL catalog와 외부 수용 결과를 같은 후보에 연결한다. 현재 선택 모듈은 314개지만 최종 동결 시 다시 계산한다. 이전 5,570건과 최근 좁은 범위 검사를 중복 합산하지 않는다. Hosted CI 결과도 해당 후보에 묶는다.

**완료 조건:** 필수 실패·미구현·확인된 차단 보안 결함이 없고 실제 통합 미시험을 통과로 표시하지 않는다. 소스 변경 후 서버 반영이 필요한 때만 사용자 터미널 재시작·브라우저 확인을 한 번 묶는다. 이번 문서 점검만으로 재시작할 필요는 없다.

### 9. 동료 검토·인계와 공개 활성화를 별도로 결정

대상: FINAL-09.05.

고정 버전, 42개 요구의 완료/대기 증거, 실제 실행/미실행 구분, 설정 항목명, 보안 한계, 실행·rollback 절차와 동료 확인 시나리오를 인계한다. 공개 Workspace 링크는 사용자가 개발 완료를 확인하고 활성화를 지시할 때 연다.

**완료 조건:** 원래 필수 개발·실제 통합 시험을 통과한 범위에 동료 확인이 남고, 미완료 조건이 있다면 전체 설계 완료와 구분해 기록한다. 공개 trust·마케팅 발송·실거래·장기 성과는 각각의 별도 승인/운영 상태를 유지한다.

## 반복을 줄이는 실행 방식

1번의 현재 상태 정리 뒤 2~5번의 지정 대상 준비·시험을 묶어 진행한다. 한도 회복이 필요한 6번과 사업 결정이 필요한 7번은 별도 대기 열로 관리해 다른 작업을 멈추지 않는다. 해당 제공자/profile의 사양이 있어야 하는 코딩은 그 사양을 확정한 뒤 진행한다. 공통 executor·로그인·평가 worker·수신기·원장·보존 도구는 재사용한다.

새 문제가 나오면 기존 요구 ID, 재현 실패, 영향 범위, 수정/검사를 기록한다. 단순 개선 아이디어는 자동 편입하지 않는다. 수정 후 영향 검사를 교체하고, 8번에서 전체 후보를 한 번 검증한다. 문서만 바꾼 이번 작업은 제품 회귀나 서버 재시작을 반복하지 않는다.
