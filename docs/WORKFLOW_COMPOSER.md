## Review and recommended order

The supplied review is a useful inventory, but several items are intentional safety boundaries rather than defects. One alternative per entire run cannot simultaneously permit two alternative calls within a node. This release preserves the existing limit, explicit input-sharing consent and unknown quarantine. Expanding the list of candidates is different from authorizing another external call. Product comparison also needs reviewed dimensions, currency/source timestamps and missing-value behavior; a generic string-to-unit parser is insufficient compatibility evidence. x402 remains a no-spend probe profile, not payment authorization.

The actual restore inventory is a private `<target>.restored-inventory.json` sibling, not a generic public inventory file. Retention reuses SQLite pages and protects active/unknown/replay evidence. A full `VACUUM` on a live database is not a zero-downtime shrink mechanism. Automated deletion, cron scheduling and a production PostgreSQL dialect switch require separate operational acceptance; a successful 27-table rehearsal does not provide a PostgreSQL application adapter. Anonymous 403 and a new PID prove neither authenticated feature correctness nor full G0/G1 acceptance.

Recommended sequence:

1. **Deployment evidence:** inspect existing local Home/admin GET, CSP and anonymous private-route refusal; retain authenticated control/recovery/retention-preview and approved-provider shadow/canary as pending gates. Do not restart the user-owned server or activate production behavior.
2. **R-07 bounded compiler — implemented here:** replace arbitrary popular-agent drafts with IntentSpec → approved candidate retrieval → restricted catalog/model plan → server compilation → fixture check → reviewed private save → explicit actual test → proof-checked publication. Add candidate replacement with identical inputs and fresh separate review/test. Isolate this logic in `workflow_composer.py` rather than enlarging the legacy route.
3. **R-07 evaluation expansion:** one private typed connection and 30 pending-human-review machine cases are implemented in v1.13; v1.14 adds single-run actual-input/source-provenance inspection. The recorded literal-input side-by-side comparison UI is implemented in v1.12. Obtain expert-reviewed task/semantic datasets and held-out provider evidence, then specify a strict connected-pair profile before admitting typed runs. Richer mappings, larger DAGs and active paired-run orchestration remain later work. Keep fixture validity distinct from actual execution and factual/expert quality certification.
4. **Versioned deployment consent:** design opt-in SDK 1.2 separately; bind candidate input sharing to a deployment principal, policy revision, graph/version, one-run nonce and revocation. Retain public SDK 1.0/admin SDK 1.1 downloads. Schedules/events need a separate purpose and expiry contract, not a remembered browser checkbox.
5. **Contract/cascade expansion:** define reviewed product units/currencies and provider adapters first, then test before expanding contracts. Any additional external attempt needs a revised run-wide budget/consent/recovery contract; do not silently turn the current one-alternative policy into a cascade.
6. **Maintenance and storage:** collect read-only size/freelist/WAL/lock evidence, schedule explicit bounded idle maintenance only after acceptance, rehearse offline/copy-based compaction and key handling, then design the full Store/FTS/collector/auth/ledger PostgreSQL adapter and rollback. No automatic VACUUM or runtime dialect toggle is added by this release.

## Implemented profile

Highest-admin private APIs only:

- `POST /admin/api/workflows/ai-generate`: legacy path retained, behavior strengthened. One `prompt` or `intent`; optional `planner=catalog|model`. No workflow is saved, executed, published or delivered by generation.
- `POST /admin/api/workflow-composer/revise`: signed proposal plus one candidate ID per requested contract. Same fixed objective, language, result limit and news period; a new proposal ID resets review/test state.
- `POST /admin/api/workflow-composer/save`: owner-bound signed proposal, explicit authority and `workflow-composer-save-v1` notice. Saves a private active draft only. It does not authorize execution or publication. Repeated explicit saves can create private copies; this is not a distributed idempotent save API.
- `POST /admin/api/workflow-composer/publish`: saved workflow ID, successful run ID, explicit authority and `workflow-composer-publish-v1` notice. Checks the exact immutable tested definition, current pins, routing fingerprint and retained signed per-node checkpoints before publication. Takes the SQLite writer lock around review/publication. Ordinary template create/update/publish paths also require a valid test reference when a compiled binding is present.
- `GET /admin/api/workflow-composer/resolved-input/runs` and `POST /admin/api/workflow-composer/resolved-input` (exactly `{run_id}`): bounded retained private typed-test inventory and single-run inspection. These read-only APIs check actual resolved inputs and source provenance; they cannot generate, execute, compare pairs, create quality evidence or publish.

Private responses use `Cache-Control: no-store`. The public frontend has no composer endpoint and exposes no planner/runtime/configuration details. These private composer/inspection changes do not alter public frontend, metadata, SDK or ZIP implementation sources; the v1.14 public gateway follow-up has a separate scope and report. Published generated templates use the existing public projection and gateway execution/download routes; private binding proofs, versions and approval metadata are excluded from their public graph.

IntentSpec supports only:

- A public objective of 1–500 characters, without URL/contact/secret/template/markup patterns; this is a bounded safeguard, not a complete personal-data detector.
- One or both of `news.search.v1` and `docs.search.v1`, with no duplicates; English output, public data and manual execution.
- One to five results; news lookback of 1–168 hours, fixed at proposal creation.
- By default, one trigger and up to two independent informational agent nodes. Both receive the reviewed objective. The optional private `news-title-to-docs-v1` profile instead connects the first news title to the documentation query under its separate contract. Neither profile consumes untyped raw output. Existing runtime ordering is sequential; parallel execution, arbitrary DAG binding and translation are not claimed.

Retrieval examines at most 30 approved resources per contract and retains at most three eligible current candidates. Every selected candidate needs active/safe stateless MCP, exact supported schemas, explicit safe annotations, current tool approval and unexpired successful execution/contract evidence. Ordering uses recent recorded execution eligibility, quality score and deterministic resource ID; relevance is constrained by the explicitly requested contract, not an expert task-specific quality benchmark. No fallback to unrelated active/popular agents occurs. Labels are fixed contract text plus an opaque reference suffix; untrusted descriptions/names never become planner instructions or executable graph fields.

The proposal signs owner, a 15-minute expiry, IntentSpec, candidates, pins and restricted plan. The server creates all resource/tool/input/node/edge values from this approved set. Saved nodes have separate integrity proofs binding contract, input and full connection/tool approval. Invocation and actual dispatch recheck the pin; output is validated against the contract before success is recorded. Actual contract evidence is recorded separately as `composer-live-test-v1`. Fixture checks never update live evidence. Compiled nodes cannot enable the existing automatic fallback profile; replacement is an explicit separately tested draft until a combined profile is designed.

## Optional model planner

Catalog planning is the default and makes no model request. The model option requires an unchecked per-draft consent to share the reviewed public objective, `model_authority=true` and `workflow-composer-model-v1`. It uses the already configured internal planner URL/model; callers cannot supply either. Only the sanitized IntentSpec and opaque candidate IDs/contracts are sent. No provider URL, credentials, tool description, raw schema, visitor or administrator history is sent.

One request, no automatic repair/fallback, no redirect following, 16 KiB response bound, 4 KiB plan-content bound, client timeouts and a cooperative body-read budget. These are not a hard global wall-time SLA. Strict JSON must select exactly one provided candidate for each requested contract, without adding inputs, URLs, tools, branches or authority. Invalid/oversized/unavailable planner results fail closed and save/execute nothing. Model transport may process a public objective after explicit consent; generation is not authorization to call agents. Real production model quality/availability has not been certified by isolated fixtures.

## Admin interaction

The native centered dialog presents the actual objective, fixed inputs, candidate selectors and factual fixture status. It preserves unrelated builder state and requires separate unchecked save, live-test and public-publication choices. Publication explicitly discloses that the search inputs and agent choices become public. A test uses the saved workflow and an idempotency key; polling does not resubmit it. Replacement keeps the original input and clears saved/run/publication state so another explicit test is necessary. Results from both profiles remain inspectable in workflow run history. **Compare completed tests** supports only independent literal-input tests. The separate **Inspect connected test** dialog verifies one typed run's actual recorded query, complete source checkpoint and target provenance before showing successful contract metrics. It checks that historical principal expiry followed admission and each successful node's start, without requiring that authority remain unexpired today or until the response completed. Current readiness is displayed separately. Connected graphs remain excluded from comparison pairs and public publication; a verified single run is not controlled-pair eligibility. Neither read-only view creates a quality grade. Statistical/expert certification and active paired-call orchestration remain later work.

No browser storage persists proposals or consent. Close, logout and authentication expiry clear private preview state; epoch guards ignore stale asynchronous responses. Candidate controls are disabled while revision/testing is pending. Model permission resets after each request. The existing shared runtime controls, principal checks, 25-second default budget, durable queue/checkpoints and public scope isolation remain authoritative. The initial compiler adds no table. v1.12 adds a recent-run SQLite metadata index at normal runtime initialization, without adding a table; the 27-table storage rehearsal inventory is unchanged.
