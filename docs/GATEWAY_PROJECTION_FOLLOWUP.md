# Public gateway projection follow-up

2026-10-18 · v1.14 · source changes and isolated verification; authenticated deployment acceptance remains separate.

## Review of the supplied findings

The attachment mixes private stored evidence with public responses and includes older snapshots. Standard Chat already uses `QualityRecommender → public_agent`, and existing REST/A2A/MCP tests verify gateway URLs in both text and JSON. Agent details already apply recursive `public_agent` projection to their reports. Therefore, stored upstream text alone does not establish a current public leak, and rewriting historical evidence is not the first fix.

There were real residual boundaries: exact-path URL matching did not cover a known executable path's descendants; legacy/stale response producers lacked an independent final recommendation projection; report detail lookup did not constrain protocol; historical targets could differ from the current resource; and old browser caches could bypass a new server projection. These are addressed here while retaining canonical upstream records and actual registered-provider execution.

Explicit read-only inventory found 836 reports in each of the two supplied databases, not the attachment's 830. Both have zero stored `Upstream` labels under the bounded audit. The collector database has 25 report/resource protocol mismatches, while the secondary gateway database has 95 mismatches and 117 missing resources. Stored raw-binding mentions (193/35) and sensitive-pattern candidates (96/96) are private-storage indicators, **not confirmed public leaks or credential findings**. The live runtime's normal public metadata and authenticated behavior require separate checks. No raw report/credential/address/path was dumped and no database was migrated.

## Applied order

1. **Canonical URL projection:** compare normalized origin/default port and decoded path segments. Exact known bindings and non-root executable path descendants map to the canonical served gateway URL. Provider paths, queries and fragments are not appended to it. Root bindings require explicit connection fields or invocation context; independent same-host documentation/source links survive. Lookalike hosts and sibling paths do not match by string prefix. JSON/percent escapes, nested wire strings and URL dictionary keys are bounded and handled without silent key collision.
2. **Public report boundary:** constrain reports by resource ID and protocol, explicitly force the report connection URL, include historical targets in its private binding set and keep public fields allowlisted. Omit private upstream/configuration sections, traceback blocks and private metadata; redact recognized personal/credential fields, URI credentials and local paths. Retain public report findings/citations and original stored evidence. Oversized historical fields use an explicit unavailable message. Original report author identities are not published. Recognized local file URIs, personal dictionary keys and colliding redacted keys are minimized without silently dropping sibling entries.
3. **Chat response boundary:** independently project structured recommendations, reply text and suggestions for REST/A2A/MCP and the simulator. Malformed, missing or protocol-mismatched identities fail closed as an unavailable recommendation, without inventing a gateway protocol or modifying session-token transport. Candidate ranking and provider facts remain unchanged. Non-list recommendation containers fail closed, and final auxiliary reply fields/text/suggestions receive credential redaction as well.
4. **UI/cache accuracy:** bump the public SWR projection cache to v3 and discard older projection caches while retaining unrelated preferences. Historical wire records are labelled sanitized historical records, not a new live test. Missing grade/status no longer becomes Grade A/HTTP200. Output escaping/CSP and synchronized embedded/extracted HTML remain authoritative.
5. **Operational tools:** retire the four implicit report-rewrite/audit scripts in favor of an explicit existing-file `--db` read-only inventory. Imports and no-argument runs cannot open/create/write a database. Counts are bounded, partial coverage is disclosed, and raw values are never printed. Canonical `resources.url`, approval/version hashes and original wire records remain intact.
6. **Schema semantics:** use the same bounded offline schema guard for registered tool admission and runnable metadata. Unsupported reference/pattern/malformed schemas are omitted rather than advertised with an invented gateway `$ref` or a boolean MCP root. Schema URI annotations are removed only in actual schema nodes; argument names and ordinary `const`/`enum` data survive. If a nonsecret validation literal cannot be published intact because it exposes a known binding or credential, omit the whole descriptor. Existing required credential-field metadata redaction is retained and does not authorize execution. Output schemas keep their own supported shape; they are not subjected to the input-object requirement.
7. **Regression and continuation:** verify public metadata, raw REST/A2A/MCP discovery, managed Testbench execution, source links, actual isolated provider invocation, original catalog preservation, workflow runs and existing ZIP/SDK behavior before continuing R-07. The next source unit is the implemented separate private resolved-input evidence inspector; it does not loosen same-input comparison or authorize new calls.

## Purpose and compatibility boundaries

A registered root URL does not prove that every page on that host is an execution endpoint. Blanket domain-prefix substitution would break documentation, source citations and schemas; appending a provider suffix would advertise a gateway route that is not served. This implementation uses known binding families and purpose context. Unknown, noncredentialed, ambiguous root-origin prose remains unchanged. It is a bounded connection projection, not a universal origin/identity/secret detector. Malformed explicit connection URLs and credentialed source URLs are redacted without inventing targets.

Projection changes the public representation, not the internal routing URL, actual provider arguments, quality evidence or historical execution facts. Public wire records disclose that they are sanitized. Source citation links remain independent of execution links. The x402 machine challenge remains factual and no payment authority is added. Chat continues to display one recommendation, use the selected/default protocol, omit commercial copy and transport its visitor token separately.

Public workflow ZIP/SDK1.0 and admin ZIP/SDK1.1 implementation sources are preserved. The new report projection adds no direct provider endpoint, callback, retry, fallback, delivery or database table. The public Home/meta discovery claims remain accurate; this is boundary hardening rather than a new public feature claim.

## Verification and limits

See [gateway verification](../reports/gateway-projection-followup-2026-10-18/README.md) and the [main design](PLATFORM_ADVANCEMENT_DESIGN.md). Tests use isolated databases, controlled MCP/A2A/x402 transports, Chromium and local TLS/PG fixtures. Source/static/dynamic results do not establish whole-platform vulnerability absence, semantic expert quality, exhaustive live provider coverage or authenticated deployment acceptance.

The user-owned server is never stopped, restarted, replaced or supplemented by a competing project server. New Python changes require a user-managed restart. Read-only GET/CSP/anonymous-denial checks after the previous restart are basic observations; privileged inspection remains pending. No production provider/model task, publication, notification, canary or automatic maintenance is activated.
