# AI AD Coin v6.2 상세 설계서

문서 ID `ai-ad-coin-v6.2-detailed-design` · 2026-11-08 한국 시간 · 상태: 상세 설계 기준안 · R0 구현 진행

## 1 목적과 적용 순서

이 문서는 [사업 정책 v6.1](AD_COIN_PLATFORM_POLICY.md), [플랫폼 설계 v6.2](AD_COIN_PLATFORM_ARCHITECTURE.md), [최신 보강 DEC-08~13](AD_COIN_PLATFORM_DESIGN_UPGRADE.md)을 실제 개발 명령·저장 제약·상태 전이·실패 처리로 구체화한다. 자산·담보·상환의 [v5 정책](AD_COIN_POLICY.md)·[INV-01~06](AD_COIN_ARCHITECTURE.md)은 유지한다. 우선순위는 **완벽 보안 → 고정된 필수 검수 범위의 품질 100% → 글로벌 최고 처리 속도**이며 달성 보증이 아니다.

문서의 수치·잠금·알고리즘은 구현 기준안이다. 2026-11-08 사용자 지시에 따라 v6.2 저장·로컬 시험·동시성 검증은 PostgreSQL 전용으로 고정하며 SQLite를 사용하지 않는다. 운영 기능·키·자금·실행용 migration을 활성화하지 않는다. R0의 첫 계약은 [v6.2 P1 OpenAPI](ad_coin_platform_p1_v6_2.openapi.json)이며 이를 조용히 수정하거나 과거 검증 결과를 덮어쓰지 않는다. 상세화 중 API shape 변경이 필요하면 별도 계약 개정과 검증을 수행한다.

## 2 상세 설계 구성

1. [도메인·권한·공통 요청 규칙](ad_coin_v6_2_detail/01-domain-security.md): 모듈 인터페이스, actor, 권리자, 인가·fresh action·hash·멱등·상태 판정.
2. [데이터·원장·트랜잭션](ad_coin_v6_2_detail/02-storage-transactions.md): 표·FK·유일성·인덱스·예산·분개·노출 시간·경쟁 조건.
3. [API 29개 처리 명세](ad_coin_v6_2_detail/03-api-handlers.md): 입력 검증, 저장·조회, 잠금·부작용, 응답·오류, 재시도 의미.
4. [작업자·체인·AI·외부 광고 연동](ad_coin_v6_2_detail/04-workers-integrations.md): 큐·lease·epoch, 영수증, 보고, 위임·결제·상환·중계·CRM·분석 확장.
5. [화면·운영·시험·이전](ad_coin_v6_2_detail/05-ui-operations-tests.md): 사용자/광고주 상태별 화면, 장애 대응, 필수 검수, 부하·복구·migration 인수.
6. [기계 판독 상세 카탈로그](ad_coin_v6_2_detail/catalog.json): API·처리 명령·트랜잭션·모듈·작업·검수 연결과 개발 기본값.

API·command·트랜잭션·worker ID는 서로 다른 식별자다. API 하나가 트랜잭션 여러 개를 시작할 수 있으며 외부 효과와 DB를 하나의 분산 원자 커밋으로 가정하지 않는다. command 성공·원장 확정·서명 완료·체인 확정·AI 실행 성공을 같은 상태로 합치지 않는다.

## 3 출시 범위

**R0:** 격리 model 자산, 초대/조직/agent binding fixture, 광고주 텍스트 P1, 심사·승인·실재원이 아닌 가상 예산, 사람 동의·플랫폼 렌더러·단회 지급·지갑 조회·JWS 영수증·UTC 기본 보고. 외부 모델·유료 도구·자체 외부 렌더러·실제 발행/상환은 비활성이다. 모형 수치를 실제 매출·담보·상환권으로 표현하지 않는다.

**R1~R4:** 실제 AI 실행 결속, 적격 발행·수탁·상환, 외부 매체·브랜드 상담·CRM·최적화, 시장 정보·글로벌 사업 순으로 확장한다. 이 상세 설계의 확장 명령/메시지는 개발 인터페이스 기준이며 아직 전체 OpenAPI나 실행 migration이 구현됐다는 뜻은 아니다. 각 출시 범위별로 별도 schema·DB·키·계약·법적·보안 인수를 완료해야 한다.

## 4 상세화하면서 고정한 판정

- 캠페인 draft 생성은 돈을 옮기지 않는다. 최초 activation에서 승인된 총예산을 광고주 가용 계정에서 캠페인 가용 계정으로 한 번 이동한다. pause/resume은 같은 금액을 다시 충전하지 않는다.
- 제안 발급은 약속한 모든 단계의 최대 광고 대가를 잠근다. 노출 시작 때 사용자 전체/캠페인별 횟수·시간을 별도로 예약한다. 이 두 예약을 혼동하지 않는다.
- campaign content revision hash와 상태 version/ETag는 별개다. 승인·심사·정지로 ETag는 바뀌지만 승인한 광고 조건의 hash는 바뀌지 않는다. 광고 조건 변경은 새 revision이다.
- 노출 시간은 서버 수신 간격과 검증한 신호의 유효 구간으로 산출한다. 첫 heartbeat 이전 시간·과도한 gap·단순 백그라운드 시간은 유효 노출로 합산하지 않는다. 소프트웨어 신호가 사람 집중의 완전한 증명은 아니다.
- 철회는 새 노출·지출·dispatch를 막는다. 이미 충족한 지급 권리·확정 원장은 보존하고, 미확정 증거는 고정된 cutoff와 검토 절차로 판정한다.
- 원장 커밋 후 서명이 지연되면 `receipt_pending`이며 재지급하지 않는다. 보고 재계산·수신 ACK도 보상을 재실행하지 않는다.
- 공개 API의 읽기는 자금·승인 상태를 바꾸지 않는다. GET 소재 조회를 노출 지급이나 시간 누적의 유일한 근거로 삼지 않는다.

## 5 완료 기준과 증거

이번 산출물의 완료 기준은 기존 29개 operation에 대한 처리 설계, 핵심 저장 제약과 원자 경계, worker/복구, UI 상태, 확장 명령, 정책·WP·검수 추적과 문서 검증이다. 실제 제품 코드 작성·API 실행·PG 경쟁·브라우저·암호 서명·체인·담보·법률·성능 검증은 다음 개발의 완료 기준이다.

[상세 설계 검증 기록](../reports/ad-coin-v6.2-detailed-design-2026-11-08/README.md)은 문서·기계 카탈로그·기존 계약/소스 해시의 범위를 명시한다. 기존 v6.2의 400개 문서 검사와 이번 검사를 합쳐 제품 검수 통과 수로 표시하지 않는다. GROW 28개·DES 10개·v5 43개는 실제 인수 증거가 필요한 계획이다.
