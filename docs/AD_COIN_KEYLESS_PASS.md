# 이용권을 계정 없이 살 수 있게 할까 (AI AD Coin, 2026-11-17, PM 과제, 설계 한 장)

결론
- **개발자 이용권(20 USDC/30일)은 지금 에이전트에게 쓸모가 없다.** 계정 없는 구매 경로도 만들지 않는다.
  - 대신 쓸모가 생기는 신호를 매일 세다가, 신호가 서면 만든다(3절).
- **제공자 이용권(10 USDC/30일)은 계정 없이 팔 수 있다.** 이미 설계된 입구(`AD_COIN_PROVIDER_PASS_AND_NECKLACE_PAID.md` 1절)에 오늘 만든 계정 없는 주문(B)을 그대로 쓴다.
  - 사는 쪽은 에이전트를 운영하는 제공자다. 운영 에이전트가 직접 사고, 알림을 읽어 갈 수도 있다.
  - 이용권 표(`adc2_paid_passes`)가 없어 운영 DB 변경이 필요하다. 그래서 11-18 B 배포 뒤에 한다.

원칙은 그대로다.
- 이용권 1건 = 결제 1건(USDC on Base)
- 자동 갱신·선충전·보관 없음
- 연락처 받지 않음
- 환불 송금은 사용자가 직접 한다.

## 1. 이용권이 실제로 여는 것과, 에이전트에게 쓸모가 있는지

| 이용권 | 여는 것(`USDC_PASS_DESIGN.md` 2절) | 지금 에이전트에게 | 근거(운영 DB 읽기 전용, 2026-11-17) |
|---|---|---|---|
| 개발자 | 높은 호출 한도(무료 한도의 배수, 배수는 아직 미정) | 없음 | 7일 동안 에이전트 지문 1,029개. 최다 123회/주, 상위 1% 44회/주. 공개 한도는 Chat 60회/분이라 닿는 곳이 없다. |
| 개발자 | 광고 없는 결과 | 거의 없음 | 광고는 결과 밖 `sponsored` 칸 한 줄뿐이다. 노출 누계 5회. 에이전트는 그 칸을 무시하면 된다. |
| 개발자 | 서명 피드 대량 접근 | 없음 | 7일 동안 마지막 경로가 피드인 에이전트는 0곳이다. |
| 제공자 | 알림 피드(다운·지문 변경·등급 변화), 노출 집계, 시험 기록 내보내기 | 있음(제공자 운영 쪽) | 우리가 이미 재고 있는 자기 에이전트의 상태를, 가져가는 방식으로 받는다. 제공자가 스스로 하려면 감시를 따로 돌려야 한다. |

- 개발자 이용권의 키·한도·광고 비우기는 아직 구현되지 않았다(9절 경계, 검색과 RAG·운영·SRE 몫).
- 쓸모없는 것을 팔면 문구가 "한도를 올려 준다"는 약속이 되는데, 지금은 아무도 그 한도에 닿지 않는다. 그런 문구는 쓰지 않는다.

## 2. 제공자 이용권: 계정 없는 구매 (B와 같은 방식)

호출 3번이고, 사람 심사 대신 소유 확인을 쓴다.
1. `POST /api/ad-coin/v2/pass {kind: "provider", host}`
   - 서버가 그 자리에서 소유 확인을 한다(`owner_proof`: well-known 파일 또는 DNS TXT). 실패하면 `claim_required`이고, 응답에 확인 방법을 붙인다.
   - 통과하면 `pass_id`, `status_url`, 읽기 키(한 번만 보여 줌)를 준다.
   - 주체 id는 B처럼 읽기 키의 서버 비밀 HMAC이다. 읽기 키는 저장하지 않는다.
2. `GET /api/ad-coin/v2/pass/{pass_id}` + `X-Read-Key`
   - 견적을 준다: 10 USDC + 고유 끝자리, 받는 주소, 체인 8453, 만료 30분.
   - 견적은 이용권 하나에 하나뿐이다(B와 같은 잠금).
3. `POST /api/ad-coin/v2/pass/{pass_id}/payment {tx_hash}` + `X-Read-Key`
   - 공용 결제 엔진으로 확인한다: Base 확인, 제재 대조, 원화 환산·tx 기록, tx 1회 사용.
   - 확정되면 30일이 시작된다.
- 쓰는 동안: 같은 `status_url`과 읽기 키로 알림 피드, 노출 집계, 시험 기록 내보내기를 가져간다. 메일과 웹후크는 없다.
- 갱신: 새 견적 + 새 결제다. 자동 갱신은 없다. 남은 기간은 돈이나 코인으로 바꾸지 않는다.
- 운영자 내림: B와 같다. 재개하지 않고, 못 쓴 기간은 refund_due로 운영자가 직접 돌려보낸다.
- B에서 그대로 가져오는 것:
  - 읽기 키 HMAC 주체, 상수 시간 비교, 틀린 키 404
  - Early-Data·QA 요청은 쓰지 않음, IP당 하루 한도
  - 시스템 주체(자격 증명 없음) + 감사 기록. 사람 확인 흉내는 쓰지 않는다.

## 3. 개발자 이용권: 언제 다시 볼지 (신호)
- 이 셋 가운데 하나가 7일 동안 이어지면 PM에 올린다.
  - 공개 한도의 50% 이상 부른 에이전트 지문이 3개 이상
  - 피드 대량 요청 때문에 페이지 한도에 걸린 거절이 하루 10건 이상
  - 광고 노출이 하루 1,000회 이상
- 신호를 세는 쿼리 하나를 매일 깔때기 줄에 붙인다(운영·SRE와 상의). 숫자는 잰 값만 쓴다.
- 신호가 서면, 계정 없는 구매는 제공자 이용권과 같은 2절 흐름에 `kind: "developer"`만 바꿔서 쓴다. 이때 소유 확인 대신 API 키를 한 번만 보여 준다.

## 4. 필요한 것과 순서 (PM 결정 뒤)
1. 11-18 낮: B 배포(이미 묶음에 있음)
2. 이용권 표 `adc2_paid_passes` 마이그레이션과 복구 SQL → 사본 리허설 → PM 적용(운영 DB 변경 절차)
3. 제공자 이용권 계정 없는 입구 구현과 시험(B 코드 재사용, `kind` 칸), 알림 피드 읽기 경로
4. 성장·유통: `owner/verify` 응답에 `next.pass_quote`를 붙이고 /advertise에 한 줄을 더한다(영어).
- 예상 작업량: 2·3을 합쳐 하루. 막힌 것은 표 생성(운영 DB 변경)뿐이다.
