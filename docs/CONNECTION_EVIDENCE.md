# Versioned connections, capability contracts and readiness (R-03)

Internal implementation contract · 2026-10-18 · source verification and user-operated deployment are separate.

## Identities and immutable versions

`connection_agents` assigns one persistent random `ag_` reference to a catalog resource. Existing numeric resource IDs and `/api/gateway/{kind}/{id}` endpoints remain compatible. `GET /api/connections/{agent_ref}` resolves the reference to a safe, no-store public connection summary. Neither reference nor numeric ID grants additional permission.

`connection_versions` stores immutable private `cv_` versions. The digest covers canonical binding/authentication metadata, the complete surveyed tool schema, completeness, and the implemented profile version. Endpoint, declared/observed authentication, registered JSON-RPC binding/method, full input/output schema or annotations changes create another version. Description-only catalog edits and guide collection timestamps do not change binding identity. Resource URLs remain private catalog bindings; this does not rewrite them to gateway URLs.

Full tool schemas are collected into `resources.usage_full_tools`/`usage_full_hash` separately from the old compact discovery representation. Names are unique, tool collections and nesting are bounded, and every input/output schema keyword is retained. Legacy compact hashes and existing JSON-RPC clients remain supported. Existing compact-only data is marked unsurveyed; it is not silently relabeled as a full schema survey. Collector refresh supplies full baselines through the normal survey path; startup does not contact every provider or backfill live success.

MCP execution compares the complete remote tool list with the surveyed full baseline before calling a tool. A mismatch, including constraints omitted by the old compactor, blocks the tool call and quarantines the resource for survey/review. Live argument validation and compact safety checks remain. Binding/authentication changes during discovery are checked before dispatch. Contract tests pin the approved version; changed versions cannot inherit approval. Workflow snapshots now pin the private connection version alongside the older endpoint/compact schema pins. Old snapshots without that extra field remain compatible.

Profile labels describe this implementation only: MCP stateless tools, A2A synchronous messages, and an x402 no-spend probe. There is no new `/api/v2` invoke route, stateful session/task registry, automatic payment, or provider fallback.

## Three semantic contracts

The immutable definitions in `capability_contracts.py` are `news.search.v1`, `docs.search.v1`, and `products.compare.v1`. All are informational. Inputs are bounded English queries and at most ten results; news also requires a UTC period start, and products require named comparison criteria.

- News requires title, public HTTPS source URL, named source, publication/retrieval time and summary. Publication times must be within the requested period, no later than retrieval, and ordered newest first. Unknown publication time must be null, appear after dated results and set partial=true. The validator never invents a date.
- Documentation requires title, public HTTPS source, excerpt, documented version and retrieval time.
- Product comparison requires a named product, public HTTPS source, bounded attributes containing the requested criteria, and retrieval time. Units are represented in the source-backed attribute strings; this version does not certify arbitrary cross-provider unit conversion.

Schemas reject undeclared output properties. Validators reject private/userinfo URLs, duplicate source URLs, stale/future retrieval, incorrect language/types and incomplete required fields. Validation performs no HTTP fetch and cannot establish the factual truth of an external page. Empty results are allowed by the contract and are not a quality grade or evidence of complete recall.

A superadmin explicitly assigns a registered safe MCP tool to a contract on the current full-schema version. Assignment alone is not success. Reassigning or reapproving a tool invalidates the prior approval's success; a test that spans an approval change cannot certify the new mapping. **실제 계약 테스트** invokes the existing bounded managed gateway with explicit input, checks the actual structured output, and stores contract evidence only for that execution/version. It accepts no supplied output, arbitrary URL, credential, or caller-selected version. Existing provider formats are not automatically claimed compatible. A provider must emit the contract shape; arbitrary normalization adapters, A2A semantic mappings, semantic benchmark certification and fallback remain future work. News/document/product fixture validation is not an exhaustive provider benchmark or a completed 30-case expert-reviewed dataset.

## Evidence, projections and recommendation ordering

`capability_evidence` separates `transport`, `execution`, and `contract` outcomes. It records actual start/finish, recording time, expiry, fixed outcome/error, validator/dataset version, sample counts, optional opaque operation reference and optional validated-output digest. It does not copy prompts, outputs, upstream URLs, destinations, visitor identities, credentials or tokens. x402 probe acceptance stays transport evidence; HTTP 402 or a valid challenge is not task success.

MCP execution, managed synchronous A2A, A2A workflow calls, and new collector tool trials feed execution evidence. Collector trials validate HTTP/JSON-RPC envelope identity before success. Old trial timestamps are not imported as new executions. Managed request timeouts detach late worker evidence before the terminal observation is recorded; a late MCP success cannot promote an uncertain request. The latest execution result for a current version supersedes earlier results; a late historical test cannot overwrite a newer eligibility timestamp. Evidence expires after 24 hours. Old versions and their evidence remain historical metadata, not permission to use a replacement endpoint.

`capability_eligibility` is an indexed per-resource projection for fast ranking. Changes to binding/schema/authentication/active/health fields invalidate it in the same catalog transaction. Guide/details changes also conservatively invalidate it. Public cached DTOs locally recheck the current version/evidence before reuse. Browser cached specifications display pending verification until fresh detail arrives. There is no request-time provider call or model evaluation in recommendation.

Chat preserves relevance/safety/protocol gates and one-result behavior. Recent actual successful execution joins recent report/trial evidence, followed by recent activity and quality grade. Current-version failure/unknown excludes a candidate. Existing reports without execution/version metadata retain their historical catalog ranking compatibility; they do not create `verified_callable` evidence. Explicit version-bound reports cannot certify a different version. The actual `executed_at` drives report recency when present; `created_at` remains report-writing time. Legacy report timestamps are explicitly legacy evidence, not proof of a freshly executed test. Global conversion, billing and customer-tier priority are not introduced.

Public `connection_readiness` distinguishes `profile_available` and `verified_callable`. The latter requires current-profile admission, a full schema baseline for MCP, a recent successful execution, and no later execution failure. A2A uses the fixed synchronous message profile rather than pretending it has an MCP tool schema. `capability_contracts[].verified` additionally requires current explicit approval and unexpired passing contract evidence. Readiness is a scoped recorded check; it is not an SLA, correctness guarantee, or transferable fallback certificate.

## Migration, security and operational limits

Startup adds registry/evidence/approval/eligibility tables, an invalidation trigger, two optional resource columns and four optional report columns. Migration is idempotent; it does not manufacture historical execution times or perform provider calls. The isolated online-backup/reopen test verifies version identity and integrity with the catalog preserved. This is not production recovery, distributed execution, lease/fencing, token audience/grants, or kill-switch implementation; those remain R-04/R-05.

Evidence and version tables preserve history; this implementation does not promise a fixed deletion deadline or a complete long-term analytics denominator. Queries are bounded/indexed and metadata excludes raw personal content. Retention/archival, authenticated actor attribution, provider normalization/benchmark coverage and large-catalog operational capacity remain separate work before expanded rollout. No new advertising, notifications, payment or outside-provider bulk tests are enabled.

File-backed trace writes now use short-lived independent SQLite writers with a 50ms busy timeout; memory tests preserve the same-connection transaction guard. A deterministic held-reader regression verifies completion recording. Real writer contention can still drop observations; coverage remains explicitly incomplete. The operator's next restart and an authenticated/shared-record smoke must verify the source fix in operation.

The user runs both servers. No server process or production database migration is operated by this development task. New source requires the next user restart.
