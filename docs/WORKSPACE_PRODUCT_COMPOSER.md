# Private typed product compilation

`workspace-products-compare-v2` compiles one literal, read-only MCP product comparison inside an explicitly selected private workspace. It does not expand the global news/documentation composer, fallback router, public connection profile or existing SDKs.

A candidate must have a complete, current immutable `mcp-stateless-v1` connection version, an exact `products.compare.v2` input/output declaration in both the full and compact tool catalog, explicit read-only/idempotent/non-destructive annotations, a current exact-tool contract approval, recent successful execution evidence and successful contract evidence recorded after that approval. Missing operating candidates are reported as unavailable. The compiler never approves a provider or manufactures evidence.

The administrator supplies a public product question, language `en`, a result bound and explicit `criterion_id`/dimension pairs. Preparation signs these exact literal inputs, current version/approval and current individual staff-session ownership for ten minutes without calling a provider. Saving creates the private draft, immutable saved snapshot and signed `workspace_product_compositions` sidecar atomically. The sidecar binds workspace/draft/snapshot identity, the saved payload/definition hashes, input and selected pin. A failed save rolls back all three. The base saved artifact remains non-executable and cannot acquire authority through its JSON.

A separate prepare creates one ordinary private execution ticket for the saved fixed input. A fresh, unchecked `workspace-products-test-v2` authorization is required for one external call. Current workspace role, session, execution controls, binding and generation checks remain those of the private executor. The shared staff executor also applies the product sidecar guard at admission/replay, immediately before dispatch and before accepting success; withdrawal or replacement of the exact product approval/evidence cannot silently continue an old composition. Provider work runs outside native database transactions.

Transport success alone does not establish a product contract pass. After a retained private response, the typed v2 validator separately checks its actual structured output, explicit evidence timestamps, dimensions/quantities, currency and price basis. A signed `workspace_product_contract_results` record binds the retained run, sidecar and input hashes to `passed` or `failed`. Successful normalization preserves reported values and exposes incompatible/missing evidence explicitly. The proof identifies its origin as retained private execution; source authenticity, factual correctness, expert review, ranking and currency exchange remain unverified. No automatic winner is selected. An ambiguous transport outcome is retained and never automatically re-executed by this UI.

The sidecar and proof tables are separate from global evidence/approval rows. The product compiler does not certify providers, write a global capability grade, or claim holdout/expert quality. Existing explicit administrative contract tests remain separate. Retained product proof is private scoped content; viewers may inspect it only while current workspace and parent snapshot access remain valid.

Product-composed snapshots are excluded from executable releases and SDK export in this first profile. Release admission and current deployment checks also reject an exact registered product-v2 tool in an unmarked copied literal graph, preventing an artifact copy from bypassing the gate. Fallback, public publication, delivery, scheduling, stateful tools and general DAG composition remain unsupported for this profile.

The native administrative dialog uses the existing individual session transport, current workspace membership and epoch guards. It resets consent when input, workspace, session or dialog state changes, renders provider content as text, and offers read-only history after uncertain submission. It stores no review, ticket, response or permission in browser storage. APIs are nested under the private workspace namespace; no public product compiler API is introduced.

Tests use disposable full Store fixtures, exact synthetic MCP tools/evidence and `httpx.MockTransport`. Chromium uses routed local fixture responses. This demonstrates the specified private workflow and security boundaries, not operating provider acceptance or factual product quality. See the completion report for frozen source hashes, actual counts and remaining acceptance gates.
