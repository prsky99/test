# AI AD Coin 발행과 유통 및 광고 보상 정책 v5

정책 ID `ai-ad-coin-policy-v5` · 수립일 2026-11-06 한국 시간

> 2026-11-07 사업 범위 확장: [광고주 중심 글로벌 플랫폼 정책 v6.1](AD_COIN_PLATFORM_POLICY.md)가 전략·유통·성과·시장 분석·성장 정책을 정한다. 본 문서의 POL-01~24는 발행·준비금·사용자 권리·보상·상환의 기반으로 유지하며 v6.1과 함께 적용한다. [v6.1 실행 기획](AD_COIN_PLATFORM_ROADMAP.md)의 추가 개발·검수 없이 광고 사업이 구현됐다는 뜻은 아니다.

## 1 적용 범위와 문서 효력

이 문서는 지금까지의 사용자 요구를 정식 발행·광고 보상·AI 사용·외부 유통 사업의 개발 정책으로 정립한다. 현재 제품은 가상 재원의 시험 모드이며 이 문서가 정식 발행·실결제·외부 출고를 활성화하지 않는다. [현재 구현](AD_COIN.md)과 [개발 현황 v4](../reports/AI-AD-Coin-implementation-v4-2026-11-06.md)는 구현 증거이고, 이 문서는 앞으로 구현할 규칙이다.

우선순위는 **완벽 보안 → 품질 100% → 글로벌 최고 처리 속도**다. 보안·고객 권리·준비금·정합성을 수익이나 속도를 위해 완화하지 않는다. 완벽 보안은 최상위 목표이며 무취약성 보증이 아니다. 품질 100%는 버전 고정된 필수 검수 범위의 전 항목 통과를 뜻한다.

사용자가 정한 사업 요구는 초기 발행량 0, 실제 광고주 입금 기반 발행, 사용자 승인 노출의 독립 보상, 추가 행동 보상, 수신 에이전트 지갑의 사용자 귀속 임시 보관, 유료 AI 사용, 사용자·다른 에이전트 지갑 이전, 외부 시스템 사용과 향후 상장 준비다. 기존 정책·기능은 이 요구에 맞게 개정한다. 현재 코드에 없는 기능을 구현 완료로 표시하지 않는다.

## 2 발행 자산과 가치 기준

**POL-01** 설계 기본안은 단일 공개 체인의 표준 토큰이며, **1 AI AD Coin을 1 USDC로 상환하는 USDC 100% 담보형 결제 토큰**이다. 초기 공급량은 0이고 선발행·팀 무상 배정·무담보 보상·알고리즘 가격 방어·보유만으로 지급하는 이자를 두지 않는다. 토큰 소수점은 6자리, 내부 계산은 최소 단위 정수로 한다. 기호·메인넷·공식 계약 주소는 발행 전에 확정·공개한다.

이 비율·소수점·단일 체인은 구현을 진행할 **설계 선택값**이며 과거 사용자가 이미 승인한 확정 발행 조건으로 표현하지 않는다. 코드의 1코인당 10원 시험 단위와는 별개다. USDC 담보형은 달러 직접 예치형과 다르며 USDC 가격 이탈·동결·발행사·체인 위험을 포함한다. 달러에 대한 직접 상환권을 자동으로 약속하지 않는다.

**POL-02** 달러 입금 경로는 적격 결제·수탁 파트너를 통해 지원한다. 초기 기술안에서는 실제 USDC로 전환되어 지정 준비금 계약에 들어간 뒤에만 발행한다. 은행 입금 화면·미결제 송금·결제대행사 알림만으로 발행하지 않는다. 다른 스테이블코인·브리지 자산·잘못된 체인의 토큰은 자동 담보 인정하지 않는다.

**POL-03** 발행은 인증된 광고주의 확인된 자산 유입과 연결된 승인 요청으로만 허용한다. 하나의 유입으로 한 번만 발행한다. 광고주 입금액 중 발행 대상 순액을 사전에 알리고, 별도 운영 수수료를 받는다면 그 금액에는 토큰을 발행하지 않는다. 거래소 거래·지갑 이전·광고 노출은 발행 사유가 아니다.

**POL-04** 광고 노출 보상은 이미 발행되어 캠페인 예산에 잠긴 토큰의 이전이다. 예산은 사용자 보상·운영자 대가·직접비·플랫폼 몫과 최대 추가 보상을 모두 충당해야 한다. 플랫폼이 추가 준비금을 기여해도 자동으로 토큰을 발행하지 않는다. 자체 프로모션에 새 발행이 필요하면 플랫폼도 실제 자산을 입금하는 하우스 광고주 절차를 따른다.

## 3 준비금과 상환 및 플랫폼 수익

**POL-05** 준비금은 운영자금·광고 운영비·가스비·고객 토큰 수탁과 분리한다. 대출·재담보·레버리지·임의 운용에 쓰지 않는다. 온체인 담보 보유량과 토큰 총공급량, 내부 수탁 잔액과 출고 기록을 대사한다. 개인정보를 빼고 자산·부채·시점·검증 한계를 보고한다. 준비금 보유 증명만으로 모든 부채가 확인됐다고 표현하지 않는다.

**POL-06** 상환 자격·고객확인·지원 관할·수취 주소·수수료·처리 상태를 사전에 공개한다. 기술 기본안에서는 같은 체인의 공식 USDC로 상환하며 토큰 소각과 USDC 지급이 한 트랜잭션에서 함께 성공하거나 함께 되돌아가야 한다. 소각 후 별도 미지급 채무가 생기는 예외 경로를 도입한다면 그 채무까지 준비금 의무에 포함한 별도 설계가 필요하다.

**POL-07** 미집행 광고비 환불은 아직 광고주 소유인 예산을 반환하거나 해당 토큰을 소각·상환하는 방식이다. 이미 사용자에게 확정 지급한 보상을 뒷받침하는 준비금을 같은 광고주에게 다시 환불하지 않는다. 정상 참여자에 대한 확정 보상은 광고주 불만·광고 수신 철회·부정적 피드백만으로 몰수하지 않는다.

**POL-08** 플랫폼 수익은 광고 집행·운영·성과 중개·외부 가맹점·서비스 유통 수수료에서 만든다. 초기 배분 기본안은 기존 정책의 사용자 50·운영자 10·직접비 15·플랫폼 25%를 잇되, 상품별 확정 견적에 배분 버전을 고정한다. 이미 승인한 보상을 관리자 변경으로 줄이지 않는다.

배분율 합계는 100%이며 사용자율은 최소 40%, 운영자와 직접비율의 합은 최대 40%를 유지한다. 최소 단위 반올림 뒤의 정확한 보상·수수료를 견적에 표시하고, 사용자 보상이 0이 되는 유료 노출 상품은 제안하지 않는다. 작업 후원에 필요한 광고 대가는 약정 사용자 몫이 작업 가격을 실제 충당하도록 계산하며 기존 시험의 원화 경매 최저가를 그대로 이식하지 않는다.

플랫폼 몫을 토큰으로 받았다면 이를 보유하거나 정상 상환하여 수익을 실현한다. 준비금 원금 전부를 매출·이익으로 쓰지 않는다. 수익 배분과 고객 채무의 회계 인식은 계약상 본인·대리인 관계를 검토해 정한다. 공급 확대·상장 가격 상승·사용자 잔액 소멸은 기본 수익원이 아니다.

## 4 광고와 사용자 승인

**POL-09** 콘시어지는 방문 에이전트에게 현재 추천, 작업별 검증 근거가 있는 추가 AI 활용, 필요 코인, 광고로 얻을 코인, 시간과 조건을 설명한다. 방문 에이전트는 사용자의 이익에 맞게 이를 전달한다. 가격만으로 품질 우위를 주장하거나 광고 수익 때문에 일반 추천을 바꾸지 않는다. 브랜드 에이전트의 판매자 역할과 전달 운영자의 대가를 공개한다.

**POL-10** 광고 제안 수신 참여와 실제 광고 한 번의 노출 승인을 구분한다. 제안에는 광고주·보상량·최소 유효 노출 시간·추가 보상 조건·보관 지갑·사용 가능 작업·거절 선택지를 포함한다. 실제 광고 소재는 승인 후 노출한다. 방문·작업 알림 동의를 광고·마케팅·송금 동의로 재사용하지 않는다.

**POL-11** 기본 상품 P1은 **추가 클릭·답변·구매 없이 유효 노출만으로 코인을 지급**한다. 초기 노출 기준은 기존 15초를 참조값으로 삼되 상품별 견적에 고정한다. 클릭·재생 구간·완료·피드백·체험·가입·구독·구매는 독립적인 추가 보상 단계다. 합산 보상인지 최종 총액인지, 자격·검증 기한·최대액을 먼저 알린다.

P2의 피드백은 긍정·부정에 같은 약정 보상을 주고, 보상형 자료임을 광고주에게 알린다. 자동 클릭·에이전트 대리 시청·단순 광고 다운로드를 사람 참여로 판매하지 않는다. B1의 기계 수신은 계약된 운영자 성과이며 사람 노출과 다른 지표·예산·보상이다.

**POL-12** 사람 전용 승인은 로그인한 권리자의 새 상호작용에 결속한다. 에이전트 키만으로 노출 동의·새 위임장·위임 확대·고액 이전 재인증을 만들 수 없다. 일일 횟수·총 시간 등 제한적 사전 승인은 사람이 별도 범위를 정한 경우만 지원하며 기본은 건별 승인이다. 실제 시청은 소프트웨어 신호만으로 완전 증명할 수 없다는 한계를 공개하고 사기 위험을 상품별로 관리한다.

**POL-13** 노출 보상 승인은 유료 작업 실행·자동 구독·사용자 정보 제공·지갑 이전 승인이 아니다. 사용자에게 추가 현금 결제가 필요 없다는 설명은 약정 코인으로 해당 작업 비용이 실제 충당될 때만 한다. 광고 거절을 이유로 기존 일반 답변 품질을 낮추거나 거절 뒤 반복 압박하지 않는다.

## 5 소유권과 지갑 및 에이전트 권한

**POL-14** 광고 보상은 사용자 소유다. 조직 계정이면 권리자가 개인인지 조직인지 참여 전에 정한다. 에이전트는 위임받은 관리 주체이며 자체 운영자의 자산으로 처리하지 않는다. 초기 관리형 에이전트 지갑은 사용자별 하위 계정으로 제공한다. 자기보관 지갑과 플랫폼 수탁의 책임·복구 가능성을 구분한다.

**POL-15** 사용자·다른 에이전트 지갑으로의 이전은 필수 기능이다. 내부 이전과 외부 체인 출고를 명확히 표시한다. 주소 소유·네트워크·공식 토큰·금액·가스비·수취인을 검증하고, 한 번의 권한을 다른 자산·체인·수취인에 재사용하지 않는다. 다른 서비스가 코인을 받으려면 해당 서비스의 수납 연동·계약이 필요하다.

상환 자격을 갖춘 보유자가 상환하거나 다른 사용처를 고르는 것을 AI 작업 구매 강제로 대체하지 않는다. AI 사용 동기는 작업 품질·사용 편의·명확한 혜택으로 만든다.

**POL-16** 에이전트의 지출·이전은 행위자가 인증된 에이전트인 경우 항상 위임을 검사한다. 본문에서 위임 ID를 빼도 사람 행위로 바뀌지 않는다. 위임에는 자산·체인·허용 기능·제공자 또는 수취인·건당·기간 합계·만료·nonce를 고정한다. 무제한 토큰 사용 승인이나 사용자 주 지갑 비밀키의 에이전트 전달을 기본으로 삼지 않는다.

**POL-17** 키 철회는 새 명령·대기 작업·위임을 막고 관리형 에이전트 잔액을 사용자 계정으로 회수한다. 14일 휴면 회수는 초기 관리형 하위 계정에 적용한다. 이미 외부 자기보관 주소로 확정 이전된 토큰을 플랫폼이 임의 회수할 수 있다고 약속하지 않는다. 확정된 체인 거래의 취소 불가능성과 복구 조건을 설명한다.

## 6 외부 시스템과 거래소

**POL-18** 외부 가맹점은 코인 보유 정산 또는 USDC 상환 정산을 선택할 수 있다. 주문별 견적·결제 요청·서명된 완료 알림·상태 조회·부분 수행·환불·분쟁을 제공한다. 결제 확인과 실제 작업 수행을 구분하며 실패한 작업의 환불 재원을 사전에 약정한다. 송금 화면·웹훅 하나·임의 거래번호만으로 결제를 완료하지 않는다.

**POL-19** 초기 유통은 단일 체인이다. 다중 체인·브리지·다른 담보·임의 래핑은 별도 위협 모델·정합성·법적 검토 전 지원하지 않는다. 상장 전에도 제휴 사용이 가능하다. 상장은 거래소의 독립 심사·지원 체인·수탁·유동성 결정이며 발행 완료가 상장을 보장하지 않는다. 1 USDC 상환 목표와 가격 상승 홍보를 혼합하지 않는다.

## 7 보안과 운영 및 출시

**POL-20** 발행·소각·준비금 이동·수탁 출고·권한 변경을 분리한다. 참조안은 비업그레이드형 최소 토큰·준비금 계약, 분리된 다중 승인, 보안 장치로 보호한 키, 지연 적용된 관리 변경이다. 관리자는 담보 없는 발행 권한을 가질 수 없다. 비상 중지는 새 발행·노출·출고·상환 중 무엇을 막는지 구분하고 증거와 이유를 남긴다. 재개는 독립 검토 후 다중 승인한다.

**POL-21** 준비금 부족·담보 동결·RPC 불일치·확정 블록 번복·수탁 대사 불일치·키 침해 때 새 위험 인수를 멈춘다. 실패한 출고를 성공으로 표시하거나 확정 여부를 모르는 요청을 새 지급으로 재시도하지 않는다. 소유권과 이미 생긴 지급 의무는 보존한다. 운영 자본으로 손실·사기·환불을 충당하며 준비금 전용으로 손실을 숨기지 않는다.

**POL-22** 공개 체인에는 개인정보·광고 내용·AI 작업 원문·로그인 식별자·토큰·비밀값을 기록하지 않는다. 불가피한 주소·금액·이벤트의 공개성과 연결 가능성을 설명한다. 해시만 남기면 자동 익명화된다고 보지 않는다. 재무·동의 기록은 기존 최소 5년의 사업 정책을 잇되 최종 법적 기간·개인정보 최소화·삭제·아카이브를 별도 확정한다.

**POL-23** 개발·로컬 모형·테스트넷 실증은 가능하지만, 정식 발행 전에는 관할·발행 주체·수탁·상환·자금세탁 방지·제재·세무·소비자 권리를 확인한다. USDC 담보가 법적 적격 준비금인지, 광고 운영 사업자가 직접 발행해도 되는지는 별도 판단이다. 필요하면 적격 발행·수탁 파트너와 광고 운영 법인을 분리한다. 이번 설계는 금융 인허가나 법률 의견서를 대체하지 않는다.

**POL-24** 실제 가치 활성화는 개발 검수와 별도다. 체인·공식 주소·최종성 프로필·고객 자격·발행 한도·출고 한도·서명자·감사 결과·수수료·상환 약정을 버전 고정한 활성화 명세가 모두 채워져야 한다. 빈 값·시험 주소·미검증 서명자가 있으면 시작을 거부한다. 현재 시험 잔액은 자동 승계하지 않으며 대응 준비금이 없는 전환은 금지한다.

## 8 정책 변경과 적용

POL-01~24는 [기술 설계](AD_COIN_ARCHITECTURE.md), [구현 순서와 검수](AD_COIN_V5_IMPLEMENTATION_PLAN.md)로 구체화한다. 신규 정책·견적·동의는 버전을 기록하며 기존 확정 권리를 소급 축소하지 않는다. 현재 구현 문서와 판매 정책의 원화 단위·시험 상품은 v1 시험 프로필에만 적용하고 정식 발행 프로필과 섞지 않는다.

## 9 공식 자료와 적용 한계

- [ERC-20](https://eips.ethereum.org/EIPS/eip-20): 표준 잔액·이전·승인 인터페이스의 근거. 자체 발행·수탁·상환 보증은 제공하지 않는다.
- [Circle xReserve FAQ](https://help.circle.com/support/en/xreserve-faq?id=kb_article_view&sysparm_article=KB0010617): USDC 담보 예치·발행·소각·상환 구조의 선례. 선정 파트너 대상이며 본 사업의 사용 가능성을 확정하지 않는다.
- [Circle USDC 약관](https://www.circle.com/legal/usdc-terms): 직접 상환 자격과 제한을 확인할 자료. AI AD Coin을 Circle 발행 자산으로 표시하지 않는다.
- [OCC 최종 규칙 발표](https://www.occ.gov/news-issuances/news-releases/2026/nr-occ-2026-92.html): 발행자·준비금·상환·위험관리 규칙의 존재를 확인한 근거. 본 사업의 적법성·적격 담보를 판정하지 않는다.
- [Coinbase 상장 절차](https://www.coinbase.com/en-ca/listings): 상장의 별도 심사와 기술·사업·준법 요건의 근거.

확인 기준은 2026-11-06이며 위 자료의 설명과 본 문서의 설계 선택을 구분한다.
