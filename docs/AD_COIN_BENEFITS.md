# AI AD Coin 포인트 혜택 후보와 비용 0 근거 (2026-11-10)

- **요청:** 11-10 총괄 PM. 혜택은 지출 0 원칙에 맞게 바깥 비용이 들지 않는 것으로만 한정한다. 워크스페이스 코드 담당이 따로 없어 AD Coin 팀이 후보를 정한다.
- **결론:**
  - 지금 바로 쓸 수 있는 혜택은 **워크스페이스 크레딧 하나**다.
  - 자체 에이전트 실행과 기록 보존 연장은 혜택으로 두지 않는다.
- **원칙:** 혜택은 사람의 포인트를 **플랫폼이 직접 제공하는 것**과 바꾸는 것이다. 외부 제공자에게 지급하지 않고, 돈도 오가지 않는다(`docs/AD_COIN_COIN_ECONOMY.md` 5절).

## 1. 후보 비교

|---|---|---|---|
| **워크스페이스 크레딧** | `agent_market/customer_credits.py`: 비금전 크레딧. 가입할 때 한 번 100크레딧(`WELCOME_CREDITS = 100`)을 준다. 1크레딧으로 새 워크플로를 하나 저장하고 그 판을 내려받는다. 추가 크레딧(top-up)은 아직 없다. 크레딧은 현금 가치가 없고 이전할 수 없다 | **0**. 저장은 우리 DB 행과 서명뿐이고, 외부 호출이 없다 | **채택** |

## 2. 채택안: 포인트 → 워크스페이스 크레딧

- **교환 비율(초안):** 10 points = 1 workspace credit. 한 번에 최대 10크레딧, 한 달에 최대 50크레딧.
  - 비율과 상한은 코드 상수로 두고 시험으로 고정한다.
- **흐름:** 두 저장소(포인트는 `adc2_` 원장, 크레딧은 애플리케이션 저장소)를 잇는다.
  1. 포인트를 사람 계정에서 플랫폼 코인 수익 계정으로 옮긴다(`kind=payment`, 멱등 키는 교환 id).
  2. outbox에 "크레딧 지급" 일을 남긴다.
  3. 작업자가 고객 크레딧 원장에 지급 기록을 남긴다(`customer_credits` 관리 변경 경로, 사유 `ad_coin_redemption:<교환 id>`).
  4. 지급이 실패하면 1단계를 같은 키로 되돌린다(환불).
  - 이렇게 하면 한쪽만 반영되는 일이 없다.
- **화면:** 사람 화면의 Rewards 영역에 "Use points" 버튼을 둔다. 확인 화면에는 교환 비율, 남는 포인트, 받는 크레딧을 보이고, 승인한 뒤에만 실행한다.
- **약관과의 관계:** 현재 크레딧 약관은 "top-up은 유료 기능으로 준비 중"이라고 쓴다. 포인트 교환은 유료가 아니므로 약관 문구에 "points earned by activity can be exchanged for credits"를 더해야 한다. 이 약관 문구 변경은 사용자 승인 사항이다(헌장: 약관은 매번 승인).

## 3. 정해야 할 것 (PM·사용자)

1. 교환 비율과 상한(초안: 10:1, 한 번 10, 한 달 50)
2. 크레딧 약관 문구 추가 승인
3. 공용 코드(`customer_credits.py`)에 지급 진입점 하나를 두는 것. 워크스페이스 담당이 없으면 AD Coin 팀이 시험과 함께 맡는다.

## 4. 구현 순서 (11-10 승인: 비율 10:1, 1회 10, 월 50, 크레딧 약관 A안)

- **완료(11-10):**
  1. 교환 상수(`points.py`), 원장 차감 + outbox(`points_exchange.py`), 작업자 처리와 실패 시 환불(`workers.py`). 시험: `tests/test_ad_coin_v2_points_exchange.py` 6개. 실제 크레딧 진입점과 잇는 시험도 들어 있다.
  2. `customer_credits.exchange_points`와 크레딧 약관 v3(기존 v2 동의 유지). 버전 `adcoin-credit-terms-frontend-20261110-r1`로 배포됐다.
- **남은 것:** 화면 버튼과 확인 화면, 운영 작업자에 `credit_grant=CustomerCredits.exchange_points` 연결(v2 운영 연결 뒤), v2 소유자와 고객 id 연결.
