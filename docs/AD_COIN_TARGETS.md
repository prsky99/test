# AI AD Coin 그랜드 오픈 기준: 보안 → 품질 → 속도

- **광고주 플랫폼 확장(2026-11-07):** [정책 v6.1](AD_COIN_PLATFORM_POLICY.md)와 [실행 기획](AD_COIN_PLATFORM_ROADMAP.md)의 GROW-01~28을 출시 범위에 맞게 추가한다. 광고주 재집행·AI 작업 효용·매체 수익·공헌이익을 함께 측정한다. 이 추가 제품 검수는 계획이며 기존 시험 통과와 별개다.
- 소스·문서 갱신일: **2026-11-06**. 사용자 최상위 목표는 **완벽 보안 → 품질 100% → 글로벌 최고 처리 속도**다.
- 보안 위험을 남긴 채 품질·처리량·수익 점수로 상쇄하지 않는다. 보안 관문을 먼저 충족하고, 그다음 정의된 품질 검수 범위 전체를 100% 통과하며, 이 조건을 유지한 상태에서 속도를 높인다.
- **완벽 보안은 지향하는 최상위 목표다.** 유한한 자동 시험·서명·정적 분석으로 미지의 취약점이 전혀 없다고 증명할 수는 없다. 미해결 출시 차단 항목, 미검증 권한·복구 경로를 숨기지 않는다.
- **품질 100%는 검수 범위와 판정 기준을 고정한 뒤의 통과 목표**다. 자동 시험 통과율이 모든 AI 답변의 정확도·모든 실제 사용자 경험의 100%를 보장하지는 않는다.
- **속도:** 화면은 3초 안, 내부 처리는 글로벌 최고를 목표로 한다. 현재 세계 최고라는 실측·독립 비교 증거는 없다.
- 최신 구현과 재검증은 [개발 현황 v4](../reports/AI-AD-Coin-implementation-v4-2026-11-06.md)를 따른다. 아래 외부 비교는 11-05에 설정한 목표의 배경이며 이번에 새로 조사한 시장 순위가 아니다.
- **블록체인·외부 유통 확장:** [정책 v5](AD_COIN_POLICY.md), [기술 설계](AD_COIN_ARCHITECTURE.md)의 POL-01~24·INV-01~06과 [신규 검수 목록](AD_COIN_V5_IMPLEMENTATION_PLAN.md)을 추가한다. 기존 89개 시험·219개 시나리오 통과는 v5의 계약·준비금·상환·외부 지갑을 검증한 결과가 아니다. 아래 10원 금액 단위 규칙은 v1 시험 프로필이며 v5는 USDC와 토큰 최소 단위 정수로 검사한다.

## 2. 그랜드 오픈 관문

### 2.1 보안(1순위): 하나라도 실패하면 오픈하지 않는다

자동 시험 통과 외에 `AD_COIN.md`의 **사람 전용 승인과 에이전트 키 권한 분리, 위임 없는 결제 방지, 노출 증거 신뢰 경계, 고액 이전 재인증**을 출시 차단 항목으로 관리한다. 현재 코드가 이 항목 모두를 충족했다고 판정하지 않는다. 실결제·외부 지급·외부 체인 경로는 해당 구현과 검증이 끝나기 전 닫힌 상태를 유지한다.

| 영역 | 통과 조건 |
|---|---|
| 객체 수준 권한(BOLA) | 다른 사람의 지갑·실행권·실행·위임장·영수증·캠페인·보고서를 읽거나 바꾸는 시도는 모두 거부한다. 광고주 A는 광고주 B의 어떤 것도 보지 못한다 |
| 기능 수준 권한 | 관리자 API는 관리자 토큰만, 광고주 API는 그 광고주의 구성원 역할(소유자·편집자·보기)대로만 쓸 수 있다 |
| 인증·세션 | 쿠키 쓰기에는 CSRF가 있어야 한다. 교차 출처 요청은 거부한다. 에이전트 키는 해시로 저장하고, 철회하거나 초대를 거두면 즉시 멈춘다. 유효한 에이전트 키여도 사람 전용 승인·권한 발급을 대신할 수 없다 |
| 위임·재인증 | 에이전트 행위자는 서버의 인증 주체로 판별한다. 본문에서 위임 ID를 빼거나 사람을 사칭해 한도를 우회할 수 없어야 한다. 고액 타인 이전은 실제 새 인증 증명을 검증해야 한다 |
| 노출 증거 | 클라이언트가 보낸 시간·포그라운드 값과 실제 사람의 노출을 구분한다. 허위 완료·재전송·자동 제출에 대한 위험과 방어 범위를 검증한다 |
| 금액 위변조 | 음수·소수·10원 단위가 아닌 금액, 범위를 넘는 금액, 다른 사람 계정은 모두 거부한다. 모든 분개 합계는 0이고 청구 계정은 음수가 되지 않는다 |
| 재전송·중복 | 같은 멱등 키·동의·노출·실행 기록·오퍼 토큰은 한 번만 반영한다 |
| 경쟁 조건 | 동시에 쏟아지는 노출·이전·결제에도 잔액이 음수가 되지 않는다. 이중 지급과 이중 차감이 0건이어야 한다 |
| 주입 | 광고 소재·메모·이름의 알려진 프롬프트 주입, 자기 보증, 지갑 요구, 숨은 문자, 마크업 패턴을 거부하고 우회 시험을 한다. 패턴 검사만으로 모든 주입이 차단됐다고 보지 않는다. SQL 값은 매개변수로 넘기며 등록 SQL 검사도 유지한다 |
| 서명 | 영수증·견적·오퍼를 위조하거나 한 글자만 바꿔도 검증에 실패한다 |
| 정보 노출 | 오류 응답에 내부 경로·SQL·키가 나오지 않는다. 비공개 워크플로의 입력·출력·이름이 응답에 나오지 않는다 |
| 복구·재원 | 백업 복구 뒤 잔액·동의·재전송 정합성, 키 교체·철회·분실 회수, 실제 지급 재원 대사와 장애 대응을 검증한다. 시험 원장의 균형을 실제 현금 보유 증거로 쓰지 않는다 |

### 2.2 품질(2순위): 100%

- 보안·금전·권한·복구의 필수 시험은 실패 0, 건너뜀 0, 미실행 0이어야 한다. 환경 제한으로 건너뛴 것은 미검증으로 남기고, 해결 후 해당 시험을 다시 실행한다. 단순히 분모에서 빼서 100%로 만들지 않는다.
- 상품·동의·지갑·이전·위임·부분 실패·환불·정산·광고주 심사·추천 독립성·실제 고객 화면을 포함한 검수 목록과 기대 결과를 버전 고정한다. 기획 기능 중 미구현인 순수 노출 코인 보상·추가 성과 상품은 구현 완료와 구분한다.
- 약정한 유료 작업의 품질은 작업별 기준과 실제 제공자 결과로 검증한다. 동일 제공자 요청 필드나 A·B 등급만으로 결과 정확도 100%를 보증하지 않는다.
- 리허설 전 단계에서 재원 불변식 위반 0, 불균형 분개 0, 음수 청구 0이어야 한다. 의도하지 않은 회로 열림도 0이어야 한다.
- 오류 응답 비율 0%(의도한 거부 응답은 제외)이고, 보내지 못한 요청도 0이어야 한다.
- 월간 후원 감사에서 "바뀜"이 0건이어야 한다.
- 후원 감사의 오류·흔들림·비교 불가 표본도 기록한다. 충분한 유효 표본과 후원 켬 실행 증거가 없으면 전체 통과로 판정하지 않는다.

### 2.3 속도(3순위)

내부 처리 시간은 서버가 요청을 받아 응답을 만들 때까지의 시간이다. 네트워크와 TLS는 뺀다. 단일 운영 노드(PostgreSQL 18)에서 p99로 판정한다.

| 경로 | 관문(오픈 조건) p99 | 도전(세계 1위 목표) p99 |
|---|---|---|
| 업그레이드 확인(읽기) | 20ms | 5ms |
| 후원 견적(경매+예산 잠금 쓰기) | 50ms | 10ms |
| 동의·노출 보상·실행권 사용(원장 쓰기) | 50ms | 15ms |
| 지갑 이전·코인 결제 | 50ms | 15ms |
| 실행 기록 정산 | 200ms | 50ms |
| 광고주 콘솔 읽기(목록·보고서) | 200ms | 50ms |

- **처리량:** 운영 예상 최대치의 10배를 1% 미만의 p99 악화로 버틴다. 단일 노드 기준 관문은 원장 쓰기 초당 200건 이상, 도전은 초당 1,000건 이상이다.
- **화면:** 첫 화면 LCP 2.5초 이하(75번째 백분위), 버튼 반응 INP 200ms 이하. 프로젝트 정책은 3초다.
- **측정 완전성:** 경로별 표본 수, 요청·원장 쓰기·업무 여정의 처리량을 각각 제시한다. 필수 경로가 누락되거나 표본이 부족하면 그 경로의 속도 통과는 미판정이다. 지연과 처리량 관문은 같은 부하 구간에서 함께 충족해야 한다.
- **글로벌 비교:** 내부 p99와 DNS·TLS·네트워크·DB 대기를 포함한 사용자 왕복 p99를 분리한다. 지역·동시성·데이터 분포·장애·보안 설정이 같은 조건의 반복 측정과 비교 대상 근거가 있어야 글로벌 우위를 주장할 수 있다.
- 현재 리허설 스크립트의 `gates()`는 계측된 경로만 속도를 판정하고 화면·전체 검수·세계 순위·처리량 관문을 종합 검증하지 않는다. JSON의 `speed_passed=true`는 출시 승인과 같지 않다.

## 3. 리허설 단계

| 단계 | 규모 | 목적 |
|---|---|---|
| 0. 연기 시험 | 사용자 10, 광고주 3 | 전체 흐름이 끝까지 돈다 |
| 1. 소량 | 사용자 1천, 광고주 20, 캠페인 100 | 기능·정합성 |
| 2. 중량 | 사용자 1만, 광고주 200, 캠페인 1천 | 경합·예산 소진·빈도 상한 |
| 3. 대용량 | 사용자 10만, 광고주 1천, 캠페인 5천, 노출 수십만 건 | 처리량·꼬리 지연·데이터 크기 |
| 4. 극한 | 관문 처리량의 2~5배 순간 폭주 | 무너지는 지점과 그때의 행동(거부·대기, 잔액 보존) |

- **실행 환경:** 격리된 PostgreSQL 18 임시 클러스터를 쓰고, 운영 DB에는 접속하지 않는다.
- **부하 관리:** 운영 맥에서 돌리므로 `nice -n 10`을 쓰고, 동시 실행 수에 상한을 둔다. 운영 서비스 지연이 늘지 않는지 함께 본다.

### 3.1 측정 방법(11-05 리허설에서 바로잡은 점)

- **서버 분리:** API는 운영처럼 별도 uvicorn 프로세스로 띄우고, 부하기는 HTTP로 접속한다. 같은 프로세스의 TestClient는 GIL을 나눠 써서 꼬리 지연을 부풀렸다.
- **일정 지키기:** 운영 상태 표본(한 번에 0.6~1초)은 별도 스레드에서 잰다. 일정 루프 안에서 재면 발사가 멈췄다가 한꺼번에 몰려, 일정 지연 p99가 600~800ms까지 올랐다. 지금은 10ms 이하다.
- **통계:** 시드 직후 `ANALYZE`를 돌린다. 운영은 autovacuum이, 이전 명령은 `migrate`가 통계를 만든다. 통계가 없으면 후보 조회가 10배 느렸다.
- **구간 분리:** 서버 응답의 `Server-Timing`으로 나눠 본다. 작업자 대기, 처리, CPU, DB, SQL 수, 세션 대기, 잠금 대기, 잠금 보유를 따로 기록한다.
- **교착 횟수:** `pg_stat_database.deadlocks`를 보고서에 남긴다.
- **기계 부하:** 측정 전후의 부하(load average)와 운영 상태 응답 시간을 함께 남긴다. 다른 작업이 몰리면(부하 15 이상) 속도 판정은 다시 잰다. 보안·품질 판정은 부하와 관계없이 유효하다.

## 4. 확인된 증거와 알려진 한계

- 2026-11-06 관련 시험의 최신 고유 결과는 89건 통과이고 기존 HTTP 동적 시나리오는 219/219 통과했다. 격리 PostgreSQL과 시험 로그인 대역을 쓴 범위다. 실제 운영 로그인·경계·사람 승인·실제 지급의 완전성 증거로 확대하지 않는다.
- 11-05 대용량 원자료의 내부 p99는 업그레이드 2.43ms, 견적 24.23ms, 노출 9.22ms, 정산 6.88ms다. 이전 지연은 표본 3건뿐이므로 부하 p99 성능을 입증하기에 부족하다.
- 이전 보고서의 원장 약 195건/초는 최종 `ad_coin_journals` 17,594행을 90초로 나눈 값이다. `seed()`가 부하 전에 만든 충전 분개도 이 행 수에 포함되므로 순수 측정 구간의 원장 처리량으로 승인하지 않는다. 극한 구간의 더 높은 누적치도 지연 관문을 초과했다. 측정 전후 분개 차이와 구간 시간을 함께 기록해 원장 200건/초·지연 관문 동시 충족을 재검증해야 한다.
- 단일 맥·격리 DB·가상 행동의 결과다. 다지역 운영 성능·독립 비교·실제 광고 전환 품질은 미검증이다. 이번 문서 갱신에서는 부하·LCP를 재측정하지 않았다.
- 도전 목표의 비교 배경에 공개 자기 신고 수치가 포함된다. 독립 감사를 받은 세계 순위가 아니며, 세계 최고 달성을 표시할 근거로 쓰지 않는다.
