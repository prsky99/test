# 18차 사용 편의성 측정 기준 (2026-10-31)

일반 사용자(프론트엔드·워크스페이스)와 자율형 에이전트(MCP·A2A·REST)의 사용 편의성을 같은 틀로 잽니다. 근거는 아래 논문·공개 자료이고, 각 항목은 이 서비스에 맞게 측정 가능한 형태로 바꿨습니다.

## 근거
- **τ-bench**(Yao 외, ICLR 2025)
  - 같은 과제를 k번 반복해 모두 성공할 확률 pass^k로 신뢰성을 잽니다.
  - 대화 품질이 아니라 마지막 상태가 목표와 같은지로 판정합니다.
  - GPT-4o도 pass^8이 25% 미만이라, 한 번 성공(pass^1)만으로는 부족하다는 것이 핵심입니다.
  - https://arxiv.org/pdf/2406.12045
- **MCP 도구 설명 결함 연구**(103개 서버·856개 도구)
  - 설명의 6요소로 채점하는 기준을 제시합니다.
  - 97.1%가 결함을 하나 이상 가졌고, 설명 품질이 에이전트 성능을 바꾼다고 보고합니다.
  - https://arxiv.org/abs/2602.14878, https://arxiv.org/html/2602.18914v1
- **MCP-Bench**(ICLR 2026)
  - 도구 이름 유효성, 스키마 준수, 계획 구조 일치, LLM 판정 의미 품질을 봅니다.
  - https://huggingface.co/spaces/mcpbench/mcp-bench
- **Arcade ToolBench**(업체 자료라 참고만)
  - 정의 품질(이름·설명·입력 스키마), 프로토콜 준수, 보안, 지원 가능성의 4축입니다.
  - https://toolbench.arcade.dev/methodology
- **에이전트 경험(AX) 논의**(Nordic APIs, AXS 프레임워크)
  - 호출 수 같은 채택 지표가 아니라 에이전트가 실제로 성공하는지를 재야 한다고 봅니다.
  - 사람 개입 없는 인증, 복구 경로가 있는 오류, 관측 가능성을 강조합니다.
  - https://nordicapis.com/what-is-agent-experience-ax/, https://github.com/sat3n/axs-framework
- **사람 사용성 지표**(SUS·SEQ·과제 시간, Sauro·Lewis 계열 실무 지표)
  - 과제 성공·시간·오류를 함께 보라고 권합니다. 쉬웠다고 답해도 실패할 수 있기 때문입니다.
  - https://dscout.com/people-nerds/sus-seq, https://maze.co/collections/reporting-analysis/measure-usability-metrics/
- **커뮤니티·SNS 관찰**(n8n·Zapier 자연어 워크플로, MCP 도구 선택 관련 글)
  - "말로 설명하면 바로 동작"은 과장인 경우가 많고, 결국 디버깅과 수정이 필요하다는 불만이 반복됩니다.
  - 도구가 많으면 선택 정확도가 떨어지고, 설명이 모호하면 엉뚱한 도구를 고른다는 지적도 많습니다.
  - https://growwstacks.com/blog/n8n-ai-workflow-builder-review/, https://tldv.io/blog/mcp-server-failures/, https://dev.to/tracepilot_2841f1db6718a1/the-mcp-server-directory-problem-nobodys-talking-about-13c3

## A. 일반 사용자(워크스페이스·프론트엔드)
| 지표 | 정의 | 목표 |
|---|---|---|
| A1 과제 성공률 | 자연어 과제 → 생성 → 저장 → 실행까지 사람 개입 없이 끝난 비율(과제 10개) | ≥ 80% |
| A2 결과 적합도 | 실행 결과 1건이 요청 주제와 맞는지(맞음·부분·무관 3단계, 근거 기록) | 맞음 ≥ 70%, 무관 ≤ 10% |
| A3 크레딧 가치 | 크레딧 1을 쓴 저장·실행이 "맞음" 결과를 낸 비율 | ≥ 70% |
| A4 과제 시간 | 입력 → 결과 표시까지(생성·저장·실행·대기 합계) | 중앙값 ≤ 30초 |
| A5 화면 이동 준비 시간 | 워크스페이스 화면별 마지막 API 응답까지 | ≤ 2초 |
| A6 상태 가시성 | 진행·완료·실패 문구가 무엇을, 얼마를 썼는지 말하는가(닐슨 1번 원칙) | 모든 단계 |
| A7 오류 예방·복구 | 지원 안 되는 요청을 미리 막거나(비활성 예시), 이유와 다음 행동을 알려 주는가 | 모든 거부에서 이유와 대안 표시 |
| A8 되돌리기·수정 | 생성 뒤 단계 수정 → 재저장 → 재실행이 되는가, 그 비용이 명확한가 | 성공·비용 표시 |
| A9 일관성 | 같은 과제를 3번 생성할 때 단계 구성이 같은가 | 3/3 동일 |

## B. 자율형 에이전트(MCP·A2A·REST)
| 지표 | 정의 | 목표 |
|---|---|---|
| B1 과제 성공(pass^1) | 에이전트가 문서만 보고 MCP·A2A·REST로 과제 8개(검색·추천·상세·연결)를 끝냄 | ≥ 90% |
| B2 신뢰성(pass^3) | 같은 과제를 3번 반복해 모두 같은 정답 계열을 얻는 비율 | ≥ 80% |
| B3 다중 턴 맥락 | 같은 `contextId`·토큰에서 후속 조건("free only", "the second one", "which of these")이 앞 목록을 이어받는 비율 | ≥ 90% |
| B4 도구 설명 품질 | `/mcp` 도구마다 6요소(목적·사용 시점·입력 설명·출력 설명·제약·예시) 충족 수 | 평균 ≥ 5/6 |
| B5 도구 수·선택 부담 | 노출 도구 수, 이름 명확성, 읽기 전용 표시 | ≤ 15개, 읽기 도구 readOnlyHint 100% |
| B6 오류 복구성 | 잘못된 입력·한도 초과·없는 자원·인증 없음에 대해 오류 코드, 원인, 고칠 방법이 있는가 | 100% |
| B7 사람 개입 없는 접근 | 키·로그인 없이 쓸 수 있는 경로 비율, 결제가 필요한 경우 기계가 읽을 수 있는 요구 조건 | 무료 경로 100% |
| B8 응답 시간 | 도구 호출·Chat·A2A 중앙값과 p90 | 중앙값 ≤ 3초 |
| B9 결과 근거 | 추천마다 이유(match_basis·why)와 검증 시각이 있는가 | 100% |

## 측정 방법
- A는 내장 브라우저에서 로그인 워크스페이스로 직접 수행합니다(크레딧 사용 허가됨).
- B는 스크립트로 `/mcp`, `/a2a`, `/chat`, `/api/*`를 호출하고 반복 측정합니다.
- 판정이 필요한 적합도(A2)는 결과 제목·주제를 근거로 기록합니다.
- OpenSearch 전환 중에는 검색 결과 이상을 전환 영향으로 따로 표시합니다.
