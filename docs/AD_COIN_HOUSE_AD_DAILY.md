# 자사 광고 매일 예약 정기 작업 설계 (2026-11-12, 설계만)

**배경**
- PM 지시(11-12 09:2x)로 쓰는 설계 문서다.
- 자사 광고(Agent Concierge, research)는 하루 단위로 예약한다. 11-13 5개국 예약 뒤 11-14부터는 다시 끊긴다.
- 매일 다음 날 칸을 채우는 정기 작업을 설계한다.

**승인**
- 운영 원장에 매일 쓰는 일이라 사용자 승인을 따로 받는다(PM을 거침).
- 승인 전에는 만들지 않는다.

## 1. 비용과 버티는 날수

| 항목 | 값 |
|---|---|
| 하루 비용 | 5개국(US, KR, JP, GB, DE) × 50 coins = **250 coins/일** |
| 성장 예산(11-12 09:2x, 운영 읽기) | 9,850 coins |
| 11-13 5개국 예약 뒤(사용자 실행 시) | 9,850 − 150 = **9,700 coins** |
| 버티는 날수 | 9,700 ÷ 250 = **38일**(11-14부터 매일 예약하면 12-21까지) |
| 월 발행 한도 | 100,000 coins/UTC 월(`ISSUANCE_MONTHLY_CAP_ATOMS`). 11월은 10,000 발행됨 |

**코인의 흐름**
- 예약에 쓴 코인은 "코인 수익" 계좌로 간다(하루 250).
- 이 코인을 성장 예산으로 되돌리는 경로는 없다(발행만이 성장 예산을 채운다).
- 그래서 38일 뒤에도 이어 가려면 12월 발행(사용자 결정)이 필요하다.

**예산 경보**
- 성장 예산이 7일치(1,750 coins) 아래로 내려가면 작업이 예약하지 않는다.
- 이때 현황판과 PM에 알린다(3절).

## 2. 동작

이미 있는 명령을 그대로 쓴다. 새 원장 경로는 없다.

```
.venv/bin/python -m scripts.ad_coin_house_ad book-regions --day <D> --regions US,KR,JP,GB,DE ...
```

- **언제:** 매일 00:10 UTC(09:10 KST)에 한 번 돈다. 그 시각 기준으로 **D+1과 D+2 두 날**을 확인하고 채운다.
  - 같은 날을 두 번 확인하므로, 하루 실행이 실패해도 칸이 끊기지 않는다(1일 여유).
  - 이미 예약된 날·나라는 그대로 두고 쓰지 않는다(멱등 request_id).
- **충전:** 자사 계정에 모자란 만큼만 성장 예산에서 운영자 지급으로 채운다.
  - 지급 1회 상한은 1,000 coins다. 하루 최대 500이라 안에 든다.
  - 감사 기록에 날짜와 나라가 남는다.
- **유료 광고주와의 관계:**
  - 칸은 하루·분야·나라마다 2개이고, 자사 광고는 1개만 쓴다. 유료 광고주는 언제나 1칸을 바로 예약할 수 있다.
  - 유료 광고주가 2칸을 다 원하면 PM 결정으로 그날 시작 전에 `cancel-regions`로 비운다.
  - 이미 2칸이 다 찬 날·나라는 `full`로 건너뛴다.
- **스위치:**
  - `gateway-data/sponsored.env`에 `AD_COIN_HOUSE_AD_DAILY=1`이 있을 때만 예약한다. 없거나 0이면 계획만 기록한다.
  - agentcon.env는 쓰지 않는다(11-11 f7cd7a83 규칙).

## 3. 멈추는 조건 (예약하지 않고 기록·알림만)

1. 성장 예산이 1,750 coins 미만일 때
2. 그날의 원장 보존 검사(`ad_coin_daily_ledger_check`)가 clean이 아닐 때
3. 자사 캠페인이 active가 아니거나 둘 이상일 때
4. 스위치가 꺼져 있을 때
5. 새벽 DB 변경 창(현황판의 "DB 변경 창")에 걸릴 때. 09:10 KST라 겹치지 않지만 검사는 한다.

## 4. 어디서 돌리나

- **권장:** 운영·SRE의 `ops_auto` 하루 1번 칸에 넣는다(원장 보존 검사와 같은 자리, 연결 1개, 1~2초).
  - Claude 세션이 아니라 사용자가 승인한 정기 작업이 쓰는 것이다.
  - 결과는 `logs/ops/house-ad/<UTC 날>.json`에 남기고, 실패나 멈춤은 현황판에 알린다.
- **대안:** 한 번에 30일치를 예약한다(7,500 coins).
  - 작업은 단순하다.
  - 하지만 예산을 미리 묶고, 중간에 나라나 분야를 바꾸기 어렵다. 그래서 권하지 않는다.

## 5. 시험 계획

| # | 확인 |
|---|---|
| D1 | D+1·D+2를 모두 채우고, 다시 돌리면 아무것도 쓰지 않음 |
| D2 | 하루 실패 뒤 다음 실행이 빈 날을 채움(여유 1일) |
| D3 | 예산 1,750 미만이면 예약 0, 알림 줄 생성 |
| D4 | 원장 검사가 clean이 아니면 예약 0 |
| D5 | 스위치가 꺼져 있으면 계획만 기록 |
| D6 | 한 나라가 full이면 건너뛰고 나머지는 예약 |
| D7 | 실행 뒤 원장 보존 검사 clean, 지급 1회 상한 안 |

## 6. 승인 뒤 순서

1. 사용자 승인(PM): 매일 예약, 하루 250 coins, 38일 한도, 12월 발행은 따로 결정
2. 스크립트에 `daily` 동작(D+1·D+2, 멈춤 조건, 스위치)과 시험 D1~D7을 추가한다. 사본 리허설을 한다.
3. `ops_auto` 등록(운영·SRE)과 `sponsored.env`의 스위치를 켠다. 첫날 결과를 확인한다.
