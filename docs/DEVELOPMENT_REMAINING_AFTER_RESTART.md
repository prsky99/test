# 현재 요청 범위의 완료 결과와 명시적 보류

2026-10-20 · 기존 42개 요구 ID 보존 · 사용자 범위 결정 반영

사용자는 실제 고객을 가상 고객으로 대체하고, 로컬 PostgreSQL에 별도 DB를
만들어 검증하도록 지정했다. 아래 결과를 이번 개발 검증의 종료 기준으로
사용한다. 과거 실제 운영 수용 조건을 모두 다시 개발 목록에 올리거나,
보류된 항목을 자동 재개하지 않는다.

## 완료

1. 최신 프론트엔드 변경 영향 138건 통과 후, 후속 CSS/테스트 변경에 영향받는4개 모듈65건을 교체 검증했다. 기존 고정 후보 5,796건 전체를
   재실행하거나 그 수에 이번 결과를 단순 합산하지 않았다.
2. 가상 고객·권한·SDK·10개 연구 워크플로우/최대10개 에이전트 입력·출력
   전달·A2A 세션·HTTPS 수신·알림·복구 시나리오 213건 통과.
3. 테스트 도구의 DB/비밀정보 경계와 고객 링크 숨김·동의·SDK·콘텐츠 보안
   111건 통과. 가상 평가자·신뢰 증거·코퍼스·프로토콜 79건 통과.
   총 **43개 모듈/고유542건, 실패·오류·skip 0**이다.
4. 기존 PostgreSQL 14.22의 신규 테스트 DB와 복원 DB에서 223개 애플리케이션
   테이블, 가상 고객 3명, SDK 실행·철회와 트랜잭션/복원 18개 검사 통과.
   8개 동시 연결의 800개 트랜잭션과 단일 claim 승자·오래된 fence 거부를
   확인했다. 백업 시점 이전 커밋 유실 0, 의도적인 백업 이후 커밋 1건은
   스냅샷에 포함되지 않음을 확인했다. 예비 DB 6개는 소유 표시 확인 후
   정리했고 최종 테스트 DB 2개만 보존했다.
5. 다른 서버에서 동일 검증을 수행할 [CLI와 절차](SYNTHETIC_ACCEPTANCE_RUNBOOK.md)
   및 TLS 연결 설정 예시를 추가했다. 임의의 기존 DB에 쓰는 대상 옵션은
   없으며, 매번 무작위 이름의 신규 DB 2개만 사용한다.
6. 공개 콘텐츠 217개 파일 위반 0, HTML mirror 일치, SQL catalog
   3,473개 문장/223개 테이블 일치, 새 도구·테스트 Ruff 오류 0.
   새 CLI의 Bandit High 0, Medium 1/Low 6은 문맥을 검토해 기록했다.
7. Cloudflare 콘솔에서 사용자 적용 직전 승인을 받은 뒤,
   `agentconcierge.biz`의 `GET /.well-known/agent-card.json`과
   `GET /api/test/presets`에만 Browser Integrity Check를 끄는 규칙을 배포했다.
   기본 Python 클라이언트가 두 경로에서 403→200으로 전환됐다.
   규칙 밖 HEAD·POST·일반 페이지 요청은 기존 차단을 유지한다.
   WAF·DDoS·속도 제한·실행/관리자 경로 설정은 변경안에 포함하지 않았다.

최초541건 완료 후 별도 CSS/테스트3개 파일 변경이 있었다. 해당4개 모듈을 다시 확인해 기존64건을 최신65건으로 교체하고 영향이 식별되지 않은477건을 유지했다. 교체 검사 중 추가 소스 변경은 없었다. 제품 서버를
중지·재시작·교체하지 않았으며 이번 테스트 도구 추가로 재시작할 필요도 없다.

## 명시적 보류와 공개 결정

- ChatGPT 실제 추론: 사용자 한도 회복 및 재개 지시까지 보류.
- Gemini·Claude: 구독 플랜 로그인/사용 제외. 기존 Gemini
  `UNSUPPORTED_CLIENT`와 Claude 개인 CLI 기록만 유지. 새 로그인·추론 없음.
- Stripe TEST/Connect·실결제 연동 검증, hosted CI, 동료 승인: 사용자 보류.
- Workspace 공개 결정: 현재 탐색 링크 숨김을 유지한다. 가상 검증 통과가
  공개 활성화 지시를 대신하지 않으며, 명시적인 활성화 요청에 따라 변경한다.

**이번 요청 범위의 실행 가능한 작업은 완료했으며, 자동으로 이어갈 개발
과제는 없다.** 가상 Push·평가자·복구 키 시험은 실제 기기/독립 기관의
증거가 아니고, 단일 로컬 PostgreSQL의 논리 복원은 HA·WAL/PITR·운영 SLA
검증이 아니다. 이 한계는 결과의 범위를 설명하며 사용자 종료 기준을
자동으로 늘리는 작업 목록이 아니다.
