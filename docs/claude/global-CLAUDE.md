# 모든 프로젝트 공통: 토큰 절약 작업 규칙

한 세션을 오래 쓴다. 매 요청마다 대화 전체가 다시 전송되므로, 대화에 들어가는 양을 줄이는 것을 우선한다.

1. **다시 읽지 않기:** 이미 확인한 파일·보고서는 다시 통째로 읽지 않는다. 바뀐 파일과 지금 작업에 필요한 부분만 읽는다(`grep -n`, `sed -n`).
2. **긴 출력은 파일로:** 로그·표본·목록 원본은 scratchpad 파일에 저장하고, 대화에는 오류 부분과 요약만 둔다(`| tail -20`, `grep -c`, `pytest -q | tail -3`).
3. **검증 반복 금지:** 바뀐 부분을 먼저 검사하고, 필요한 통합 검사는 한 번만 한다. 새 변경이나 문제가 없으면 같은 검사를 다시 하지 않는다.
4. **범위 고정:** 요청한 작업과 완료 기준을 먼저 정한다. 작업 중 떠오른 개선 아이디어는 작업 기록의 '보류' 칸에만 적고, 그때마다 개발·검증을 새로 시작하지 않는다.
5. **보고는 짧게:** 계획·진행 보고·최종 답변에서 같은 설명을 반복하지 않는다. 변경 사항, 검증 결과, 남은 문제만 쓴다. 꼭 필요할 때만 하위 에이전트를 쓴다(큰 탐색·조사를 대화 밖으로 빼는 경우).
6. **압축 후 재조사 최소화:** 프로젝트에 짧은 작업 기록(예: `WORKLOG.md`의 완료·진행 중·다음·보류)을 유지하고, 작업이 끝날 때마다 몇 줄로 갱신한다. 압축되면 그 기록부터 보고, 끝난 작업을 다시 하지 않는다.

- 스킬·플러그인을 토큰 절약 목적으로 새로 설치하지 않는다(지침 자체도 토큰을 쓴다).
- 압축은 계정 한도를 되돌리지 않는다. 대화를 작게 유지하는 것이 유일한 절약이다.
