# 11차 재현·수정·검증 결과

2026-10-30 KST. 사용자의 “QA11 두 웹 배포 승인”에 따라 frontend/admin의 qa11-remediation-각역할-20261030-r1을 **운영 적용·확인 완료**했다. 두 웹 모두 활성 a이며, 직전 QA10 r1은 b에 롤백용으로 보존했다. Cloudflare Worker·jobs·execution·프록시·DB 스키마는 이번에 변경하지 않았다.

## 수정 내용

1. **일반 검색 0건**
   - 운영에서 data/api/agent/mcp가 모두 0건인 것을 재현했다. Explore가 작업 추천의 불용어·관련성 경로를 공통 사용한 것이 원인이다.
   - Explore에서 일반 용어와 프로토콜만 입력한 요청을 카탈로그 탐색으로 처리한다. a·기호·불용어만 입력했을 때도 목록을 보여 주되, ‘일반적인 검색이므로 선택한 카탈로그를 표시한다’는 안내를 명시한다. 임의 항목을 해당 작업의 검색 성공이라고 표시하지 않는다.
   - 명시한 프로토콜·카테고리·검증/보고서·인증 필터를 유지한다. MCP만 입력하면 MCP 목록이며, 사용자가 별도 선택한 프로토콜이 우선한다. 다음 페이지 커서와 중복 없는 추가 조회를 검증했다.
   - 날씨·데이터 분석·API 문서처럼 구체적 작업은 기존 작업 검색을 유지한다. 알아볼 수 없는 문자열을 무조건 전체 목록으로 바꾸지 않는다. Chat의 관련성 필터도 느슨하게 바꾸지 않았다.
   - 오래된 화면 결과 재사용을 피하도록 Explore 화면 캐시 구분을 v4로 변경했다. 별도 Workflows 화면의 빈 상태가 Explore에서 보이지 않는 것도 브라우저에서 확인했다.

2. **검색 지연**
   - 운영 재현에서 `weather forecast seoul`은 6.83초였다. 읽기 전용 카탈로그 프로파일과 기존 집계에서 계약 읽기·검사, 후보 투영, ANN 조회의 누적 비용을 확인했다.
   - 원래 A2A→MCP를 순차로 조회하던 경로를 기존 읽기 풀 안에서 병렬 처리한다. 부모는 연결을 점유한 채 자식 연결을 기다리지 않는다. 프로세스당 한 요청만 두 갈래로 실행하고, 다른 요청·연결 1개짜리 풀·명시적 단일 프로토콜은 순차 처리한다. 풀의 최대 연결 수는 늘리지 않는다.
   - 작업별 메모는 스레드마다 분리하고, 집계 갱신은 잠금으로 보호한다. 보안·현재 상태·계약 일치·관련성 검사와 프로토콜 우선순위는 유지한다.
   - 현재 원본에 결합된 ‘모든 MCP 도구가 미지원’ 사실이 있으면 전체 계약 파싱 전에 거절한다. 오래된 원본의 사실은 재사용하지 않는다.
   - 운영 카탈로그·설정된 임베딩/pgvector를 사용한 읽기 전용 교차 비교에서 동일한 결과 순서를 유지했다. 브라우저 검사 부하가 끝난 비교의 중앙값은 순차 1.869초, 병렬 1.565초(약 16% 감소)였다. 각 3회인 작은 표본이고 공개 HTTP 지연은 포함하지 않는다. 브라우저 시험과 동시에 진행한 첫 비교에서는 개선이 일정하지 않았으며 그 원자료도 보존했다. 배포 후 공개 API의 꼬리 지연을 재측정해야 한다.

3. **Test CLS**
   - 결과 영역만의 문제가 아니었다. 로딩 미리보기와 실제 예제의 그리드 열 수가 바뀌면서 본문이 위로 움직였고, 선택 제목·설명과 입력 항목이 바뀌는 추가 이동이 있었다.
   - 미리보기·실제 예제 카드의 열 수·높이·줄 수를 맞추고, 선택 제목·설명 공간을 미리 잡았다. 모바일 열 수와 줄바꿈을 별도로 유지한다.
   - 같은 격리 데이터에서 현재 운영 릴리스의 원본 정적 파일과 수정 파일을 비교했다. 데스크톱 라이트 CLS 0.1275→0.0397, 모바일 0.1087→0.0001, 데스크톱 다크 0.1276→0.0397이다. 3조건 모두 0.1 미만이다. 운영 사용자 p75 측정값으로 주장하지 않는다.
   - `test-page-baseline-*.png`와 `test-page-fixed-*.png`, `test-cls-baseline-*.json`과 `test-cls-fixed-*.json`에 전후 증거를 남겼다.

4. **Chat 추천·문맥**
   - 운영에서 ‘계약서를 영어로 번역해줘’는 Faceabot이지만 ‘한국어 계약서를 영어로 번역해줘’는 Agent Tollgate가 1위인 것을 재현했다.
   - 네이티브 simple-token 검색에서 translation과 translate/translator가 서로 다른 단어로 취급되어 번역 전용 서비스가 후보에서 빠질 수 있었다. 한정된 표현 변형을 매개변수로 조회하여 후보를 보완했다. 품질·보안·검증 기준과 전용 서비스 우선순위는 유지한다.
   - 변경 소스와 실제 카탈로그/임베딩의 읽기 전용 검증에서 두 계약서 요청 모두 Faceabot Translate가 1위다.
   - 일반 날씨에서 우주·항공 기상을 주로 설명하는 서비스를 전용 날씨 서비스로 분류하지 않는다. 그 안에 실제 지상 날씨 도구가 있으면 대안 자격은 유지한다. 변경 소스 검증에서 일반 날씨 1위는 Weather이며 Tanod Sky는 1위가 아니다. 일반 날씨와 우주 날씨를 별개로 요구할 수 있다.
   - 순번·it의 기본 4턴 참조는 이미 일부 운영 시험에서 동작했다. `tell me more about the second one`, `could you tell me about the second option`, `can you tell me more about it` 같은 자연스러운 표현을 추가로 지원하고, 실제 브라우저의 4턴 전송에서도 선택 항목이 유지되는지 검증했다. 없는 순번이나 새 작업을 임의로 같은 참조로 처리하지 않는다.

5. **문서**
   - 실제 공개 OpenAPI에는 `/api/agent/v1/openapi.json`과 `/api/agent/v1/badge/{resource_id}.svg`가 있다. llms의 badge 자리표시자도 resource_id로 맞추어 비교 혼동을 줄였다. 없는 `/badge`·`/openapi` 경로를 새 API로 위장하지 않았다.

## 실제 운영 Test 실행

Technology News, Research Papers, Country Profile, Package Metadata, GitHub Issues and Pull Requests의 게시된 도구와 샘플 입력을 먼저 확인한 뒤 각각 한 번 실행했다. 5/5 HTTP200, execution_succeeded=true, simulated=false, 약 0.8~2.4초였다. 결제·서명·제공자 자격 증명·외부 쓰기 요청은 보내지 않았다. `live-examples.json`에 결과가 있다.

이 실제 실행 기록은 운영 관측 근거로 남긴다. 과거 보고서 40건을 새로 실행한 것과 같지 않으며, 과거 문서의 실행 시각·성공 여부를 임의로 바꾸지 않는다. 이번 변경으로 과거 40건이 모두 현재 실행 보고서가 되었다고 주장하지 않는다.

## 검증

- 기능·API·보안 회귀 346건 통과. 추가 문서 일치 검사를 포함한 표적 검사 23건 통과(앞선 검사와 중복됨).

- 10화면×4조건 접근성 행렬: 심각/치명 axe 오류 0, 가로 넘침 0. 작은 타깃은 원시 bbox와 실제 클릭 가능한 label/인라인 예외를 구분한다. 별도 all-pages-targets.json의 로그인·현황까지 포함한 40조건에서 유효 작은 타깃 0건을 확인했다. 로그인 skip link는 키보드 포커스 시 실제로 펼쳐지는 것까지 확인했다. QA 도구도 화면에서 잘린 키보드 전용 링크를 잘못 세지 않도록 보정했으며, 이 도구 보정은 프로젝트 루트의 scripts/uiux_audit.js에 적용했다.
- 두 고정 웹 후보 각각 PostgreSQL 18에서 일반 검색·커서·번역 표현·병렬 읽기·연결 반환 검증 통과. 후보별 1,336개 파일 해시 확인. 임시 Unix 소켓 클러스터에서 외부 TCP를 차단한 시험이다.
- 공개 콘텐츠 320파일 위반 0. 변경 런타임의 오류성 린트와 신규 검사/헬퍼 Ruff 통과. 기존 파일 전체의 오래된 형식 항목까지 정리했다고 주장하지 않는다.
- HTML/extracted_html.txt/manifest 일치. 활성 릴리스에 검토한 변경만 덧씌운 후보이며 공유 작업 트리 전체를 패키징하지 않았다.

## 남은 항목을 해석할 때

- **8004**는 기능 카테고리가 아닌 ERC-8004 등록 체계다. 실제 금융 에이전트가 등록된 사실 자체는 검색 오류가 아니다. 작업을 추가해 좁히는 안내를 유지한다.
- **CORS**: 허용되지 않은 출처의 세션·실행 가능한 Chat/MCP 요청은 403을 유지한다. 임의 사이트에 세션·실행 권한을 개방해 점수를 올리지 않는다. 익명 공개 탐색 GET은 다른 출처에서도 사용할 수 있고, 설정된 브라우저 출처의 전송은 회귀로 검증했다. 새로운 브라우저 클라이언트는 의도한 출처를 별도로 연결해야 한다.
- **작은 타깃**: 숨겨진 skip link, 활성화되지 않은 컨트롤, 24px 이상의 연결된 클릭 label, 인라인 링크 예외까지 단순 bbox로 세면 실제 문제와 다르다. 원시 값도 보존하며 현재 공개 조건에서 실제 작은 클릭 영역을 검사한다.
- Learn 검색·없는 해시 안내는 이미 동작하는 소스가 있고 관련 브라우저 회귀가 통과했다.
- 개인 계정으로 로그인한 운영 워크스페이스 전체, 실제 금전 결제, 임의 외부 에이전트 40개 실행, 실제 사람/스크린리더 참가자 시험은 이번 완료 범위에 포함하지 않았다. 새로운 종합 UI/UX 점수도 임의로 산출하지 않았다.

## 승인 후 실제 운영 확인

- 두 정확한 r1 후보를 각각 배포하고 인증된 준비 상태를 확인했다. jobs·execution의 릴리스/PID와 프록시 PID는 배포 전후 동일하다. `deployment-after-status.json`, `deployment-readiness.json` 참조.
- 배포 전후 공개 status.json을 약 2초 간격으로 178회 확인해 모두 HTTP200이었다. 이는 상태 경로의 관측 결과이며 모든 요청에서 오류가 없었다는 주장은 아니다.
- 공개 API 검사 20건 통과: 일반 검색 7종의 명시적 탐색 안내와 45건 결과, data/MCP 다음 페이지 45건 및 중복 0, MCP 엄격 필터, 조회 도구 주석 4개, 날씨 및 한국어 계약서 번역 2종, 4턴 순번/it 참조, 문서 경로 일치, 기존 x402 검사 전용 402 경계, 어드민 접근 제한. `post-deploy-api-checks.json` 참조.
- 검색 HTTP 13회 중앙값 0.424초, 최대 5.927초였다. 첫 weather forecast seoul은 서버 처리 5.579초였고 같은 검색 재요청은 전체 0.388초였다. translate 첫 요청 2.071초/재요청 0.458초, github 0.424초/0.398초다. **일부 첫 요청의 3초 초과는 남아 있어 검색 지연을 완전 해결했다고 볼 수 없다.** `post-deploy-search-timings.json` 참조.
- 실제 공개 예제 API 5/5가 execution_succeeded=true, simulated=false로 완료됐다(0.713~2.153초). `post-deploy-examples.json` 참조.
- 실제 브라우저 MCP 검색과 Load More 클릭으로 45→90건을 확인했고 로딩이 종료됐다. 뉴스 첫 클릭은 실행 불가로 한 차례 실패했으나 동일 입력 재실행은 정상 완료됐다(게이트웨이 838.2ms/전체 2.0초). 논문 실행도 정상 완료됐다(1387.6ms/2.1초). **첫 뉴스 실패의 구체적 원인은 응답만으로 확정하지 못했으며 재실행 성공을 최초 성공으로 바꾸어 기록하지 않았다.** `post-deploy-browser-checks.json`에 전후 증거가 있다.
- 이번 API 4턴 검증에서 직접 만든 QA 세션 1개·메시지 8개·관심 1개만 ID/토큰 해시/생성 시각 대조와 비공개 백업 후 정리했다. 다른 방문자·실제 실행 관측은 변경하지 않았다.
- 추가 파싱 캐시 분리·compact 음성 필터 실험은 동일 결과를 유지했으나 개선 폭이 작아 채택하지 않았다. 배포 후 추가 실험 코드는 제거했고 실제 QA11 r1 소스로 유지한다. 운영 추가 교체는 없었다.

확인한 기능 회귀는 수정·배포됐다. 남은 첫 검색 지연과 뉴스 실행의 일시 실패, 과거 보고서의 실제 실행 범위, 제한 없는 외부 Origin의 세션/실행 CORS 허용은 별개다. 안전 경계를 임의로 열거나 과거 보고서를 실행 성공으로 소급 수정하지 않았다.
