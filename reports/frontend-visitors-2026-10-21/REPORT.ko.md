# 프론트엔드 방문자 분석

분석 구간: **2026년 10월 21일 00:00–17:59 한국시간**. PostgreSQL의 읽기 전용 반복 가능 스냅샷과 당일 운영 로그를 분석했습니다. 시스템 설정·서버·사용자 데이터는 변경하지 않았습니다.

## 핵심 판단

**홈에서 오늘 관측된 익명 접속 버킷은 39개이며, 일반 브라우저 형식은 29개입니다. 이 수치를 실제 사람이나 외부 고객 수로 발표할 근거는 부족합니다.** 자동화·내부 점검을 분리하는 표식과 전체 페이지 방문 계측이 없습니다. AI 대화 기록은 증가했지만 일반 웹 사용자 이용 증가로 해석할 수는 없습니다.

## 1. 유입과 재관측

- 홈 익명 접속 버킷 39개: 오늘 최초 관측 24개, 이전부터 존재한 버킷의 오늘 재관측 15개입니다. IP와 User-Agent 조합에서 만든 해시 집계이며, 고유 사람·브라우저 쿠키 세션 수가 아닙니다. 재관측 비율 38.5%는 사람의 재방문율이 아닙니다.
- 기록된 User-Agent 형식 기준: 일반 브라우저 29개, 봇·헤드리스 4개, 프로그램형 클라이언트 4개, 분류 불명 2개입니다. 브라우저 형식도 내부 QA 및 위장 접근을 포함할 수 있습니다.
- 일반 브라우저 형식 29개 중 모바일 형식 18개(62.1%), 데스크톱 형식 11개입니다. 작은 표본이며 실제 고객 기기 구성으로 확정할 수 없습니다. 모바일의 메뉴·로그인·AI 입력 흐름을 우선 확인할 근거로는 활용할 수 있습니다.
- 동일한 한국시간 00:00–17:59 구간의 신규 익명 관측은 어제 44개에서 오늘 24개로 45.5% 감소했습니다. 전체 하루 수치와 비교한 결과가 아닙니다. 기록 방식과 자동화 혼입 때문에 외부 신규 고객이 45.5% 감소했다고 결론 내릴 수 없습니다.
- 최근 7일 같은 구간 최초 관측: 10/15 29개, 10/16 98개, 10/17 77개, 10/18 71개, 10/19 61개, 10/20 44개, 10/21 24개입니다. 현 저장소에 남은 기록 기준입니다.

## 2. AI 이용과 워크스페이스

- 오늘 입력 메시지 220건, 대화 프로필 83개, 신규 대화 프로필 81개가 기록됐습니다. 코드에서 입력 역할은 `agent`, 서비스 응답 역할은 `concierge`임을 확인했습니다. 83명 또는 신규 사용자 81명을 뜻하지 않습니다.
- 현재 대화 프로필에 저장된 User-Agent로 분류하면 일반 브라우저 형식 프로필 2개에 입력 3건, 프로그램형 프로필 47개에 입력 47건, 분류 불명 프로필 34개에 입력 170건입니다. **분류 불명 170건을 봇 또는 사람으로 확정하지 않습니다.** 이는 개별 요청 당시 User-Agent를 보존한 이벤트 분류도 아닙니다.
- 채널별 입력은 REST 193건, A2A 20건, MCP 7건입니다. REST 요청이 모두 브라우저에서 온 것은 아닙니다. 각 프로토콜·대화 프로필과 홈 관측 버킷 사이에 검증된 방문자 전환 연결은 없습니다.
- 추천 저널은 133건 중 matched 121건(91.0%), no_match 2건, failed 10건입니다. 추천 처리 상태이며 고객 만족·안전성·외부 실행 성공률이 아닙니다. 입력 메시지 220건과 같은 단위가 아니므로 합산하거나 단순 전환율을 계산하지 않습니다.
- 워크스페이스 로그인 세션은 11개, 로그인한 계정은 2개, 당일 신규 계정은 0개입니다. 이 대화에서 진행한 실제 로그인 점검이 포함돼 있으므로 외부 고객 전환 수로 해석할 수 없습니다.
- 공개 워크플로우 실행 테이블에는 당일 성공 2건이 있습니다. 내부 점검 여부는 분리되지 않습니다. 작업 관측 저널에는 workflow_public succeeded 1건과 pending 1건이 있어, 다른 계층의 기록을 합산하거나 동일한 최종 상태로 치환하지 않습니다.

## 3. 운영 실패 기록을 방문 실패율과 분리

- 기록된 실패 HTTP 요청은 2,083건입니다. 정상 응답 로그는 운영 로그 절감 정책에 따라 저장되지 않으므로 전체 요청 수와 HTTP 실패율을 산출할 수 없습니다.
- 그중 1,410건(실패 기록의 67.7%)은 관리자 `/admin/api/test-reports/existing`의 400 응답입니다. 프론트엔드 방문 실패나 고객 이탈로 혼합해서는 안 됩니다. 반복 요청과 거절 사유를 별도 운영 점검할 필요가 있습니다.
- 5xx는 총 30건: `/chat` POST 503 15건, `/a2a` POST 500 6건, 관리자 overview GET 500 9건입니다. 실제 일반 사용자 피해인지, 승인된 보안·기능 점검에서 발생한 것인지 요청 이력 대조가 필요합니다. 모든 실패 로그의 연결 주소가 루프백인 것은 역방향 프록시 경유일 수 있어 내부 요청임을 증명하지 않습니다.
- CMS·비밀 파일을 탐색하는 경로 그룹의 GET 403 응답은 255건입니다. 사람 방문수로 포함하지 않았으며, 이 수치만으로 침해 성공을 뜻하지 않습니다.

## 4. 지금 측정할 수 없는 항목

익명 홈 관측은 `/` 진입만 저장하고, 정적 페이지 직접 진입이나 SPA 메뉴 클릭을 모두 기록하지 않습니다. 누적 `hits`는 오늘 페이지뷰가 아닙니다. 메뉴 인기 순위, 검색 유입·캠페인 유입, 국가, 실제 사용자 수, 체류 시간, 이탈률, 사람 기준 재방문율, 방문→로그인·AI 사용 전환율은 현재 자료로 신뢰성 있게 복원할 수 없습니다. 외부 엣지 분석·GA 대시보드나 별도 동의 기반 분석 데이터는 이번에 조회하지 않았습니다.

## 5. 개선 우선순위

1. **P0 — 방문 집계 기준 통일:** 홈·정적 직접 진입·SPA 메뉴 전환의 최소 page_view를 같은 기준으로 기록하고 내부 QA·모니터링·선언된 봇을 별도 구분합니다. 저장은 운영 장애 로그와 분리된 경량 이벤트·집계로 구성합니다. 기존 개인정보·동의 설계를 유지하고 분석 산출물에는 식별자·질문 원문·연락처를 넣지 않습니다.
2. **P1 — 실제 이용 여정 측정:** Explore 검색, Chat 입력·추천 상태, Workspace 클릭·로그인 완료, 워크플로우 저장·실행 결과를 단위와 원인에 맞게 연결합니다. 관측 가능한 동일 집단이 마련된 뒤 전환율과 재방문율을 계산합니다.
3. **P1 — 운영 오류 별도 조사:** 관리자 보고서 기존 여부 확인 400의 반복 원인, Chat 503 및 A2A 500을 테스트 요청과 실제 이용 요청으로 나누어 확인합니다. 이 보고서는 원인 수정이나 장애 복구를 수행한 결과가 아닙니다.
4. **P2 — 모바일 우선 검토:** 브라우저 형식 관측의 모바일 비중을 참고해 접이식 메뉴, Google·GitHub 로그인, 긴 질문 입력, 워크플로우 단계 전환·로딩·복구의 모바일 완주를 지속 검증합니다.

## 근거와 한계

`metrics.json`: 원천별 집계와 고정 분석 마감. `crosschecks.json`: 역할 의미·클라이언트 분류·동일 시간대 비교·오류 경로 교차 확인. `validation.json`: 합계 일치 검사. `collect.py`, `refine.py`: 재수집용 읽기 전용 분석 스크립트입니다. 재실행하면 당시의 보존·가변 상태 때문에 과거 숫자가 완전히 재현되지는 않을 수 있습니다.

개인 식별자, 해시 지문, 방문자 토큰, IP, User-Agent 원문, 이름·이메일·연락처, 질문·답변 원문은 산출물에 저장하지 않았습니다. 테스트·운영 변경·서버 재시작·외부 전송 없이 분석만 수행했습니다.
