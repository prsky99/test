# Reviewed connected SDK 1.3 deployments

2026-10-18 · v1.20 · manual deployments of one published canonical public news-to-documentation connection.

## Implemented scope

[Contract and APIs](../../docs/WORKFLOW_CONNECTED_SDK13.md). A highest administrator reviews a currently published canonical connection, exact fixed inputs/recipients, the unknown future-title rule, exact HTTP(S) origins, quotas and expiry, then separately issues its deployment grant and ZIP or single HTML. Publication itself never authorizes deployment or a visitor run. Each manual run requires fresh unchecked title-sharing and live-run declarations. All requests use the fixed `https://agentconcierge.biz` gateway; no provider endpoint, private graph/pin, administrator credential or private grant/principal payload is embedded in the package. Fresh signed run tickets are fetched and submitted separately at runtime.

The independent `capp_` identity is outside legacy apps. Only a publish-key hash is stored. Signed deployment/run purposes bind publication revision, definition/proof/rule, owner, origin, nonce and expiry. A proposal is consumed once, including after revocation; issuance is capped at 20 per owner/hour. Distinct prepare/start/read/cancel quotas preserve accepted replay without another start. The original absolute 25-second deadline, two tool dispatches, signed source certainty/provenance, lease/fence and conservative unknown quarantine remain. New capabilities have no legacy access hash and cannot cross app/origin/public-page/old SDK scopes.

Deployment and publication withdrawal prevent later dispatch and request cancellation of unfinished dependent runs. Restore deactivates grants, increases revisions and retains tombstones; it does not automatically reissue authority. Accepted history is separate from fresh provider readiness and proof retention while still requiring current publication/deployment/owner/origin/key/capability authority. Raw provider wrappers, known connection URLs and internal diagnostics remain outside semantic public results. This known-binding minimization is not universal personal-data or factual-truth classification.

The supplied English app uses local Lucide SVG, text-only semantic results, metadata, responsive light/dark styles, keyboard focus, reduced-motion preferences, nonce CSP and footer policy links. It refuses framed preparation/start; the host must additionally configure HTTP `frame-ancestors 'none'`/`X-Frame-Options: DENY` because meta CSP cannot enforce ancestors. It performs no automatic POST retry, persists no tickets/keys, locks uncertain starts/unknown outcomes and resumes only an existing status capability. Read-only deployment-history refresh reveals a possibly issued grant after an ambiguous export, without another issuance POST.

Existing public SDK 1.0, admin SDK 1.1 and literal SDK 1.2 builders/assets (8), main public HTML/source (2) and existing public connection page/script (2) are byte-identical to v1.19. The new profile adds one public builder and two scripts: current content selection is **66 source/maintenance files, zero policy violations**, not 66 pages or agents. [Inventory](public-content-files.txt). Private pairs, arbitrary/dynamic graphs, credentials, fallback, extended budgets, schedules/events, result delivery and marketing remain separate unsupported purposes.

## Corrections and honest test limits

The browser test reproduced a real new-client logout race: confirmed logout awaited the server before clearing a pending SDK export, allowing its late successful response to create a download. [Initial exposed failure](browser-final.xml) · [log](browser-final.log). The client now clears the SDK review/download epoch immediately after logout confirmation and before awaiting logout. The complete 22-case suite passes. Its earlier string-predicate CSP failure had masked the race; the test was corrected without weakening CSP. Further review reproduced the same pre-existing SDK 1.2 race while its logout response was explicitly held: a valid late ZIP produced a Blob/download before logout completed. [Cross-SDK reproduction](logout-cross-sdk-reproduction.xml) · [log](logout-cross-sdk-reproduction.log). The common workflow-review clearing now happens immediately after confirmed logout, before the awaited logout request. [Final existing/new SDK scope](logout-common-final.xml) passes. The first own broad run was interrupted with SIGINT after this finding and retained under broad-before-common-logout; it is excluded from final totals. A fresh full regression uses the final common fix.

Review also added a single-use atomic export nonce, bounded grant issuance and dependent-run cancellation on publication withdrawal before final freeze. Tests verify them; they are not described as separately reproduced initial exploits. The initial minute-one quota assertion crossed a real minute boundary; only its quota-bucket test clock was fixed, preserving runtime chronology. Browser route fulfillment did not expose native preflight, so that assertion became an explicit API contract check. A separate actual socket test below supplies native browser CORS evidence. The initial native fixture sent the local static host through its denying proxy; adding an exact localhost test bypass corrected the harness, with exported SDK bytes unchanged. Sandbox-only Chromium setup errors were rerun with isolated browser permission. The first post-broad publication browser rerun also exposed an old Stop test assumption: cancellation raced a real provider dispatch, so the UI correctly preserved an unknown outcome and locked another start rather than promising definite cancellation. [Focused initial observation](publication-browser-certainty-initial.xml) · [log](publication-browser-certainty-initial.log). The test now holds its isolated run queued before dispatch, sends the actual cancel request, explicitly completes that cancelled worker and asserts zero provider inputs/attempts. Existing unknown tests still assert the locked/no-replay branch. This is a test-harness correction; product code did not change. Exploratory artifacts remain available and are excluded from final latest totals.
