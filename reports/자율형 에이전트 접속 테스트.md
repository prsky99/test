# 자율형 에이전트 접속 테스트 (agentconcierge.biz)

- **일시:** 2026-10-26
- **방법:** 소스 코드를 보지 않고, 실제 에이전트처럼 공개 주소에 접속했습니다.
  - 종류 조사: `reports/자율형 에이전트 종류 조사.md`(논문·공식 문서·SNS, 12종)
  - 대상 종류: 크롤러, LLM 브라우징, 코딩 에이전트, MCP·A2A 클라이언트, REST 도구 에이전트, 레지스트리 수집기, 준비도 점검 봇, x402 결제 에이전트, 적대적 에이전트, 브라우저 에이전트
- **규모:**
  - 자동 시나리오 76개(`scripts/agent_scenarios.py`)
  - 손으로 한 탐색 약 120건
  - 브라우저 에이전트(Playwright) 1회
  - 다시 돌리는 방법: `docs/qa/autonomous-agent-scenarios.md`
- **지킨 것:** 결제·자격 증명 전송·실행 도구 호출을 하지 않았고, 연속 요청은 25건 이하로 보냈습니다.

## 요약
- **자동 시나리오 결과:** PASS 42, WARN 30, FAIL 4
- **잘 된 점:** 에이전트용 진입점이 매우 잘 갖춰져 있습니다.
  - `robots.txt`, `llms.txt`(링크 22개 모두 정상), `skill.md`
  - A2A 카드(0.3·1.0 둘 다), MCP 매니페스트, 에이전트용 OpenAPI
  - 홈 응답의 `Link` 헤더
  - x402 v2 402 응답
  - 프로토콜 동작: MCP `initialize`·`tools/list`·`tools/call`과 A2A `message/send`·`SendMessage`가 모두 동작합니다.
  - 방어: 프롬프트 주입, SQL 주입, 1MB 본문(413), 가짜 Web Bot Auth 서명이 모두 안전하게 처리됐습니다.
- **가장 큰 문제는 추천 품질과 채널 간 차이입니다.**
  - 같은 요청 "weather forecast for Seoul"에 MCP·A2A·REST는 모두 푸에르토리코 뉴스(`com.787daily/mcp`)를 1위로 줬습니다.
  - 웹 Chat은 "맞는 결과 없음"이었습니다.
  - 짧은 요청 "weather"만 보내야 맞는 결과(Geocoding & Weather)가 나옵니다.
- **에이전트가 기계적으로 쓰기 어려운 부분이 남아 있습니다.**
  - MCP 도구 주석과 outputSchema가 없습니다.
  - A2A 결과가 글 텍스트뿐입니다.
  - CORS를 지원하지 않습니다.
  - 요청 한도 헤더와 다음 페이지 커서가 없습니다.

## 개선 필요 (우선순위 순)

### 높음
1. **문장형 요청의 추천이 엉뚱하고, 채널마다 결과가 다릅니다.**

   | 채널 | 요청 | 1위 |
   |---|---|---|
   | MCP `search` | weather forecast for Seoul | com.787daily/mcp(푸에르토리코 뉴스) |
   | A2A `message/send` | Find an agent that gives a weather forecast for Seoul | 같음 |
   | A2A | 지금 서울 날씨 알려주는 에이전트 찾아줘 | 같음 |
   | REST `/chat`(protocol mcp) | weather forecast | 같음, `more` 뒤에 AgentBIT weather |
   | REST `/chat` | weather | Geocoding & Weather(맞음) |
   | 웹 Chat(브라우저 에이전트) | Find an MCP server that returns the current weather for Seoul | 맞는 결과 없음 |

   - 에이전트는 사람보다 긴 문장으로 묻습니다. "Why: the listing covers weather, forecast"처럼 단어만 맞은 항목이 올라옵니다.
   - 개선:
     - 지역명·동사를 뺀 핵심 작업(weather forecast)으로 다시 검색합니다.
     - 상위 결과가 그 작업을 주 기능으로 하는지 한 번 더 거릅니다.
     - 웹·MCP·A2A·REST가 같은 검색 함수를 쓰게 맞춥니다.
   - Chat 보고서 1번과 같은 원인입니다.
2. **sitemap에 404 주소가 들어 있습니다.**
   - 29개 중 6개가 404였습니다: `communication_messaging`, `database_analytics`, `media_generation`, `productivity`, `public_legal`, `social` 카테고리.
   - `media_generation`은 첫 실행에서는 200이었다가 두 번째 실행에서 404가 됐습니다. 검증된 항목 수에 따라 페이지가 생겼다 없어지는 것으로 보입니다.
   - 영향: 검색 크롤러가 사이트 품질을 낮게 보고 재수집을 줄입니다.
   - 개선: 항목이 0개여도 카테고리 페이지는 200으로 두고 "현재 검증된 항목 없음"을 보여 줍니다. 아니면 sitemap에서 빼는 것을 같은 기준으로 처리합니다.
3. **HEAD 요청이 405입니다.**
   - `/llms.txt`, `/.well-known/agent-card.json`, `/.well-known/mcp.json` 모두 GET은 200, HEAD는 405였습니다.
   - 준비도 점검 봇과 링크 검사기는 HEAD를 먼저 보내므로 "지원 안 함"으로 판정합니다.
   - 개선: 모든 GET 경로에서 HEAD를 허용합니다(FastAPI는 `api_route(methods=["GET","HEAD"])`).
4. **MCP 도구에 위험·읽기 전용 표시가 없습니다.**
   - `search`, `find_agents`, `whats_new`, `credit`에 `readOnlyHint`가 없습니다. `hello`는 `readOnlyHint:false`입니다.
   - 실행·외부 호출 도구(`call`, `adapt_rest`, `subscribe`)에 `openWorldHint`·`destructiveHint`가 없습니다.
   - 영향: Claude·ChatGPT 같은 클라이언트가 조회 도구에도 매번 승인을 묻거나, 실행 도구를 조회처럼 다룰 수 있습니다.
   - 개선:
     - 조회 도구에 `readOnlyHint:true`를 붙입니다.
     - `call`·`adapt_rest`에는 `openWorldHint:true`를 붙입니다.
     - 결제가 따르는 `call`에는 `destructiveHint:true`를 붙입니다.
5. **브라우저에서 실행되는 에이전트가 호출할 수 없습니다(CORS).**
   - `/chat`, `/mcp`에 대한 `OPTIONS` 프리플라이트가 405를 돌려줍니다.
   - 영향: 웹 기반 MCP Inspector, 브라우저 확장, 다른 사이트의 웹 앱이 쓸 수 없습니다.
   - 개선: 공개 조회 경로(`/chat`, `/mcp`, `/api/explore`, `/api/agent/v1/*`)에 CORS를 허용합니다. 허용 헤더에 `content-type`, `x-visitor-token`, `mcp-session-id`, `mcp-protocol-version`을 넣습니다. 계정·결제 경로는 막아 둡니다.

### 중간
6. **A2A 응답이 사람용 글뿐입니다.**
   - 결과가 `parts:[{kind:"text"}]` 하나뿐입니다. 엔드포인트·도구·등급을 얻으려면 글을 파싱해야 합니다.
   - MCP는 `structuredContent`를 주므로 A2A가 뒤처집니다.
   - 개선: 같은 내용을 `DataPart`(`kind:"data"`)로 함께 줍니다.
7. **A2A 대화가 이어지지 않습니다.**
   - 같은 `contextId`로 "only free ones, and tell me more about the second one"을 보내도 첫 답과 같은 목록이 왔습니다.
   - REST는 방문 토큰으로 `details 1`·`more`가 동작하므로, A2A `contextId`에도 같은 대화 상태를 연결해야 합니다.
8. **MCP 도구에 outputSchema가 없습니다.**
   - 13개 모두 `structuredContent`를 주지만 `outputSchema`가 없습니다.
   - 에이전트 프레임워크가 결과 구조를 미리 알 수 없어 검증하지 못합니다.
9. **규격 경계 처리가 느슨합니다.**
   - MCP:
     - `MCP-Protocol-Version: 1999-01-01` 헤더에 400이 아니라 200을 줍니다.
     - 낯선 `Origin: https://evil.example`도 200입니다. 공개 원격 서버라 위험은 낮지만, 규격은 Origin 검사를 요구합니다.
     - 배치 요청을 거절할 때 코드가 -32700(Parse error)입니다. -32600(Invalid Request)이 맞습니다. "Parse error (batches not supported)"라는 문구는 깨진 JSON에도 같이 나와 헷갈립니다.
   - A2A:
     - `A2A-Version: 9.9`에도 결과를 돌려줍니다. 규격은 VersionNotSupported(-32009)입니다.
     - 빈 `parts`에도 결과를 돌려줍니다. -32602가 맞습니다.
   - REST:
     - 깨진 JSON에 200(clarify)을 줍니다.
     - 범위 밖 `limit`(1000)에 pydantic 원문 422를 줍니다(`loc`, `type` 노출).
10. **모르는 방문 토큰을 조용히 새로 발급합니다.**
    - 가짜 토큰이나 잘못된 토큰으로 `/chat`·`whats_new`를 부르면 오류 없이 새 방문자로 시작합니다.
    - 에이전트는 기억이 사라진 줄 모르고 계속 진행합니다.
    - 개선: `visitor.status: "unknown_token"`과 "새 세션을 시작했습니다" 안내를 줍니다.
11. **문서마다 숫자와 경로가 다릅니다.**
    - 카탈로그 수:
      - llms.txt 172,648
      - Status 페이지 HTML 172,646·186,507·186,544
      - 사이트 전반 테스트 때 Status 화면은 185,754
    - llms.txt에 있는 `/api/agent/v1/entry`, `/badge`, `/openapi`가 에이전트용 OpenAPI에 없습니다. 반대로 OpenAPI의 `/api/agent/v1/discover`는 llms.txt에 없습니다.
    - 배지는 llms.txt에 "최대 5분 캐시"라고 적혀 있지만, 실제 응답은 `Cache-Control: no-store`입니다.
    - 개선: 숫자는 한 출처에서 만들고 갱신 시각을 함께 적습니다. llms.txt의 경로 목록은 OpenAPI에서 자동으로 만듭니다.
12. **사설 주소 차단 이유를 알리지 않습니다.**
    - `adapt_rest`에 `169.254.169.254`, `127.0.0.1`을 넣으면 0.3초 만에 거절합니다. 차단은 되고 있습니다.
    - 하지만 문구가 "Failed to parse or reach OpenAPI specification."이라, 공개 주소를 잘못 넣은 경우와 구분되지 않습니다.
    - 개선: "Private or internal addresses are not allowed."로 나눕니다.
13. **실행 거절 문구가 문서와 다릅니다.**
    - llms.txt는 "실행에는 고객이 승인한 informational grant가 필요하다"고 합니다.
    - 그런데 grant 없이 `call`을 부르면 "Payment Required … 20000 micro-USDC … credit account"라고만 합니다.
    - 에이전트는 결제만 하면 되는 줄 알게 됩니다. 필요한 조건(grant, 크레딧, 결제)을 순서대로 알려야 합니다.
14. **skill.md가 에이전트의 지시 파일을 고치라고 안내합니다.**
    - "Copy the following block into your agent instruction file or system prompt"라는 문구가 있습니다.
    - 영향: 신중한 코딩 에이전트(Claude Code 등)는 외부 문서가 자기 지시문을 바꾸라는 요구를 프롬프트 주입으로 보고 거절합니다. 사용자에게 경고를 띄우기도 합니다.
    - 개선: 이 블록을 "사람 운영자가 검토해 추가할 수 있는 예시"로 표현을 바꿉니다. MCP 도구 `hello`의 "Start here"처럼 호출 순서를 지시하는 말도 줄입니다.

### 낮음
15. **요청 한도와 페이지 넘기기 안내가 없습니다.**
    - 연속 25건에 429가 한 번도 없었고, `RateLimit`·`Retry-After` 헤더도 없습니다.
    - `/api/agents/1`, `/2`, `/3`…처럼 연속 ID로 1건에 15~87KB짜리 상세를 끝까지 긁을 수 있습니다. 17만 건이면 수 GB입니다.
    - `/api/explore`에 다음 페이지 커서가 없습니다(더 보기는 `limit`을 늘려 처음부터 다시 받음). `Cache-Control: no-store`라 수집기가 캐시를 쓰지 못합니다.
    - 개선:
      - IP·토큰별 한도를 두고, 넘으면 429와 `Retry-After`를 줍니다.
      - 목록에 `next_cursor`를 넣습니다(변경 피드에는 이미 있습니다).
      - 공개 목록에는 짧은 `max-age`를 줍니다.
16. **응답 시간이 들쭉날쭉합니다.**
    - MCP `search` 1~5.6초, A2A 3~6초, `/api/agent/v1/discover` 8.8초가 걸렸습니다.
    - `/api/explore` 연속 호출은 두 번째 실행 때 중앙값 1.5초였지만, 첫 실행 때는 25건에 129초(건당 약 5초)였습니다.
    - 에이전트 도구 호출의 기본 제한 시간(흔히 10~30초) 안이지만, 여러 번 부르는 오케스트레이터에는 부담입니다.
17. **크롤러가 보는 본문이 페이지마다 같습니다.**
    - `/new/en/*.html` 9개가 모두 4,009~4,013단어였습니다. 모든 화면을 한 HTML에 담은 것으로 보입니다. 검색엔진은 중복 문서로 판단합니다.
    - 카테고리 페이지(`/agents/category/*`)는 50~94단어로 얇습니다.
    - 개선: 페이지마다 그 화면의 내용만 서버에서 렌더링합니다. 카테고리 페이지에는 대표 항목 목록을 넣습니다.
18. **마크다운 협상과 캐시 헤더가 없습니다.**
    - `Accept: text/markdown`에 JSON을 줍니다. `.md` 주소(`/new/en/about.md` 등)는 404입니다.
    - `robots.txt`에 `ETag`·`Last-Modified`가 없고 `no-store`입니다.
    - 코딩 에이전트와 크롤러가 매번 전체를 다시 받습니다.
19. **MCP 서버 카드 후보 경로가 없습니다.** `/.well-known/mcp/server.json`이 404입니다(규격 논의 중인 경로). `/.well-known/mcp.json`과 같은 내용으로 두면 두 방식 모두에 대응합니다.
20. **추천 결과 주소가 robots.txt에서 막혀 있습니다.**
    - 추천 엔드포인트는 모두 `/api/gateway/...`인데, robots.txt는 `Disallow: /api/gateway/`입니다.
    - API 호출은 robots.txt 대상이 아니지만, robots를 엄격히 지키는 사용자 요청형 fetcher는 이 주소를 열지 않을 수 있습니다.
    - 개선: robots.txt 주석이나 llms.txt에 "게이트웨이 주소는 에이전트 호출용이며 수집 대상이 아님"을 적습니다.

## 문제없었던 항목
- **발견:**
  - robots.txt에 Sitemap과 AI 수집기 정책이 있습니다.
  - 12가지 UA(GPTBot, ClaudeBot, Claude-User, ChatGPT-User, PerplexityBot 등) 모두 같은 200 응답이었습니다. 차단·클로킹이 없습니다.
  - llms.txt 링크 22개가 살아 있습니다. 없는 주소는 404입니다(soft-404 없음).
  - 홈의 `Link` 헤더가 agent-card·mcp-manifest·llms·sitemap을 가리킵니다.
- **MCP:**
  - `initialize`(2025-06-18) 응답에 세션 ID가 있고, `notifications/initialized`는 202, `ping`과 `tools/list`도 정상입니다.
  - 순서가 매번 같습니다.
  - 구버전(2024-11-05) 협상과 `server/discover`도 응답합니다.
  - 필수 인자 누락·2,000자 초과·없는 도구에 -32602로 이유를 알립니다.
  - compact MCP(5개 도구)도 정상입니다.
- **A2A:**
  - 카드에 0.3과 1.0 인터페이스가 함께 있습니다.
  - `message/send`와 `SendMessage` 모두 응답합니다.
  - 없는 메서드 -32601, 깨진 JSON -32700, 없는 task -32001이 맞게 나옵니다.
- **REST:**
  - 방문 토큰 발급, `details 1`·`more`·`worked 1`·`what's new`, `report` 뒤 대안 제시가 동작합니다.
  - `resume`의 ETag→304가 동작합니다.
  - 잘못된 타입에 400 JSON을 줍니다.
- **결제(x402):**
  - 결제 없는 요청에 402를 줍니다.
  - `PAYMENT-REQUIRED` 헤더가 v2 형식(`exact`, `eip155:8453`, Base USDC, `payTo`, `maxTimeoutSeconds`)으로 정확합니다.
  - 잘못된 결제 헤더로는 자료가 나오지 않았습니다.
- **게이트웨이 MCP:** 추천된 게이트웨이 MCP(`/api/gateway/mcp/34471`)의 `initialize`·`tools/list`가 0.4초 안에 동작했습니다.
- **방어:**
  - 프롬프트 주입 질의에 내부 정보가 나오지 않았습니다.
  - SQL 주입 문자열에 오류가 나지 않았습니다.
  - 1MB 본문은 413, 깊이 1,000 중첩 JSON에도 5xx가 없었습니다.
  - 가짜 Web Bot Auth 서명에 특별 대우가 없었습니다.
  - 카탈로그에서 "ignore previous instructions" 같은 주입 문구 항목은 찾지 못했습니다.
- **브라우저 에이전트:**
