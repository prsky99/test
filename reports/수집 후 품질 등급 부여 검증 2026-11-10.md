# 수집 후 품질 등급 부여 검증 (2026-11-10)

수집한 자원(resources, 322,641행)과 시험 결과 보고서(agent_test_reports, 20,998행)의 등급을 운영 DB에서 전수 점검했다. 읽기 전용으로 집계했다.

## 등급이 매겨지는 과정

1. 수집기가 자원을 조사한다.
   - MCP: `capabilities.py`
   - A2A: `a2a.py`
   - x402: `evaluate_x402`
2. 원 평가(`evaluation.evaluate*`)로 점수와 등급을 낸다.
3. 같은 자리에서 품질 정책(`apply_quality_policy`, v1)을 적용한다. 정책은 네 가지를 반영한다.
   - 7일 가동률의 Wilson 하한
   - 속도
   - 기능 시험
   - 보안 통제
4. 증거 수준에 따라 등급 상한을 둔다.

| 증거 수준 | 조건 | 등급 상한 |
| --- | --- | --- |
| verified | 기능 시험 통과, 점검 3회 이상, 7일 성공률 95% 이상 | 없음 |
| observed / limited | verified 조건 미달 | B (84.9) |
| failed | 실패 | C (69.9) |

5. 자원 등급 기준
   - A ≥ 85, B ≥ 70, C ≥ 55, D ≥ 40, F
   - 보안 격리는 점수 상한 40
6. 시험 결과 보고서 등급(AQEF-30)은 별도 기준이다. A ≥ 90이고, 실행 근거가 있고, 지연이 2000 ms 미만이어야 한다. 11-10에 바로잡았다.

## 고친 것

- `grade_for()`가 화면에 보이는 점수(소수 한 자리)로 등급을 매긴다.
  - 84.96점은 85.0으로 보이므로 A다.
  - 시험: `tests/test_quality_policy.py`
  - jobs를 배포한 뒤, 다음 재평가 때 92건이 바로잡힌다.

## 결정이 필요한 것

1. **x402 자원 등급: 결제 없는 402 응답만으로 A를 줄지.**
   - 시험 보고서는 같은 근거를 전송 확인으로 보고 B로 제한한다.
   - 자원 등급에도 같은 기준을 쓰면 x402 A 37,459건이 B로 내려간다.
   - 그러면 탐색과 추천의 순서가 바뀐다.
2. **헬스 상태가 down·failing으로 바뀔 때 등급을 바로 다시 매길지.**
   - 지금은 다음 재평가(약 하루 반)까지 A가 유지된다.
   - 바로 다시 매기는 데는 네트워크 요청이 필요 없다. `apply_quality_policy`는 DB 값만 쓴다.
   - 헬스 점검이 상태 변화를 기록할 때 정책을 다시 적용하면 된다.
