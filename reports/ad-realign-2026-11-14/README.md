## 1. 한 줄 요약

광고는 AgentValCon의 신뢰(검증 → 진주 → 목걸이)를 해치지 않는 별도 칸이다. 그 안에서 우리는 자사 광고로 방법론과 목걸이를 알리고, 외부 광고는 USDC로 운영비를 번다. 결제 스위치는 안정성 관문 뒤에만 켠다.

## 2. 법률 검토 없이 쓰는 근거 (지시 1)

법률 검토는 더 이상 선행 조건이 아니다. 대신 **법률 검토가 필요한 영역에 들어가지 않는 설계**가 근거다. 이 설계는 이미 코드와 운영에 들어 있고 그대로 지킨다.

| 하지 않는 것 | 어떻게 막혀 있나 |
|---|---|
| AD Coin 판매·현금화·법정화폐 교환·사람 사이 이전 | 코인은 발행(issuance)으로만 생긴다. 판매·교환 경로가 없다(`issuance_only` 시험). 실가치 스위치는 운영 설정 허용 목록에 없다 |
| 선충전 잔액 | USDC는 예약 1건 = 결제 1건(견적 금액 정확 일치)만 받는다 |
| 고객 자산 보관 | 서버는 받기만 한다. 받는 지갑 키는 서버에 없다. 환불 송금은 사용자가 직접 한다 |

문서에서 "그랜드 오픈 전 법률 검토" 조건을 뺐다.
- 대상: `docs/AD_COIN.md`, `AD_COIN_SALES_POLICY.md`, `AD_COIN_TARGETS.md`, `AD_COIN_PRIVACY_FLOW.md`, `AD_COIN_TERMS_DRAFT.md`, `AD_COIN_TOKEN_CONTRACT.md`, `live_service.py` 주석
- 공개 화면에는 그런 문구가 원래 없었다(검색 0건).

## 3. 신뢰 원칙: 광고는 판정에 영향을 주지 않는다 (코드 수준 보장)

차별점의 핵심이다. 아래 네 가지를 시험(`tests/test_ad_neutrality.py`)으로 고정했다. 구조가 바뀌면 시험이 실패한다.

1. **import 경계:** 광고 코드를 import하는 바깥 파일은 `concierge/front.py` 하나다. 가져오는 것은 라우터 조립 이름 6개뿐이다.
   - 수집·평가·순위·진주·목걸이 모듈은 광고·예약·코인 데이터를 읽을 수 없다.
2. **SQL 경계(읽기):** 메인 앱이 실행할 수 있는 SQL 목록(`application_store_sql.json`)에는 광고 표가 한 번도 나오지 않는다.
3. **SQL 경계(쓰기):** 광고 SQL은 광고 표(`adc2_*`, `ad_coin_*`)에만 쓴다. 등급·시험 보고서·헬스·순위·목걸이 표를 바꿀 수 없다.
4. **표시 경계:** Sponsored 응답은 별도 블록이다.
   - 응답에는 "Sponsored" 표시, 공개 문구, 보상 없음만 들어간다.
   - 카드에는 id, 표시, 광고주 이름, 문구만 있다. 순위·점수·등급·위치는 없다.

그대로 유지하는 것:
- 별도 영역과 "Sponsored" 표시
- Chat 답변 안에는 넣지 않고 답변 아래에만 둔다
- 노출 수에서 내부 측정 요청과 0-RTT 재전송을 뺀다(11-12)

## 4. 자사 광고 (하루 250 coins, 5개국 research)

| 시기 | 광고주 이름 | 문구 |
|---|---|---|
| 지금 → 첫 목걸이 공개 전 | **AgentValCon** | "AgentValCon tests AI agents and MCP tools on real tasks and publishes how it scores them. Find one that does your task." |
| 첫 목걸이 공개 뒤(11-21 목표) | AgentValCon | 그 목걸이 이름과 한 줄 결과. 문구는 성장·유통 팀이 측정값으로 쓰고, 공개 문구 규칙(측정값·방법론 링크)을 따른다 |

**바꾸는 방법(`scripts.ad_coin_house_ad rebrand`, 오늘 구현)**
- 승인·자금이 들어간 캠페인은 고칠 수 없게 막혀 있다(심사받은 광고를 몰래 바꾸지 못하게 하는 장치). 그래서 다음 순서로 바꾼다.
  1. 새 캠페인을 만들고 심사·승인·시작한다.
  2. 내일부터의 자사 예약을 취소하고 같은 날·나라로 새 캠페인에 다시 예약한다.
  3. 옛 캠페인을 멈춘다.
- 오늘 남은 시간은 카드가 빈다. 오늘 날짜는 다시 예약할 수 없기 때문이다. 그래서 09:10 매일 예약 직후 실행을 권한다.
- 코인: 첫 예약 지원으로 성장 예산이 낸 예약은 취소하면 성장 예산으로 돌아간다. 그래서 자사 계정에 정확한 부족분만 운영자 지급으로 채운다(감사 기록).
- 시험: 앞으로의 예약 10건 이동, 나라마다 1칸 유지, 카드에 AgentValCon 표시, 원장 clean, 다시 실행하면 쓰지 않음, 다음 날 매일 예약 정상
- 예약 확인 방식도 바꿨다: 계산한 id 대신 자사 광고주의 실제 예약을 조회한다. 그래서 캠페인이 바뀌어도 한 나라에 두 칸을 잡지 않는다.
- **주의:** 매일 예약(launchd `biz.agentconcierge.opsauto.housead`)은 저장소 작업본의 스크립트를 실행한다. 이번 변경은 커밋 즉시 다음 09:10 실행에 쓰인다. 그래서 관련 시험을 모두 통과시킨 뒤 커밋한다.
- **운영 실행:** 운영 원장 쓰기라 사용자 실행 명령으로 PM에 전달한다(미리 보기 → 실행, 복구는 6절).

**예산(11-14 09:10 기준)**
- 성장 예산은 8,949.999998 coins, 하루 250이라 36일 남았다.
- rebrand는 11-15·11-16 예약 10건을 옮긴다. 추가 비용은 첫 예약 지원 반환분만큼이다(최대 50 coins + 표시 예산 2 atoms).

## 5. 광고 상품과 대상

| 항목 | 지금 | 재정렬 뒤 |
|---|---|---|
| 상품 | Sponsored 1일 칸(분야 × 나라, 하루 2칸), 5 USDC 또는 50 coins | 같음. 목걸이 페이지·워크플로우 메뉴에는 광고를 두지 않는다(목걸이는 우리 홍보 단위다) |
| 광고 대상 | 카탈로그에 올라 있는 제공자(신청 때 목록 주소) | **보안 격리·검토 상태가 아닌 에이전트만**(아래 제안 A) |
| 광고 옆 정보 | "Sponsored" 표시 | **검증 상태 함께 표시**(아래 제안 B) |
| 결제 | USDC 스위치 꺼짐 | 그대로. 안정성 관문(11-11) 뒤에만 켠다 |

**제안 A: 광고 대상 제한(다음 묶음, PM 승인 뒤 구현)**
- 신청 승인과 캠페인 시작 때, 광고주의 목록 항목이 보안 격리(quarantined)나 검토(review) 상태이면 거절한다.
- 매일 예약·노출 시점에는 다시 확인하지 않는다(요청 경로에 실시간 재확인을 넣지 않는 속도 원칙).
- 대신 매일 한 번 상태를 대조한다. 격리된 광고주는 정지하고, 남은 예약은 운영자 반환으로 처리한다.
- 구현 방식은 이렇다. front.py가 광고 라우터를 조립할 때 "목록 상태 읽기" 함수 하나를 넘긴다(읽기 전용, 방향은 광고 → 카탈로그만). 그러면 import 경계 시험에도 이름 하나만 추가된다.
- 지금 외부 광고주는 0명이라(자사 광고만), 열기 전에만 들어가면 된다.

**제안 B: 광고 옆 검증 상태 표시(검토안)**
- 카드 아래에 "Listed · Grade A · Last tested 11-13 · Methodology"처럼 카탈로그의 공개 사실만 붙인다.
- 광고 돈이 이 값을 바꿀 수 없다는 것은 3절의 경계가 보장한다. 값은 공개 확인 API(`/api/agent/v1/check`)와 같은 출처를 쓴다.
- 장점: 광고가 신뢰 신호와 함께 보인다. 등급이 낮은 광고주는 광고 효과가 낮아지니, 품질을 올릴 동기가 생긴다.
- 위험: 표시 값이 늦으면 오해를 부른다. 그래서 "Last tested" 날짜를 함께 보인다.
- 결정: PM. 구현은 제안 A 뒤에 한다.
