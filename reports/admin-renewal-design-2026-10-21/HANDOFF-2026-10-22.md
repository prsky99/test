# 어드민 리뉴얼 인계 (Claude → Codex, 2026-10-22)

이 문서만 읽고 이어서 작업할 수 있게 정리했다. 세부 이력은 `README.md` 13.5~13.12절에 있다.

## 0. 먼저 지킬 규칙 (AGENTS.md·메모리)

- 사용자 응답은 한국어. 공개 프론트는 영어 전용, 어드민 화면은 한국어.
- 사용자 서버를 멈추거나 재시작하지 않는다. 검증은 격리된 테스트 앱과 임시 PostgreSQL로 한다(`scripts/rehearse_*_postgres.py --run`).
- 커밋은 요청이 있을 때만 한다. 비밀번호 입력이나 대리 로그인은 하지 않는다.
- **보존 기간은 현재 상태를 유지한다(사용자 결정, 2026-10-22).** 보존 정책을 제안하거나 적용하지 않는다.
- 운영 DB는 읽기 전용으로만 확인한다(`SET default_transaction_read_only=on`). 예시는 아래 6절.
- 다른 작업자가 "Provider connections" 기능을 병행 개발 중이다(`customer_provider_connections_*`, 워크스페이스 사이드바 8개). 그 파일들은 건드리지 않는다.

## 3. 남은 작업 (우선순위 순)

### 3.1 [바로] 재시작 후 운영 확인
- 1절의 "재시작 후 확인할 것"을 수행하고 `README.md`에 결과를 기록한다.
- 홈 cold 시간을 재측정해 13.6절 한계 항목을 갱신한다. 스냅샷이 있으면 첫 응답에 `cache: stale`이 나와야 한다.

### 3.2 [결정 필요] 워크스페이스 전문 패널 이전 (P3 잔여, 부록 B)
- 남은 기존 패널은 `agent_market/gateway/*-admin.js` 약 22개, 25만 바이트 규모다. 대부분 **직원 비공개 워크스페이스**(`/admin/api/workflow-workspaces/*`: 초안·스냅샷·실행·릴리스)와 신뢰성·연구 제어, 성장·제품 지표다.
- 사용자에게 아직 묻지 않았다. 패널별로 새 콘솔에 이전할지, 기존 화면 바로가기로 둘지 먼저 확인한다.
- 이전한다면 권장 순서:
  1. 조직 상세 › 워크플로·실행·증거(`workspace-flow`, `workspace-typed-evidence`, `workspace-evidence`, `workflow-quality`)
  2. 릴리스·배포(`workspace-release`, `workspace-typed-release`, `workspace-machine-updates`)
  3. 원격 A2A·규격(`workspace-remote-a2a`, `workspace-protocol-conformance`)
  4. 신뢰성·연구 제어 4종
  5. 성장·제품(`workspace-growth`, `advancement`, `workspace-product`)
  6. 합의서·신원(`workspace-agreement`, `workspace-identity`)
- 이전 규칙(기존 이전분과 동일):
  - 변경 작업은 사유를 받고 감사 기록(`log_op`)을 남긴다.
  - 위험 작업은 `ReviewedCommands`에 적용기를 등록해 2인 승인으로 처리한다.
  - 고객 본문은 텍스트로만 표시하고, 캐시 허용 목록(`core/api.js` `cacheAllowed`)에 넣지 않는다.
  - CSP는 `script-src 'self'`이므로 스타일은 CSSOM으로만 넣는다. 클래스는 `adm-` 접두사, 진주 토큰을 쓴다.
  - 각 이전 단위마다 Chromium 테스트를 `tests/test_admin_next_browser.py` 또는 `tests/test_workspace_admin_browser.py`(WAC 월드, 셸 스텁 패턴)에 추가한다.

### 3.3 [근거 필요] P4 변경 기능·폐기
- SNS, 연락 동의, 보안 규칙의 변경 기능을 새 UI로 이전한다. 보안 규칙 일괄 해제는 2인 승인 대상이다(설계 4.3).
- 관리자 역할 변경도 2인 승인 대상이다. 현재는 기존 화면에서 바로 변경되므로 `ReviewedCommands` 적용기로 옮겨야 한다.
- 수신 해지 재활성화는 고객 동의 확인이 필요해 기존 화면에만 있다. 새 콘솔로 옮기려면 동의 근거 설계가 필요하다.
- 기존 `/admin/ui`, 웹앱 v1/v12 폐기와 옛 SQLite 3.5GB 이동은 30일 사용량·배포 확인 근거가 있어야 한다(설계 13.3의 5번). 지금은 하지 않는다.

## 4. 반드시 알아야 할 함정

1. **SQL 카탈로그와 서버 시작 검증.**
   - `agent_market/application_store_sql.json`의 `tables`, `constraints`, `metadata`는 서버 시작 때 운영 스키마와 정확히 일치해야 한다. 어긋나면 서버가 뜨지 않는다.
   - 새 테이블을 기본 `Store` 스키마에 넣지 말고, `workspace_admin_events.SCHEMA`(명시 마이그레이션)에 넣는다. 생성기가 이 테이블들을 검증에서 뺀다.
   - 코드를 바꾸면 `.venv/bin/python -m scripts.build_application_store_postgres_catalog --write`를 실행하고, `tables`가 229개 그대로인지 확인한다.
2. **PostgreSQL 결과 상한.** `store._execute`는 결과 2,000행, 8MB까지만 반환한다(`result_limit`). 큰 집계는 키셋으로 페이지를 나눈다.
3. **전역 쓰기 잠금.** 쓰기 트랜잭션은 `pg_advisory_xact_lock(WRITER_LOCK)`을 잡는다. 1초 이내로 짧게 나눈다(Chat 503 교훈). 큰 인덱스는 `CREATE INDEX CONCURRENTLY`로 트랜잭션 밖에서 만든다.
4. **인증 정책(Codex P1).**
   - 공용 `ADMIN_TOKEN`은 `GET /admin/api/overview`, `/timeseries`만 허용한다.
   - 초기 sadmin은 비밀번호를 바꾸기 전까지 428을 받는다.
   - 조회자는 `admin_policy.VIEWER_READS`만 볼 수 있다. 새 v2 경로는 기본 거부이므로 필요하면 명시적으로 추가한다.
   - 테스트는 `tests/conftest.py`의 개인 세션 헬퍼를 쓴다. 기계 토큰을 쓰면 401이다.
5. **WAC 키.** 테스트에서 `migrate()`에는 앱이 활성화에 쓴 키(`store._workspace_admin_identity_key`)를 넘긴다. 임의 키를 쓰면 다른 라우터가 activate할 때 충돌한다.
6. **zsh 함정.** 셸 반복문에서 `path`를 변수명으로 쓰면 PATH가 덮어써진다. `route`처럼 다른 이름을 쓴다.
