# 리뉴얼 누락·화면 보완 마감 (2026-10-23)

## 고정 작업 순서와 결과

이번 요청의 범위는 13.24의 G01~G06과 관리자 **데스크톱 7개 영역**의 공통 배치·표현·이동 문제다. 기존 미적용 정책을 새 개발 작업으로 확대하지 않는다.

1. **G01 운영 경계:** 기존 로그 메모리 비우기·방문 시뮬레이터를 명시적 개발 모드의 개인 최고관리자로 제한했다. 운영 모드는 개발 환경변수 값과 무관하게 거부한다. 개발에서도 사유와 선행/완료 감사를 남긴다. 운영 화면의 버튼·시뮬레이터 카드도 숨긴다.
2. **G02·G05 공통 기반:** 새 화면의 인증·카탈로그 상세·고객 운영을 v2 별칭으로 연결하고 기존 처리기·권한을 재사용했다. v2 오류의 error_code/message_ko/retryable와 no-store를 통일했다. 고객 요청에 안정된 keyset cursor, 공통 표에 열 선택·표시된 행 정렬, 카탈로그에 관리자 전용 최대 200행 CSV를 적용했다. CSV 수식 주입을 방지하고 민감 본문을 제외한다.
3. **G03·G04 운영 화면:** 홈의 핵심 지표 6개·보조 지표 3개, 전역/고객 승인 합계·지원·사고 대기 작업, 권한별 최근 감사 10건을 연결했다. 저장소는 기존 작업자가 시간당 수집하는 UTC 일별 표본과 실제 설정된 백업·복원·보관 파일 메타데이터를 사용한다. 조회 실패/미설정을 정상·0으로 꾸미지 않는다.
4. **U01 화면 보완:** 카드 간격·폼·버튼·탭·표 도구 모음·고정 사이드바·상세 레이어를 정리했다. 워크플로 이름/ID 검색은 현재 직원 멤버십에 허용된 초안만 반환한다. 카탈로그 상세/탭 URL, 제한된 페이지 복원·영역별 스크롤 복원, 중복 로딩/오래된 응답 방지, 로딩 상태를 연결했다. 상세 사전 읽기는 허용된 일별 상태에만 적용한다. 두 테마와 기존 키보드/감소 모션 경계를 유지했다.
5. **G06 시각화:** typed-flow 전문 패널에 현재 허용된 정의·최근 단계 상태의 Pearl 미리보기를 연결했다. 원래 JSON 편집기·승인·실행 경계를 보존하며 고객 비공개 입력/출력 권한을 추가하지 않는다.
6. **기능·보안 검증:** 아래 격리 회귀와 임시 PostgreSQL 검증을 완료했다. 다음은 사용자 터미널의 일괄 반영과 운영 읽기 확인이다.

## 검증 결과와 해석

- 선택한 **고유 230건**의 검사 범위를 수집했다. 마지막 통합 실행은 **228건 통과·2건 실패(284.38초)**였고, 두 실패는 크레딧/ID 검색 mock의 기존 고객 API 경로였다. mock을 v2로 맞춘 뒤 해당 두 건과 실제 지연 요청을 확인하도록 강화한 로그아웃까지 **3건 모두 통과**했다. 단일 통합 실행 230건이 모두 녹색이었다고 표시하지 않는다. 최초 통합 181건 중 174건 통과·7건 실패 후, 실패 7건을 모두 수정·재검증했다. 원인은 브라우저 mock이 새 `/admin/api/v2/auth/me`를 제공하지 않은 것이었다. 후속 19건 여정, 설정/보완 55건, 마지막 보완 11건, 화면 1건 등 **중복 실행을 합산하지 않고** 최종 판정을 기록했다. 선택 범위는 `suites.json`, `collected-final.txt`, 실행별 결과는 validation.json을 참조한다.
- 추가로 실제 PostgreSQL NULL cursor 매개변수의 타입 추론 오류를 발견해 CAST로 수정했다. `postgres-last.json`의 최종 리허설은 통과했고 임시 클러스터를 제거했다. 이 검증에는 새 읽기 모델·권한·멤버십·CSV·페이지 이동·일별 표본 기록이 포함된다. 운영 부하 SLA나 운영 복원 합격 증명은 아니다.
- 7개 영역을 1440px, light/dark로 검사하고 가로 넘침·콘솔 오류·외부 호출, 열 선택/정렬·고객 승인 바로가기를 확인했다. `screenshots/after-*.png` 14개를 남겼다. 전문 패널의 저장/실행·동의·해제·세션 종료·직원 초안 여정도 영향 회귀로 확인했다. 관리자 모바일은 사용자 지시에 따라 제외했다.
- JavaScript **42개 문법 오류 0건**, 신규 보완/공통 보안의 Ruff 검사 통과, 전문·직원 생성물 동기화 변경 없음, PostgreSQL SQL 카탈로그 **3,695문장/229테이블** 동기화 통과, 공개 콘텐츠 **249개 위반 0건**이다. 기존 영역에 남은 미사용 import/변수 Ruff 경고 13건은 `affected-lint-final.txt`에 보존했다. 저장소 전체 정적 경고 0건으로 주장하지 않는다.
- 운영 DB 변경·외부 제공자 호출·운영 시뮬레이션·로그 삭제·서버 재시작은 수행하지 않았다. 과거 실패 기록도 보존했다. 과거 completion-audit/probe.py는 누락 재현 코드이며 수정 후 합격 검사로 다시 사용하지 않는다.

## 운영 반영과 조건

이번 소스·격리 검증 완료와 운영 배포 확인을 구분한다. 사용자 터미널에서 다음 묶음을 한 번 반영한 뒤 읽기 전용 확인을 진행한다. 프론트엔드/실행 워커의 배포는 필요하지 않다.

```bash
agentcon package admin-renewal-ui-20261023-v1
agentcon deploy admin admin-renewal-ui-20261023-v1
agentcon worker-deploy jobs admin-renewal-ui-20261023-v1
```

시간별 저장소 표본에는 jobs 변경본이 필요하다. 7일 전 UTC 표본이 생기기 전까지 증가율은 수집 중으로 표시한다. 초기 표본 수집 시각은 기존 작업자의 유지보수 주기에 따른다. 표본 실패가 원래 고객 이벤트 처리·정리 작업을 중지시키지 않도록 분리했다.

백업/보관의 선택적 설정 파일은 `gateway-data/admin-evidence.env`이며 소유자 전용 0400/0600, 리터럴 키/값만 허용한다. 키는 `AGENTCON_ADMIN_BACKUP_ROOT`, `AGENTCON_ADMIN_SQLITE_ARCHIVE` 두 개다. 운영 경로를 추측해 설정하거나 파일을 이동·삭제하지 않았다. 실제 백업 폴더의 manifest.json과 같은 백업 지문에 연결된 restore-report.json이 있어야 복원 기록으로 표시한다. 웹 조회가 백업 본문의 무결성을 재검사하거나 복원을 수행하는 것은 아니다. 이전 릴리스는 이 선택적 파일을 읽지 않아 롤백 설정과 분리된다.

## 완료 범위의 한계

G01~G06의 위 기능 보완과 U01 공통 화면 수정은 개발·격리 검증을 마쳤다. 모든 설계 문구의 100% 완료나 모든 운영 화면의 사용자 수용을 선언하지 않는다. 공통 정렬은 표시된 행 대상이고 CSV는 카탈로그 제한 추출이다. 페이지 복원은 카탈로그에서 최대 10페이지이며 모든 전문 패널의 임의 편집 상태를 영속 저장하지 않는다. typed 미리보기는 권한 내 읽기 전용이다. 비민감 허용 목록 밖으로 캐시·사전 읽기를 확대하지 않는다.

기존 TOTP·분 단위 집계·전용 페이싱/완전한 후보 전환 계측·파티션/보존 변경·운영 SLA·기존 화면/API/웹앱/SQLite 폐기 조건은 **기존 보류/운영 수용**으로 유지한다. 원본 링크 6곳도 호환을 위해 유지한다. 이번 묶음의 추가 개발 누락으로 반복 등록하지 않는다. 실제 화면에서 새로운 재현 결함이 확인되면 해당 결함만 후속 수정한다.

## 사용자 반영 후 운영 읽기 확인

사용자 재시작·새로고침 보고 후 admin·jobs가 모두 `admin-renewal-ui-20261023-v1`, 배포 상태 stable임을 확인했다. 양쪽 패키지의 해당 런타임/빌드 소스 **34/34**가 이전 지문과 일치한다. 검사 전용 테스트 4개가 패키지에서 제외된 것은 정상이다.

로컬 운영 HTTP GET 확인 **56/56 통과**: JS/CSS 자산 **44/44** 내용 일치, 관리자 셸 CSP/no-store와 기존 개발 카드 숨김, 새 API 7개 비인증 거부 및 표준 오류, 기존 모니터링 집계 허용·비공개 새 API 거부를 확인했다. 서명된 준비 상태 GET에서 관리자 ready, jobs의 실제 DB heartbeat available, 기본 헬스 주기 **21,600초(6시간)**를 확인했다. 저장소 표본도 **1일분** 기록돼 있다. 운영 변경 명령·외부 제공자 호출은 하지 않았다.

**범위 제한:** 컴퓨터유즈 도구의 전체 상태 조회가 32초·45초에 두 번 시간 초과돼 현재 개인 직원 세션으로 실제 화면/비공개 API를 다시 확인하지 못했다. 따라서 위 결과를 인증 후 모든 화면 기능 합격으로 확대하지 않는다. 이전 격리 브라우저 검증과 실제 운영의 자산/권한 경계 확인은 구분한다. 이 도구 한계 때문에 추가 서버 재시작은 필요하지 않다. 실제 7일 표본 축적·백업/보관 근거 설정과 기존 보류도 그대로 구분한다.
