## 1. 진주 판정 (PM 05:5x 엄격 기준)
아래 조건을 **모두** 만족해야 진주입니다. 판정은 매일 다시 하고, 하나라도 깨지면 그날 진주에서 빠집니다.

| # | 조건 | 지금 쓰는 데이터 | 비고 |
|---|---|---|---|
| 1 | 등급 A | `resources.eval_grade='A'` | 지금은 A가 최고 등급입니다 |
| 2 | 보안 격리·검토가 아님 | `eval_security NOT IN ('quarantine','review')` | |
| 3 | 최근 7일 헬스 정상 | 지금 `healthy`이고, `health_checks` 7일 기록이 3회 이상이며 `fail`이 0회 | |
| 4 | 시험 호출 성공 | `trial_ok=1`이고, `trial_info.at`이 7일 안 | |
| 5 | **실행 범위 공개 시험 보고서** | 최신 성공 보고서 `agent_test_reports.evidence_scope='execution'` | 연결만 확인한 transport 보고서는 인정하지 않습니다 |
| 6 | 보고서가 **일 도구**를 실행함 | 보고서의 `tool_name`이 계정·문서·헬스·범위 안내·분류 목록 도구가 아님 | 이번에 새로 넣은 조건(아래 설명) |
| 7 | 도구 정의 변경 없음 | 지금은 `usage_changes`가 비어 있음으로 대신 잼 | 운영·SRE 도구 지문이 생기면 교체합니다 |

조건 6이 필요한 이유:
- 지금 진주 33개 가운데 8개는 실행 보고서가 `get_account`, `list_coverage`, `docs_health` 같은 도구를 실행했습니다.
- 이런 보고서는 연결은 증명하지만, 과제를 해내는 가치는 증명하지 못합니다.
- 그래서 일 도구로 확인된 진주는 25개입니다.

## 4. A2A 진주 (지금 0개)
- 원인: A2A 시험은 에이전트 카드만 확인합니다(transport). `message/send`를 실행하지 않으므로 실행 범위 보고서가 생기지 않습니다.
- 제안: 범위를 좁힌 읽기 전용 과제 시험입니다. **PM 확인을 받은 뒤 착수합니다.**
  - 대상: 카드의 skill이 조회형일 때만 합니다(search, lookup, price, weather, summary of public data 등).
    - 쓰기·주문·예약·결제·계정 동사가 있는 skill은 뺍니다.
  - 입력: 카드에 있는 그 skill의 `examples` 값만 씁니다. 개인정보나 자격 증명은 절대 넣지 않습니다.
  - 횟수: 제공자당 하루 1회, 시간 제한 20초, 응답 본문은 4KB까지만 저장합니다.
  - 성공 판정: 응답이 task(completed) 또는 message이고, 본문이 skill과 관련 있을 때입니다. 판정 규칙은 기존 A2A 평가(`collector/evaluation.py`)를 재사용합니다.
  - 지금 a2a 후보 775개 가운데 읽기 전용 일 skill이 있는 것은 144개입니다.

## 5. 진주 표 (1단계: 파일, 2단계: 표)
### 1단계 (이번 주)
- jobs 정비 칸에서 매일 `scripts/pearls.py snapshot`(새 파일)을 실행해 `exports/pearls/YYYY-MM-DD.json`을 씁니다.
- 수정 경로는 정해야 합니다. `exports/`는 git에 넣지 않습니다.
- 항목:
  - id, kind, host, category
  - 판정 조건별 통과 여부와 근거 값(보고서 id·시각, 헬스 횟수, 시험 시각)
  - 진주가 된 날, 빠진 날과 이유
  - 역할 키(6절)
- 전날과 비교해 새로 된 진주와 빠진 진주를 현황판과 워크플로우 팀에 넘깁니다.

### 2단계 (판정이 1주 안정된 뒤)
- `agentcon_search.pearls` 표를 만듭니다. public 스키마가 아니고, 트리거도 없습니다.
- 운영 DB 변경 순서를 따릅니다: 리허설, 복구 SQL, 승인.

## 6. 진주 관계와 "같은 역할" 묶음 (Neo4j, 대체 사슬의 재료)
- **역할 키**: (분야, 동작 동사, 입력 타입 서명, 출력 타입 서명)
  - 예: `(travel_maps_weather, get_forecast, {location:string}, {forecast:object})`
  - 입력·출력 서명은 도구 `inputSchema`의 필수 키 이름과 타입을 정규화한 것입니다. 출력은 실행 보고서의 `output_wire`에서 뽑습니다.
- **같은 역할**: 역할 키가 같거나 거의 같은 진주끼리 SAME_ROLE 관계로 묶습니다.
  - "거의 같음"은 필수 입력이 같고, 출력 필드가 70% 이상 겹치는 경우입니다.
  - 묶음 안에서 순위를 매깁니다: 실행 성공률 → 지연 → 등급 점수 → 호스트 다양성.
  - 이 순위가 목걸이 자리의 **외부 대체 사슬**이 됩니다. 사슬 정책은 워크플로우 팀이 정합니다.
  - 외부 대체가 1개 이하인 역할은 "Agentcon 대체 필요"로 표시해 넘깁니다(PM 05:1x).
- **함께 쓸 수 있음**: A의 출력 타입이 B의 필수 입력을 채우면 FEEDS 관계, 같은 분야의 다른 동작이면 COMPLEMENTS 관계입니다.
- **위치**: 맥미니 Neo4j(GDS). 앞서 맡은 P1(호스트·중복 묶기)은 진주 후보 정리 단계로 이어집니다.
  - 원천은 PG 스냅샷 파일입니다(5절). Neo4j는 계산만 하고, 결과는 파일로 넘깁니다.

- 카드 항목:

### 배치 규칙 (`scripts/pearl_batch.py`)
- 켜는 곳: `batch_report_runner.py`가 `PEARL_BATCH=1`을 줄 때만 켜집니다.
  - 시험과 수동 실행에서는 꺼집니다.

- 제공자별 규칙: 하루 3회, 60초 간격, 429나 `Retry-After`를 받으면 그날 다시 부르지 않습니다.
  - 상태 파일 `logs/ops/report-batch/hosts-YYYYMMDD.json`에 남겨, 같은 날 두 번째 실행도 이 규칙을 따릅니다.
- MCP: 수집기 시험 호출 도구가 계정·문서·헬스 도구이면 보고서를 만들지 않습니다(`SKIP_METADATA_TOOL`).
- A2A(②): 아래 조건일 때만 `message/send`를 1회 보냅니다.
  - 카드에 `securitySchemes`가 없음
  - 조회형 skill이고, 실행·결제 동사가 없음
  - 카드가 공개한 `examples` 입력만 씀. 개인정보·자격 증명 패턴이 있으면 쓰지 않음

  - 보고서 문구는 "the card's published example input was sent, once; the reply was received and recorded, not judged for accuracy"입니다.
- 비용: 보고서는 템플릿으로 만들고 LLM을 쓰지 않습니다. 유료 호출은 0입니다.
