# 등록 기능 테스트 (agentconcierge.biz)

- **일시:** 2026-10-26
- **방법:** 공개 화면이 쓰는 API를 화면과 같은 형식으로 직접 호출했습니다.
  - 입력 형식은 화면 스크립트(`operating.js`)에서 확인했습니다.
  - 요청은 1.5~3초 간격으로 약 110건 보냈습니다.
  - 고객 가입은 OAuth라 Google/GitHub 로그인 직전에서 멈췄습니다.
  - 결제·자격 증명은 쓰지 않았습니다.
- **대상 기능:**
  - 에이전트 등록: 조사 `/api/register/inspect`, 등록 `/api/register`, 구형 `/agents/register`
  - 문의
  - 작업 알림 구독: `/api/task-updates`와 MCP `subscribe`
  - 고객 가입·로그인
  - 개인정보 요청·수신 거부
  - 결과 보고: `/api/agent/v1/report`
  - 서명 클라이언트 전용 등록: `/needs`, `/sns/posts`, `/offers`

## 요약
- **잘 막는 것:**
  - 사설 주소: 12가지 변형 모두 차단
  - 위험한 스킴(`javascript:`·`file:`·`ftp:`), HTML 태그, 너무 긴 입력
  - 중복 등록
  - 요청 한도: 429 뒤 자동 차단
  - 알림 구독의 동의·주소 검사
  - OAuth의 state·PKCE·고정 redirect_uri
- **잘못 받아들이는 것:**
  - 법적 동의가 없거나, 버전이 틀리거나, 날짜가 미래인 등록
  - 에이전트가 아닌 사이트(example.com 등)를 "verified, healthy"로 등록
  - 사이트 자기 자신의 MCP 등록
  - 문의 폼의 줄바꿈 헤더 주입·스크립트 문자열·같은 문의 반복

## 개선 필요 (우선순위 순)

### 높음
1. **법적 동의 없이도 에이전트가 등록됩니다.**
   - `legal_consent`를 빼고 보내도 200 "Successfully registered and verified!"였습니다(206598).
   - 약관 버전을 `1999.1`로 보내도, 동의 시각을 `2099-01-01`로 보내도 등록됐습니다(206603, 206604).
   - 화면에는 필수 체크박스가 있지만, 서버가 검사하지 않아 API로는 그냥 지나갑니다.
   - 개선: 서버에서 다음을 모두 검사하고, 하나라도 어긋나면 400을 돌려줍니다.
     - `legal_consent`가 있는지
     - `tos_version`·`privacy_version`이 현재 버전과 같은지
     - `agreed_at`이 요청 시각 ±10분 안인지
2. **에이전트가 아닌 사이트가 "검증됨"으로 등록됩니다.**
   - 조사(`inspect`): `https://example.com/`에 `ok:true`, `kind:"mcp"`, 설명 "Example Domain MCP service endpoint", 카테고리 `network_ops`를 지어서 돌려줍니다.
   - 등록: example.com이 x402 `healthy`(206599)로, example.org·example.net 주소가 MCP `reachable`(206602~206604)로 들어갔습니다.
     - MCP `initialize`에도, x402 402 응답에도 답하지 않는 일반 웹 페이지입니다.
   - 메시지는 "Successfully registered and verified!"입니다.
   - 영향: 아무 URL이나 카탈로그에 올라가 추천 품질과 신뢰를 떨어뜨립니다.
   - 개선: 종류마다 프로토콜 응답을 확인한 뒤에만 등록합니다.
     - **MCP:** `initialize` 결과가 와야 합니다.
     - **A2A:** 카드에 `name`·`skills`가 있어야 합니다.
     - **x402:** 402와 `accepts`가 와야 합니다.
     - 실패하면 "MCP initialize 응답이 없습니다"처럼 이유를 알려 줍니다.
     - 조사 결과에서 지어낸 설명은 빼고, 찾은 값만 보여 줍니다.
3. **사이트 자신의 엔드포인트가 등록됩니다.**
   - `https://agentconcierge.biz/mcp`가 일반 MCP로 등록돼 `/api/gateway/mcp/206598`이 생겼습니다.
   - 게이트웨이가 자기 자신을 다시 감싸는 고리가 생깁니다.
   - 개선: 자기 도메인과 `/api/gateway/` 주소는 등록을 거절합니다.
4. **문의 폼에 줄바꿈 헤더 주입이 그대로 저장됩니다.**
   - 제목 `"hi\r\nBcc: victim@example.com"`이 200으로 접수됐습니다.
   - 운영자 알림 메일의 제목에 이 값이 들어가면, 메일 헤더가 추가돼 스팸 발송에 쓰일 수 있습니다.
   - 개선: 제목·이름에서 `\r`, `\n`을 거절하거나 공백으로 바꿉니다. 메일을 보낼 때 다시 한 번 검사합니다.
5. **문의를 같은 내용으로 반복해도 모두 접수됩니다.**
   - 같은 이름·메일·제목·본문으로 4번 보내자 4건 모두 다른 번호로 접수됐습니다. 문의 경로에는 요청 한도가 걸리지 않았습니다.
   - 개선:
     - 같은 메일·본문은 10분 안에 한 번만 받습니다.
     - 문의 경로에도 IP·메일별 한도를 둡니다.
     - 공개 폼에는 Turnstile 같은 확인 단계를 검토합니다.

### 중간
6. **문의 본문의 `<script>` 문자열이 그대로 저장됩니다.**
   - 에이전트 등록은 HTML 태그를 막는데, 문의는 받아들입니다.
   - 관리 화면에서 이스케이프하지 않고 보여 주면 저장형 XSS가 됩니다.
   - 개선: 관리 화면(`/admin/ui`)에서 반드시 이스케이프하는지 확인합니다. 아니면 등록과 같이 꺾쇠를 거절합니다.
7. **없는 값을 조용히 받아들입니다.**
   - 문의의 없는 분류(`zzz`)가 접수됐습니다.
   - 등록의 없는 카테고리(`nope`)는 `other`로 바뀌어 저장됐습니다. `other`는 14개 카테고리에 없습니다.
   - x402 가격 -5는 0으로 바뀌어 저장됐습니다.
   - 개선: 허용 목록에 없으면 400과 허용 값 목록을 돌려줍니다.
8. **오류 문구가 실제 원인과 다릅니다.**

   | 입력 | 지금 문구 | 맞는 문구 |
   |---|---|---|
   | 없는 도메인(`*.invalid`) | Private or internal network addresses are strictly prohibited | 주소를 찾을 수 없습니다(DNS) |
   | `https://user:pass@example.com/` | 같은 사설 주소 문구 | 주소에 자격 증명을 넣을 수 없습니다 |
   | OAuth `begin`에 `return_to`나 `redirect_uri` 추가 | Choose Google or GitHub sign-in. | 지원하지 않는 매개변수입니다 |

9. **한 경로의 요청 한도 위반이 사이트 전체를 막습니다.**
   - `inspect`를 1분에 13번쯤 부르면 429가 나오고, 429가 5번 쌓이면 모든 경로가 403 "Auto-jail"이 됩니다. 문의, 알림, 검색까지 막힙니다.
   - 방어로서는 동작하지만, 같은 IP를 쓰는 다른 사용자나 에이전트까지 함께 막힐 수 있습니다.
   - 개선:
     - 차단은 해당 경로나 기능 범위로 한정합니다.
     - 403 응답에 `Retry-After`와 풀리는 시각을 넣습니다.
     - 429에도 `Retry-After`를 넣습니다.

### 낮음
10. **빈 개인정보 요청도 접수됩니다.** `{}`를 보내도 "received"와 접수번호, 45일 처리 안내가 나옵니다. `request_type`을 필수로 합니다.
11. **구형 등록 경로가 영어 사이트에서 한국어로 답합니다.**
    - `/agents/register`는 `{"url": "<에이전트 base URL>"}`, "사설/내부 주소는 등록할 수 없습니다."라고 답합니다.
    - `/needs`·`/sns/posts`는 "X-Client(지갑 주소)와 X-Signature가 필요합니다.", `/offers/accept`는 "없는 제안입니다."라고 답합니다.
    - 에이전트용 문구는 영어로 통일하고, 구형 경로는 새 경로를 안내하거나 닫습니다.
12. **등록 성공 문구가 과장돼 있습니다.**
    - `reachable`(연결만 됨)인데도 "Successfully registered and verified!"라고 합니다.
    - 상태별로 문구를 나눕니다. 예: "등록됨, 프로토콜 확인 대기".
13. **알림 webhook 인증 대기 건이 남습니다.**
    - webhook 구독을 만들면 확인 전에도 `pending_verification`으로 약 90일간 남습니다.
    - 확인 코드를 받지 못한 건은 24시간 뒤 지웁니다.

## 문제없었던 항목
- **에이전트 등록 검사:**
  - 사설·내부 주소 12가지 변형을 모두 거절했습니다: 127.0.0.1, localhost, 10.0.0.1, 169.254.169.254, [::1], 0.0.0.0, 10진수 IP 2130706433, localtest.me, 127.0.0.1.nip.io, 사설 주소 등록, 메타데이터 주소 등록, 구형 경로 사설 주소.
  - `javascript:`, `file:`, `ftp:`를 거절하고 문구도 정확합니다.
  - URL 1,000자, 설명 2,000자 제한이 있습니다.
  - 이름·지갑 주소의 HTML 태그를 거절합니다.
  - 없는 프로토콜 종류를 거절합니다.
  - 같은 URL의 중복 등록은 409와 기존 ID로 알려 줍니다.
- **요청 크기:** 100KB 문의 본문은 413입니다.
- **문의 검사:** 이름 길이(2~100), 메일 형식, 본문 길이(5~4,000)를 검사합니다.
- **작업 알림 구독:**
  - 권한·동의 확인이 없거나 오래된 안내 버전이면 거절합니다.
  - http, 사설 주소, 자격 증명이나 쿼리가 붙은 webhook 주소를 거절합니다.
  - 마케팅 동의는 안내 버전이 있어야 합니다.
  - 개인정보처럼 보이는 작업 이름과 없는 채널을 거절합니다.
  - 다른 토큰으로는 남의 구독을 바꿀 수 없습니다(401).
  - 정상 poll 구독은 생성·조회·이벤트·삭제가 모두 동작했습니다.
- **구형 MCP `subscribe`·`verify_contact`:** 새 절차(task updates)로 안내하고 등록하지 않습니다.
- **고객 가입(OAuth):**
  - Google·GitHub 모두 `state`와 PKCE `S256`을 쓰고, `redirect_uri`는 자기 도메인 콜백으로 고정돼 있습니다.
  - 공급자 목록 외의 값과 외부 `return_to`·`redirect_uri`를 거절합니다. 열린 리다이렉트가 없습니다.
- **로그인 없는 고객 기능:** 세션 조회는 401, 크레딧 등록·지원 문의 생성은 403입니다.
- **결과 보고:** 없는 ID, 문자열·음수 ID, 목록에 없는 오류 종류를 모두 400으로 거절합니다.
- **서명 클라이언트 전용 경로:** `/needs`, `/sns/posts`는 서명 없이 401입니다.

## 확인하지 못한 것
- **OAuth 로그인 이후 단계:** 계정 생성, 워크스페이스 생성·초대는 실제 Google/GitHub 계정이 필요해 진행하지 않았습니다.
- **webhook·A2A 수신함 인증:** 확인 코드를 받을 수신 주소가 없어 끝까지 진행하지 않았습니다. 브라우저 푸시 구독도 같습니다.
- **알림 메일:** 문의와 헤더 주입 문자열이 운영자 메일에 실제로 어떻게 들어가는지는 메일함을 볼 수 없어 확인하지 못했습니다.
- **관리 화면 표시:** `<script>` 문의가 관리 화면에서 이스케이프되는지는 확인하지 못했습니다.
- **결제가 필요한 등록:** 크레딧 충전·결제 흐름은 시험하지 않았습니다.

## 권장 수정 순서
1. 서버의 법적 동의 검사(1번)와 문의 줄바꿈 제거(4번): 법적·보안 위험이 가장 큽니다.
2. 프로토콜 응답을 확인한 뒤에만 등록하고, 자기 도메인 등록을 막습니다(2, 3번).
3. 문의의 중복 방지와 요청 한도, 관리 화면 이스케이프 확인(5, 6번)
4. 허용 목록 검사와 오류 문구 정리(7, 8, 10~12번)
5. 자동 차단 범위 조정과 `Retry-After`(9번), 인증 대기 건 자동 정리(13번)
