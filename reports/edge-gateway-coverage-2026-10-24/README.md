# 전체 Provider의 Edge Gateway 적용 재점검

2026년 10월 24일 오전 9시 47분 KST 기준 스냅샷. 공개 Agent API에는 A2A·MCP·x402 전체를 대상으로 동적 Edge 라우팅이 적용돼 있다. 신규 ID를 개별 설정 파일에 추가하는 방식이 아니라, 요청 시 등록 상태와 입력을 심사한다. 다만 모든 등록의 성공 실행과 서비스 전체 실행 경로의 Edge 전환은 별도 검증 항목이다.

## 실제 적용 범위

Cloudflare 공식 API로 현재 Worker `30b03bd3-c801-446d-a157-3cf70063d803` 100%와 5개 fail-open Route를 재확인했다. 로컬 테스트 소스 SHA는 해당 배포 때 보관한 소스 스냅샷과 같다. 운영 정책은 `catalog_policy`, Protocol은 A2A·MCP·x402, canary 제한 없음, 현재 신규 요청 우선 경로는 Worker(`free_available`)다. 설정 파일의 명시적 Provider 한 개는 기존 검증 pin이며 전체 대상의 유일한 허용 목록이 아니다.

- `/api/gateway/a2a/*`: 지원되는 동기 정보 요청을 Edge 후보로 심사한다.
- `/api/gateway/mcp/*`: 등록된 안전한 `tools/call`을 Edge 후보로 심사한다. initialize·ping·tools/list 등은 기존 Origin 메타데이터 경로를 이용한다.
- `/api/gateway/x402/*`: 결제·지갑·인증정보 없이 GET challenge 조회만 지원한다. 유료 작업 완료와 구분한다.
- `/api/test/execute`: 지원되는 Protocol·입력에 같은 Edge 준비 절차를 적용한다.
- `/api/edge-gateway/v1/*`: 승인된 단일 실행과 서명된 health를 처리한다.

등록 개수는 제공자 회사 수가 아닌 리소스·연결 등록 수다. 조건을 통과한 실행 요청이 Edge 후보가 되며, 한도·health·관찰값이 유효해야 Worker로 실행한다. 지원 밖의 프로필은 실행권 확보 전에 기존 Origin으로 넘길 수 있다. 인증·안전 정책 위반은 제한한다. 실행권 확보 후 결과 불확실 상태는 Origin에서 자동 재실행하지 않는다.

## 전체 등록과 증가분

최신 일관된 읽기 전용 스냅샷은 **152,713건 / 27,102개 호스트**, 최대 등록 ID 163836다. 이전 149,052건 대비 **3,661건 증가**했고 삭제된 등록은 0건이다. 신규는 A2A 1,769건, MCP 219건, x402 1,673건이다.

공개 Edge 프로필의 정적 후보는 **73,765건**, 같은 연결·입력·Schema 중복 14건을 정리한 입력 후보는 **73,751개**다. 구성은 A2A 3,737건, MCP 14,387건, **x402 미결제 probe 55,641건**이다. x402 수를 유료 실행 가능 수나 AI 작업 성공 수로 해석하지 않는다. 현재 DNS·실시간 capability 제한·응답 계약·CPU는 실제 요청 시 추가로 확인한다.

이번 점검에서 집계 도구가 x402의 미결제 조회까지 유료 실행과 함께 제외하던 불일치를 수정했다. 실제 운영 정책은 원래 미결제 challenge 조회를 허용하고 있었다. 따라서 이전 18,080개 정적 후보에서 증가한 수에는 집계 보정과 상태 변화가 함께 포함되며, 전부 신규 확보로 계산하지 않는다. 최초 재집계 파일은 비교 근거로 보존했고 최종 집계는 `probe-aware-census/census-summary.json`을 사용한다.

새로 등록된 3,661건 중 **1,688건**이 정적 Edge 후보다: A2A 18건·MCP 74건·x402 미결제 probe 1,596건. 나머지 1,932건은 정책상 제외, 9건은 Schema 확보, 22건은 안전 입력 준비, 10건은 프로필 검토가 필요하다. ID·Protocol·호스트별 목록은 `new-registrations.csv`, 후보는 `new-edge-candidates.csv`에 저장했다. 기존 등록에서 후보로 바뀐 목록은 `existing-new-candidates.csv`로 분리했다. 기존 x402 54,040건의 변화에는 집계 방식 차이가 포함된다.

## 앞으로 확대할 수 있는 대상

현 상태에서 보완 검토할 등록은 **7,216건**이다. 이는 최대 전환 보장 수가 아니라 확인 작업 대기 목록이며, 같은 제공자가 여러 등록을 가질 수 있다.

1. **MCP Schema 확보 3,134건:** 공식 tools/list·버전·입력 계약을 확보하고 해시 및 안전 정책을 확인한 뒤 후보로 편입한다. 현재 목록에서는 조회·메타데이터 확보만 준비하고, 이번 점검에서 해당 Provider에 네트워크 요청을 하지 않았다.
2. **안전한 정보 조회 입력 3,226건:** 무해한 조회 tool과 최소 입력을 준비한다. 이 중 44건은 원격 예제의 민감·부적절 값 때문에 제외된 건이므로 예제를 그대로 재사용하지 않는다.
3. **프로필 검토 856건:** 대용량 메타데이터·지원 계약을 검토한다. 60KB 등의 기존 경계를 단순히 늘려 전환하기보다 제어 메타데이터 처리와 출력 streaming 범위를 분리해 성능·보안을 검증한다.
4. **앞으로 새로 등록되는 항목:** 지원 Protocol·공개 HTTPS·안전 정책·현재 Schema·사용 가능한 입력을 갖추면 ID별 수동 추가 없이 동적 심사를 받는다. 새로 등록됐다는 이유만으로 성공 실행 상태로 표시하지 않는다.
5. **인증·유료 Agent 실제 작업:** 현재 공개 프로필 밖이다. 명시적 사용자 승인, credential 격리, 결제 권한과 재시도 방지 계약을 별도로 설계한 뒤 확대할 대상으로 분리한다. x402 미결제 probe와 구분한다.

추가로 확대할 실행 경로도 있다. 현재 소스에서 Workspace 비공개 실행은 `workspace_execution.py`의 Native Proxy, typed flow는 `workspace_typed_flows.py`, Workflow MCP 노드는 `workflows.py`의 Native Proxy를 사용한다. 다운로드 웹앱 SDK는 `/api/workflows/run`과 상태 조회 API를 사용하고, 게시 웹앱은 서버 Runtime에 작업을 제출한다. 이 경로에는 위 5개 공개 Edge Route가 직접 적용되지 않는다. 모든 Workflow 결과를 Edge로 출력하려면 기존 단일 실행권·취소·입력 pin·완료 기록·세션 보안을 보존하는 별도 연결이 필요하다. 단순 Route 추가만으로 비용·기능 검증을 완료할 수 없다. 이번 작업에서는 해당 실행 구조를 변경하지 않았다.

## 계속 확인할 사항

기존 실제 순회 219건의 영수증을 읽기 전용 재확인한 결과 Worker 성공 121건·결과 미확정 30건·실패 55건·완료 대기 1건·영수증 없는 항목 12건이다. 현재 테스트 순회는 ID 55450의 완료 미확정 때문에 `allow_probes=false` 보호 대기 중이다. 신규 후보 1,688건과 보정된 x402 후보를 기존 순회에 자동 추가하지 않았다. 기존 후보·idempotency 기록과 이미 실행한 요청을 보존했다.

기존 격리 시험은 8.2시간·115,404건 후 메모리 안전 기준으로 중단됐다. 후속 24시간 목표 시험은 기록 시점 1.3시간·18,964건, 예상 밖 응답 오류 0건으로 실행 중이다. 이전 운영 확대 표본의 CPU 23.6ms와 완료 callback 미확정, 장기 메모리 기준 실패는 여전히 검증 과제로 남아 있다. 후속 격리 24시간 완료와 원인 확인을 마친 뒤 확대 범위를 판단한다. 읽기 전용 자동 추적과 기존 운영 보호 장치는 유지했다.
