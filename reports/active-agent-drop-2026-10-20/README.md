# 어드민 활성 에이전트 감소 조사

측정 시각: 2026-10-20T15:58:48.332705+09:00. 운영 DB는 읽기 전용으로 조회했습니다. 수치 복구, 코드 변경, 서버 재시작은 하지 않았습니다.

## 결론

큰 감소의 주원인은 **외부 x402 카탈로그에 보이지 않게 된 항목을 내부 수집기가 자동 비활성화한 것**입니다. 추가로 오늘 7일 실패 제외 정책이 적용된 2,122건이 어드민 활성 수에서 빠졌습니다. 최근 파일·제안서 정리로 DB가 삭제돼 발생한 현상은 아닙니다. 확인한 대량 비활성화는 파일 정리보다 이른 오늘 새벽에 이미 발생했습니다.

단순히 외부 서버 2만 개가 모두 중단됐다는 뜻은 아닙니다. 외부 목록 등록 상태와 실제 서비스 응답 상태가 다르며, 내부의 대량 제외 방어와 재등장 복구도 개선할 필요가 확인됐습니다.

## 어드민 숫자의 정확한 의미

어드민은 `dashboard.html`의 `totals()`에서 `active=1`인 항목 중 `health_status='retired'`를 제외합니다. `healthy`만 세는 수치는 아닙니다.

- DB 전체 등록: **123,281건**.
- 레지스트리 활성 플래그: **98,146건**.
- 그중 7일 실패 제외(retired): **2,122건**.
- 어드민 개요 활성 수: **96,024건**.
- 활성 중 최근 저장 상태가 healthy/reachable인 항목: **87,415건**.

소스 위치: `agent_market/gateway/dashboard.html:4389`, `agent_market/gateway/dashboard.py:619`. 홈의 cataloged 수치와 어드민 활성 수치는 retired 포함 여부가 다를 수 있습니다. 신규 수집이 계속되므로 현재 화면은 조사 스냅샷과 몇 건 달라질 수 있습니다.

## 외부 목록 축소를 뒷받침하는 독립 확인

현재 외부 전체 목록과 문제 배치에 해당하는 20,863개 URL 집합을 비교했습니다.

- **20,795건(약 99.67%)**이 지금도 외부 목록에 없습니다.
- **68건**은 현재 목록에 다시 나타났지만, 독립 조회 시작 시 로컬에서는 비활성이었습니다. 새벽 당시에도 외부 목록에 있었는지는 과거 raw 페이지가 없어 확정할 수 없습니다.
- 전체 비활성 이력을 통틀면 현재 외부 목록에 있는데 로컬 active=0인 항목은 **102건**입니다.
- 이번 감소 집합의 **19,715건(94.50%)**은 `market.datapackvibe.com` 한 호스트에 집중됩니다. 이 중 현재 외부 목록에도 없는 것은 19,647건입니다.
- 해당 호스트에서 현재 외부 목록에 노출되는 URL은 236개입니다. 호스트별 여러 API 주소가 각각 항목으로 집계되므로 한 제공자의 목록 변화만으로 수만 건이 변할 수 있습니다. 수만 개 독립 제공자가 사라진 것으로 해석하면 안 됩니다.

Coinbase의 이 API는 발견·캐시된 활성 리소스 목록이며 실시간 서버 전수 점검 결과 자체가 아닙니다. 캐시 및 offset/limit 페이지 방식을 사용합니다. [Coinbase 공식 SDK의 목록 API 설명](https://github.com/coinbase/cdp-sdk/blob/main/typescript/packages/cdp-sdk/src/openapi-client/generated/x402-facilitator/x402-facilitator.ts).

목록에서 제외된 원인이 제공자 등록 철회, 외부 정리 정책, 외부 시스템 장애 중 무엇인지는 공개 응답만으로 확정할 수 없습니다.

## 외부 제공자가 전부 죽었다는 증거는 없음

비활성화 집합에는 마지막 저장 상태가 healthy/reachable인 항목도 **9,444건** 있습니다. 이는 마지막 점검의 상태이며 현재 실행 성공을 보장하는 값은 아닙니다.

`market.datapackvibe.com`의 비활성 4개·활성 1개에 대해 결제·인증 없이 진단 GET을 수행했으며 모두 HTTP 405로 응답했습니다. 등록된 메서드는 POST이므로 405는 이번 GET 방식에 대한 응답입니다. 서버 연결·응답이 가능함을 확인했지만, 실제 POST 기능 성공이나 결제 실행을 검증한 것은 아닙니다.

`api.magentlab.com`의 비활성 표본 2개는 약 8초 후 타임아웃됐습니다. 표본 수가 작고 타임아웃 원인을 개별 분해하지 않았으므로 844개 전체의 장애나 외부 측 단독 책임을 단정하지 않았습니다.

## 내부에서 확인된 보완점

**우선순위 1 — 대량 제외 보류 장치.** 현재는 두 차례 미등장 조건을 만족하면 20,863건도 한 번에 제외합니다. 소스별 수집량/활성 수가 급감하거나 한 호스트에 집중된 경우 비활성화를 보류하고 요약 경고·관리자 검토로 넘기는 장치가 필요합니다. 숫자만 복원하는 일괄 활성화보다 원인과 실제 응답을 확인해야 합니다.

**우선순위 1 — 전체 수집 완료 검증.** 격리된 가짜 Store·HTTP 응답으로 재현한 결과, pagination total이 없거나 max_pages에 도달해도 성공 처리와 deactivate_unseen 호출이 가능합니다. 필수 페이지 메타데이터, 끝 페이지 도달, total/실수집 고유 개수, 중복 비율을 검증한 경우에만 제외해야 합니다. 이번 사건에서 이 결함이 실제 발동했다는 증거는 없습니다. 현재 독립 조회는 정상 끝까지 완료됐습니다.

**우선순위 2 — 재등장 복구 지연.** x402 증분 조회는 앞쪽 두 페이지가 연속 무변경이면 멈추고 기본 전체 수집은 약 24시간마다 실행됩니다. 다시 등장한 URL이 뒤쪽에 있으면 복구가 늦을 수 있습니다. 비활성 후보 재대조나 페이지 순환 확인으로 이미 알려진 재등장 항목을 갱신할 필요가 있습니다.

**우선순위 2 — 등록 여부와 서비스 가능 상태의 분리 표시.** registry_missing, retired, 실패, 최근 정상 등을 이유별로 표시하고, 대량 상태 변화의 건수·원인·시점을 배치 단위로 보존해야 합니다. 로그 용량을 늘리지 않도록 항목마다 로그를 남기는 대신 요약 이벤트를 남기는 방법이 적합합니다. 한 호스트가 차지하는 비중도 함께 확인할 수 있어야 합니다.
