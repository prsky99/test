## ① 발견됨-현재 색인 안 됨 8,787: 원인 가설과 근거 (11-16 운영 스냅샷, 코드 계산)
1. **고립된 에이전트 페이지(가장 큼)**
   - 색인 대상 에이전트 페이지는 3,863개다. 그중 2,692개(70%)는 랭킹·과제·비교 페이지 621개 어디에서도 링크되지 않는다. 사이트맵으로만 알려진다.
   - 링크되는 1,171개는 모두 허브에서 한 단계로 닿는다.
   - 에이전트 페이지는 평균 6개의 다른 에이전트로 링크하지만, 이미 링크된 1,171개 안에서만 이어진다. 그래서 고립 페이지가 줄지 않는다.
   - Google은 내부 링크가 없는 사이트맵 전용 주소를 크롤링 순서 뒤로 미룬다.
2. **크롤링할 가치가 없는 주소가 대기열을 채움**
   - x402·얇은·중복 에이전트 5,369개(noindex)는 x402 랭킹 20개와 비교 203개(noindex, follow)에서 링크된다. 그래서 대기열에 들어간다.
   - 8,787개 중 상당 부분이 이 noindex 예정 페이지로 보인다. 크롤링되면 NOINDEX로 옮겨 갈 뿐 색인 수는 늘지 않는다.
3. **크롤 속도**
   - Googlebot은 원서버에서 에이전트 페이지를 하루 460~783건 가져갔다(11-13~15 traffic bots). 엣지 HIT는 세지 않았으니 실제로는 더 많다.
   - 새 사이트로서는 적지 않다. 다만 위 2의 낭비가 섞여 있다.
4. **응답 속도:** Googlebot은 미국에서 오므로 LAX 지연(한국 기준)은 해당하지 않는다. 성장 페이지는 엣지 6시간 캐시다. 가장 작은 원인으로 본다.
5. **얇은 생성 페이지 비중**
   - 사이트 전체 주소 약 1만 개 중 색인 대상은 4,500개다. 나머지는 의도한 noindex다.
   - Google은 사이트를 통째로 평가한다. 생성 페이지가 많을수록 크롤링 우선순위가 낮아질 수 있다(가설, 검증 어려움).

### 개선안 (효과 큰 순서)
- **A. 고립 페이지를 없애기(권장)**
  - 카테고리별 전체 목록 페이지(예: /agents/best/<category>/all?page=N, 한 쪽 100개)를 만들고 랭킹 페이지에서 링크한다. 색인 대상 3,863개 모두가 허브에서 2~3번 클릭 안에 닿는다.
  - 또는 에이전트 페이지의 "비슷한 에이전트" 6개를 같은 카테고리 순위의 이웃(앞뒤)으로 바꾼다.
  - 두 방법 모두 새 주소는 색인 대상만 링크한다.
- **B. noindex 페이지로 크롤 예산이 새지 않게 하기**
  - x402 랭킹·x402가 낀 비교 페이지를 "noindex, nofollow"로 바꾼다. 그러면 x402 에이전트 5,264개로 가는 링크를 Google이 따라가지 않는다. 페이지와 API는 그대로 열려 있다.
- **C. 하위 사이트맵 따로 제출(②)**
- **D. 비교 쌍 고정**
  - 비교 주소가 매일 바뀌어 404·302가 생긴다(108건).
  - 한 번 나온 쌍은 두 에이전트가 목록에 있는 동안 페이지를 유지한다. 사이트맵에는 오늘 쌍만 낸다.

## ② 사이트맵 '발견 650'
- 공개 /sitemap.xml은 형식이 맞는 sitemapindex다. 하위 3개(pages 650, agents-1 2,000, agents-2 1,863)를 가리키고 모두 application/xml이다(12:2x 확인).
- 650은 pages.xml 수와 같다. Google이 11-15에 읽을 때 agents-1·2를 아직 처리하지 않았을 수 있다.
- 원서버 traffic은 /sitemaps/ 주소를 세지 않는다(entry 없음). 엣지 HIT도 원서버에 오지 않아, Googlebot이 가져갔는지 우리 기록으로는 알 수 없다.
- 할 일(PM, Search Console)
  - 사이트맵 상세에서 하위 사이트맵별 상태를 본다.
  - /sitemaps/agents-1.xml과 /sitemaps/agents-2.xml을 따로 제출한다.
