# 지능형 어댑터와 특급 진주: 조사와 타당성 검토 (2026-11-15, PM)

사용자 지시(11-15): ① 에이전트 팀은 목걸이에서 에이전트를 잇는 자리의 입력·출력을 어떤 상황에서도 처리하는 지능형 어댑터를 개발해 적용한다. ② 많이 쓰는 목걸이는 하나의 자체 에이전트(특급 진주)로 만들어 AA 등급으로 등록하고, 일정 사용량을 넘으면 유료로 전환한다. 타당하고 매출에 도움이 되면 도입한다. ③ 방법은 논문과 SNS를 조사해 가장 효율적인 것으로 한다.

표기: [읽음] = 원문을 열어 확인, [요약] = 검색 결과 요약만 확인, 추정 = 추론.

## 1. 결론
- **어댑터: 도입한다.** 구조는 "만들 때 연결 규칙을 합성하고 검증해 고정, 실행할 때는 그 규칙만 돌린다"이다. 실행 경로에서 모델을 부르지 않는다.
- **특급 진주: 방향은 타당하다. 지금은 기준과 계량만 만들고, 대상 목걸이가 기준을 넘으면 만든다.** 공개 목걸이가 0개이고 실제 외부 질의가 30일 400건이라 만들 대상이 아직 없다.
- **유료 전환의 기대는 낮게 잡는다.** 찾은 실제 사례는 작다(5주 매출 1.19달러). 매출의 병목은 가격이 아니라 발견과 유입이다.

## 2. 어댑터

### 2.1 지금 상태
- 자리 연결은 `agent_market/necklaces/runner.py`의 계약별 정규화 함수 10개와 `{{slot.X.Y}}` 틀이다.
- 11-15 하루에 이 연결에서 나온 결함: registry ticker 칸 오해, 서경 좌표 부호 유실, "lat X lon Y" 문장 읽기 실패, package → GitHub 저장소 넘기기, 규모 칸이 정수라 4.5를 거절.
- 실행 기록이 적어 실패 유형을 셀 자료가 거의 없다. 첫 단계는 자리 사이에서 오간 것과 버려진 것을 남기는 기록이다.

### 2.2 채택한 구조
| 단계 | 내용 | 근거 |
|---|---|---|
| 1. 만들 때: 연결 규칙 합성 | 앞 자리의 실제 답 표본 여러 개와 뒤 자리의 입력 스키마를 모델에 주고 변환 규칙을 후보 여러 개로 만든다 | 한 번 만든 코드를 재사용하는 쪽이 행마다 모델을 부르는 쪽보다 정확하다(아래 표 1·2) |
| 2. 만들 때: 검증과 순위 | 후보를 실행 가능 여부, 정답 세트 대비 정확도로 걸러 가장 좋은 것만 채택한다. 오류는 모델에 되돌려 다시 만든다 | 생성-검증-순위 절차 [읽음] |
| 3. 실행할 때: 고정 규칙만 | 저장된 규칙만 돌린다. 결과는 뒤 자리의 입력 스키마로 검증한다. 모델 호출 없음 | 3자리 5초 예산(추정). 중간 결과를 모델에 통과시키면 토큰과 복사 오류가 는다 [읽음] |
| 4. 실행할 때: 실패 처리 | 검증에 실패하면 지어내지 않고 그 자리를 "값 없음"으로 끝내 다음 멤버로 넘긴다 | PM 조건. 형식 제약이 추론 정확도를 깎는 사례(표 5) |
| 5. 변화 감지와 재합성 | 도구 정의 지문과 답 모양의 지문을 저장한다. 바뀌면 그 연결을 격리하고, 다시 합성해 정답 세트를 통과한 뒤에만 교체한다 | 자동 반영 대신 승인 관문을 두라는 권고 [요약] |

- 4단계에서 "좁은 모델 예비 경로"(스키마 제약 출력으로 1회 추출)는 조사에서 권장됐지만 **처음에는 넣지 않는다.** 실행 경로에 모델이 들어가면 속도 목표, 주입 위험, 지어낸 값의 위험이 함께 들어온다. 고정 규칙의 실패율을 기록으로 잰 뒤 필요가 숫자로 보이면 로컬 모델로 넣는다.
- 합성에 쓰는 모델: 오프라인이라 지연 제약이 없다. 사용자 API 키 예산(하루 4달러 상한, 공개 Chat 금지)이나 맥미니 로컬 모델을 쓴다. 연결 한 쌍당 한 번이라 비용이 작다(추정).

### 2.3 버린 대안
- **호출마다 모델로 추출**: 긴 JSON 도구 답에서 가장 좋은 모델도 정확도 77%이고 답이 길수록 떨어진다. 단계마다 지연이 붙는다.
- **이름 유사도·임베딩으로 칸을 자동 연결**: GPT-4도 평균 F1 0.47~0.58. 단위와 식별자의 뜻은 이름으로 잡히지 않는다. 합성 때 후보를 좁히는 보조로만 쓴다.

### 2.5 실패 유형과 막는 방법
| 실패 | 막는 방법 |
|---|---|
| 없는 칸을 지어냄 | 실행 경로에 모델 없음. 결과를 뒤 자리 스키마로 검증. 실패하면 멈춤 |
| 단위·식별자가 조용히 어긋남 | 중간 값에 단위·식별자 종류를 형으로 붙임(통화, 좌표 부호, 날짜, CIK·ticker). 합성 때 정답 세트로 검증. 범위·자릿수 점검 |
| 답 속의 주입이 다음 자리로 넘어감 | 목걸이의 흐름은 고정이고 답이 그것을 바꾸지 못함. 다음 자리에는 형이 정해진 값만 넘김. 자리별 도구 고정 |
| 도구 정의 변경·바꿔치기 | 도구 정의 지문(이미 있음) + 답 모양의 지문 + 주기적 계약 시험. 바뀌면 재검증 전까지 차단 |
| 부분 답·빈 답 | 필수 칸이 없으면 넘기지 않고 "값 부족"으로 끝냄. 빈 목록과 실패를 구분 |
| 오류 문구를 자료로 읽음 | 전송 계층의 오류 표시(MCP isError, HTTP 상태)를 먼저 봄. 오류 응답에는 추출을 시도하지 않음 |
| 다시 만든 규칙이 틀린 채 반영됨 | 정답 세트 통과와 관문 뒤에만 교체 |

### 2.6 "어떤 상황에서도"에 대해
- 조사한 어떤 방식도 모든 답을 맞게 읽지 못한다. 어댑터가 지킬 수 있는 약속은 "읽을 수 없으면 틀린 값을 넘기지 않고 멈춘다"이다.
- 그래서 처리 범위는 숫자로 관리한다: 연결마다 고정 규칙이 읽어 낸 비율, 멈춘 비율, 멈춘 뒤 다른 멤버가 채운 비율.

## 3. 특급 진주 (많이 쓰는 목걸이를 하나의 자체 에이전트로)

### 3.1 타당성
찬성
- 여러 단계를 한 도구로 묶으라는 권고가 있고, 도구 호출 기록에서 자주 나오는 흐름을 찾아 묶으라고 한다 [읽음: anthropic.com/engineering/writing-tools-for-agents].
- 에이전트 쪽 조율은 실제로 약하다(위 표 7).
- 목걸이 자체가 이미 "한 번 호출"이다. 특급 진주는 그 목걸이에서 외부 멤버 의존을 걷어 내 속도와 가용성을 우리가 책임지는 판이다.

반대와 주의
- "한 번 호출이 에이전트 조율보다 낫다"를 토큰·지연·정확도로 함께 잰 통제 실험은 찾지 못했다. 우리 값 증명 측정(reports/necklace-value-method-2026-11-15)이 그 숫자를 낸다.
- 유료 수요가 작다. 개인이 만든 x402 API는 5주에 유료 호출 67건·매출 1.19달러였고, 10곳 넘게 등록해도 발견이 병목이었다 [읽음: printmoneylab.com 2026-05-19]. x402 전체 거래의 약 절반이 자기 거래라는 추정도 있다 [읽음: forkast.news 2026-07-10].
- 외부 멤버를 걷어 내면 "진주를 발굴해 잇는다"는 서비스의 중심과 멀어진다. 그래서 특급 진주는 목걸이를 대체하지 않고 나란히 둔다.

### 3.2 전환 기준 (PM 초안, 사용량이 생기면 조정)
목걸이가 아래를 모두 채우면 특급 진주 후보로 올린다.
1. 최근 30일 외부 실행 성공이 일정 수 이상이고(초안 300건), 서로 다른 호출자가 일정 수 이상이다(초안 20). 봇·우리 측정·자동 반복은 뺀다(11-15 수요 표 정정에서 쓴 기준).
2. 다시 온 호출자의 비율이 보인다(초안 30%).
3. 모든 필수 자리를 유료 제공이 허용된 원천으로 채울 수 있다(약관 표의 "유료 제공 가능" 칸).
4. 자체 구현의 정답률이 그 목걸이의 관문 기준 이상이다.
- 숫자는 근거가 없는 초안이다. 공개한 사례를 찾지 못했다. 첫 한 달의 실제 분포를 보고 정한다.

### 3.3 AA 등급
- AA는 같은 시험 기준으로 받는 등급으로 둔다. 기준을 방법론에 공개하고, 제3자 에이전트도 채우면 AA가 된다.
- 초안: 시험 보고서 v2 95점 이상, 서로 다른 날 7회 연속 성공, 7일 가용성 기준, 자료 신선도 표시, 대체 경로 있음.
- 우리 것에는 "Operated by AgentValCon"을 붙인다(7b1dcba9). 순위에서 올리거나 내리지 않는다.
- 근거: 플랫폼이 자기 서비스를 유사한 제3자보다 유리하게 순위에 두는 것이 규제 대상이 된 사례가 있다(EU DMA 6(5), Amazon 2022 약속) [요약]. 우리에게 직접 적용되는 규정은 아니지만, 순위의 신뢰가 우리 상품이다.
- classify·evaluation의 규칙 버전을 올려야 하면 재처리 시간을 먼저 잰다.

### 3.4 유료 전환
- 방식: 무료 한도 뒤 건별 결제. 기존 결정대로 USDC on Base, 선충전·잔액·보관 없음. x402가 이 모양에 맞는다(요청마다 결제, 계정 없음).
- 참고 가격 [읽음]: Tavily 무료 월 1,000회·그 뒤 호출당 0.008달러, CoinMarketCap x402 요청당 0.01 USDC. 조회형 API의 흔한 선은 호출당 0.005~0.01달러, 무료 월 1,000회 안팎(추정).
- "무료 한도 뒤 x402 건별 결제"를 구현한 공개 사례는 찾지 못했다. 무료 한도를 계정 없이 세는 방법이 과제다(호출자 식별이 날마다 바뀜).
- 과금 시작은 그때 사용자 확인을 받는다. 목걸이 실행은 지금 무료 이벤트다.

### 3.5 라이선스
- 유료가 되면 원천 약관을 다시 본다. 지금 확인된 것: GitHub API는 과금 시 재판정, CC BY 원천은 표시 의무를 지키면 상업 이용 가능, World Bank의 제3자 데이터셋은 원 라이선스가 따로 적용 [읽음].
- 무료 이용만 허용하는 원천은 유료 판에서 빼거나 원문 링크만 준다.

| 성장·유통 | AA 기준을 방법론에 공개(확정 뒤), 자체 에이전트 표시 유지 |

## 5. 확인하지 못한 것
- 방식별 지연·비용의 직접 비교, 형이 붙은 중간 값과 계약 시험의 효과 수치.

- 디렉터리가 자체 에이전트를 표시·분리하는 정책 문서.
