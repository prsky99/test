# AI AD Coin 개발 현황과 우선 검수 기준 v4

기준일 2026년 11월 6일 한국 시간

## 문서의 목적과 현재 결론

이 문서는 AI AD Coin의 현재 소스를 기준으로 사업 기획과 개발 현황을 연결한다. 11월 4일 사업 기획 v3를 이어받되, 현재 구현·시험·남은 검증을 구분한다. 새 시장 조사 문서가 아니며 기존 연구·법률 자료의 조사 기준일을 오늘로 바꾸지 않았다.

**우선순위는 완벽 보안, 품질 100%, 글로벌 최고 처리 속도 순서다.** 보안 위험을 속도나 수익으로 상쇄하지 않는다. 보안 관문 뒤에 품질 검수 범위 전체 통과를 확인하고, 그 조건을 유지하며 속도를 높인다.

현재는 가상 재원의 닫힌 시험 구현이다. 관련 자동 시험의 최신 고유 결과는 89건 통과, 기존 HTTP 동적 보안 시나리오는 219건 통과다. 사람 승인과 에이전트 인증의 경계, 실제 노출 증거, 재인증·복구 등 미완 항목이 있어 상용 보안 완료나 품질 100% 달성을 선언하지 않는다. 다지역 비교 증거도 없어 글로벌 최고 속도 달성을 주장하지 않는다.

이번 작업은 문서와 검증 원자료만 갱신했다. 운영 서버를 중지·재시작하거나 릴리스를 배포하지 않았고, 운영 DB·플래그·실광고·결제·외부 지갑을 변경하지 않았다. 기존 운영·배포 상태는 11월 5일 기록을 인용하며 이번에 현재 상태를 재확인한 것은 아니다.

## 1 사업 요구와 실제 구현

사업의 기본 순환은 콘시어지의 광고·추가 AI 활용 제안, 방문 에이전트의 사용자 설명, 사용자 승인, 노출 보상, 에이전트 지갑 임시 보관, 코인 사용 또는 사용자·다른 에이전트 지갑 이전, 제공자 정산이다. 기존 기능과 정책은 이 순환의 수익·안전·활용을 강화하는 방향으로 발전시킨다.

현재 `agent_market/ad_coin/`은 Python 모듈 20개이며 등록 SQL은 174개 모양이다. `config.py`에서 1코인을 10원 상당의 시험 AI 작업 차감 단위로 정의하고 기본 배분을 사용자 50%, 운영자 10%, 직접비 15%, 플랫폼 25%로 둔다. 이는 실물 예치금·현금 상환·수익률을 보장하는 값이 아니다. 플랫폼 몫도 고정비·환불·세금 이후 순이익을 뜻하지 않는다.

구현 상품은 세 가지다.

- **S1 작업 후원:** 이미 정해진 유료 작업을 후원한다. 승인·노출 조건을 충족하면 해당 작업의 실행권을 지급한다. 지갑 코인 지급과 다른 경로다.
- **P2 노출과 확인:** 승인·15초 포그라운드 값·확인 답변을 받고 지갑 코인을 지급한다. 답의 정답 여부는 지급 조건이 아니다.
- **B1 서명 오퍼:** 인증된 에이전트 운영자가 오퍼 수신 영수증을 제출하면 운영자 보상을 기록한다. 사람 노출이나 사용자 코인 획득으로 계산하지 않는다.

**승인된 광고 노출 자체의 독립 코인 보상은 사업 요구로 유지한다.** 현재 P2에는 답변이 필수이므로, 추가 행동 없는 순수 노출 코인 상품까지 완성됐다고 표현하지 않는다. 클릭·시청 구간·가입·구독·구매별 추가 보상도 구현 완료 상품에 포함하지 않는다.

견적 패킷은 후원·보상·동의 조건을 설명한다. 방문 자율형 에이전트가 외부 사용자에게 설명하고 다시 승인을 전달하는 전체 연동까지 검증한 증거는 없다. 가격만으로 품질 우위를 주장하지 않는 사업 원칙도 유지한다.

근거는 `config.py`, `exchange.py`, `service.py:PRODUCTS`, `quote()`, `exposure()`와 `upgrade.py`다.

## 2 지갑과 작업 정산의 현재 범위

코인 지갑은 내부 복식부기 원장의 사용자·에이전트 계정이다. 원장은 분개 균형, 음수 잔액 방지, 멱등 처리, 이행 의무와 시험 재원의 정합성을 검사한다. 코인을 옮긴다고 새 가치나 광고 성과가 생기지 않는다. 외부 블록체인 주소 출고와 현금 출금은 이 내부 이전에 포함되지 않는다.

고객 계정 초대, 고객 세션과 CSRF, 에이전트 키의 해시 보관·이름 결속·철회는 구현되어 있다. 키 철회 때 위임장을 철회하고 에이전트 지갑을 사용자 지갑으로 회수하는 경로도 있다. 14일 휴면 회수, 제공자·건당·총액·최대 30일의 의도 위임장 제한을 서비스 계층에서 처리한다. 다만 인증된 에이전트의 API 권한이 이 제한을 우회하지 않는지는 4절의 출시 차단 항목이다.

공개 워크플로, 본인 권한의 비공개 워크플로, 단계·호출 수 묶음 견적이 구현되어 있다. 가격은 묶음 전체에서 한 번 반올림하고 줄별 합계와 맞춘다. 실행 기록 정산은 작업·실행 횟수·시작 시각·중복 사용을 확인해 성공 호출 몫을 지급 예정으로 기록하고 나머지를 지갑 또는 광고주 에스크로로 돌린다. 실행 중이면 정산을 기다린다.

실행 기록을 읽는 기능과 실제 유료 제공자 호출·실제 대금 지급은 별개다. 숨김 시험 상품은 시뮬레이션이고 관리자 완료 API도 존재한다. 실제 외부 제공자의 과금·결과·자동 정산을 끝까지 검증한 상용 흐름으로 표현하지 않는다. 실행 기록과 결제된 작업 정의의 강한 결속도 검수 범위에 포함한다.

Ed25519 영수증은 원장이 어떤 사실을 기록했고 서명 후 변조되지 않았는지를 검증한다. 사람이 실제로 주의를 기울였는지, 광고주 매출이 발생했는지, 외부 돈이 움직였는지는 독립적으로 증명하지 않는다. 이 한계는 `receipts.py`에도 명시되어 있다.

근거는 `ledger.py`, `people.py`, `service.py:transfer()`, `spend()`, `sweep_agent()`, `private_workflows.py`, `run_results.py:reconcile()`다.

## 3 기존 기능과 관리 기능의 연결

일반 추천은 광고 재원과 분리한다. 현재 업그레이드 확인은 이미 반환된 후보를 읽고 가격·등급·상태를 검사한다. 광고주 입찰·지갑 잔액으로 일반 추천을 바꾸는 기능은 아니다. Chat·Explore 본문에 코인 내용을 자동 삽입하는 연결도 완료되지 않았다. 현재는 `/ad-coin`과 별도 API를 이용하며, Chat 답변 뒤 사용자가 업그레이드 확인을 선택하는 정책을 유지한다.

세 화면의 역할은 다음과 같다.

- `/ad-coin`: 계정, 에이전트 키, 지갑, 후원 제안, 실행권, 영수증.
- `/ad-coin/advertiser`: 광고주 계정·역할, 캠페인·소재, 일 예산·일정·제외, 검토·이의 제기, 가상 충전, 집계·CSV·명세·변경 기록.
- `/ad-coin/admin`: 상태·재원·회로, 배분·캠페인·초대·검토, 감사, 시험 상품, 실행·정산 운영.

PostgreSQL의 전용 세션 풀, 사람·캠페인·계정 잠금 순서, 원자적 잔액 증감, 합계 분할, 재시도, 만료 정리와 등록 SQL 검사가 구현되어 있다. 환경 변수의 저장소 기본 해석은 `auto`로, 앱이 PostgreSQL이면 `application`, 아니면 SQLite다. 직접 생성한 `Settings()`의 기본값은 SQLite이므로 둘을 구분한다.

후원 감사는 끔·켬·끔의 추천을 비교하고 불일치 때 회로를 연다. 수동 실행 도구이며 운영 정기 실행 등록은 완료 근거가 없다. 11월 4일 공개 Explore 반복 조회 안정성 기록은 실제 후원을 켠 감사 전체 결과가 아니다.

기존 크레딧은 워크플로 권리와 약정이 다르다. AI AD Coin과 자동 통합·교환됐다고 표시하지 않는다. 기존 기능의 추가 개편은 사업 목표를 유지하면서 실제 구현·권한·재원 약정에 맞춰 진행한다.

근거는 `api.py`, `upgrade.py`, `page.py`, `advertiser_page.py`, `admin_page.py`, `advertisers.py`, `db.py`, `sql_registry.py`, `audit.py`다.

## 4 보안을 최우선으로 적용할 출시 차단 항목

목표인 완벽 보안을 위해 미해결 위험과 미검증 경계를 명시한다. 아래 항목은 소스 검토로 확인한 현재 동작과 필요한 검수다. 이번에 제품 코드를 수정하거나 새로운 공격 시나리오를 구현한 것은 아니다.

1. **사람 승인과 에이전트 키 권한 분리.** `api.py:person()`은 에이전트 키를 사용자 식별값으로 연결하고, 동의·노출·위임장 등의 경로가 같은 `person` 권한을 사용한다. 유효한 키가 사람의 새 승인이나 권한 부여를 대신하지 못하도록 행위별 인증 주체를 검증해야 한다.
2. **위임 없는 결제 우회 방지.** `/spends`는 요청의 `mandate_id` 존재 여부로 `actor`를 정한다. 서비스 계층의 위임 제한은 `actor='agent'`에 적용된다. 에이전트 키 호출에서 위임 ID를 빼더라도 사람 결제로 처리되지 않아야 한다. 이 경계가 완성됐다고 보증하지 않는다.
3. **실제 노출 증거.** `displayed_ms`와 `foreground`는 요청 본문에서 받는다. 현재 값 검사·동의 기록·중복 차단은 실제 사람이 15초 봤다는 독립 검증과 다르다. 자동 제출·허위 시간·대리 승인에 대한 부정 시험과 상용 위험 통제가 필요하다.
4. **고액 이전 재인증.** 타인에게 5,000원 상당 이상 이전하면 서비스는 추가 인증을 요구하지만 공개 API는 `step_up=False`로 고정한다. 따라서 현 상태는 해당 이전의 보류이며, 실제 새 인증 후 해제하는 기능의 완성을 뜻하지 않는다.
5. **운영 경계와 복구.** 실제 고객 로그인·Web Bot Auth, 공개 경로의 경계 속도 제한, 키 교체·분실·위임 철회, 백업 복구 후 재지급 방지, 실제 예치금 대사·외부 정산·장애 대응을 검증해야 한다. 가상 원장 균형만으로 실재원을 보증하지 않는다.

현재의 결정론적 소재 검사, 매개변수 SQL, 등록 SQL, 권한·CSRF·잔액·멱등·회로·서명·출력 보호는 중요한 기반이다. 그러나 알려진 패턴 거부와 유한한 시험 통과는 모든 주입·사기·오용에 대한 무취약성 증명이 아니다. 219개 기존 시나리오가 위 미완 항목을 모두 검증했다고 확대 해석하지 않는다.

## 5 품질과 검증 결과

품질 100%는 범위와 기대 결과를 정한 검수 항목 전체의 통과 목표다. 보안·금전·권한·복구의 필수 시험은 실패·미실행·미해결 건너뜀이 없어야 한다. 제공자 결과의 사실 정확도, 약정 이행, 실제 사람의 승인, 접근성·화면 사용성도 각각 검수해야 한다. 자동 시험 통과율만으로 모든 사용자 질문에 100% 올바른 답을 준다고 보증하지 않는다.

11월 6일 현재 소스로 다음을 실행했다.

- AI AD Coin 관련 7개 시험 파일: 최초 80건 통과·9건 건너뜀. 건너뜀은 샌드박스에서 격리 PostgreSQL 클러스터를 시작하지 못했기 때문이다.
- 해당 PostgreSQL 파일을 허용된 격리 환경에서 재실행: 10건 통과. 최초 결과와 중복된 1건을 합쳐 최신 고유 항목은 **89건 통과, 실패 0, 미확인 건너뜀 0**이다.
- 기존 동적 보안 도구: **219/219 통과**. 인증·권한, BOLA, CSRF·출처, 악성 입력, 정보 노출, 금액·재전송, 동시 차감, 메서드·속도 제한, 헤더·원장 정합성을 다룬다.

시험 DB는 운영과 분리한 임시 PostgreSQL이며 동적 API 서버는 localhost의 별도 시험 서버다. 동적 로그인은 시험용 대역이다. 이번에는 운영 OAuth·실제 고객 브라우저·실제 외부 제공자·실광고 매출·외부 체인 지급을 검증하지 않았다. 공용 TestClient의 폐기 예정 사용 경고 1종이 있었으며 시험 실패는 아니다.

11월 5일 Bandit 원자료는 높음 0, 중간 18, 낮음 6건이다. 당시 보고서는 중간·낮음 항목의 오탐·용도를 검토했다. 이번에 정적 분석이나 전체 의존성 감사를 재실행하지 않았고 현재 전체 저장소의 보안 인증으로 확장하지 않는다.

원자료는 [이번 검증 요약](ad-coin-doc-refresh-2026-11-06/verification.json), [동적 보안 결과](ad-coin-doc-refresh-2026-11-06/security/dynamic-security.json), [11월 5일 보안 보고서](AI-AD-Coin-보안점검-2026-11-05.md)다. 원자료와 소스 해시를 함께 보관한다.

## 6 처리 속도 목표와 측정 한계

글로벌 최고 처리 속도는 보안·품질을 유지하면서 달성할 목표다. 내부 처리와 사용자 왕복 시간을 분리하고 다지역·동일 부하·동일 데이터·동일 보호 설정의 비교 증거로 평가해야 한다.

다음은 **11월 5일 저장된 대용량 리허설 원자료**의 내부 p99다. 이번에 다시 측정한 값이 아니다. 가상 사용자 10만·캠페인 5천의 단일 호스트·격리 PostgreSQL 환경이다.

| 경로 | 내부 p99 ms | 기존 내부 관문 ms | 표본 수 |
|---|---:|---:|---:|
| 업그레이드 확인 | 2.43 | 20 | 3,600 |
| 후원 견적 | 24.23 | 50 | 3,599 |
| 동의 | 3.64 | 50 | 2,105 |
| 노출 보상 | 9.22 | 50 | 2,105 |
| 실행권 사용 | 6.46 | 50 | 1,762 |
| 실행 정산 | 6.88 | 200 | 1,762 |
| 지갑 이전 | 2.57 | 50 | 3 |

지갑 이전의 표본 3건은 부하 p99 성능을 입증하기에 부족하다. 해당 경로의 집중 부하를 별도로 측정해야 한다. 이전 보고서의 원장 약 195건/초는 최종 분개 17,594행을 90초로 나눈 값인데, `seed()`가 부하 전에 만든 충전 분개도 포함한다. 순수 측정 구간의 처리량으로 승인하지 않으며 전후 분개 차이를 계측해야 한다. 원장 쓰기 200건/초와 지연 관문 동시 충족은 미확인이다. 극한 구간은 정합성을 지켰지만 견적 p99가 1,223.73ms여서 일반 속도 관문을 초과했다.

스크립트의 `speed_passed=true`는 계측된 경로의 지연 비교 결과다. 누락 경로·표본 충분성·처리량·화면·세계 순위의 종합 통과가 아니다. 로컬 LCP 관찰도 실제 다지역 LCP·INP·왕복 p99의 증거와 구분한다. 부하·LCP·세계 비교는 이번에 재실행하지 않았다.

근거는 [대용량 원자료](ad-coin-rehearsal-2026-11-05/large.json), [극한 원자료](ad-coin-rehearsal-2026-11-05/extreme.json), `scripts/ad_coin_rehearsal.py:gates()`와 [목표 기준](../docs/AD_COIN_TARGETS.md)이다.

## 7 다음 작업과 문서 적용 순서

먼저 사람 전용 승인과 에이전트 권한 분리, 위임 없는 결제 방지, 노출 증거와 재인증·복구의 차단 항목을 해결한다. 그다음 상품·지갑·정산·실제 고객 화면과 제공자 결과의 검수 목록을 고정하고 전 항목 통과를 확인한다. 이후 동일 검수·보호 설정을 유지하며 부족한 경로의 표본과 글로벌 성능을 측정·개선한다.

사업 기능에서는 순수 승인 노출 코인 지급, 추가 성과 상품, 방문 에이전트의 사용자 전달, 실제 유료 작업·정산, Chat의 별도 업그레이드 영역, 감사 정기 운영을 구현·검증 상태에 맞춰 진행한다. 실결제·실광고주 집행·외부 체인 출고는 별도 출시 검토 전 열지 않는다. 보존 정책은 최소 5년의 사업 결정을 반영하되 소스에 5년 후 아카이브·삭제 자동화가 있다고 보지 않는다.

문서별 역할은 다음과 같다.

- [개발 현황](../docs/AD_COIN.md): 모듈·API·설정·이행 범위와 현재 미완 항목.
- [최상위 검수 기준](../docs/AD_COIN_TARGETS.md): 보안·품질·속도의 우선순위와 출시 판단.
- [광고 판매 정책](../docs/AD_COIN_SALES_POLICY.md): 현재 시험 상품과 보상·배분·보존·판매 가능 범위.
- [사업 기획 v3](AI-AD-Coin-business-plan-v3-2026-11-04.md): 11월 4일 조사·의사결정의 역사 자료. 현재 개발 상태는 v4와 위 문서를 우선한다.

현재 구현을 문서에 반영하는 것과 출시를 승인하는 것은 별개다. 이번 최신화의 결과는 **사업 목표는 유지하되, 실제 구현·검증·출시 차단 항목을 근거와 함께 구분한 상태**다.
