# 채팅 자연어 추천 품질 개선 개발 결과

2026-10-26. 준비 릴리스: `frontend-chat-task-quality-20261026-r1`. **초기 개발 준비 시점의 결과다. 이후 사용자가 R1을 적용했으며 운영 확인과 R2 추가 수정은 [후속 보고서](post-deploy/REPORT.ko.md)에 기록했다.**

## 구현 내용

- 원문 요청의 허용 길이를 2,000자로 맞췄다. 입력 단계에서 넘는 요청을 명확하게 거절하며, 중간 해석 단계에서 500자 이후 조건을 조용히 버리지 않는다. 내부 별칭 확장에는 더 큰 제한을 적용한다. 임베딩 예산보다 긴 확장문은 일부를 잘라 사용하지 않고 lexical 경로로 돌아간다.
- `chat_task_spec.py`에 명시적 후속 조건·새 작업 구분과 도구별 조건 판정을 구현했다. PDF 입력, OCR, 표 구조, JSON 출력, DOI, 타임스탬프, 인증·가입 불필요 조건을 다룬다. 서로 다른 도구의 기능을 합쳐 존재하지 않는 기능으로 인정하지 않으며, 필수 조건이 불명이면 충족으로 처리하지 않는다.
- 계약서 조항 검토 등 기존 한국어 별칭에 없던 표현과 지역·언어 표현을 보강했다. 지역은 날씨 기능 자체의 단어가 아니라 요청 범위로 처리한다.
- 일반 요청은 기존의 생성 호출 없는 경로를 유지한다. 추출 가능한 검색어가 전혀 없는 요청에만 설정된 LocalLLM의 선택적 영어 정규화를 시도한다. 전체 원문의 연속 구간이 빠짐없이 대응하고 숫자·고유명사·확인 가능한 필수/부정 조건이 보존되는지 검사한다. 잘못된 JSON·출처 누락·추가 URL·미완료 모델 응답은 사용하지 않는다. 자격증명·방문자 토큰·이메일로 탐지되는 입력은 이 경로로 전달하지 않는다.
- 기존 FTS 파이프라인은 이미 도구 이름·설명을 `resources_fts.description`에 포함한다는 점을 구현 단계에서 확인했다. 새 중복 색인이나 운영 DDL 대신 이를 재사용했다. PostgreSQL 후보의 기능 단어 coverage 계산에도 현재 도구 설명을 포함했다. 새 테이블 구축·기존 데이터 일괄 재적재는 수행하지 않았다.
- 선택한 Tool과 성공 보고서의 `tool_name`이 일치할 때만 해당 도구의 확인 근거로 표시한다. 리소스 전체의 연결 실행 성공은 별도로 유지하고, 도구 단위 기록이 없으면 `Not separately recorded`로 표시한다. 기존 보고서를 임의로 도구별 성공으로 변환하지 않았다.
- 조건 일치 이유와 결과 없음 안내를 보강했다. 화면은 주 추천 한 개를 우선 보여주고, 사용자가 `Show alternatives`를 펼칠 때 대안을 표시한다. 상세 버튼·최신 답변 순서·모바일·중복 전송 방지·입력 복구·로딩 해제를 함께 확인했다.
- 기존 개인정보 없는 운영 집계에 조건 불명/위반과 도구별 근거 유무 카운터를 추가했다. 원문·개인정보를 집계 로그에 추가하지 않았다.

## 정책과 설계 구현 범위

기존 API는 최대 3개 추천과 자동 A2A 우선·MCP 보충, x402 명시 선택을 유지한다. 최종 검증 시각 → 활동 → 등급 정렬도 유지한다. 기본 화면의 주 추천 1개와 사용자 선택 후 대안 공개는 구현했다. 설계 1.0에서 제안한 기본 프로토콜/Any 범위 변경은 이 품질 배포에 섞지 않았다.

기능·입출력 조건에 대한 결정적 판정과 선택적 언어 정규화를 적용했다. 광범위한 조건을 이해하는 의미 재정렬기, 전역 원격 모델 슬롯 lease, 영속 Tool 프로파일 테이블, 임베딩 모델 교체는 이번 패키지에 도입하지 않았다. 현재 색인·증거·동시성 보호를 유지하는 단계적 구현이며, 설계의 모든 연구 실험을 완료했다는 뜻은 아니다.

## 검증 결과

최종 고유 테스트 **404건 통과**, 실패·건너뜀 0건이다. 반복 실행은 중복 합산하지 않았다.

- API·추천·입력 조건·버전 근거·보안 회귀 375건: `api-security-final.xml`.
- 기본/공개 Pearl 화면, 대안 펼치기, 모바일, CSP·출력 이스케이프, 최신 답변 순서 등 Chromium 회귀 24건: `browser-final-release.xml`.
- 동시성 1·4·8·16의 격리 Chat 검사 4건: 각 16개 요청, 합계 64/64 HTTP 200·정답·인증 조건 보존. `concurrency.xml`, `fixture-concurrency-*.json`.
- PostgreSQL 18 임시 클러스터의 실제 네이티브 런타임·저장·롤백 1건: `postgres18-release.xml`. 임시 클러스터 종료 후 정리됐다.
- 최종 변경 후 영향 범위를 좁힌 추가 회귀 64건도 통과했다. 위 집합과 겹치는 항목은 총계에 다시 더하지 않았다: `final-targeted.xml`.
- 공개 콘텐츠 296개 파일 위반 0건, 내장 HTML과 추출 HTML 일치. 수정 핵심 모듈·새 테스트의 Ruff F/E9/S 검사 통과. Front 전체의 기존 미사용 import는 이번 범위에서 일괄 제거하지 않았으며 변경 Python 소스는 별도 컴파일도 통과했다.
- 명시 SQL 카탈로그의 소스 해시·줄 위치를 현행화했다. 스키마와 SQL 번역 쌍은 변경되지 않았다. 검사 결과 3,802문장·232테이블 일치, 추가 DB 마이그레이션 불필요.
- 준비 패키지의 변경 파일 해시가 검증한 작업 소스와 모두 일치한다: `release-source-match.json`.

초기 확장 검사에서 예전 단일 프로토콜 계약을 기대하는 테스트 3건이 실패했다. 개발 전과 `fast_chat.py` 해시가 동일한 운영 보존 릴리스를 격리 import해도 같은 3건이 실패함을 재현했다 (`historical-contract-baseline.xml`). 현행 자동 A2A/MCP 정책을 명시적으로 검사하도록 이 테스트들을 현행화했다. 새 기능의 오류를 테스트 완화로 숨긴 것으로 계산하지 않았다. 기존 브라우저 테스트의 쿠키 배너 가정도 세션 초기화 상태에 맞췄다.

테스트 도구에는 Starlette 테스트 클라이언트의 향후 사용 중단 경고가 남아 있다. 검증 실패나 알려진 보안 취약점 발견을 의미하지 않으며 이번 작업에서 새 의존성을 추가하지 않았다.

## 실제 모델 확인과 성능 해석

초기 0.8초 예산은 실제 설정 모델에서 한국어·일본어 합성 요청 2건 모두 완료되지 않았다. 단일 추가 진단에서 올바른 정규화가 약 1.41초에 반환되는 것을 확인해 기본 예산을 1.8초, 호출자가 지정할 수 있는 상한을 2초로 조정했다. 재검증 결과 두 요청 모두 올바른 구조로 반환됐다.

- 합성 한국어 보험 조항 검색 요청: 1,461.9ms.
- 합성 일본어 여행 계획 요청: 999.9ms.

증적: `configured-model-initial-0.8s.json`, `model-budget-diagnostic.json`, `configured-model-smoke.json`. 이는 언어 정규화 2건의 관찰이며 다국어 정확도·전체 채팅 p95·16개 모델 동시 처리량·최종 추천 정답률을 입증하지 않는다. 원문 구간·조건 보존 검사도 번역 의미의 완전한 정확성을 증명할 수는 없다.

동시성 64건은 합성 카탈로그를 사용하는 SQLite TestClient 검사이며 생성·임베딩·외부 제공자 호출은 0건이다. 공개 운영 카탈로그나 모델 서버의 최대 처리량으로 해석하지 않는다. 600개 독립 작업군의 라벨링·잠금 품질 평가와 임베딩/의미 판정 모델의 비교는 후속 검증 대상이다. 설계의 Recall 95%·Top-1 8%p 개선 목표를 달성했다고 주장하지 않는다.
