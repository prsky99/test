# 운영 반영 확인과 추가 수정

2026-10-26. 사용자가 적용한 `frontend-chat-task-quality-20261026-r1`이 frontend b에서 준비 완료 상태임을 확인했다. 공개 HTTPS의 JavaScript 해시가 해당 릴리스와 일치하고 Chat 페이지는 HTTP 200·no-store·CSP를 제공한다. 비공개 준비 상태 URL은 공개 경로에서 404다.

## 운영에서 직접 확인

- 합성 검색 API 6건 모두 HTTP 200. 한국어 날씨·계약서 요청이 요청 구조화 경로로 진입하고, 논문 검색 후 DOI 조건은 이전 논문 목적과 MCP 범위를 보존했다. 결과가 없으면 일반 추천으로 위장하지 않고 별도 안내를 표시했다.
- 실제 공개 Chromium 여정 3건: 논문 검색 → 대안 펼치기/접기 → 상세 열기, DOI 후속 조건 → 모바일 배치, 정답 없는 요청 → 버튼·로딩 복구. 스크립트 오류 0건. 캡처: `papers.png`, `doi-followup.png`, `no-match.png`.
- 외부 에이전트 업무 실행·워크스페이스 저장·결제·크레딧 사용은 0건. 테스트용 방문은 QA User-Agent로 구분했다. 토큰·방문자 식별 정보는 증적 파일에 저장하지 않았다.

## 추가로 발견하고 수정한 사항

1. MCP 소개문은 요청과 맞지만 실제 관련 Tool이 없거나, 지원할 수 없는 스키마 때문에 공개 Tool 정보가 비어도 추천 자리를 차지할 수 있었다. 관련 도구의 기능·지원 스키마·안전하게 보존 가능한 공개 계약을 **최종 개수 제한 전에** 확인하도록 보강했다. 탈락한 후보가 뒤의 후보를 가리지 않게 한다. `forecast`처럼 명백한 기상 기능 이름은 weather 동의어로 인정한다.
2. DOI 후속 조건은 실제 검색에 반영됐지만 상태의 `operation`은 다시 파싱하면서 `new`가 됐다. `refine` 상태를 끝까지 보존하도록 수정했다.
3. 일반 Front 생성자에 선택적 언어 정규화가 있었으나 실제 서비스 조립은 `llm=None`이어서 연결되지 않았다. 운영자가 Workspace 모델을 활성화한 경우에만 동일 승인 모델로 제한된 정규화 경로를 연결했다. 알려진 요청은 생성 호출을 하지 않는다. 기존 임베딩 HTTP 클라이언트를 공유해 별도 수명 관리 누수도 피했다. 네트워크 요청 없는 실제 서비스 팩토리 테스트를 추가했다.

연결 검증이 만료된 것을 새 성공으로 변환하지 않는다. 도구별 보고서가 없으면 계속 `Not separately recorded`로 표시한다. 최신 검증·활동·등급 정렬과 기존 프로토콜 정책은 유지했다.

## 실제 카탈로그 비교와 한계

추가 코드를 읽기 전용 PostgreSQL 연결에서 실제 FTS+pgvector+설정된 임베딩으로 검사했다. 생성·제공자 업무 실행과 DB 쓰기는 하지 않았다. 논문 검색은 공개 호출 계약이 있는 `Research Papers`와 `search_research_papers`를 유지했고 연결 검증도 유효했다.

서울 날씨·기술 뉴스·계약 검토의 해당 MCP 후보 창에서는 강화된 조건을 통과하는 후보가 없었다. 이를 전체 카탈로그의 기능 부재로 일반화하지 않는다. 이 결과는 기존 추천 세 개가 모두 실행 가능하다는 보장이 아니었음을 보여준다. 없는 호출 계약을 만들어 결과를 채우지 않았으며, 후보 Recall·현재 카탈로그 계약 보강은 여전히 별도 평가 대상이다. 특히 뉴스·날씨 추천이 항상 성공한다고 보고하지 않는다.

처음 읽기 전용 비교에서는 임베딩을 끈 lexical 제한 경로만 사용해 논문도 누락됐다. 운영과 같은 임베딩·ANN을 연결한 최종 비교와 구분해 로그를 보존했다. 현재 대표 정확도나 p95를 측정한 것은 아니다.

## 추가 검증 및 반영

추가 릴리스 `frontend-chat-task-quality-20261026-r2`를 준비했다. API·보안·동시성 383건, Chromium 24건, PostgreSQL 18 네이티브 1건으로 고유 **408건 통과**했다. 공개 콘텐츠 296개 파일 위반 0건, 정적 검사 통과, SQL 카탈로그 일치, 준비 패키지와 변경 소스 해시 일치를 확인했다.

호출 가능한 Tool이 없는 항목을 더 이상 Chat에 추천하지 않으므로, 과거 소개문만으로 만든 양성 테스트 데이터에 명시적 도구 계약을 추가했다. 잘못된 주제의 음성 후보에도 실제 도구를 붙여 주제 판정 검증을 유지했다. 스키마를 안전하게 보존할 수 없는 항목은 빈 도구의 추천 대신 제외되는 것을 검사하도록 보안 회귀를 보강했다.
