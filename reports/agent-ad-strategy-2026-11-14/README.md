# 자율형 에이전트 대상 광고 기획 (2026-11-14, PM)

사용자 요청: "광고 전략에 자율형 에이전트를 대상으로 한 새로운 광고 기법을 적용해야 함. 논문과 뉴스와 SNS 검색으로 정보를 수집해 가장 효과 있는 광고 기법을 새롭게 만들고, 광고 시장에서 가장 효과 있을 것으로 예상하는 기법을 병행하고, 일반적인 광고 기법을 폴백으로 적용해 광고 기획을 설계해서 적용해줘."

- 근거 원자료: `research.md`(주제 6개, 출처·날짜 포함, 회사 자체 발표 수치는 따로 표시)
- PM 직접 확인: arXiv 2508.02630(ACES, v3 2025-12-17) 초록 — "agents consistently penalize sponsored tags while rewarding platform endorsements", 위치 편향, 판매자 쪽 설명 조작으로 점유율 변화

## 0. 조사에서 얻은 핵심
1. **에이전트는 "Sponsored" 표시를 감점합니다**(ACES). 사람용 광고 카드를 그대로 보여 주면 에이전트에게는 효과가 약합니다.
2. **에이전트는 구조화된 사실(가격·평점·조건)과 플랫폼의 독립 평가에 반응합니다**(ACES). 우리는 이미 독립 검증(등급·시험 보고서·서명)을 갖고 있습니다. 광고를 "검증된 사실과 함께 제시되는 제안"으로 만들면, 감점받는 광고가 아니라 판단 재료가 됩니다. 이것이 우리만 할 수 있는 광고입니다.
3. **답변 속 설득형 광고는 표시를 붙여도 선택을 크게 바꿉니다**(22% → 61%). 도구 설명 조작은 선택률을 20%에서 81%까지 올립니다(ToolTweak). 둘 다 우리 신뢰 원칙에 어긋나므로 쓰지 않고, 광고주가 그렇게 하지 못하게 막아야 합니다.
4. **시장에서 통한 형태는 "답변과 분리된 문맥 광고 1칸"입니다.** ChatGPT 광고(회사 발표 수치)가 그 예입니다. 답변 흐름에 섞은 형태는 신뢰 문제를 겪었습니다.

## 1. 광고 기법 세 층

### (A) 주력·새 기법: 에이전트가 읽는 검증 첨부 스폰서 제안 (Verified Sponsored Offer)
에이전트 응답(MCP·A2A·REST)에 기계가 읽는 스폰서 제안을 **유기 결과 뒤 별도 칸에 1건만** 넣습니다.

| 항목 | 설계 |
|---|---|
| 위치 | 응답의 `sponsored` 필드(유기 결과 배열과 분리). 항상 결과 뒤, 최대 1건 |
| 광고주가 넣는 것 | 정해진 칸만 받습니다: 제공 도구·엔드포인트, 가격, **에이전트용 무료 시험 조건**(예: 하루 N회 무료 호출, 키 없이 시험 가능 여부), SLA. 자유 문장은 120자 1줄, 명령형·주입 문구 검사 통과 필수 |
| 우리가 붙이는 것 | **광고와 무관하게 계산한 독립 사실**: 등급, 최신 시험 보고서 점수와 링크(서명 포함), 데이터 시각, 최근 7일 헬스. 낮아도 그대로 보여 줍니다 |
| 표시 | 텍스트 맨 앞 `Sponsored:`, 필드에 `advertiser`, `paid_by`, `why_shown`(과제 분야 일치 등), `disclosure_url` |
| 끄기 | 에이전트가 `ads=none`(파라미터·헤더)을 보내면 광고 칸을 비웁니다 |
| 대상 자격 | 보안 격리·검토가 아닌 에이전트만. 등급·점수 기준으로 거르지 않고 사실을 그대로 보여 줍니다 |
| 가격 | 지금 규칙대로 예약 1건 = 결제 1건(분야·지역·하루 1칸 5 USDC). 성과형 과금은 6절 결정 대기 |
| 측정 | 서버 쪽만: 에이전트 응답 노출 수, 그 세션 안에서 광고 대상에 `verify_agent`·연결·호출이 이어진 비율(쿠키·추적 없음) |

왜 효과가 있을 것으로 보나: 에이전트는 Sponsored 표시를 감점하지만 독립 평가와 구조화된 사실에는 반응합니다. 우리 광고는 표시를 숨기지 않으면서, 판단에 쓸 검증 사실과 무료 시험 조건을 함께 줍니다. 효과 크기는 아직 확인되지 않아, 출시 뒤 측정으로 판단합니다.

### (B) 병행: 결과 아래 문맥 매칭 1칸 (시장형, 사람·에이전트 공통)
지금의 Sponsored 칸을 시장에서 통한 형태로 다듬습니다.
- 질의의 과제 분야와 광고 분야가 맞을 때만 보입니다(문맥 매칭). 민감 주제(의료·금융 조언 등)는 광고를 붙이지 않습니다.
- 카드에 "왜 이 광고인가" 한 줄을 넣습니다.
- 클릭은 쿠키 없이 서버에서 셉니다.
- 사람 화면은 지금 카드를 유지하고, 에이전트 응답에는 (A) 형식으로 같은 예약을 보여 줍니다(예약 1건이 두 표면에 나감).

### (C) 폴백: 일반 광고 기법
(A)·(B)에 예약이 없거나 효과가 낮을 때 쓰는 기본 기법입니다.
1. **고정가 Featured 칸**: 분야 페이지·`/advertise` 안내에 기간제 Sponsored 칸(표시 그대로)
2. **목걸이·진주 소식 후원**: 공개 변경 피드(`/api/feed/necklaces.json`)와 방법론 변경 이력에 후원 표시 1줄(구독자 추적 없음)
3. **개발자 관계(DevRel) 후원**: 후원 표시를 단 예제·가이드 페이지
4. **자사 광고(무상 코인)**: 예약이 없는 칸은 자사 광고(목걸이·방법론 홍보)가 채웁니다(지금 매일 250 coins)
5. **우리 쪽 정직한 GEO**: 사실 기반 설명과 구조화 데이터로 AI 검색에 인용되게 함(지출 0)

## 2. 하지 않는 것 (조작·신뢰 훼손)
- 답변·추천 문장 속에 광고를 섞는 설득형 광고
- 추천·검증 배지 판매, 유료 순위, 광고비에 따른 등급·점수 변경
- 광고주의 도구 설명 조작 대행(ToolTweak식), 광고 문구 속 명령형·지시문
- 에이전트 세션·기억에 광고 끼워 넣기, 먼저 보내는 A2A 광고 메시지, 리타기팅
- 광고주가 비용을 대는 시험 보고서(이해충돌)

## 3. 신뢰 장치 (증거 기둥과 연결)
- **광고 중립 감사**: 같은 질의에 광고가 있을 때와 없을 때 유기 결과가 같은지 매일 표본으로 비교해 결과를 공개합니다. 결과에 서명합니다.
- **공개 광고 저장소**: `/ads/library`에 현재·과거 광고(광고주, 기간, 분야, 문구, 노출 이유)를 공개합니다(EU DSA 광고 저장소 방식 참고).
- **주입 검사**: 광고 문구가 에이전트를 지시하는 문장인지 자동 검사하고, 걸리면 게재하지 않습니다.
- 기존 광고 중립 시험(자연 선택 코드가 광고 모듈을 import하지 않음)은 그대로 둡니다.

## 4. 지표
- 광고 매출(USDC, 확정 기준), 채워진 칸 비율, 표면별 노출(사람·MCP·A2A·REST)
- (A) 에이전트 후속 행동률: 광고 대상에 대한 verify_agent·연결·호출
- 중립 감사 일치율(목표 100%), 주입 검사 차단 수, `ads=none` 사용 비율
- 광고주 재예약률
