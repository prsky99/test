# MCP·A2A 디렉터리·레지스트리 선별 (2026-11-09, 승인 대기)

외부 유입 계획 1단계 2·3번. 공개 페이지만 읽었고, 가입·제출·카드 검사 요청은 하지 않았다. "미확인"은 공개 페이지로 확인하지 못한 것이다.

| 1 | **공식 MCP Registry** | remote 전용 게시가 문서로 정해져 있다. PulseMCP는 제출을 멈추고 "공식 Registry에 게시하면 재개할 때 자동으로 가져간다"고 밝혔다. Glama도 공식 Registry를 데이터 소스로 든다. 한 번 등록이 여러 곳으로 퍼진다. | `mcp-publisher` CLI (PR로는 등록되지 않음) | 도메인 확인(HTTP 파일 권장). 절차는 `deploy/mcp-registry/README.md` |

## 2. 보류·제외

| 곳 | 판단 | 근거 |
|---|---|---|
| PulseMCP | 보류(자동) | 신규 제출이 멈춰 있다. 재개하면 공식 Registry에서 자동으로 가져간다고 밝혔다. 1번을 하면 따로 할 일이 없다. |
| Smithery | 보류 | "MCP Proxy와 managed identity가 10-31에 종료"했다는 공지가 있다. 지금은 Arcade 소속이고, remote 전용 제출 경로를 확인하지 못했다. 운영이 안정되면 다시 본다. |
| mcp.so | 보류 | 활발하지만 무료 등록은 검토 기간을 알 수 없다. 폼에 Repository URL이 필수다(우리 공개 저장소 이름은 `prsky99/test`라 소개용으로 맞지 않음). $39 유료 즉시 게시는 지출이라 쓰지 않는다. 자체 광고 패널의 "12개월 방문자 220만"은 검증되지 않은 자기 주장이다. |
| 8004scan (ERC-8004) | 별도 검토 | 등록 수 2,029,452는 원시 온체인 등록이라 실사용과 다르다. 온체인 등록은 지갑·가스비가 들어 지출 승인 사항이다. |
| a2aproject GitHub | 해당 없음 | 공식 에이전트 레지스트리·카탈로그 저장소를 찾지 못했다. |

## 3. 실제 유입 근거에 대한 주의
- 어느 곳도 방문 수를 공개하지 않는다. 유입 근거는 **목록 갱신 빈도와 규모**, 그리고 **다른 곳이 그 데이터를 가져가는지**뿐이다.
- 이 디렉터리들을 읽어 서버를 자동으로 붙여 주는 특정 MCP 클라이언트는 확인하지 못했다.
- 그래서 등록 효과는 0단계 계측(MCP `clientInfo.name` 수, 외부 에이전트 요청)으로 직접 잰다. 기준선은 11-16이다. 등록 날짜를 WORKLOG에 남겨 전후를 비교한다.

## 4. 사용자 승인이 필요한 것
1. 공식 MCP Registry 도메인 확인과 게시 (`deploy/mcp-registry/README.md` 3절, 명령 6줄)
2. Glama 계정 만들기와 원격 커넥터 등록
3. a2aregistry.org에 카드 URL 제출
4. a2a.directory 제출(연락 이메일을 무엇으로 할지 함께 결정)
