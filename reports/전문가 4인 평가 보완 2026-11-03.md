## 2. 2026년 흐름과 2027년 전망

**2026년에 이미 나타난 흐름**
1. 에이전트가 웹의 정식 사용자가 됐다. 사이트는 사람용 화면과 함께 기계용 계약(llms.txt, A2A Agent Card, MCP 서버, OpenAPI)을 낸다. 이 서비스는 이 흐름의 앞쪽에 있다.
2. MCP가 도구 연결의 표준이 됐다. 원격 MCP, 도구 annotations, `outputSchema`, 공식 레지스트리용 `server.json`이 기본이 됐다. 긴 작업용 비동기 작업(tasks)과 인증 강화를 담은 새 사양이 나왔다.
3. A2A가 v1.0으로 안정됐다. 에이전트끼리 맡기는 일은 `contextId`·`taskId`로 이어진다.
4. 에이전트 결제(x402 등)와 에이전트 신원 확인이 시작됐다. 사이트는 들어오는 봇이 누구인지 확인하고, 나가는 크롤러는 자기를 증명하는 방향(Web Bot Auth, HTTP 메시지 서명)으로 간다.
5. 화면 쪽에서는 생성형 UI(대화 결과를 카드·표로 바꿔 보여 줌), 결과 근거 표시, INP 중심 성능 지표, WCAG 2.2가 기본이 됐다.

**2027년 전망(판단)**
1. 사람이 직접 찾기보다 개인 에이전트가 대신 찾고 비교한다. 사이트의 경쟁력은 첫 화면의 인상보다 "에이전트가 바로 쓸 수 있는 구조화된 답과 증거"에 더 기운다. 가능성 높음.
2. 에이전트 신원·평판·결제가 한 흐름으로 묶인다. "검증된 에이전트만 추천" 같은 신뢰 신호에 값이 붙는다. 가능성 중간.
3. 브라우저가 페이지의 도구를 에이전트에게 직접 노출하는 방식(WebMCP 같은 제안)이 실험에서 보급으로 넘어간다. 가능성 불확실. 지금 준비할 가치는 있다.
4. MCP 결과를 대화 안의 작은 앱으로 보여 주는 방식(MCP Apps 계열)이 늘어난다. 가능성 중간.

## 3. 전문 분야별 평가

점수는 5점 만점이고, 2026년 상위 서비스와 비교한 관점 점수다.

### 3.1. UI/UX 기획 (3.5/5)

**좋은 점**
- 메뉴가 사용자의 일 순서와 맞는다. 찾기(Explore), 추천받기(Chat), 시험하기(Test), 연결하기(Workflows)로 이어진다.
- Explore와 Chat의 역할을 화면마다 한 문장으로 구분한다("For up to three checked recommendations, ask Chat").
- 화면 정책(고정 내용 즉시 표시, 영역별 로딩)이 지켜진다. Test·Workflows는 첫 요청 없이 열린다.

**지적**
- **B1. 첫 화면의 주인공이 과업이 아니라 숫자다.** 모바일 홈 첫 화면은 카탈로그 숫자 4개가 차지하고, "무엇을 하려는가" 입력은 두 번째 화면에 있다. 2026년 서비스는 첫 화면에서 바로 과업을 받는다. 숫자는 신뢰 근거로 입력 아래에 둔다.
- **B2. "사람용이 아니다"와 사람용 화면이 충돌한다.** Agent Card·홈 JSON·응답 헤더는 "FOR AI AGENTS ONLY … not for humans"라고 말한다. 그런데 같은 사이트가 사람용 워크스페이스·로그인·요금 화면을 운영한다. 사람이 이 문구를 보면 떠나고, 에이전트는 사람 승인 흐름을 무시할 수 있다. "Built for AI agents and the people who run them"처럼 두 대상을 함께 말해야 한다.
- **B3. 추천 이유가 사용자의 조건을 말하지 않는다.** 이유가 "목록이 이 단어를 포함한다"에 그친다. 사람은 "API 키 없이"라는 조건이 지켜졌는지 알고 싶다(본 보고서 A1·A4).
- **B4. 모호한 요청을 되묻지 않는다**(본 보고서 A3).

### 3.2. 웹 디자인 (4.0/5)

**좋은 점**
- 진주 목걸이 상징이 "따로도 가치 있고 함께 더 강하다"는 메시지와 맞고, 기억에 남는다. 다크·라이트를 모두 지원한다.
- 375px에서 가로 넘침이 없다. 11-02에 본문 최소 12px, 체크 박스 24px로 올렸다.

**지적**
- **W1. 모바일 Explore에서 결과가 첫 화면에 없다.** 검색어, 프로토콜, 카테고리, 검색 버튼, 필터 버튼이 375×812 첫 화면을 모두 쓴다. 프로토콜과 카테고리를 한 줄의 칩으로 접고, 검색 뒤에는 양식을 한 줄 요약으로 줄여야 결과가 첫 화면에 들어온다.
- **W2. 홈 제목의 추상도가 높다.** "Valuable alone. Remarkable together."는 브랜드 문구로는 좋지만, 무엇을 하는 서비스인지는 아래 문단을 읽어야 안다. 제목 바로 위나 아래에 "Find a checked AI agent for your task" 수준의 한 줄을 크게 둔다.
- **W3. 숫자 카드가 많고 비슷해 보인다.** 카탈로그 숫자 4개가 같은 무게로 보인다. "지금 연결 가능한 수" 하나를 크게, 나머지를 작게 둔다(본 보고서 디자인 항목과 같은 방향).

### 3.3. AI 개발 (3.0/5)

**좋은 점**
- 응답 하나에 사람용 문장(`reply`)과 기계용 구조(`data.recommendations`: 인증 방법, 연결 단계, 검증 시각, 시험 보고, 과업 적합도)가 함께 온다. 에이전트가 바로 쓸 수 있는 형태다.
- 실행에는 별도 승인이 필요하고, 제공자 설명을 지시문으로 믿지 않는다는 원칙이 문서와 도구 annotations에 들어 있다.
- 검색 3초, Chat 5초 목표를 지킨다(Chat 3.3초·4.3초).

**지적**
- **A-1. 추천 적합성이 가장 큰 약점이다.** 일반 과업 2건 모두 1위가 과업의 핵심과 어긋났다. 환율은 특정 국가 통화 위주였고, PDF 요약은 토큰 줄이기 도구였다. 단어 일치 점수가 과업 의미보다 앞선다. 본 보고서 A1·A4·A5와 같은 문제가 일반 과업에도 있다는 추가 근거다.
  - 개선: 과업에서 필수 조건(대상, 입력 형식, 언어·지역, 키 필요 여부)을 먼저 뽑고, 후보가 조건을 충족하는지 따로 판정한 뒤 순위를 매긴다. 이유에는 충족한 조건을 적는다.
- **A-2. 질의 의미를 보여 주지 않는다.** 응답에 `task_spec`이 있지만 사람용 문장에는 "이렇게 이해했다"가 없다. 첫 줄에 해석한 과업을 한 줄로 보여 주면, 사람은 바로 고칠 수 있다.
- **A-3. 품질 측정이 일회성이다.** 오늘 같은 표본 시험은 사람이 한다. 고정 평가 세트(과업 100~200개, 기대 조건, 허용 후보)를 두고, 배포 전 점검(`release_gate`)처럼 정책 파일이 바뀔 때마다 적합도 점수를 잰다. 2026년 AI 서비스는 평가 세트를 회귀 시험처럼 쓴다.

### 3.4. 웹 개발 (4.0/5)

**좋은 점**
- 보안 헤더가 강하다. 요청마다 nonce를 쓰는 CSP, HSTS, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`가 있다.
- 오류는 `application/problem+json`으로 오고, 요청 한도는 `RateLimit` 헤더로 알린다. POST는 `Idempotency-Key`를 받는다.
- A/B 슬롯 무중단 배포가 있고, 11-02부터 배포 전 사본 시험을 자동으로 돌린다.

**지적**
- **D1. 공개 응답을 가장자리(edge)에서 캐시하지 않는다.** `llms.txt`, `agent-card.json`은 `public, max-age=30`인데도 Cloudflare가 `DYNAMIC`으로 원 서버까지 간다. HTML은 `no-store`다. 새 연결의 첫 응답이 1~4초, `llms-full.txt`는 한 번 8.9초였다. 탐색 정책상 스냅샷 응답이 허용되므로, 공개 문서·카드·정적 HTML에 Cloudflare 캐시 규칙(짧은 TTL + stale-while-revalidate)을 걸 수 있다. 에이전트는 이 파일들을 가장 먼저 읽는다.
- **D2. HTML 하나에 여러 화면이 들어 있다.** 공개 HTML이 각각 약 200KB, DOM 3,000개 수준이다. 숨긴 화면의 마크업을 해당 페이지에만 남기면, 첫 응답과 메모리가 줄고 INP에도 유리하다.
- **D3. `security.txt`가 없다.** 공개 저장소이고 결제·지갑 기능이 있으므로 RFC 9116 보안 연락처가 필요하다. 반나절 작업이다.
- **D4. 프로토콜 최신화와 봇 신원.**
  - MCP는 `2025-06-18`로 답한다. 새 사양의 버전 협상을 받아들이고, 긴 작업(워크플로 실행)에는 비동기 작업 방식을 검토한다.
  - 수집기·헬스체크가 남의 서버에 요청할 때 Web Bot Auth(HTTP 메시지 서명)로 자기를 밝히면, 차단이 줄고 신뢰가 오른다.
