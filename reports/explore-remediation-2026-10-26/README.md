# Explore 검색·중앙 로딩 개선

2026-10-26. 대상은 공개 Explore 검색과 그 검색을 제공하는 API다. 고객 계정, 실행 워커, 결제, 관리자 기능은 변경 대상이 아니다. 운영 서버 교체·재시작·배포와 운영 애플리케이션 테이블 변경은 하지 않았다.

## 반영 내용

- 검색 입력 즉시 화면 **중앙**에 `Finding matching agents…`를 표시한다. 입력 대기, 검색 버튼, 빠른 검색, 프로토콜·카테고리·증거 필터, 더 보기, 캐시 재검증에 적용한다. 입력·메뉴 조작은 계속 가능하다. 완료·오류·취소·메뉴 이동 시 자신이 만든 로딩 표시만 해제하며, 이전 응답이 최신 요청의 표시를 지우지 않는다. 기존 접근성 상태 알림과 reduced-motion 처리를 유지했다.
- 검색어와 필터를 `#explore?...` 주소에 보존한다. 직접 진입, 새로고침, 뒤로·앞으로 이동 시 검색창·필터·결과를 복원한다.
- 작업 검색은 소개글의 키워드만으로 통과시키지 않고 실제 광고된 도구·스킬의 역량을 확인한다. `translate`/번역 입력에 번역 도구 없이 마케팅 문구만 있는 결제·시장 에이전트가 끼는 경우를 차단한다. 명시적 이름 조회는 유지한다.
- `wether`, `gihtub`, `clima` 등 지원하는 단어는 결과가 없을 때 영어 대체 검색 버튼을 제공한다. 자동 치환하지 않으며 사용자가 눌러야 실행된다. 기존 프로토콜 선택을 유지한다. 임의 언어 전체 번역 기능을 도입한 것은 아니다.
- 500자 입력 제한과 잘못된 긴 공유 주소에 구체적인 수정 안내를 제공한다. 서버 장애처럼 보이지 않으며 과도한 입력을 전송하지 않는다. 시간 초과·속도 제한도 구분하고 내부 오류 원문을 노출하지 않는다.
- 같은 프로토콜·동일한 정규화 전체 URL의 별칭을 중복 카드에서 제외한다. 같은 호스트의 다른 경로까지 동일 에이전트로 간주하지 않는다.
- 더 보기는 `limit=45&offset=45`처럼 다음 구간만 응답받는다. API의 기존 기본 limit와 최대 300건 경계는 유지한다. 캐시 키와 완료 페이지 표식을 분리하여 초기 미리보기·다른 크기의 캐시가 완성된 결과를 덮지 않게 한다.
- 카드 카테고리 표기를 필터 목록의 실제 표기와 통일한다. 프로토콜 버튼은 폭이 부족하면 줄바꿈하여 글자 겹침을 방지한다. 모바일에서 명시적 검색 후 결과 제목으로 초점과 화면을 이동한다.
- 쿠키 안내는 문서 흐름 안에 배치하여 검색 결과를 덮지 않는다. 기존 필수/선택 쿠키 동의 처리와 거부 기능을 유지한다.
- 자동 검색은 A2A 우선 후 MCP를 채우고 x402는 명시적으로 선택한 경우만 유지한다. 건강 상태, 보안, 입력 요구사항, 검증 증거, 보고서 정합성 관련 기존 경계를 유지한다.

붙여넣은 점검 내용의 빠른 검색 20개와 체크박스 변경은 현재 소스에서 검색을 실행하고 있었다. 별도 근거 없이 전부 고장으로 단정하지 않고, 20개 버튼과 세 증거 필터가 실제 API 요청을 보내는 회귀를 추가했다. 원문에 적힌 `reports/Explore 검색 브라우저 테스트.md` 파일은 이 작업 시 로컬에서 확인되지 않아 사용자가 붙여넣은 내용을 대조 기준으로 사용했다.

## 보안 검사와 한계

선택된 세 Python 파일의 Bandit 결과는 `bandit.json`이다. 새 `explore_search.py`에는 경고가 없고 전체 스캔은 High 0 / Medium 19 / Low 10이다. 정적 SQL 조합·기존 예외 처리·테스트 경로 판별 문자열에 대한 경고가 남아 있어 검사 종료 코드는 1이다. 검색 SQL은 고정된 조건/열 조각과 바인딩된 값으로 구성됨을 검토했다. 이 결과를 저장소 전체 취약점 0건으로 해석하면 안 된다. 동적 검증에는 CSP·스크립트/이벤트 차단·입력 HTML 출력 방어·공개 경로·오류 메시지·입력 한계 회귀가 포함된다.

실서비스 사전 읽기 측정은 `live-baseline.json`에 6개 검색만 남겼다. 번역 관련 오탐과 오타 무결과를 확인했지만 원문에 있는 전체 48개 질의의 지연 분포를 재현했다고 주장하지 않는다. 이번 변경은 캐시된 결과의 즉시 표시와 다음 페이지 전송량을 개선하며, 반복 정규화 작업을 줄인다. 콜드 검색의 DB/검색 처리 시간 자체를 모두 3초 이하로 보장하지 않는다. 임시 스키마 검증은 실제 PG 행과 격리 FTS 경로를 사용하며 운영 GIN/HNSW 인덱스 성능이나 동시 부하 시험을 대신하지 않는다.

## 운영 반영

이번 수정은 frontend 서비스에 API와 정적 자산을 함께 반영해야 한다. 관리자·jobs·execution 재시작이나 DB 마이그레이션은 필요하지 않다. 준비한 불변 패키지의 해시 확인은 `package.json`에 기록한다.

사용자 터미널에서 실행:

```bash
./agentcon deploy frontend explore-search-ux-20261026-r1
```

이후 브라우저를 새로고침한다. 배포 전 운영 서버는 이전 동작을 계속 사용하므로 이 보고서는 소스·격리 검증 완료 기록이다. 배포 후 운영 화면과 실제 검색 지연은 별도 읽기 확인이 필요하다.
