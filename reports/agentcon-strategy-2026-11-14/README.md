## 1. 우리는 누구인가

**Agentcon — Agent Value Gateway(에이전트 밸류 게이트웨이)**

> 수많은 에이전트 가운데 진짜 가치(진주)를 찾아내고, 그 진주들을 연결해 기존에 없던 새로운 가치(진주 목걸이)를 만들어 공급한다.

| 단계 | 하는 일 | 결과물 | 지금 있는가 |
|---|---|---|---|
| 1. 수집 | A2A·MCP·x402 에이전트를 키 없이 모은다 | 카탈로그 39.5만 개(연결 가능 30.7만) | 있음 |
| 2. 등급 | 헬스체크, 시험 호출, 품질 등급 | 등급과 증거 | 있음 |
| 3. 시험 보고서 | 실제 과제로 시험하고 보고서를 쓴다 | 시험 보고서 | 일부(공개 보고서 운영 중, 약한 보고서 4건 철회) |
| 4. **진주 인증** | 등급·시험·재검증·변경 감시를 모두 통과한 에이전트만 "진주"로 확정 | 진주 목록과 진주 카드 | **없음(새로 만듦)** |
| 5. **진주 목걸이** | 진주 2개 이상을 연결해, 단일 진주로는 얻을 수 없는 결과를 내는 워크플로우를 만든다 | 워크플로우 = 새 에이전트 | **형식만 있음(아래 실측)** |
| 6. 공급 | 목걸이 하나를 MCP 서버, A2A 카드, 웹 페이지 하나로 내놓고 계속 다시 시험한다 | 살아 있는 목걸이 | 경로는 있음(중계 게이트웨이, A2A run 배포 대기) |
| 7. 홍보 | 개별 에이전트가 아니라 **우리가 만든 목걸이**를 홍보한다 | 목걸이 페이지·등록 | 없음 |

**지금 실측(11-14, 운영 DB 읽기 전용): 진주와 목걸이가 이어져 있지 않습니다.**
- 워크플로우는 33개이고, 그중 공개는 28개입니다. 모두 우리가 만들었고, 실행은 누적 125회로 대부분 내부입니다.
- 28개의 단계 74개가 쓰는 자원은 7개뿐입니다. 그중 6개는 우리가 직접 운영하는 데이터 에이전트입니다.
- 수집한 39만 개 가운데 워크플로우에 들어간 외부 에이전트는 **1개(Paper Finder), 1회**입니다.
- 사용자 지적이 그대로 맞습니다. "기존 에이전트를 활용해 기존 에이전트보다 품질이 좋은 워크플로우를 공급하고 있지 않다."

### 2-2. 도입은 실험이 넓고 확산은 좁습니다
- 62%가 실험 중이고, 확산 중인 곳은 23%입니다(McKinsey, 2025-11).
- 운영 단계의 가장 큰 장벽은 **품질(32%)**입니다(LangChain, 2025-12).
- Gartner는 2027년 말까지 에이전트 프로젝트의 40% 넘게 취소될 것으로 봅니다. "에이전트"를 내세우는 업체 가운데 진짜는 약 130곳으로 봤습니다(2025-06, agent washing).
- 뜻: 시장은 크고 빠르게 크지만, **"무엇이 진짜로 되는가"를 가려 주는 일**이 가장 부족합니다.

### 2-4. 추세
- 표준: A2A 지지 조직이 150곳을 넘었고, MCP와 A2A는 Linux Foundation AAIF에서 함께 관리합니다. ARD·NANDA 같은 연합 발견은 초안 단계입니다.
- 결제: x402 누적 거래는 2억 건이 넘지만, 실제 상거래는 하루 약 2.8만 달러이고 95% 넘게 신호용 거래입니다. OpenAI의 Instant Checkout은 철수했습니다. **결제 수익은 아직 이릅니다.**
- 빅테크는 조합 기능(AgentKit, Zapier 에이전트 간 호출)을 직접 넣습니다. 조합 "기능" 자체는 흔해지고 있습니다.

### 2-5. 학계: 진주 목걸이 전략의 근거와 반론
- **근거**
  - 자동으로 탐색한 워크플로우가 사람 설계보다 낫습니다. AFlow(ICLR 2025) +5.7%, AgentSquare +17.2%, ADAS(ICLR 2025) DROP +13.6 F1입니다. 비용도 줄어 MaAS(ICML 2025)는 6~45%만 씁니다.
  - **부품 품질이 다양성보다 중요합니다.** Self-MoA는 +6.6%였고, MASS(ICLR 2026)는 부품을 먼저 다듬고 조합하는 순서가 낫다고 했습니다. "진주를 먼저 고르고 연결한다"는 우리 순서와 맞습니다.
  - 도구 조합의 핵심은 의존 관계를 아는 검색입니다(Graph RAG-Tool Fusion +22~72%p).
  - 중앙 조율자와 검증 단계를 두면 오류 증폭이 17.2배에서 4.4배로 줄고(Google·MIT 2025-12), 검증 단계는 +15.6%입니다(MAST).
  - 공개 레지스트리의 제3자 에이전트로 워크플로우를 만들어 새 에이전트로 공급한 연구·사례는 **찾지 못했습니다.** 빈자리입니다.
- **반론**
  - 멀티에이전트 시스템의 실패율은 41~86.7%입니다(MAST).
  - 순차 과제에서는 39~70% 나빠졌습니다(Google·MIT).
  - 잘 짠 단일 에이전트가 멀티에이전트와 비슷할 때도 많습니다(ACL 2024).
  - 제3자를 연결할수록 공격면이 넓어집니다(MCPTox 72.8%, 멀티에이전트 임의 코드 실행 58~90%).
  - 그래서 **"목걸이가 가장 좋은 단일 진주보다 실제로 나은가"를 재고, 나을 때만 공급**해야 합니다.

## 3. SWOT — Agentcon(에이전트 밸류 게이트웨이)

| | 도움 | 해 |
|---|---|---|
| **내부** | **S**: 39.5만 개 카탈로그와 실측 증거, A2A·MCP·x402를 한곳에서 다룸, 읽기 전용 중계 게이트웨이와 엣지 Worker(실행 경로), 워크플로우 엔진(체크포인트·서명·노드 실행 기록), 실제 과제 채점 체계, 지출 0 구조 | **W**: 진주 인증이 없음, 목걸이가 외부 진주를 쓰지 않음(외부 1개), 목걸이 품질 지표(단일 대비 향상)가 없음, 외부 이용 거의 0, 속도 미달(차선 16%), 1인·맥 1대 |
| **외부** | **O**: 멀티에이전트 부문이 가장 빨리 큼(48.5%), 품질이 1위 장벽(32%), 빅테크는 자기 생태계만 검증, 템플릿은 깨지고 "살아 있는 결과"에 지불, 공개 부품 조합 공급자가 비어 있음, A2A·MCP로 목걸이를 에이전트 하나처럼 배포 가능 | **T**: 빅테크·Zapier가 조합 기능을 넣음, 멀티에이전트 실패율이 높음, 제3자 부품의 보안 위험(tool poisoning, rug pull), 결제 시장이 아직 작음, 템플릿 단품에는 지불 의사가 낮음, 레지스트리 계층은 무료 공공재(인수 대상) |

### 교차 전략
- **SO — 진주 목걸이 공장**
  - 카탈로그와 증거로 진주를 인증하고, 병렬 조회 후 합치는 유형부터 목걸이를 자동·반자동으로 만듭니다.
  - 목걸이마다 MCP·A2A·웹 페이지를 하나씩 둡니다.
  - "단일 대비 몇 % 나은지, 1회 비용, 최근 시험 성공률"을 공개합니다.
- **ST — 중립성과 공개 시험 데이터로 빅테크와 다른 자리**
  - 빅테크 스토어가 못 하는 "생태계를 가로지르는 검증된 조합"을 합니다.
  - 목걸이 부품의 도구 정의 지문을 감시하고, 바뀐 진주는 자동으로 교체하거나 보류합니다. rug pull 대응이 곧 품질이 됩니다.
- **WO — 목걸이로 유입 얻기**
  - 홍보 단위를 개별 에이전트에서 목걸이로 바꿉니다.
  - 목걸이를 공식 MCP Registry에 서버 단위로, A2A 레지스트리에 카드 단위로 올릴 수 있습니다(외부 게시라 사용자 승인 필요).
- **WT — 작게, 증명된 것만**
  - Δ(단일 대비 향상)가 0 이하인 목걸이는 공급하지 않습니다.
  - 첫 목걸이는 순차 의존이 강한 과제를 피하고 병렬·합성 과제로 시작합니다.
  - 결제는 수요를 본 뒤로 미룹니다.

**Glama와의 관계(사용자 지시)**
- Glama가 하는 일(목록, 헬스, 도구 품질 점수)은 뒤처지지 않게 유지합니다.
- 경쟁 축은 "누가 더 많이 나열하나"가 아니라 **"누가 검증된 진주로 새 가치를 만들어 계속 공급하나"**입니다. Glama는 개별 서버 단위 점수이고, 우리는 목걸이 단위 결과입니다.

## 4. 경영전략 (바뀐 것)

1. **정체성**: "에이전트 소개(디렉터리)"에서 **"에이전트 밸류 게이트웨이: 진주 발굴 → 진주 목걸이 공급"**으로 바꿉니다.
2. **핵심 상품**: 진주 목걸이(검증된 외부 진주 2개 이상을 연결한 워크플로우). 하나하나가 새 에이전트로 동작합니다(MCP 도구, A2A 카드, 웹 실행 페이지).
3. **품질 원칙**
   - 목걸이는 같은 정답 세트에서 가장 좋은 단일 진주보다 성공률이 높을 때만 공급합니다(Δ > 0).
   - 매일 다시 시험하고, 진주가 고장 나거나 정의가 바뀌면 자동으로 교체하거나 보류합니다.
3-1. **대체 원칙(사용자 11-14 추가: "끝까지 실행이 되게 만드는 것이 우리의 역할")**
   - 목걸이의 단계(진주 자리)마다 대체 에이전트를 여러 개 미리 준비합니다. 같은 역할을 하는 다른 외부 진주를 순위대로 둡니다.
   - 대체 사슬의 마지막에는 **Agentcon이 직접 만든 대체 에이전트를 최대 2개**까지 둡니다. 외부 진주가 모두 멈춰도 목걸이가 끝까지 실행되도록 하는 마지막 보증입니다.
   - 순서는 주 진주 → 외부 대체 진주(여러 개) → Agentcon 대체 에이전트(최대 2개)입니다.
   - 기반 구현이 이미 있습니다: 워크플로우 대체 실행(docs/WORKFLOW_FALLBACK.md, workflow_fallback_*·workflow_routing_*). 지금은 운영에서 꺼져 있고 범위가 좁습니다. 계약은 news.search·docs.search 두 종류뿐이고, 실행 한 번에 대체 1회, 관리자가 고른 짝, canary 10%입니다.
   - 이것을 목걸이 단위로 넓힙니다. 진주 자리마다 역할 계약(입출력 스키마)이 있어야 하고, 대체 사슬은 진주 인증과 매일 재시험으로 늘 최신으로 유지합니다.
   - 지켜야 할 기존 경계: 읽기 전용·멱등 도구만, 자격 증명·결제·쓰기는 대체하지 않음, 공개 사용자는 "같은 입력이 다른 검증된 에이전트로 갈 수 있음"에 동의
   - 지표: 목걸이 **완주율**(대체를 써서라도 끝까지 성공한 비율), 단계별 대체 발생률, Agentcon 대체 에이전트 사용률. 사용률이 높으면 그 자리의 외부 진주를 다시 찾습니다.
   - 우리의 일: 목걸이 에이전트가 실제로 실행되고 서비스되는 **최고 가치의 서비스로 자리 잡게** 만드는 것까지입니다.
4. **홍보 원칙**: 홍보·SEO·등록·SNS 초안의 단위는 목걸이입니다. 개별 에이전트 페이지는 근거(진주 카드)로만 둡니다. 이미 결정한 근거 약한 페이지 noindex와 같은 방향입니다.
5. **유지 원칙**: 수집, 등급, 탐색, 추천(현재 기능)은 진주 발굴의 기반이라 계속 개선합니다. Glama 수준에 뒤처지지 않습니다.
6. **수익 원칙**: 지출 0과 USDC 건별 광고 상품을 그대로 둡니다. 목걸이 실행 과금은 외부 실행 수요가 확인된 뒤 검토합니다. 결제 시장이 아직 작기 때문입니다.
7. **바뀌지 않는 경계**: 남의 서버에 자격 증명·결제를 보내지 않습니다. 시험 호출은 읽기 전용만 합니다. 실행은 중계 허용 도구만 씁니다. 외부 게시·계정·지출은 사용자 승인을 받습니다.

## 6. 실행 계획

| 순서 | 일 | 담당 | 기간 |
|---|---|---|---|
| 1 | **진주 인증 기준과 진주 표** — 등급·헬스·시험·보고서·도구 정의 지문(rug pull 감시)을 묶은 진주 판정과 진주 카드 | 검색과 RAG(판정) + 운영·SRE(지문·재검증) | 1주 |
| 2 | **목걸이 품질 측정 틀** — 목걸이별 정답 세트, 최고 단일 진주 대비 Δ, 단계별 성공률, 비용·지연, 보안 시험 | 검색과 RAG | 1주 |
| 3 | **첫 목걸이 5개** — 병렬 조회 후 합성 유형(예: 여러 출처 논문·뉴스·지표 종합 브리프, 패키지 보안+유지 상태 감사, 여행 날씨+환율+지역 정보). 진주에서 자동 후보를 만들고 사람이 검토. 기존 워크플로우 엔진 재사용 | 검색과 RAG(후보 생성: Neo4j 관계 그래프 활용) + 성장·유통(페이지) | 2주 |
| 4 | **목걸이 = 새 에이전트** — 목걸이마다 MCP 도구와 A2A 스킬로 노출하고 웹 실행 페이지를 둠. A2A run과 MCP run 재사용 | 성장·유통 | 2주 |
| 5 | **매일 재시험·자동 교체** — 고장·변경된 진주는 같은 역할의 다른 진주로 교체하거나 보류. 결과를 공개 시험 기록에 남김 | 운영·SRE | 2~3주 |
| 6 | **홍보 전환** — 홈, 탐색, llms.txt, 사이트맵의 중심을 목걸이로 바꿈. 목걸이 단위 등록(외부 게시는 사용자 승인) | 성장·유통 | 2주부터 |
| 7 | **브랜드 Agentcon 적용** — 공개 화면, 구조화 데이터, 카드 이름. 검색 연속성을 위해 "Agent Concierge"를 alternateName으로 유지(아래 결정 필요) | 성장·유통 | 사용자 확인 뒤 |

**Neo4j 활용 연결**: 맥미니 Neo4j(GDS)는 진주 사이의 "함께 쓸 수 있는" 관계를 만드는 데 씁니다. 관계는 입출력 타입 맞춤과 같은 분야를 기준으로 합니다. 앞서 정한 호스트·중복 묶기(P1)는 진주 후보를 정리하는 단계로 바로 이어집니다.

## 6-1. 목걸이 출시 흐름 (11-14 사용자 지시)
1. **워크플로우 팀**: 생산체계로 진주 목걸이(새 워크플로우 = 새 에이전트)를 만든다.
2. **운영·SRE 팀**: **품질 95% 이상** 관문을 검수한다. 정답 세트 종단 성공률 95% 이상, Δ > 0, 완주율, 5초 지연, 보안 시험을 본다. 통과하면 프론트엔드 **워크플로우 메뉴**에 적용한다.
3. **성장·유통 팀**: 워크플로우 메뉴에 올라간 새 목걸이를 홍보한다.
- 탈락하면 워크플로우 팀으로 돌려보낸다. 공개 뒤 매일 재시험에서 95% 아래로 떨어지면 운영·SRE가 보류하고 워크플로우 팀이 고친다.
