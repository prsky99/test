# 로그인 진입 및 초기 로딩 수정

- 공개 프론트앤드의 Workspace 메뉴를 `/customer/sign-in`으로 연결했습니다. 로그인 화면이 먼저 표시되고, 이 화면에서 세션 확인 후 로그인된 사용자만 워크스페이스로 이동합니다.
- 세션이 없는 사용자가 `/customer/workspaces`, `/customer/organizations`를 직접 열면 서버가 로그인 화면으로 이동시킵니다. 워크스페이스 HTML을 먼저 반환하지 않습니다. 활성화된 서비스의 이전 `/new/en/` 계정·워크스페이스 경로도 네이티브 로그인 화면으로 연결합니다.
- 워크스페이스 진입 시 중앙 로딩을 먼저 렌더링하고 초기 본문·메뉴를 감춥니다. 세션, 권한, 조직·초대·멤버·초안 또는 워크플로우 목록·상세·이력 등의 해당 초기 조회가 끝난 뒤 문서 로딩, 폰트 준비, 최종 화면 렌더링까지 기다리고 로딩을 닫습니다.
- 세션 만료로 이동 중인 화면은 다시 드러나지 않습니다. 초기 조회가 실패하면 오류·재시도 화면을 표시하며 로딩을 종료합니다. 기존 사용자 액션 로딩과 백그라운드 조회 정책을 유지합니다.

## 검증

- 로그인·라우팅·세션 만료 브라우저 회귀: 36개 통과.
- 지연된 워크플로우 이력과 폰트 준비, 기존 UI·공개 페이지·캐시 회귀: 73개 통과.
- 고객 인증·조직 접근·공개 차단 API 회귀: 80개 통과.
- 총 189개 테스트 통과. 모두 격리 고객·DB·가짜 제공자 응답 사용.
- 공개 콘텐츠 243개 파일 검사 위반 없음. JavaScript 구문 및 Python 컴파일 검사 통과. SQL 카탈로그 최신성 확인.
- 보안 변경 검토: 서버 페이지는 기존 세션 검증을 재사용하며 세션을 새로 발급하지 않습니다. 이동 목적지는 고정된 동일 서비스 경로이며 URL 입력을 새로 받지 않습니다. CSP nonce, 출력 이스케이프, no-store 및 API 권한 검증을 유지합니다.
- 화면 캡처: `initial-loading-mobile.png`, `initial-ready-mobile.png`.

운영 서버 재시작과 실제 계정 로그인은 실행하지 않았습니다. Python 라우팅과 HTML 응답 변경의 운영 반영에는 서버 재시작이 필요합니다.
