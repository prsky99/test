# CSS 구조 정리 (PM 11-14 00:3x 안 3: "보이는 화면은 그대로, CSS만 줄이기")

목표는 첫 화면 CSS와 전체 CSS 묶음을 줄이는 것이다. 보이는 결과는 바꾸지 않는다. 기준은 화면 10개 × 1280·375 × 라이트·다크(40장)의 픽셀 차이 0이다. 디자인 시스템(Pearl Connection 토큰, 공용 assets)을 그대로 따르고, 페이지 전용 스타일은 만들지 않는다.

## 기준과 도구 (1단계, 11-14 01:2x 완료)

- 도구: `scripts/css_pixel_compare.py`
  - `shoot <단계>`: 작업본을 고정 카탈로그(8개)로 띄운 앱에서 40장을 찍는다. 네트워크는 쓰지 않고, 애니메이션·전환을 끄고, 글꼴이 다 오기를 기다린다.
  - `diff <기준> <단계> --noise <기준 두 번째>`: 그림마다 다른 픽셀 수를 세고, 다르면 빨간 차이 그림을 남긴다.
- 대상 화면 10개: 홈, agent-status, explore, learn, test, workflows, chat, list-agent, about, privacy.
- 잡음 확인: 같은 작업본을 두 번 찍었다.
  - 처음에는 화면에 나오는 현재 시각(16:23 → 16:24 UTC) 때문에 8장이 달랐다. 찍기 전에 "시:분" 글자를 고정값으로 바꾸게 했다.
  - 그 뒤 40장 중 39장이 같았다. 남은 1장(chat 375 다크)은 패널 테두리 7픽셀의 안티앨리어싱이다.
  - 이것은 기준을 두 번 찍어 흔들린 픽셀로 빼고 센다(`--noise`). 같은 작업본끼리 0.
- 기준 사진: `baseline/`, `baseline-2/`. 안 1 작업본(34b064a4) 기준이다.

## 단계 계획 (단계마다 40장 픽셀 차이 0, 현황판에 진행 기록)

1. 기준과 도구 — 끝.
2. 원본 파일의 같은 선택자 덮어쓰기 정리: 뒤 파일(pearl-live)에서 이기는 값을 앞 파일 규칙 자리에 합치지 않는다. 앞 파일의 진 선언만 지운다(prune 규칙 그대로, 원본에 적용). 예상: 묶음 −10KB, 첫 화면 −1~2KB 추가.
3. 어떤 화면에서도 맞는 요소가 없는 규칙 찾기: 공개 화면 전부와 상태(메뉴 열림, 다크, 결과 카드 종류, 대화 진행 중)에서 coverage를 모은다. 한 번도 쓰이지 않은 규칙 후보를 목록으로 만든다. 지우기 전에 목록을 PM에 올린다(상태를 놓치면 그 화면이 깨지므로).
4. 다른 선택자로 같은 요소를 겹쳐 쓰는 부분(styles → pearl-live)을 컴포넌트별로 하나로 합친다. Pearl 토큰 값을 쓰고, 화면별 전용 규칙은 만들지 않는다.
5. 첫 화면 CSS를 다시 만들고, 공개 주소에서 전후 크기와 본문 시간을 잰다.

- 차이가 0이 아닌 단계는 그 화면만 사진과 함께 PM에 올리고, 사용자 화면 승인 전에는 내보내지 않는다.
