# Protocol, SDK and portable metadata source verification

The final component runs contain **200 distinct pytest cases**, with no failures, errors or skips: 158 core/API/SDK-threat/existing-ledger/release cases, 27 portable receipt cases and 15 desktop browser/SDK cases. `verification.json` binds these results to the component source hashes. Prior intermediate JUnit files are retained and are not added to this count.

Four changed/new Python modules produced zero Bandit findings or errors. The new admin JavaScript passed the Node syntax check. Desktop Chromium used routed TestClient applications and synthetic providers only; it did not connect to the operating server, identity providers, payment rails or notification targets.

## Implemented source

- `ProtocolConformance` and its named-session admin service validate a fixed x402 v2 HTTP wire subset and a local quote-bound mandate fixture. The latter is **not AP2 credential verification**. Local fixture signatures are not EVM network authorizations. Upstream commit pinning, facilitator behavior and deployed escrow remain unimplemented and are explicitly false in reports.
- Reports reference existing signed sandbox capture/refund receipts and the existing TEST_UNIT ledger. They create no captures, refunds, replacement ledger, provider calls, real claims or payouts. Quote, local authorization, commitment fixture, simulated settlement, claim, finality, refund and payout states remain distinct. Receipt absence is held without dispatch; a retained historical report is never silently upgraded after a later event.
- Reports have current-owner/source checks, bounded exact fields, atomic workspace/event dedupe, signed immutable observations and explicit historical/restore-blocked semantics. Browser tests verify fresh consent, source-change reset, a centered modal, lost-response history inspection without automatic retry, and logout cleanup.
- SDK/BFF hardening adds strict duplicate/nonfinite/depth/count validation to gateway responses and rechecks session capacity when an exchanged token is committed. Existing PKCE, server-only app tokens, scoped status capabilities, current gateway authority and atomic quotas remain in place. Existing single and typed SDK browser flows pass. `sdk-v2.js` was not rewritten. The compatibility matrix distinguishes public SDK 1.0.0, admin managed SDK 1.1.0, private SDK 2.0.0 and private typed SDK 2.1.0 from upstream protocol revisions.
- `reliability_portable_receipt.py` adds a separate **disabled-by-default** Ed25519 metadata helper with explicit injected key configuration and a trusted sanitized projection callback. It registers no public route and creates, stores or exports no private key. Tests use ephemeral in-memory keys. The canonical payload admits only public subject/contract/digest/verdict/time metadata, is bound to issuer/audience/key ID/purpose and expires no later than its source or 300 seconds.
- Offline verification establishes signature and time only. It explicitly does **not** establish current withdrawal, independent quality, business completion, payment permission or legal settlement. A test demonstrates that an old unexpired signature can still verify after source withdrawal; public online status and issuance controls remain separate required integration work.

## Remaining acceptance

No real external account, monetary transaction, provider payout, public Workspace access, advertising delivery or public portable receipt endpoint was enabled. Official AP2/rail credentials, actual network scheme bindings, upstream implementation pins, approved external sandbox reconciliation, public receipt exposure authorization and operating acceptance remain separate gates. The shared platform/router/native SQL/restore wiring is owned by the parent integration work and is not established by this component-only report.
