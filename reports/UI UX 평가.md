# agentconcierge.biz UI/UX·에이전트 경험·접근성 평가

- **일시:** 2026-10-28
- **평가 기준:** `docs/qa/uiux-evaluation-criteria.md`
  - 2025~2026 논문·표준·업계 글을 조사해 만든 기준입니다.
  - 기준마다 0~3점을 매기고 가중치를 곱합니다.
  - 종합 점수 = 0.40 × 사람 + 0.35 × 에이전트 + 0.25 × 접근성
  - 등급: A ≥ 85, B 70~84, C 55~69, D < 55
- **측정 방법:**
  - **자동 측정:** `scripts/uiux_audit.js`(axe-core 4.10, Web Vitals, 키보드 Tab 25회, 24px 타깃, 320px 리플로)로 화면 10개를 4가지 조건(데스크톱, 모바일 390, 320px, 다크)에서 쟀습니다.
  - **에이전트 측정:** `scripts/agent_scenarios.py` 76개 시나리오
  - **이전 기록:** Explore·Chat·등록·결제·워크스페이스 재시험 결과(`reports/개선 확인 4차.md` 등)를 함께 썼습니다.
- **한계:**
  - 사람 사용자 과업 시험(H1.1)과 실제 스크린리더 사용자 시험(X6.9)은 하지 않았습니다. 해당 점수는 자동 측정과 화면 검토로 추정했습니다.
  - 성능은 배포 직후 서버가 불안정할 때 측정한 값이 섞여 있어, 평소보다 나쁘게 나왔을 수 있습니다. 안정된 뒤 다시 잰 값도 함께 적었습니다.

## 개선 방안 (점수 효과 / 작업량 순)

### 1단계: 작은 작업, 큰 효과
1. **정적 파일 캐시와 압축** (H6, A8 / +3~4점)
   - JS·CSS·이미지 파일 이름에 해시를 붙이고 `Cache-Control: public, max-age=31536000, immutable`을 줍니다. Cloudflare 캐시를 켜고 br/gzip으로 압축합니다.
   - HTML은 `no-cache`(ETag로 재검증)로 둡니다.
   - 목표: LCP p75 ≤ 2.5초, TTFB ≤ 0.8초
2. **색 대비 231곳** (X1, H10 / +3점)
   - 라이트·다크 디자인 토큰의 보조 글자색과 표 머리색을 4.5:1 이상으로 올립니다.
   - 확인: `scripts/uiux_audit.js`의 `color-contrast` 0
3. **포커스 표시와 가림** (X2, A6 / +2~3점)
   - 모든 대화형 요소에 `:focus-visible { outline: 2px solid; outline-offset: 2px }`를 주고, 다크 모드 색도 정합니다.
   - 고정 헤더 높이만큼 `scroll-padding-top`(또는 `scroll-margin-top`)을 둡니다.
4. **CLS(Explore 0.24, Chat 0.23~0.33)** (H6)
   - 결과 목록, 추천 카드, 쿠키 배너, 웹 폰트 자리를 미리 잡습니다(`min-height`, `aspect-ratio`, `font-display: optional` 또는 크기 맞춤).
5. **작은 접근성 수정** (X5, X3)
   - 다크 모드 로그인 `select`에 라벨을 붙입니다.
   - `#pearlWorkflowTemplates`를 최상위 `aside`로 옮기거나 `section`으로 바꿉니다.
   - `aside`의 역할 오용을 정리합니다.
   - 24px 미만 타깃을 24px 이상으로 키우거나 간격을 둡니다.

### 2단계: API 계약 (에이전트 점수)
6. **표준 오류 형식** (A3 / +3점)
   - 모든 4xx·5xx를 `application/problem+json`으로 보내고, 지금의 `error_code`를 `type` URI로 씁니다. `retryable`도 넣습니다.
   - 깨진 JSON은 400, `limit` 범위 오류는 사람이 읽을 문장으로 바꿉니다.
7. **요청 한도·캐시 헤더** (A3, A8, A2 / +2점)
   - 모든 공개 API에 `RateLimit`·`RateLimit-Policy`·`Retry-After`를 넣습니다.
   - 목록에 `next_cursor`와 `ETag`/304를 넣습니다.
   - `Idempotency-Key`: 등록, 워크플로 실행, 결제가 대상입니다.
8. **결제 실패 이유 코드** (A5 / +2점): `docs/qa/payment-improvement-plan.md` 1장
9. **MCP·발견 보완** (A1, A7)
   - `search`·`find_agents`·`whats_new`에 `readOnlyHint: true`를 붙입니다.
   - `/.well-known/mcp/server.json`을 둡니다.
   - `Accept: text/markdown`에 마크다운으로 답합니다.
   - 문서의 숫자·경로는 한 출처에서 자동으로 만듭니다.
10. **에이전트 상태 JSON** (A8): `/status.json`으로 가동률, 최근 장애, 카탈로그 수를 제공합니다.

### 3단계: 사람 경험
11. **Chat 대화 이어 가기** (H3)
    - "the second one"·"it"이 직전 추천 목록을 가리키게 합니다.
    - 추천마다 좋아요/싫어요와 이유를 받습니다. 지금 있는 `worked 1`/`failed 1`을 UI로 노출하면 됩니다.
    - 생성 중지 버튼을 둡니다.
12. **검색 자동완성과 실제 오타 제안** (H2)
    - 2~3글자에서 카테고리·흔한 작업을 추천합니다(combobox 패턴, `aria-activedescendant`).
    - 0건일 때 편집 거리 1~2의 실제 제안 링크를 보여 줍니다.
13. **신뢰 표시** (H4, A7)
    - 품질 점수를 누르면 구성(가동률, 응답 시간, 스키마 품질, 시험 결과)과 방법론 링크를 보여 줍니다.
    - 제공자가 쓴 문구는 "Provider description" 라벨과 다른 배경으로 구분합니다.
14. **공유·비교** (H1): Chat 추천과 상세에 고유 URL을 둡니다. 2~4개 항목 비교 화면을 만듭니다.
15. **Chat 안 AI 고지·기록 안내** (H9): EU AI Act 50조 시행(2026-08)에 맞춰, 입력창 아래에 "AI가 추천합니다. 대화는 N일 보관됩니다"를 적습니다.
16. **Test 결과 표시 정확성** (H8): 캐시된 결과면 "캐시: 05:21 조회"로 표시합니다. 실제 지연을 보여 줍니다.

### 4단계: 가까운 미래 대비(2026~2027)
17. **WebMCP**(`navigator.modelContext`)로 검색·추천을 브라우저 에이전트용 도구로 선언합니다(A6.6).
18. **Web Bot Auth(RFC 9421 서명)** 를 확인해 검증된 에이전트에 더 높은 한도를 줍니다(A4.4).
19. **AP2 mandate 수용**이나 A2A x402 확장을 선언합니다(A5.5).
20. **사람 과업 시험**(5명, 과업 6개)과 **스크린리더 사용자 시험**(1~2명)을 분기마다 하고, H1.1·X6.9 점수를 실제 값으로 바꿉니다.
