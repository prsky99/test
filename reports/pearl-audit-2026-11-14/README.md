# 진주 찾기 전수 점검 (2026-11-14, PM)

사용자 요청: "우리가 진정 진주 찾기를 잘 하고 있고 현재 자체 프로세스로 검증된 진주를 찾았는지 그리고 그걸 테스트 결과 보고서로 작성하고 있는지 전수 점검. 품질등급 A가 진주여야 하고 테스트 결과 보고서 최고 품질이 최종 진주가 되어야 함."

- 근거는 운영 PG를 읽기 전용으로 집계한 값입니다(11-14 04시대). 아무것도 바꾸지 않았습니다.
- 대조한 파일: `reports/pearls-2026-11-14/`(진주 판정·역할 시험), 보고서 배치 기록 `logs/ops/test-reports/`, 보고서 품질 감사 `logs/ops/report-quality/summary.json`

## 결론
**절반만 하고 있습니다.**
- 1단계 "등급 A = 진주 후보"는 자체 과정으로 돌고 있습니다.
- 2단계 "시험 보고서 최고 품질 = 최종 진주"는 아직 만들어지지 않았습니다.

| 사용자 기준 | 지금 상태 | 판정 |
|---|---|---|
| 등급 A를 자체 과정으로 매김 | 수집기가 직접 연결하고 시험 호출해 점수를 냅니다(평가 v5). 활성 A는 **8,209개**(MCP 6,842, A2A 1,367)입니다 | 됨 |
| A를 시험 보고서로 검증함 | A의 51%(4,198개)는 보고서가 아예 없습니다. 보고서가 있어도 99%는 연결 확인뿐입니다 | 부족 |
| 보고서 품질로 최종 진주를 고름 | 보고서마다 품질 점수가 없습니다. 지금 진주 25개는 "실행 보고서가 우연히 생긴 A"입니다 | 안 됨 |

## 1. 등급 A (진주 후보)
- 점수 구성: 가용성 25, 정의 25, 보안 15, 맥락 10, 프로토콜 10, 출처 15. 85점 이상이면 A입니다(`collector/evaluation.py`).
- 활성 A 8,209개는 모두 7일 안에 수집기의 시험 호출에 성공했습니다(`trial_ok=1`).
  - 시험 호출이 4일 넘게 묵은 것은 84개뿐입니다. 재시험은 잘 돌고 있습니다.
- 한계 1: A는 "연결이 잘 되고 설명이 잘 된 서버"라는 뜻입니다. "과제를 잘 해낸다"는 뜻이 아닙니다.
  - MCP 시험 호출은 인자가 필요 없는 안전한 도구 하나를 부릅니다. `list_categories`, `list_identifiers` 같은 목록 도구가 많습니다.
- 한계 2: A2A는 수집기가 실제로 메시지를 보내고 응답을 받습니다(1,367개 모두 `completed`). 그런데 이 증거가 시험 보고서로 이어지지 않습니다(3절).
- 정리할 것: 비활성 x402 자원 861개에 옛 A 등급이 남아 있습니다. x402 상한은 B라서 등급만 정리하면 됩니다. 탐색에 보이지는 않습니다.

## 2. 시험 보고서
| 범위 | 건수 | 내용 |
|---|---|---|
| transport | 20,729 | 카드나 도구 목록만 확인. 마지막 생성은 11-10, 16,319건이 7일 넘음 |
| legacy | 215 | 10-15~10-19에 seed 스크립트로 넣음. 작성자 이름이 지금 과정과 다름(Antigravity 등) |

문제점:
1. **실패 보고서가 0건입니다.** 20,986건이 모두 `is_success=1`입니다.
   - 실패한 에이전트는 보고서가 생기지 않으니, 보고서끼리 비교해 우열을 가릴 수 없습니다.
2. **실행 보고서도 내용을 판정하지 않습니다.**
   - 42건 중 28건은 인자 없이 도구를 불렀습니다.
   - 저장되는 것은 결과 글자 수(`output_chars`)뿐이고, 결과가 맞는지는 보지 않습니다.
   - 요약 문구는 "passed MCP Tool Call check (HTTP 200, 165 ms)" 수준입니다.
3. **에이전트당 보고서가 1개뿐이고 다시 쓰지 않습니다**(`REPORT_ALREADY_EXISTS`).
   - 연결 보고서가 있는 A 약 4,000개는 지금 경로로는 실행 보고서로 올라갈 수 없습니다.
   - "매일 다시 시험"한 결과가 보고서에 반영되지 않습니다.
4. **보고서 품질 점수가 저장되지 않습니다.**
   - 11-10 AQEF-30 표본 감사에서 810건의 중앙값은 68점이었고, 85점 이상은 0건이었습니다.
   - 주된 문제는 한계 누락(1,037), 근거 없는 주장(998)이었습니다.
   - 점수는 표본 파일에만 있고 보고서 행에는 없습니다. 그래서 "최고 품질 보고서"를 고를 수 없습니다.

## 3. 지금 진주 25개 점검
- 판정 조건 1~6(A, 보안, 7일 헬스, 시험 호출, 실행 보고서, 일 도구)은 지금도 25개 모두 통과합니다.
- **조건 7(도구 정의 변경 없음)을 엄격히 적용하면 11개만 남습니다.**
  - 14개는 `usage_changes`에 도구 추가·삭제 기록이 있습니다.
  - 예: 33328은 진주 근거 도구인 `rssa_board_changes`가 "추가됨" 기록에 있습니다.
- **역할에 맞는 실제 과제는 실패한 진주가 있습니다.**
  - 38634(itsnum): 역할 시험에서 unauthorized
  - 47538(festival-finder): 엉뚱한 결과(힌두 축제)
- 분야 분류가 맞지 않습니다.
  - popdot.ai 도메인 검색과 ceadigital CISA KEV 취약점이 finance_crypto로 분류돼 있습니다.
- 뽑힌 방식: 보고서 배치가 `sort=recent`로 고른 대상 가운데 실행 보고서가 생긴 A가 진주가 됐습니다. 같은 역할의 다른 A와 비교해 이긴 것이 아닙니다.

## 4. 더 좋은 증거가 보고서로 이어지지 않음
- 검색과 RAG의 역할 시험(11-14, 30건)은 실제 인자로 호출하고 결과 발췌를 남겼습니다. 21건이 성공했고, 실패와 건너뜀도 기록했습니다.
  - 예: openalex 논문 검색에 "large language models"를 넣어 실제 논문 결과를 받음
- 이것이 사용자가 말한 "테스트 결과"에 가장 가까운 증거입니다. 하지만 파일에만 있습니다.
  - 성공 21개 가운데 실행 보고서가 있는 것은 4개뿐입니다.
- A2A 수집기 시험의 응답 발췌도 보고서가 되지 않아, A2A 진주는 0개입니다.

## 5. 진주 배치
- 하루 30건(MCP 25, A2A 5)으로 늘린 배치(`scripts/pearl_batch.py`)는 오늘 03:55에 커밋돼 **아직 한 번도 돌지 않았습니다.** 첫 실행은 11-15 02:30입니다.
- 이 배치도 2절의 문제를 그대로 가집니다.
  - 보고서가 없는 대상만 처리합니다.
  - 인자가 없는 시험입니다.
  - 내용을 판정하지 않습니다.
  - 실패는 기록하지 않습니다.
- 200개 목표를 숫자로는 채울 수 있습니다. 하지만 "최고 품질로 고른 진주"는 되지 않습니다.

## 6. 바로잡는 설계 (사용자 기준 2단계)
1. **진주 후보 = 활성 A**: 보안 격리가 아니고 7일 헬스가 정상인 것. 지금 약 8,040개입니다.
2. **시험 보고서 v2 = 역할 과제 시험**
   - 역할 시험 방식을 표준 보고서로 만듭니다.
     - 실제 인자(역할별 고정 과제 입력)로 호출합니다.
     - 결과 발췌를 남기고, 기대 필드나 낱말로 내용을 판정합니다.
   - **실패도 보고서로 남깁니다.**
   - 에이전트당 보고서 1개 제한을 "새 판 추가" 방식으로 바꿉니다. 재시험할 때마다 판이 쌓이고, 공개 화면은 최신 판을 보여 줍니다.
   - A2A는 카드에 공개된 예시 입력으로 실행하고, 그 응답으로 보고서를 만듭니다. 이미 승인된 규칙을 따릅니다.
3. **보고서 품질 점수(100점)를 보고서마다 저장합니다.**
   - 증거 60점: 실제 인자 실행, 내용 판정 통과, 최근 7일 안 반복 성공 횟수, 지연
   - 글 품질 40점: AQEF-30 항목. 근거 없는 주장과 한계 누락은 감점합니다.
   - 1단계는 파일(`exports/pearls/`)에 저장합니다. 표에 열을 더하는 것은 DB 변경이라 리허설과 승인 뒤에 합니다.
4. **최종 진주 = 같은 역할 안에서 보고서 품질 점수 1위**
   - 85점 이상이어야 합니다.
   - 2·3위는 목걸이 자리의 외부 대체가 됩니다.
   - 매일 다시 시험하고 점수가 떨어지면 순위를 바꿉니다.
5. **조건 7을 명확히 합니다.**
   - 운영·SRE의 도구 정의 지문으로 바꿉니다.
   - 진주 근거 도구의 정의가 바뀌었으면 재시험 전까지 진주에서 뺍니다.
   - 단순히 다른 도구가 추가된 것만으로는 빼지 않습니다.
6. 분야 오분류를 고칩니다. 진주의 분야는 역할 키 기준으로 다시 정합니다.
