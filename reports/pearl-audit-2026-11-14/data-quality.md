# 시험 보고서 v2의 데이터 품질 평가 점검 (2026-11-14, PM)

사용자 요청: "에이전트 테스트 결과 보고서에는 양질의 데이터도 중요함. 품질 테스트에 데이터 품질이 떨어지는 것에 대한 품질 평가도 잘 적용이 되었는지 확인해줘."

- 대조한 것
  - `scripts/report_v2.py`의 판정(judge)과 점수(quality)
  - `scripts/role_catalog.py`
  - 오늘 만든 판 파일 30개(`exports/pearls/reports/`)
- 운영 DB는 건드리지 않았습니다.

## 결론
**데이터 품질 평가는 제대로 적용되지 않았습니다.**
- 응답의 데이터가 정확한지, 최신인지, 빠짐없는지, 깨끗한지는 거의 점수에 들어가지 않습니다.
- 지금 85점 이상 11개 가운데 데이터가 실제로 맞는지 확인한 것은 0개입니다.
  - 공개 정답 대조는 11-15부터 워크플로우 과제가 있는 역할에만 적용됩니다.
  - 가격 기준값 대조는 코인·주가 역할에만 있습니다.

## 1. 점수 구조의 문제
| 항목 | 배점 | 실제 동작 |
|---|---|---|
| 실제 인자 | 15 | 인자를 보냈으면 만점 |
| 내용 판정 | 20 | 역할마다 2~3개의 "있는지" 검사(정규식) |
| 반복 성공 | 15 | 성공한 날 1일당 3점 |
| 지연 | 10 | 1초 안이면 만점 |
| 보고서 글 | 40 | **우리가 쓴 보고서 문장을 채점합니다. 판 30개 모두 40점(건너뜀만 30)으로 같습니다** |

- 글 40점은 모든 판에 똑같이 붙습니다. 그래서 85점 기준은 사실상 "증거 60점 가운데 45점"입니다.
- 데이터 내용에 걸린 점수는 20점뿐이고, 그나마 "있는지"만 봅니다.
  - 예: 논문은 "제목 줄 또는 200자 넘음", 백과는 "80자 넘음", 환율은 "0보다 큰 숫자"
- 판정은 응답의 앞 300자만 봅니다(11-15부터 1,000자).

잘 걸러진 것도 있습니다.
- "[DEMO] 백엔드 일시 중지" 응답(40897)은 53점이었습니다.
- 오류 응답 2건은 실패로 처리됐습니다.
- 다만 이것은 검사에 일부러 넣은 결과가 아닙니다. "있는지" 검사에 우연히 걸린 것입니다.

## 3. 바꾸는 점수 (PM 결정, 100점)
| 묶음 | 항목 | 배점 | 판정 |
|---|---|---|---|
| 데이터 품질 60 | 정확성 | 25 | 공개 정답(워크플로우 정답 세트)이나 같은 시각의 공개 기준값과 대조합니다. **대조할 정답이 없는 역할은 0점이라 검증 진주(85점)가 될 수 없습니다** |
| | 최신성 | 10 | 응답 속 데이터 시각이 역할 기준 안에 있어야 합니다. 예: 뉴스 7일, 환율·가격 2일, 날씨는 오늘 이후 예보, 행사는 오늘 이후, KEV·CVE는 원천 갱신 1일 안. 시각 표기가 없으면 0점 |
| | 완전성 | 10 | 요청한 필드와 개수가 채워져 있어야 합니다. null·N/A·빈 목록 비율로 감점 |
| | 깨끗함 | 10 | 데모·자리표시(lorem, example, sample, mock)·오류 문구·결제 요구·잘린 응답·깨진 인코딩이 없어야 합니다. **하나라도 있으면 판을 실패로 처리합니다** |
| | 일관성 | 5 | 변하지 않는 사실(예: ICN 공항, CVE 내용)은 다른 날 같은 입력에 같은 답을 내야 합니다 |
| 증거 30 | 실제 인자 10, 반복 성공(서로 다른 날) 10, 지연 10 | | |
| 보고서 글 10 | 한계 명시, 입력 공개, 근거 연결 | | |

- 판정은 응답 전체로 합니다(최대 20KB). 보고서에는 발췌 1,000자와 응답 해시를 남깁니다.
- 공개 시험 보고서 문구에 데이터 품질 항목별 결과를 적습니다(정확성 대조 원천, 데이터 시각, 빈 칸 수).
- 새 점수로 오늘 판 30개를 다시 매기고, 바뀐 순위를 보고합니다.

## 4. 담당
- 검색과 RAG: `report_v2.py` 점수 교체, 다시 매기기, 역할별 최신성 기준 표
- 워크플로우: 32개 역할 가운데 정답 세트가 없는 역할의 정답 확보 순서. 공개 원천으로 확인할 수 있는 고정 과제부터 합니다.
- 운영·SRE: 검증 진주 관문에 "정확성 대조 있음, 깨끗함 통과"를 필수 조건으로 넣습니다.
- 에이전트 팀: 자체 대체 응답에 데이터 시각과 스냅샷 나이를 표기합니다(이미 지시함).

## 5. 함께 남는 문제
- 이미 공개된 옛 보고서 2만 건(대부분 연결 확인)은 데이터 품질을 다루지 않습니다. v2 판이 쌓이면 공개 화면은 v2 판을 먼저 보여 줍니다. 옛 보고서 처리는 2단계 DB 표 작업과 함께 정합니다.
- 수집기 등급 A의 시험 호출 점수는 응답 길이만 봅니다(`output_chars`). 등급은 후보를 고르는 단계라 지금은 두고, 데이터 품질은 시험 보고서에서 판정합니다.
