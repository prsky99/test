# R-07 private controlled news-to-documentation pairs

2026-10-18 · v1.17 · private execution implemented; publication and expert/holdout claims remain blocked.

## Result

The highest administrator can prepare one signed private plan, review one news source and two distinct documentation targets, authorize sharing plus one live run, then inspect the retained results. News runs once; both targets use the exact same checked first title, complete argument object and signed source checkpoint within the same durable run. Preparation makes no provider/model call and does not reserve a workflow/run; candidate validation can refresh internal registry metadata. The run uses existing managed tool invocation and records normal contract evidence, not an expert grade or automatic winner. [Contract and API](../../docs/WORKFLOW_CONTROLLED_PAIRS.md).

The new centered dialog preserves the unsaved builder, keeps private state in memory, clears stale plans/consents on selection/session/close changes, blocks duplicate submission and polls inspection without automatically repeating execution. Exact backend capability gating disables the new action when an older Python server serves the updated HTML. Existing literal comparison, three-node connected inspection, public frontend, footer consents and SDK/download implementations retain their contracts.

At most three tool invocations are dispatched under the existing standard 25-second absolute deadline. B requires A's authenticated certain successful attempt/checkpoint, rechecked before preparation and actual dispatch; failure, unknown, cancellation, tamper, insufficient time or revoked authority blocks B. No fallback or automatic replay of an uncertain external call is added. Source/A checkpoints can be reused after a pre-B crash; a dispatched B with unknown outcome is not repeated. Two actual SIGKILL subprocess tests exercise these boundaries.

Publication readiness always reports the four missing public-sharing/per-run/SDK-deployment/publication permissions. It is read-only and collects no unused publication consent. Existing public, export, delivery, schedule/event and generic-run boundaries continue to deny this private purpose. Fixed-order observations are not a randomized comparison, factual/source review, representative holdout or quality certification.

## Security correction and exploratory results

An independent isolated test reproduced a real race: execution controls were paused and resumed after proposal validation/reservation but before admission, allowing the stale reviewed plan to run. The preserved [initial failing test](control-race-initial.xml) and [log](control-race-initial.log) demonstrate it. The plan and pair bindings now sign `reviewed_at`; admission, dispatch and recovery compare it against the authoritative execution-control change time. A fresh review is required after control changes or restore quarantine. Historical inspection still validates valid old evidence at its original admission/call times. Final independent 9 and core 72 cases pass, including this race and admission/dispatch/resume revocation boundaries. This operational revocation marker is not a trusted holdout chronology record.

The initial UI suite had 68 passes and one timing assertion failure: a deliberately mocked inspection 503 returned before the accepted worker started, while the test asserted dispatch count immediately. The test now waits for accepted terminal state; no security boundary was relaxed. [Initial XML](admin-final.xml) · [final 69](admin-release-final.xml). An early core trial had 32 passes and one error-classification assertion failure: B stayed blocked but was classified as an upstream protocol error. The pair guard now uses the existing `ExecutionDenied` type. That initial core output survives only in the tool transcript, not a separate saved artifact. The preserved control-race/UI exploratory artifacts are not counted as final passes. The final preview sentence was corrected to the historically accurate “Preparation did not call agents”; [18 final Chromium cases](admin-copy-final.xml) cover that last HTML-only correction after broad start.
