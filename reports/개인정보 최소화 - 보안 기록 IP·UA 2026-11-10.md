# 개인정보 최소화: 보안·감사 기록의 IP·User-Agent (2026-11-10, 운영·SRE)

사용자 지시: 보안 목적의 기록이라도 IP는 줄여서(IPv4 /24, IPv6 /48) 남기고, 90일만 보관한다. 이 문서는 안이다. 코드 변경은 PM 결정 뒤에 하고, 기존 행을 바꾸거나 지우는 SQL은 사용자 승인 뒤 PM이 실행한다.

## 2. 바꿀 것 (새 행)
1. **공용 함수** `agent_market/privacy.py`(새 파일)
   - `coarse_ip(value)`: IPv4는 `a.b.c.0/24`, IPv6은 `/48` 네트워크 주소로 바꾼다. 형식이 틀리거나 비어 있으면 `None`이다(원문을 남기지 않음).
   - `ua_family(value)`: 알려진 봇·클라이언트 이름(예: Googlebot, curl, python-httpx, Chrome, Safari, Firefox)이나 `other`를 40자 안에서 돌려준다. 공개 트래픽 집계(`concierge/traffic.py`)의 분류를 다시 쓴다.
2. **쓰는 곳 5개에서 저장 직전에 적용한다.** 메모리 안의 실시간 차단·요청 제한은 그대로 정확한 IP를 쓴다. 저장하는 값만 줄인다.
3. **관리 화면 검색:** `ip LIKE` 검색은 축약된 값(`203.0.113.0/24`)으로 맞춰지므로 그대로 둔다. 화면 문구만 "IP(/24)"로 바꾼다.
4. **AD Coin v2:** `audit_log_insert` 인자를 같은 함수로 줄인다. AD Coin 바깥 코드가 AD Coin을 import하면 안 된다는 분리 규칙이 있다. 그래서 AD Coin 쪽이 `agent_market.privacy`를 가져다 쓰고, 이 일은 AD Coin 팀이 맡는다.
5. **90일 보존:** jobs의 보존 작업(`log_retention`)에 하루 한 번 아래 삭제를 더한다.
   - `security_events`, `admin_audit_logs`: `at < now-90일`
   - `adc2_audit_log`: `timestamp_ms < now-90일`
   - 한 번에 1,000행씩 지운다.
   - 이 SQL은 등록 SQL 목록에 등록해야 한다. 그 파일에는 다른 팀의 큰 미커밋 변경이 있어, 그 변경이 들어간 뒤에 넣는다.
6. 시험
   - 축약: IPv4·IPv6·IPv4-mapped IPv6·잘못된 값
   - 저장 경로마다 원문 IP·UA가 DB에 남지 않는지
   - 보존 삭제 범위
- 영향: 같은 /24 대역의 다른 사람과 기록이 구분되지 않는다. 보안 사건 추적은 대역 수준까지만 된다. 정확한 IP가 필요한 차단은 실시간 판단과 차단 규칙 표가 맡는다.

## 3. 기존 행 정리 SQL 초안 (데이터 변경, 사용자 승인 뒤 PM 실행)
실행 전에 `scripts.db_change_rehearsal run --sql <이 파일>`로 사본에서 통과시킨다(구조 변경은 없지만 같은 절차로 확인한다). 백업은 그날 새벽 백업이 있다.

```sql
BEGIN;
-- IPv4 → /24
UPDATE security_events SET ip = regexp_replace(ip, '^(\d+\.\d+\.\d+)\.\d+$', '\1.0/24')
 WHERE ip ~ '^\d+\.\d+\.\d+\.\d+$';
UPDATE admin_audit_logs SET ip = regexp_replace(ip, '^(\d+\.\d+\.\d+)\.\d+$', '\1.0/24')
 WHERE ip ~ '^\d+\.\d+\.\d+\.\d+$';
-- IPv6 → /48 (형식이 맞는 것만; 나머지 비정상 값은 NULL)
UPDATE security_events SET ip = network(set_masklen(ip::inet, 48))::text
 WHERE ip ~ ':' AND ip ~ '^[0-9A-Fa-f:.]+$';
UPDATE security_events SET ip = NULL
 WHERE ip IS NOT NULL AND ip !~ '/(24|48)$';
UPDATE admin_audit_logs SET ip = NULL
 WHERE ip IS NOT NULL AND ip <> '' AND ip !~ '/(24|48)$';
-- User-Agent → 계열 이름(코드의 ua_family와 같은 규칙을 SQL로 줄인 것)
UPDATE security_events SET user_agent = CASE
   WHEN user_agent ~* 'googlebot' THEN 'Googlebot'
   WHEN user_agent ~* 'bingbot' THEN 'bingbot'
   WHEN user_agent ~* '(gpt|claude|perplexity|anthropic)' THEN 'ai-bot'
   WHEN user_agent ~* '^curl/' THEN 'curl'
   WHEN user_agent ~* 'python' THEN 'python'
   WHEN user_agent ~* 'firefox/' THEN 'Firefox'
   WHEN user_agent ~* '(edg|chrome)/' THEN 'Chrome'
   WHEN user_agent ~* 'safari/' THEN 'Safari'
   WHEN user_agent IS NULL OR user_agent = '' THEN NULL
   ELSE 'other' END;
-- 90일 지난 행 (11-10 기준 0행)
DELETE FROM security_events WHERE at < extract(epoch FROM now()) - 90*86400;
DELETE FROM admin_audit_logs WHERE at < extract(epoch FROM now()) - 90*86400;
COMMIT;
```
- 11-10 기준 영향: security_events 3,130행, admin_audit_logs 76행의 IP가 바뀐다. 삭제 대상은 0행이다. adc2_audit_log는 0행이라 대상이 없다.
- 되돌리기: 원문 값을 지우는 변경이라 되돌릴 수 없다. 필요하면 그날 백업에서만 볼 수 있고, 백업은 7일 뒤 순환으로 사라진다.
