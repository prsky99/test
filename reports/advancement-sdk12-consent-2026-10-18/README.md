## Security and browser corrections

An independent isolated test reproduced a real registration flaw: a legitimate nested registry metadata transaction could commit an active app before grant issuance failed, leaving an ungranted app eligible for the legacy route. [Initial failing XML](atomic-initial.xml) · [log](atomic-initial.log). Registration now stages inactive, stores the signed grant, verifies its bound row and activates last. A nested commit can leave only an unusable inactive orphan. No global transaction behavior was changed; legacy SDK 1.2 downgrade checks retain revoked/expired grant tombstones.

Actual Chromium export also found that a raw Store workflow in the signed proposal included integral floats such as 0.0; JavaScript serialized them as 0 and the strict HMAC failed. Proposals now bind canonical definition hashes and reconstruct the graph server-side. Integral timestamps are normalized before signing, not permissively normalized during verification. [Original browser failure](browser-final.xml) · [explicit 409 diagnosis](download-diagnostic.xml). Final real ZIP-download/self-hosted-app browser tests pass.

Polling/cancellation checks are separated from fresh invocation readiness. Real invalid/unknown fixture runs remain readable with their existing capabilities after their own failed evidence update. New invocations still require full eligibility/proof/current controls. A simulated HTTP 400 after real fixture admission is treated as uncertain, with one call and no new start; a 4xx response after submission is not proof that nothing was admitted. Provider output is rendered through known contract items with text nodes, no trigger/structuredContent/content wrapper or implementation diagnostic display.
