# Explore 검색 브라우저 테스트 (agentconcierge.biz/#explore)

- **일시:** 2026-10-26
- **방법:** 실제 Chromium 브라우저(Playwright)로 사용자처럼 입력·클릭했습니다. 소스 코드는 보지 않았습니다.
- **환경:** 데스크톱 1366×900, 모바일 390×844
- **범위:** 검색어 48개(일반·다국어·오타·특수문자·주입 문자열·이모지·초장문), 필터·칩·더 보기·상세·연속 검색·새로고침·뒤로 가기·모바일 등 상호작용 20여 가지

## 개선 필요 (우선순위 순)

### 높음
1. **빠른 검색 칩이 검색을 실행하지 않습니다.**
   - 대상: Common tasks와 More tasks의 칩 20개(News, Research, Weather, Translation 등).
   - 증상: 누르면 검색창 내용만 바뀌고 API 요청은 0건, 결과는 이전 그대로입니다. 두 번 반복해 확인했습니다.
   - 개선: 칩을 누르면 바로 검색하도록 합니다.
2. **검색 상태가 주소에 남지 않습니다.**
   - 증상: 검색해도 주소는 `#explore` 그대로입니다. 그래서 새로고침하면 검색이 사라지고, 검색 결과를 공유하거나 북마크할 수 없고, 뒤로 가기를 누르면 사이트를 벗어납니다.
   - 개선: 검색어와 필터를 주소에 넣습니다(예: `#explore?q=weather&kind=a2a`).
3. **관련성이 떨어지는 상위 결과**
   - `translate` 상위 5개: Star Guard(결제), Sats4AI(미디어), Sirius Cartographer, Lunar Curator 등. 번역 에이전트가 아닌 것이 위에 옵니다. `번역`도 같은 현상입니다.
   - `8004`: ERC-8004 관련이 아니라 임의의 에이전트(KIMI 등)가 나옵니다.
   - 개선: 이름·설명에 맞는 결과를 스킬 본문에만 맞는 결과보다 앞에 둡니다.
4. **오타나 다른 언어로 검색하면 결과가 0건입니다.**
   - `wether`, `translte`, `gihtub`, `clima`(스페인어)가 모두 0건이고, "Try a broader task" 외에 대안을 제시하지 않습니다.
   - 개선: 비슷한 철자 제안("weather를 찾으셨나요?")과 흔한 동의어·번역어를 붙입니다.
5. **긴 검색어에 "Search unavailable"이 뜹니다.**
   - 증상: 640자(`weather`를 80번 반복)를 넣으면 API가 422를 돌려주고, 화면은 서비스 장애처럼 "Search unavailable"을 보여 줍니다. 300자는 0건으로 처리됩니다.
   - 개선: 입력창에 최대 길이를 두고, 넘으면 "검색어가 너무 깁니다"라고 안내합니다. 반복된 단어는 하나로 줄입니다.

### 중간
6. **응답 속도가 들쭉날쭉합니다.**
   - 검색 48건 기준 중앙값 1.5초, 상위 10% 4.5초, 최대 8.9초(`"web search"`). 16건(33%)이 3초를 넘었습니다.
   - 흔한 검색어(`weather forecast seoul` 6.3초, `Weather API` 5.0초)가 느립니다.
7. **의미 없는 검색어에도 임의 결과 45개가 나옵니다.**
   - 대상: `*`, `?`, `-`, `\`, `🌦️`, `the and of`, `a`.
   - 개선: 무시된 검색어임을 알리고 최신 목록이나 안내를 보여 줍니다.
8. **필터를 바꿔도 결과가 갱신되지 않습니다.**
   - 증상: 체크박스(Execution checked 등)를 바꿔도 재검색하지 않아, Search를 다시 눌러야 합니다.
   - 개선: 변경 즉시 재검색하거나, 결과가 갱신 전 상태라고 표시합니다.
9. **결과에 중복이 있습니다.**
   - 상위 결과에 같은 이름이 연달아 나옵니다(Sidequest Commons Guide ×2, Claix ×2, Kronos Quant Signal API ×2).
   - `data` 검색에서 더 보기를 누르면 90개 중 이름 중복이 8개였습니다.
   - 개선: 같은 서비스는 묶어서 보여 줍니다.
10. **더 보기가 처음부터 다시 받습니다.**
    - 증상: 두 번째 페이지 요청이 `limit=90`이라 앞의 45개를 다시 받습니다. 누를수록 느려집니다.
    - 개선: offset이나 커서 방식으로 다음 묶음만 받습니다.
11. **결과 수 문구가 일관되지 않습니다.**
    - "Showing 45 of up to 165 matches"와 "Showing 45 of 214 matching agents"가 섞여 나옵니다. "up to"는 뜻이 모호합니다.
12. **카드의 카테고리 이름이 필터와 다릅니다.**
    - 카드: "Finance Crypto", "Data Utility", "Trading Derivatives", "Payments", "Ai Models"(대소문자 오류)
    - 필터 목록: "Finance, Payments & Crypto" 등 14개
    - 분류 오류도 있습니다: 날씨 API(Weather Ensemble, Japan Weather API)가 금융·크립토로 표시됩니다.

### 낮음
13. **데스크톱(1366px)에서 프로토콜 버튼이 겹칩니다.** "A2A + MCP"와 "A2A"가 붙어 `A2A + MCPA2A`로 보입니다. 모바일은 정상입니다.
14. **쿠키 배너가 첫 화면의 결과 카드를 가립니다.**
15. **모바일에서 검색 후 결과로 스크롤되지 않습니다.** 결과가 화면 아래에 있어서, 검색이 된 것을 알기 어렵습니다.
16. **칩 검색어에 내부 용어가 그대로 들어갑니다.** 예: "web search SERP", "news headlines article", "translate language text".
17. **422 응답이 브라우저 콘솔에 오류로 찍힙니다.**

## 문제없었던 항목
- **보안:** XSS 시도 2종(`<img onerror>`, `<svg onload>`)에서 실행된 스크립트가 없었습니다. SQL 주입 문자열과 `../../etc/passwd`도 정상 처리됐습니다.
- **연속 검색:** 검색 중에 다른 검색을 하면 마지막 검색 결과가 보였습니다. 같은 검색을 반복하면 같은 순서가 나왔습니다.
- **다국어:** `날씨`, `天气`, `погода`, `주식 시세`가 관련 결과를 냈습니다.
- **기본 동작:** 검색 버튼과 Enter 모두 동작했습니다. 초기화 버튼은 검색어·필터·체크박스를 모두 되돌렸습니다. 상세 창이 열리고 Esc로 닫혔습니다.
- **필터 조합:** 프로토콜·카테고리·증거 필터를 각각 또는 함께 걸어도 요청과 결과 수가 맞게 바뀌었습니다.
- **모바일:** 가로 넘침이 없었고 입력창 크기도 적절했습니다.

## 확인하지 못한 것
- 검색 버튼을 빠르게 두 번 누르는 경우: 두 번의 실행 결과가 달라(요청 0건 / 1건) 판단을 보류했습니다.
- 로딩 표시, 키보드 탐색, 스크린리더 등 접근성은 이번 범위에 넣지 않았습니다.
