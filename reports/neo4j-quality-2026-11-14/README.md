# 맥미니 Neo4j로 품질을 올리는 방안 (2026-11-14, PM 조사)

사용자 요청(11-14 02시대): "맥미니에 neo4j가 설치되어 있음. 이걸 활용해서 품질 향상을 할 수 있는 방안을 찾아줘. 논문과 sns검색을 통해 진행."

## 결론
- **Neo4j는 밤 배치 계산기로만 씁니다.** 결과는 PostgreSQL 스냅샷 표로 내보내고, 요청 경로는 PG 조인 한 번만 합니다.
  - 이유: 응답 목표(추천 5초·탐색 3초 차선, 2초 최종)와 지출 0입니다.
  - Community Edition은 병렬 런타임이 없고 GDS 동시성이 4라서 요청 경로에는 맞지 않습니다. 배치 계산에는 충분합니다.
- **효과가 확인된 쓰임**
  - 도구와 서버(호스트)를 함께 노드로 둔 그래프
  - 도구 사이의 의존·함께 쓰기 그래프
- **효과가 약하거나 나빴던 쓰임:** 문서를 LLM으로 요약해 만드는 GraphRAG
  - 단순한 한 번 조회에서는 일반 RAG보다 못했습니다(GraphRAG-Bench 2025-06).
  - 우리 39만 개를 gemma로 엔티티 추출하면 약 54시간이 걸립니다(추정).

- 실무 의견(dev.to, tianpan.co 2026-04): "하이브리드 검색을 먼저 하고, 실패한 유형에만 그래프를 붙이라." 엔티티 해석과 그래프 유지가 가장 어렵다고 합니다.
- 이 규모는 Python igraph나 PG만으로도 계산할 수 있습니다. Neo4j가 필수는 아니지만, 이미 설치돼 있고 GDS 알고리즘(Leiden, WCC, Node Similarity, FastRP)이 무료라 쓰기 편합니다.

| ① 어형·전치사 경계에서 빠짐 | 중간 | 오프라인 낱말 그래프로 동의어·어형 묶음 표를 만들고, 실행 시에는 사전만 조회 |

| ③ 지역 한정, ④ 인증 오기록 | 작음 | 수집기 판정을 고치는 것이 먼저. 호스트 단위 "의심" 전파만 보조로 |

## 제안 순서
1. **P1 호스트·중복 클러스터 스냅샷 (⑥, 간접적으로 ②)**
   - 오늘 승인된 그래프 상한(호스트당 1,000개)을 정교하게 잇는 일입니다.
   - 중복 도구 cluster_id와 대표, 호스트 신뢰 점수, 형제 도구 의심 표시를 PG 표로 만듭니다.
   - 온라인에서는 클러스터당 1개, 호스트당 k개만 남깁니다.
   - 측정: Chat 110세트 정답 수, 탐색 상위 10개의 고유 호스트 수, MRR, user_slo 지연
2. **P2 능력 동의어 묶음과 도메인 커뮤니티 (①②)**
   - gemma로 도구별 예시 질의를 오프라인에서 만듭니다(Tool2Vec식, 비용 0). 밤에 병렬 4 안에서 돌립니다.
   - 측정: ①② 하위 세트 재현율, 첫 추천 오답률, 회귀 수
3. **P3 워크플로 다음 도구 표 (⑤)**
   - 연결·실행 기록이 쌓인 뒤에 합니다. 지금은 기록이 적어 효과가 불확실합니다.

## 접속 상태 (11-14 04:1x 다시 확인)
- 사용자가 내부망 접속을 열었습니다. 운영 맥에서 두 대 모두 7474(HTTP), 7687(Bolt)이 열려 있습니다.
- 두 대 모두 Neo4j 2026.10.2 Community Edition입니다.
- .25의 응답이 bolt_routing·bolt_direct를 .24로 알립니다. 두 대가 같은 DB를 가리키는지, .25의 광고 주소 설정이 잘못된 것인지는 접속 뒤 확인합니다.
- 인증이 켜져 있습니다(인증 헤더가 없으면 Unauthorized). 접속 정보 파일이 아직 없습니다.
- 필요한 것(사용자): `gateway-data/neo4j.env`(git 제외 확인됨)에 아래 세 줄을 직접 넣어 주세요. 비밀번호는 Claude가 입력하거나 추측하지 않습니다. 가능하면 읽기·쓰기 전용 일반 사용자를 따로 만들어 주세요(관리자 계정 말고).
  - `NEO4J_URI=bolt://192.168.0.24:7687`
  - `NEO4J_USER=...`
  - `NEO4J_PASSWORD=...`
- 맥미니는 gemma4 생성 모델(병렬 4)과 메모리를 나눠 씁니다. GDS 계산은 밤에만 하고, 메모리 추정(`gds.graph.project.estimate`)을 먼저 합니다.


## 접속 뒤 확인 (11-14 02:5x, 읽기 전용)
- 인증 성공. 접속 정보는 gateway-data/neo4j.env(권한 600, git 제외)에 있습니다.
- 두 주소(.24, .25)는 같은 인스턴스로 보입니다. 버전, DB 목록, 설정이 모두 같고, 광고 주소도 둘 다 192.168.0.24입니다.
- Neo4j 2026.10.2 Community, Cypher 5·25. DB는 neo4j(기본)와 system 두 개뿐입니다.
- **데이터: 비어 있음(노드 0개, 라벨 없음)**
- **플러그인: GDS와 APOC가 없습니다.** 프로시저 이름공간은 db, dbms, fleetManagement, tx뿐입니다.
- 메모리: heap과 pagecache는 자동 크기입니다. 트랜잭션 전체 상한은 11.20GiB이고, procedures.allowlist는 `*`, unrestricted는 비어 있습니다.

### 뜻
- 계획의 P1·P2(연결 요소, 커뮤니티, 노드 유사도)는 GDS가 있어야 Neo4j 안에서 계산할 수 있습니다. GDS 없이 Cypher만으로는 39만 노드 규모의 커뮤니티 계산이 현실적이지 않습니다.
- 할 수 있는 길은 둘입니다.
  1. 맥미니에 GDS Community와 APOC Core 플러그인을 설치합니다(무료). 사용자가 맥미니에서 합니다.
     - 플러그인 jar를 plugins 폴더에 넣습니다.
     - `dbms.security.procedures.unrestricted=gds.*,apoc.*`를 설정합니다.
     - 재시작합니다.
  2. Neo4j 없이 운영 맥 밖의 계산(Python igraph 등)으로 같은 결과를 만듭니다. 그래프 저장과 조회만 Neo4j에 둡니다.
- PM 권고는 1입니다. 사용자가 Neo4j 활용을 요청했고, GDS 알고리즘은 무료이며, 맥미니에서 계산하면 운영 맥의 부하가 0입니다.
