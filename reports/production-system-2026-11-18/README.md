# 생산 체계 최적화 조사 (2026-11-18 PM)

사용자 지시: 최신 논문·SNS를 조사해 지금 생산 체계를 최적화한다. 품질은 떨어지면 안 되고, 오히려 좋아져야 한다. 결과로 정한 규칙은 `docs/PRODUCTION_SYSTEM.md`에 있다.

조사는 하위 에이전트 세 갈래로 했다. 2026년 arXiv 일부는 심사 전 프리프린트이고, 일부 수치는 원문으로 확인하지 못했다(아래에 [미확인]으로 표시).

## 2. 평가·관문을 빠르게 하되 품질은 지키기

## 4. 결론 (`docs/PRODUCTION_SYSTEM.md`로 옮긴 것)

1. 완료 = 개발 브랜치 sha. 승인한 그 턴에 통합한다.
2. PM 승인은 예외만 한다. 결정은 `logs/ops/decisions.jsonl`에 한 번만 남긴다.
3. 팀마다 진행 중인 일은 2개까지다. 순서가 얽힌 일은 한 팀이 소유한다.
4. 목걸이 라인: 초안 → 후보 → 미리보기(품질 조건) → 정식. 정답 세트를 미리 쌓고, 탈락이 확정되면 멈추고, 약한 멤버는 먼저 바꾼다.
5. 배포 전에 묶음의 조상 관계를 검사한다. 배포는 하루 두 차로 낸다.
6. 매일 단계별 수, 리드타임, 다시 묻기 횟수를 잰다.
