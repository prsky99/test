# AI AD Coin 최종 정책 기반 개발 설계

2026-11-07 · 상태: 설계 산출물, 제품 구현 전

## 산출물과 개발 진입점

- [서비스·권한·업무·운영 설계](../../docs/AD_COIN_PLATFORM_ARCHITECTURE.md): 설계 결정 7개, 모듈 9개, P1·중계·브랜드 대화·측정·시장 통계·보안 경계.
- [데이터·API 계약](../../docs/AD_COIN_PLATFORM_DATA_API.md): 논리 스키마·FK/유일성·정수·tenant·예산·원장·상태·첫 개발 API와 후속 계약.
- [개발 작업 12개·출시 단위](../../docs/AD_COIN_PLATFORM_IMPLEMENTATION_PLAN.md): 선행 작업·예정 파일·인수 기준·격리 P1부터 실가치·열린 시장까지.
- [첫 P1 OpenAPI](../../docs/ad_coin_platform_p1.openapi.json): 플랫폼 렌더러의 모형 시험 API. 전체 플랫폼·온체인·CRM API의 완성본이 아니다.
- [기계 판독 설계](../../docs/ad_coin_platform_v6_1_spec.json): 38개 정책의 모듈·작업·검수 연결, 상태 전이, 출시/실가치 관문, 개발 기본값.

첫 개발은 WP-01의 사람/에이전트 권한 분리와 WP-02의 v2 모형 원장·DB·작업 기반이다. 이어서 광고주 캠페인·심사·승인·예산과 플랫폼 렌더러 P1을 연결한다. 기존 시험 자산은 상환 가능한 토큰으로 자동 승계하지 않는다.

## 검증 방법

프로젝트의 기존 `.venv-tests/bin/python`에서 `build_contracts.py`로 기계 계약을 생성하고 `validate_design.py`로 검사한다. 두 도구는 운영 서비스나 제품 모듈을 호출하지 않는다. 검증 결과와 파일 해시는 [validation.json](validation.json)에 보관한다.

검증은 JSON Schema 문법·선택한 양/음성 payload, 내부 `$ref`, 경로 변수·멱등·사람/검토자 인증 표기, 38개 정책 추적·12개 작업 의존 관계, P1 상태 경로·정수 배분·hold 보존 예시, 로컬 링크·생성 재현성을 확인한다. 설치된 FastAPI의 OpenAPI 모델은 `mutualTLS` 타입을 지원하지 않아 해당 enum만 제외한 부분 구조를 검사하고 원래 mTLS 형식·검토자 AND 요구는 별도로 검사한다. 실제 계약에서는 인증 요구를 제거하지 않았다. 완전한 OpenAPI 표준 인증이라고 표현하지 않는다.

기존 33개 제품/시험/스크립트 소스와 v5 자산 명세의 해시를 대조하며 과거 v4·v5·v6·v6.1 정책 검증 기록은 덮어쓰지 않는다. 데이터 설계는 논리 스키마이며 실행용 migration·SQL 허용 목록·RLS·PG 경쟁 검증은 후속 구현에서 만든다.

## 한계와 변경 범위

제품 보안·DB 동시성·브라우저·실제 시청·스마트 계약·준비금·법률·광고 효과·성능은 검증하지 않았다. 제품 인수 기준 통과는 이번 작업에서 0건이다. 모형의 회계·상태 예시가 실제 경제 명령의 정확성이나 무취약성을 증명하지 않는다.

설계 문서·기계 계약·검증 도구·문서 진입점만 변경했다. 제품 코드·공개 화면·운영 서버·배포·DB·플래그·실자금·키·체인 거래는 변경하지 않았다. TTL·집계 최소 인원·단계별 한도는 개발 기본안이며 실제 활성화 때 검증·버전 고정한다.
