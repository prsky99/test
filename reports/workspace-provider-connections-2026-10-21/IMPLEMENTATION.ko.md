# 워크스페이스 제공자 연결 개발 결과

작성일: 2026-10-21

## 구현 범위와 현재 상태

수집된 에이전트를 이름·주소·카탈로그 번호로 찾아 인증 방식에 맞게 연결하는 공통 화면과 서버 기능을 구현했다. 워크스페이스의 **Provider connections** 메뉴, 워크플로우 상단 버튼, 각 단계의 연결 옵션 버튼으로 접근한다. 워크플로우에서 연결 창을 열 때 페이지를 이동하지 않아 작성 중인 입력을 유지한다.

현재 작업은 제공자 인증정보 연결·보관·확인·교체·삭제와 선택 화면 개선이다. 저장된 자격증명을 사용한 유료 워크플로우 실행이나 결제·정산을 활성화한 작업이 아니다. 이 구분은 연결 화면에도 명시했다. 기존 실행기는 현재 실행 가능 조건을 계속 검사한다. 실제 고객의 키를 사용하거나 제공자 계정·OAuth 앱을 생성하지 않았다.

## 실제 카탈로그 분석

운영 PostgreSQL의 읽기 전용·반복 읽기 스냅샷에서 전체 **131,011건**을 분류했다. 개인 정보, 키, 에이전트 주소 목록은 보고서로 내보내지 않았다. 외부 제공자 호출과 운영 DB 변경은 없었다.

활성 카탈로그 항목의 연결 방식 분류:

- API 키·Bearer 헤더 입력 대상: **31,956건**.
- OAuth 안내 대상: **7,980건**.
- 인증 불필요로 선언·관측된 대상: **24,156건**.
- x402 결제 프로토콜 대상: **50,621건**.
- 추가 문서·설정 또는 안전한 연결 주소가 필요한 대상: **12,026건**.

위 분류는 수집 메타데이터와 주소 형식에 따른 분류다. 과금 여부에 대한 확인이나 각 제공자의 실계정 연결 성공 건수가 아니다. 실제 OAuth 가능 여부는 사용자가 선택한 제공자의 현재 메타데이터를 다시 확인한다. 인증이 없다고 무료라고 표시하지 않는다. 전체/비활성 항목과 원본 인증 방식별 집계는 `catalog-inventory.json`에 있다.

## 인증 방식별 처리

### API 키 및 Bearer 토큰

제공자가 선언한 지원 인증 헤더를 사용한다. 키 발급 문서가 수집되어 있으면 별도 창 링크로 안내한다. 제공자 이름·프로토콜·키 전달 대상 HTTPS 주소를 먼저 표시하고, 마스킹 입력·표시 전환·붙여넣기·명시적 저장 동의를 제공한다.

키는 서버에서 워크스페이스별로 암호화한다. 저장 직후에는 **Saved · authentication not verified**로 표시한다. 실제 검증 없이 성공 배지를 붙이지 않는다. 키 원문은 조회 응답·브라우저 저장소·워크플로우 정의·다운로드 앱에 제공하지 않는다.

사용자가 별도로 승인한 MCP 연결 확인은 도구 실행 대신 initialize 요청을 사용한다. 무인증 요청이 401/403이고 인증 요청에서 유효한 MCP 응답이 확인된 경우만 **Authentication verified**로 표시한다. 무인증 메타데이터가 공개되어 있거나 지원되지 않는 프로토콜이면 검증 불가를 안내한다. 제공자 요청 제한·과금 가능성을 승인 전에 설명한다.

키 교체·삭제 및 현재 상태 조회를 제공한다. 삭제는 우리 시스템의 자격증명을 삭제하는 것이며, 제공자 구독 취소나 제공자 측 키 폐기는 별도로 해야 한다는 안내를 표시한다.

### OAuth

선택한 리소스의 최신 보호 리소스 메타데이터와 인가 서버 메타데이터를 확인한다. HTTPS 공개 주소, 정확한 resource·issuer, authorization-code 및 PKCE S256 지원을 검사한다. 요청 권한은 선택형으로 표시하고 기본 체크하지 않는다.

제공자가 지원하면 Client ID Metadata Document를 사용하고, 그렇지 않으면 public-client 동적 등록(DCR)을 사용한다. 둘 다 제공하지 않으면 정확한 callback URL과 public client ID 입력을 안내한다. client secret이나 제공자 계정 비밀번호를 받는 방식은 지원하지 않는다.

승인은 제공자 창에서 수행한다. 일회성 state, 현재 고객 세션, 워크스페이스·에이전트·인가 서버, PKCE 및 resource에 결합한다. 인가 코드 재사용·issuer 불일치·scope 확대·만료·취소를 검사한다. 토큰은 서버에만 저장한다. 만료 시 재연결을 안내하며 refresh token을 보관하거나 자동 갱신하지 않는다.

리디렉션 callback의 일회성 query는 앱 응답 시점 접근 로그에서 제거한다. 앞단 프록시·제공자·사용자 브라우저 기록까지 검사하거나 변경한 것은 아니다. 팝업 차단과 취소·실패 시 기존 작성 내용을 유지하고 다시 확인할 수 있다.

### 인증 불필요

불필요한 키 입력란을 표시하지 않는다. 제공자 이용 조건과 실행 가능 여부는 별도로 확인하도록 안내한다.

### x402

API 키와 지갑 결제 승인을 혼동하지 않도록 별도 안내한다. 지갑 개인키·시드 문구를 수집하지 않는다. 이번 작업은 결제 승인·정산 기능을 활성화하지 않는다.

### Basic, URL 키, 미확인·비표준·추가 설정 필요

계정 비밀번호, URL query로 전달해야 하는 키, 위험하거나 불명확한 헤더는 입력받지 않는다. 알려지지 않은 방식을 추측해 키를 보내지 않는다. 이유와 제공자 문서·설정 확인 안내를 표시한다. 이들 방식에 대한 자동 연결을 완료했다고 표시하지 않는다.

## 워크플로우 선택 화면 개선

수동 후보에 실제 이름과 현재 상태를 표시하고, 선택 단계에서 현재 실행 검증을 수행한다. 현재 조건에서 실행할 수 없는 후보를 선택하면 이유와 **Provider connection options**를 보여주고 검토 버튼을 비활성화한다. 과거 승인 기록만으로 유료·인증 필요 후보가 곧바로 실행 가능해 보이던 문제를 줄였다.

API 키를 저장하거나 OAuth 승인을 받는 것만으로 후보를 실행 가능으로 바꾸지 않는다. 연결된 자격증명을 실행 경로에 사용하려면 별도로 제공자 인증 전달, 리소스·도구 권한, 지출 승인·사용량 한도와 실행 증빙을 결합해야 한다.

## 보안 및 저장 구조

- 현재 고객 세션·CSRF·동일 출처 검증. 소유자만 자격증명 변경, 멤버는 상태 조회.
- 기존 지속 키에서 목적별 키를 유도하고 AES-GCM으로 워크스페이스 문서를 암호화. 다른 워크스페이스로 암호문을 이동하면 복호화 실패.
- 기존 영속 meta 테이블의 별도 비공개 이름공간 사용. 새로운 테이블이나 운영 데이터 마이그레이션 없음. 동시 변경은 기존 Store 트랜잭션과 PostgreSQL writer lock으로 직렬화.
- 현재 연결별 revision과 삭제 이후 revision을 유지. 늦게 도착한 확인·OAuth 응답이 삭제 또는 새 연결을 덮어쓰지 못하게 차단.
- 에이전트 주소·인증 정보가 바뀌면 재연결 요구. 다른 제공자로 키를 자동 재사용하지 않음.
- TLS 검증, 공개 IP 전용 제한 전송, 리디렉션 금지, 요청 시간·응답 크기·본문 크기 제한.
- 연결 검색 UI는 POST를 사용해 사용자가 붙여넣은 검색 내용을 주소창·접근 query에 남기지 않음.
- 실제 요청에서 원문 키를 응답하지 않고 예외도 고정된 사용자 오류 코드로 변환.
- 인증 실패 재확인 후 이전 성공 상태 유지 방지.

## 검증 결과와 증적

- 신규 연결 최종 브라우저/API 시나리오: **39개 통과** (`provider-final.xml`, `provider-final.log`). 그 뒤 MCP 응답 ID 타입·protocolVersion·error 동시 필드를 더 엄격히 검사하는 보완에 대해 백엔드 테스트를 다시 실행했다 (`backend-final.log`).
- 로그인·기존 워크플로우·신규 연결·DB 경계 관련 회귀: **124개 통과**, 임시 PG 중복 전체 실행 테스트 1개 제외 (`final-regression.xml`).
- 세션 만료·개인정보·외부 요청·부트스트랩·콘텐츠 관련 추가 회귀: **38개 통과** (`security-regression.xml`).
- 임시 Unix 소켓 PostgreSQL 실제 검증: **95개 항목 통과**, 임시 클러스터 제거 (`postgres-final.json`). 신규 암호화 저장·검색·삭제 검증 포함.
- 공개 콘텐츠 검사: **243개 파일, 위반 0개**. front.py의 기존 HTML과 extracted_html.txt 동기화 검사 포함.
- Bandit 정적 점검: 3건 검토. OAuth 공개 프로토콜 값 `none`을 비밀번호로 판단한 2건과 기존 인라인 HTML/JS를 SQL로 판단한 1건으로, 실제 비밀값 하드코딩·SQL 실행 경로가 아니다. 자동 도구의 미검출만으로 보안 완전성을 주장하지 않는다.

검증 건수는 실행 묶음별이며 일부 중복된다. 실제 고객 계정이나 유료 제공자의 실키를 사용한 종단 검증은 수행하지 않았다.

## 반영

새 라우터·소스·SQL 목록을 실행 중인 프로세스에 반영하려면 사용자의 `./agentcon restart`가 필요하다. 운영 서버 재시작·중지·교체는 수행하지 않았다. 재시작 후 실제 서비스의 Provider connections 메뉴와 연결 창을 확인해야 한다. 실제 키 입력·OAuth 승인 및 유료 호출은 고객이 선택한 제공자와 권한으로 각각 확인해야 한다.
