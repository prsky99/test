# 목걸이 홍보·주문 제작·상시 점검 실행 계획 (2026-11-15, PM)

사용자 지시(11-15 14:5x)를 팀 과제로 옮긴 문서다. 지시 원문 요지는 CLAUDE.md 수익 규칙 블록에 있다.

## 1. 지시 네 가지
1. 목걸이가 만들어지고 수가 늘면 방문자와 자율형 에이전트에게 홍보한다.
2. 내세울 것은 토큰 절약, 빠른 답, 정확한 답이다.
   - 에이전트가 여러 에이전트를 찾아 각각 답을 모으고 정리해 최종 답을 만들면 토큰과 시간이 많이 든다.
   - 한정된 시간 안에 처리하다 틀린 정보로 답하는 일이 생긴다.
   - 목걸이는 이 과정을 한 번의 호출로 대신한다.
3. 필요한 목걸이를 주문받는다. 연락처를 등록하면 만든 뒤 확인 결과(토큰 절약·속도·정확도)와 사용 방법을 알린다.
4. 모든 목걸이에 폴백 에이전트와 자체 대체 에이전트를 붙이고, 문제없이 실행되는지 정기·상시 점검한다.

## 2. PM이 정한 실행 기준
- 홍보에 쓰는 숫자는 목걸이마다 실제로 잰 값만 쓴다. 재지 않은 숫자와 "최대 N배" 같은 표현은 쓰지 않는다.
- 비교 대상은 "목걸이 없이 같은 과제를 하는 에이전트"다(멤버 도구를 직접 찾아 부르고 스스로 정리).
- 우리 화면과 에이전트용 안내에서의 홍보는 첫 목걸이가 공개될 때부터 한다. 외부 커뮤니티 게시는 목걸이 100개 뒤라는 결정을 그대로 지킨다.
- 연락처는 받지 않는다(위 3.3).
- 주문 제작은 지금 무료다(목걸이 실행은 무료 이벤트). 과금은 사용자가 늘어난 뒤 사용자 결정으로 한다.
- 만들 수 없는 주문(진주 부족, 약관 금지, 쓰기·결제가 필요한 일)은 이유와 함께 그렇게 답한다.

## 3. 과제

### 3.1 값 증명: 토큰·시간·정확도 측정 (워크플로우, 검색과 RAG)
- 목걸이마다 같은 보류 사례로 두 길을 잰다.
  - 목걸이 한 번 호출: 호출 수 1, 응답 크기(토큰 추정), 걸린 시간, 정답률.
  - 목걸이 없는 길: 멤버 도구를 직접 부르는 경우의 호출 수, 주고받는 크기(도구 목록·스키마·각 답·정리), 걸린 시간, 정답률.
- 관문의 Δ(R23)와 같은 사례·같은 날 짝을 쓴다. 관문을 통과한 목걸이만 숫자를 공개한다.
- 결과는 판정 스냅샷에 싣고, 날짜와 사례 수를 함께 적는다. 값이 나빠지면 나빠진 그대로 보인다.

### 3.2 홍보 문구와 자리 (성장·유통, 영어)
- 방문자용: 홈·Workflows·목걸이 화면에 "왜 목걸이인가" 한 단락과 그 목걸이의 잰 값.
- 에이전트용: skill.md, llms.txt, agent-entry.json, MCP 도구 설명, find_agents·Chat 답 끝 한 줄. 질문이 live 목걸이에 맞을 때만 그 목걸이를 권한다.
- 문구는 명령형·주입형으로 쓰지 않는다(우리 광고 심사 기준과 같음).

### 3.3 주문 제작 (성장·유통, 워크플로우, 운영·SRE)
- 받는 것: 하려는 일(자유 글), 입력 예시, 원하는 출력. **연락처는 받지 않는다(11-15 사용자 결정 "연락처 없이 진행", 11-10 원칙 유지).** 접수하면 무작위 주문 번호와 상태 주소를 주고, 완성되면 그 주소에 결과와 사용 방법이 뜬다.
- 자리: 사람용 화면 한 곳과 에이전트용 API·MCP 도구 한 곳.
- 저장: 운영 DB 표가 필요하면 리허설 절차를 따른다. 개인정보 고지와 약관에 항목을 더한다(PM).
- 흐름: 접수 → 분류(이미 있는 목걸이로 되는가, 진주가 있는가, 만들 수 없는가) → 제작 → 관문 → 알림.
- 알림에 담는 것: 목걸이 주소, 사용 방법(사람·MCP·API), 잰 값(토큰·시간·정확도), 범위와 한계, 대체 단계.
- 알림은 주문 상태 주소로 한다(사람은 다시 열고, 에이전트는 다시 읽는다). 메일·콜백 발송과 새 표는 만들지 않는다. 저장은 기존 customer_inquiries의 분류 necklace_order(ip·user_agent 없음).
- 악용 방지: 속도 제한, 주입·명령형 문구 차단, 같은 연락처의 반복 주문 묶기.

### 3.4 대체와 점검 (워크플로우, 에이전트 팀, 운영·SRE)
- 모든 목걸이의 필수 자리마다 외부 대체 1개 이상과 자체 대체를 목표로 한다. 관문 check와 공개 화면이 지금 어디까지 대체되는지 보여 준다(da2f47b4, 233fa0bb).
- 상시: necklace-watch가 멤버 헬스·지문·약관 변화를 본다.
- 정기: live 목걸이는 하루 표본 재시험(f2b8db10). 여기에 대체 훈련을 더한다. 선두 멤버를 일부러 빼고 대체만으로 완주하는지 주 1회 확인한다.
- 자체 대체가 없는 필수 자리 목록은 현황판 준비 상태 표에서 관리하고, 에이전트 팀이 순서대로 만든다.
- 점검이 돌지 않은 날은 감시가 경보를 낸다(점검 자체의 누락을 잡음).
