## 1. 지문 정의 (v1)
- **도구 지문**: `sha256(canonical({name, description, inputSchema}))`
  - PM 지시 범위(이름·설명·입력 스키마)만 쓴다.
  - outputSchema·annotations는 지문에서 빼고 따로 본다(위험 신호 2번).
  - canonical은 `capability_registry.canonical`이고, 자르지 않는다.
- **서버 지문**: `sha256(canonical(sorted([name, 도구 지문])))`. 도구 순서는 영향을 주지 않는다.
- **정규형 지문**(보조, 오경보 판별용): 설명에서 숫자·날짜·UUID·16진 문자열을 자리표시자로 바꾼 뒤 같은 방식으로 계산한다.
  - 원래 지문이 바뀌고 정규형 지문이 같으면 **동적 설명**으로 분류한다. 경보는 내지 않고, 기록만 하고, "잦은 변경" 횟수에 넣는다.

## 2. 변경 분류와 대응

| 분류 | 판정 | 진주·목걸이 대응 |
|---|---|---|
| 동적 설명 | 정규형 지문 같음 | 경보 없음, 기록만. 7일 10회 넘으면 "불안정 정의"로 진주 자격 보류 |
| 일반 변경 | 도구 추가·삭제, 설명 변경, inputSchema 변경 | 목걸이 사슬에서 그 멤버를 즉시 뺌(워크플로우 설계 a-3). 진주 "변경 없음" 기간 다시 시작. 워크플로우 팀이 검토·재자격 시험 |
| **위험 신호**(rug pull 의심) | ① 바뀐 설명·스키마에 지시문 주입 패턴(`security.check_malicious_text`·`check_malicious_dict`) ② annotations가 readOnlyHint true→false 또는 destructiveHint false→true ③ 새 도구가 relay 안전 기준에 안 맞음(`usage.is_relay_safe_tool` false: 쓰기·결제·자격 증명) ④ required 파라미터에 자격 증명처럼 생긴 이름이 새로 생김 | 목걸이 **즉시 보류**(관문 문서 7절), 그 자원은 진주 표에서 격리, 현황판 경보 |

## 3. 언제 재나 (남의 서버 부하는 늘리지 않음)
1. **도구 조사(지금처럼 하루 1번 안팎)**: 이미 tools/list를 받으므로 추가 호출 없이 지문을 계산한다. 대상은 모든 MCP다.
2. **진주·목걸이 멤버만 헬스 점검 때 tools/list 한 번**
   - 대상 목록: `gateway-data/necklaces/members.json`(워크플로우 팀) + 진주 표(검색과 RAG). 지금 목걸이 5개 기준 약 60개 자원이다.
   - 주기: 6시간마다 1번(헬스 주기 15분마다 하지 않음). 호스트당 2초 간격을 두고, 429면 쉰다(`provider_rest`).
3. **매일 재시험·출시 관문 실행 직전**: 멤버마다 tools/list 한 번. 관문 판정은 이 값과 자격 시험 때 값을 비교한다.

## 4. 저장 (1단계: DB 구조 변경 없음)

| 대상 | 저장 | 이유 |
|---|---|---|
| 모든 MCP(조사 때) | 지금의 `usage_full_hash`·`connection_versions` 그대로 + **변경이 생길 때만** 한 줄씩 `gateway-data/fingerprints/changes-<YYYYMMDD>.jsonl`에 추가 | 지금 구조로 "언제 바뀌었나"는 이미 있다. 도구 단위 내용과 분류만 파일로 더한다(하루 약 2천 줄 예상, git 제외, 90일 보존) |
| 진주·멤버 | `gateway-data/fingerprints/pearls.json`: 자원별 기준 지문(자격 시험 때), 마지막 지문, 마지막 측정 시각, "변경 없음" 시작 시각 + 도구별 지문 | 판정과 관문이 바로 읽는다. 원자적 교체 |

- 변경 기록 한 줄: `{at, resource_id, source: survey|health|retest|gate, server_fp, prev_server_fp, normalized_same, added[], removed[], changed[{name, fields[]}], risk[], classification}`
- 설명 원문은 남기지 않는다. 바뀐 필드 이름만 남겨 남의 문구를 대량 저장하지 않는다. 위험 신호일 때만 해당 도구 정의를 `gateway-data/fingerprints/evidence/<rid>-<at>.json`에 보관한다(30일).
- 쓰는 곳: jobs(수집기 스레드, 도구 조사·헬스)가 쓴다. 매일 재시험·관문 실행 결과는 운영·SRE 스크립트가 같은 형식으로 쓴다. frontend는 읽지 않는다.
- **2단계(필요할 때만)**: 자원 전체의 도구별 이력을 질의해야 하면(예: 공개 "정의 변경 이력" 페이지), 자기 스키마(`fingerprint`)에 표를 만드는 안을 따로 올린다. 사본 리허설 → 복구 SQL → 사용자 승인 → 실행 직전 check 0. public에는 만들지 않는다(트리거 불변식).

## 5. 진주 판정과 관문에 넘기는 값

  - `pearls.json`의 `unchanged_since`가 **7일 이상**이다.
  - 위험 신호 이력이 30일 안에 없다.
  - 7일 동적 설명 변경이 10회 이하다.
- 목걸이 관문: 멤버마다 기준 지문 = 지금 지문이어야 한다. 다르면 그 멤버를 뺀 사슬로 다시 검수한다. 위험 신호면 탈락·보류.
- 매일 재시험 결과(워크플로우 설계 b-5)의 `fingerprint`, `fingerprint_changed`를 이 값으로 채운다.
