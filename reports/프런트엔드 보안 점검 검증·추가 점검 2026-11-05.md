# 프런트엔드 보안 점검 검증·추가 점검 (2026-11-05)

다른 세션이 커밋 `134aca61` 사본으로 한 프런트엔드 보안 점검 보고서를 검증하고, 그 뒤 운영에 들어간 새 코드를 추가로 점검했다. 1번 권고(큰 ID 500)를 고쳤다.

## 1. 원 보고서 검증

가장 큰 빈틈은 점검 대상이 운영 코드가 아니었다는 점이다.
- `134aca61` 이후 운영 판에는 39개 파일이 새로 생기거나 바뀌었다.
- 여기에는 다른 세션의 미커밋 변경도 들어 있다.
- 이 차이를 2절에서 점검했다.

### 남은 관찰 (낮음)
- **번역 대기:** `llm.py`의 다른 언어 번역 경로는 바쁜 슬롯을 최대 1초 기다리고 3초까지 쓴다(11-04 변경). 한국어 요청을 대량으로 보내면 LLM 슬롯과 요청 스레드를 더 오래 붙잡는다. IP당 Chat 61번째 요청부터 429가 나서 한 IP로는 제한된다. 운영 부하 시험은 하지 않았다.
- **점검 범위 밖:** 로그인이 필요한 작업공간·관리자 화면, 의존성 CVE(`pip-audit` 미설치)는 원 보고서처럼 이번에도 보지 않았다.

## 3. 수정 (`agent_market/concierge/front.py`)
- `get_safe_agent_detail`: 데모 프리셋(-1~-4)이 아니면서 1~9223372036854775807 밖인 id는 DB 조회 없이 404로 응답한다.
- `body_json`: 객체가 아닌 JSON 본문 처리를 바꿨다. 문자열은 그대로 질문으로 받는다. `null`, 숫자, 불린, 배열은 빈 요청으로 본다(이전에는 `str(data)` 때문에 "None"을 검색했다).
- 시험: `tests/test_agent_detail_id_range.py` 12건.
- 릴리스: `id-range-frontend-20261105-r1`(`neighbor-focus-frontend-20261105-r1` 위, 바뀐 파일 `front.py` 하나).
- 게이트: 기본 56건과 새 시험 12건이 통과했다. Chat 파일 변경이 없어 Chat 표본 평가는 건너뛰었다.
- 배포: 활성 a. 운영에서 다시 확인한 결과는 아래와 같다.
  - `/api/agents/9223372036854775808`, `/api/agents/-9223372036854775809`, `/api/agents/9223372036854775807`은 모두 404를 돌려준다.
  - 데모 `-1`은 200을 돌려준다.
  - `/chat`에 `null`을 보내면 400("Chat message or payload data is required.")을 돌려준다.
  - `"weather forecast"` 문자열 본문은 추천 3건을 돌려준다.

## 4. 다른 세션에 알릴 것
- `tests/test_fast_single_recommendation.py` 9건이 작업본에서 실패한다. 의미 순위 코드가 `vectors`를 기대하는데 시험의 모의 객체에는 `len()`이 없어 `TypeError`가 나고, 응답이 500이다. 이번 변경과는 무관하다.

## 5. 2차 정리 (원 보고서 6번·2번)
- **6번:** 운영 코드에서 `"testclient"` 분기 2곳을 없앴다.
  - `deployment_security.forwarded_client`는 이제 신뢰 프록시만 IP 헤더를 따른다.
  - `security.py` 자동 차단 면제에서도 `"testclient"`를 뺐다.
  - 시험 클라이언트 기본 주소는 `tests/conftest.py`에서 127.0.0.1로 바꿨다. 운영 기본 `FORWARDED_ALLOW_IPS`(127.0.0.1, ::1)와 같은 조건이다.
- **2번:** 검색어가 든 탐색 캐시(`explore:v4:["검색어",…]`)를 `sessionStorage`에 둔다. 탭을 닫으면 지워진다.
  - 검색어 없는 기본 목록·개요·에이전트 캐시는 `localStorage`에 그대로 둔다.
  - 예전 판이 `localStorage`에 남긴 검색어 항목은 페이지를 열 때 지운다.
- **시험:** `tests/test_agent_detail_id_range.py`에 3건을 더해 15건이 됐다. 보안 관련 9개 파일 277건이 통과했다.
- **전체 pytest:** 133건이 실패했고, 10,469건이 통과했다.
  - 실패 원인은 다른 세션의 의미 순위 코드다. `vectors` 모의 객체에 `len()`이 없어 `TypeError`가 난다.
  - 대표 3개 파일을 이번 변경을 넣은 상태와 뺀 상태로 각각 돌렸다. 둘 다 같은 13건이 실패했다.
- **배포:** `sec-cleanup-frontend-20261105-r1`(`ad-coin-frontend-20261105-r2` 위)이 게이트 56건을 통과해 배포됐다(활성 b).
- **운영 확인:**
  - 새 검색어("solar panel")는 `sessionStorage`에만 저장된다.
  - 미리 심어 둔 옛 검색어 항목은 새로고침 뒤 `localStorage`에서 지워졌다.
  - 홈·탐색·Chat이 정상이고, 큰 ID는 404를 돌려준다.
- **admin·jobs:** 같은 `deployment_security.py`를 쓴다. 바뀐 분기는 운영 접속에서 쓰이지 않으므로 다음 배포 때 함께 반영된다.
- **남은 것:** 로그인이 필요한 작업공간·관리자 화면 점검(의존성 점검은 6절).
