# Shared integration recipe

Owned files are `agent_market/reliability_evaluation.py`, `reliability_trust.py`, `reliability_routing.py`, `reliability_control_service.py`, `gateway/workspace-reliability-controls-admin.js`, the focused tests and `docs/BOUNDED_RELIABILITY_CONTROLS.md`. This agent did not edit the shared platform, dashboard, catalog, restore code or master plans.

1. In the shared private platform constructor, instantiate `ReliabilityEvaluation(access, runtime)` with its default absent adapters, `ReliabilityTrust(access, evidence_source=reliability_evidence.get_agent_projection)` and `ReliabilityRouting(access, runtime, evidence_source=reliability_evidence.get_agent_projection)`. Reuse the same access/store/runtime objects. Store them as `reliability_evaluation`, `reliability_trust` and `reliability_routing`. Never infer an evaluator from the execution proxy or a public URL.
2. Include `reliability_control_service.router_for(platform.access, runtime, evaluation=platform.reliability_evaluation, trust=platform.reliability_trust, routing=platform.reliability_routing)` only in the private admin router. Its distinct subroutes are `/reliability/evaluation`, `/reliability/trust`, and `/reliability/routing`. Do not add the proposed public `/api/reliability` paths.
3. Add `workspace-reliability-controls-admin.js` to the dashboard's existing script and static asset allowlists/route decorators. Expose one desktop workspace button named `Reliability controls` calling `window.WorkspaceReliabilityControlsAdmin.open(workspace.id)`. Call `.leave()` on workspace changes and `.onSession()` or `.leave()` on identity/logout changes. This is separate from the evidence-plane `WorkspaceReliabilityAdmin` dialog.
4. The new native schema families are `reliability_eval_controls`, `reliability_eval_corpora`, `reliability_eval_plans`, `reliability_eval_jobs`, `reliability_route_policies`, `reliability_route_decisions` and `reliability_controls_restore_blocks`. Their SQL is authoritative in `reliability_evaluation.SCHEMA`, `reliability_routing.SCHEMA` and `reliability_controls_restore.SCHEMA`; both main modules include the same idempotent restore-table creation. Add both profiles (`bounded-continuous-evaluation-v1`, `zero-dispatch-safe-routing-v1`) wherever private artifact profiles, application SQL/catalog and native schema inventories require enumeration. Trust stores nothing.
5. Restore inserts permanent tombstones before releasing the target; it does not rewrite signatures. Use `reliability_controls_restore.authority_id()` or exactly equivalent keys: `eval_control:{workspace_id}:{control payload revision}`, `eval_plan:{workspace_id}:{plan row revision}`, `eval_job:{job row id}`, `routing_policy:{workspace_id}:{policy row revision}`. Insert every restored control/plan/job/policy key into `reliability_controls_restore_blocks(authority_id)` with `ON CONFLICT DO NOTHING` (SQLite `INSERT OR IGNORE` is also supported). Parse control payload revisions with the same bounded JSON validation used for restore; plan/policy revisions already have indexed columns. All old job keys, including terminal jobs, remain tombstoned. Guards project disabled controls/policies, quarantined plans, expired undispatched jobs and unknown dispatched jobs without mutating signed rows. A fresh owner plan/control does not unblock an old job. Do not delete unknown/dedupe history or tombstones, and do not silently re-sign authority to a new session.
6. Keep finite/private profile status separate from operating evaluation, public badges, production routing, representative load or full application readiness. Actual IdP/provider/notification/payment targets remain absent. These modules make no request-driven provider calls except the explicitly injected evaluation adapter; the shared constructor leaves that adapter absent.

The router's `routing/replay` action is historical rule replay, not paired-corpus qualification. Job actions include `prepare`, `dispatch` (disabled without both trusted hooks), and `cancel`. The desktop offers reservations/cancellation and recommendations; it does not expose an invocation button while the evaluator is absent.
