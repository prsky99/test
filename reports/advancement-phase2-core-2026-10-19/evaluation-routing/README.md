# Evaluation, trust preview and routing profile verification

Current owned-source verification on 2026-10-19: **38 tests passed, failures/errors/skips 0**, in 50.80 seconds. This is one combined run; earlier exploratory runs are not added. [JUnit](pytest.xml), [desktop preview](desktop-controls.png), [security review and source hashes](security-review.json), [raw Bandit output](bandit.json).

The implemented source profiles are `bounded-continuous-evaluation-v1`, `private-expiring-trust-preview-v1` and `zero-dispatch-safe-routing-v1`. [Exact scope](../../../docs/BOUNDED_RELIABILITY_CONTROLS.md) and [shared wiring recipe](wiring.md) document the integration and remaining limits. The new desktop component is private and English-only.

The combined run covers 35 API/core/security checks, two offline Chromium checks and one actual retained-evidence-to-trust interface integration. Tests use temporary isolated SQLite stores, named synthetic administrator sessions and mocked transport/evaluator hooks. No operating server, live database, real provider, IdP, notification recipient or payment target was used. Chromium initially could not create its required macOS Mach port inside the process sandbox; the authorized offline test run succeeded outside that sandbox. The browser intercepted all requests and rejected other hosts.

Security checks cover current owner/session/member authority, machine/customer token exclusion, cross-origin/CSRF denial, cross-workspace references, malformed/duplicate/nonfinite JSON, immutable corpus versions, training/holdout overlap, host budgets and jitter, reservation dedupe, concurrent single dispatch, cancellation, kill switches, contract withdrawal, unknown and expiry recovery, changed permission after dispatch, actual observation coverage debt, neutral synthetic trust, exact conditional reads, representation-bound ETags, source revocation/deletion, current version changes, fixed escaped SVG, equivalent-candidate gating, common-host failures, no half-open user probe, R-06 budget exclusion, independent routing pause, signed historical replay without denominator inflation, and stale desktop session removal.

Bandit inspected the five new Python modules and the native fixture helper with **High 0, Medium 0, Low 0 and scan errors 0**. The manual review checked fixed SQL identifiers, existing signed artifacts/current contract pins, narrowed DTOs, no built-in provider adapter, durable dispatch and replay barriers, no-store/private conditional responses, fixed SVG structure and text-only DOM rendering. Restore guards preserve original signatures and block older signed authority from being revived. Literal schema tuples were separately checked with `ast.literal_eval` for the native catalog builder. This scope does not certify the whole application as vulnerability-free.

No public trust route or operating certification is released. No actual evaluator/provider is configured. Reservations and preparation are offline; adapter dispatch requires both trusted injected hooks and current purpose approval. Routing makes zero business calls and no replacement calls, and issues no execution capability. Recorded one-call/zero-replacement bounds describe a future distinct profile. Offline replay compares retained snapshots and explicitly does not establish a paired-corpus outcome improvement. There is no online learning, automatic model promotion, canary, production scheduler, representative load or operating storage/DR/HA acceptance.

The parent integration task owns shared platform/dashboard/native schema/catalog/restore wiring and the final cross-profile verification. Permanent `reliability_controls_restore_blocks` guards are covered by the focused suite, including signature preservation, unknown projection and old plan resurrection denial. The owned native helper `scripts/rehearse_reliability_controls_postgres.py` runs only inside the parent's fixed synthetic PostgreSQL store/graph/session and creates no server/cluster or DSN. It exercises the actual bounded APIs and fails if any evaluation/trust/routing path attempts a provider send; its PostgreSQL execution belongs to the parent harness report. This report alone is not acceptance of the shared operational restore path.
