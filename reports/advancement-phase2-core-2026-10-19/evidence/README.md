# Private bounded reliability evidence

The new `bounded-reliability-evidence-v1` plane extends the existing private retained-metadata rollup. The default `bounded-evidence-rollup-v1` API and its unassessed quality/fidelity behavior remain unchanged. This change does not activate provider calls, public trust pages, workspace customer access or operating qualification.

## Implemented source contracts

- Signed immutable versions of plans, cases and cohorts, with expected revisions and bounded workspace storage. Plans pin dataset, rubric and evaluator versions, source hashes, a sample threshold, a Wilson 95% interval policy, observation window and declared evaluation environment. Cases pin their exact plan revision; cohorts pin cases and a catalog resource and read contract.
- Separate explicit owner consent for private evaluation and encrypted source retention. Every use rechecks current named administrator access, current owner and membership revisions, exact cohort/case/plan revisions, resource connection version and observation generation, schema, contract content and execution-control revision. A saved contract never dispatches a provider.
- Purpose-scoped AES-256-GCM source bundles using `ArtifactCipher`. Retention requires an existing configured encryption key; there is no plaintext fallback. Bundles are capped at 32 KiB and contain only input, output and a bounded source list. Command receipts retain request hashes rather than raw bundles. Default report and inventory APIs never expose plaintext source input/output.
- Explicit audited owner inspection of a retained source. An observation can bind only a current signed original private execution that occurred after its cohort authorization. Bundle input/output must match the signed execution's snapshot input and original output. The initial ingestion profile reuses the existing bounded single-read private MCP execution path; this is not an assertion of A2A/x402 or external evaluator acceptance.
- Actual execution outcomes are taken from signed original evidence. Failed, unknown and quality-unassessed counts stay separate. Deterministic union of original run IDs and logical-task IDs prevents alias and retry sample inflation regardless of arrival order. Cohorts retain separate denominators and are never pooled into an overall quality score.
- The code-only `EvaluatorVerdict` adapter is unconfigured by default. Request bodies cannot assert independent evaluator status. Every report read must receive a fresh, exact binding from the trusted adapter, including qualification and independence hashes and unexpired qualification, before recording assessed quality or verified fidelity. The binding covers agent/version/contract/schema/case/dataset/rubric/evaluator/permission/source/observation time and environment. Unsupported, expired, mismatched or unavailable qualification is neutral. A declared external environment is not an external acceptance record.
- Reports include logical sample/outcome counts, duplicate removal, the pinned observation window and threshold, Wilson interval denominator, gateway-observation p50/p95, reviewer agreement when a trusted adapter actually supplies it, and an unassessed ratio. Provider latency is not inferred. Independent qualification, task correctness and source fidelity remain separate.
- Permanent signed revocation and erasure tombstones. Source deletion removes encrypted source rows and blocks the same bundle hash under a replacement label. Consent withdrawal erases its source bundles. Object revocation makes all dependent evidence ineligible. Bounded explicit retention cleanup removes expired ciphertext and retains minimal signed deletion/hash receipts. Expired bundles become ineligible immediately, independently of cleanup execution.
- Restore quarantine permanently blocks archived consent IDs and erases source rows through the shared backup integrations. Restoring an old signed source row cannot defeat an existing source/hash tombstone. Fresh owner authorization is required after restore; an old execution predating new consent cannot qualify again.

## Private desktop and transport

`workspace-reliability-admin.js` exposes immutable contract creation/version inspection, cohort consent, encrypted source retention, explicit source inspection, erasure/withdrawal, expired-source cleanup, observation binding and current report inspection. Consent controls start unchecked and reset after commands. DOM rendering uses text nodes, including private untrusted source content. Dialog content is discarded on session or workspace changes.

Routes are under `/admin/api/workflow-workspaces/{workspace_id}/reliability`. They use current individual administrator sessions, workspace scopes, owner-only mutations and inspection, `WorkspaceRoute` origin/CSRF protections, strict bounded JSON, request limits, generic errors and no-store responses. Conditional reads recompute current evidence and authority before comparing an exact ETag. Wildcard, weak and combined validators cannot retain a stale body.

The dependent scheduler/router/subscription read interface is `get_agent_projection(workspace_id, resource_id, actor)`. The caller supplies a currently authorized named actor through its own purpose-bound control path. There is no actorless machine bypass. The sanitized projection exposes exact version/schema/contract hashes, a source revision hash, scoped counts, observed/expiry times, qualification/fidelity and environment; it exposes no raw bundle, provider URL, session token or execution grant. Operating qualification and public activation remain false. Positive private projection requires exactly one independently assessed, source-verified cohort meeting its pinned threshold with no failed/unknown executions or failed/unassessed quality.

## Verification and actual limits

Verification uses only temporary SQLite fixture stores, signed synthetic original runs and mock provider transports. Browser requests are offline and routed into in-process fixture APIs. No development server, live database or external provider is launched or modified.

- `focused.xml`: 20 passing new API/domain/offline Chromium browser tests.
- `compatibility.xml`: 49 passing tests: the new evidence tests plus the existing metadata-rollup API/browser compatibility tests.
- `unassessed-regression.xml`: focused check that a currently qualified evaluator returning unassessed quality is not counted as an independently assessed task.
- `private-evaluation-desktop.png`: actual 1440×1000 isolated desktop dialog, visually inspected.
- `source-manifest.json`: hashes of the implementation, focused tests and the owned native-fixture helper at the evidence-plane source freeze.
- `scripts/rehearse_reliability_postgres.py`: guarded helper for the parent's fresh Unix PostgreSQL fixture. It is syntax-checked here; native execution results belong to the parent integration report.

Coverage includes immutable revisions, exact fields, replay, encrypted retention with no fallback, current evaluator expiry and binding, explicit failed/unknown/unassessed counts, logical-task relabeling, source input/output forgery, permanent deletion/hash-relabel/old-row restoration, consent withdrawal, owner/case/resource ABA/contract revisions, restore blocks, session and workspace IDOR, machine-token rejection, cross-origin mutations, duplicate JSON, ETag revalidation, expiry/key loss, original-run deletion, ciphertext signature tampering, escaped source inspection and session-state cleanup.

Secure-coding review checked parameterized static SQL, signed column/payload binding on authoritative reads, encryption context binding, bounded storage and payloads, current scoped authorization, generic transport errors, absence of shell/eval/deserialization/network dispatch in these modules, and text-only DOM output. JavaScript syntax and Python compilation were checked. Bandit is unavailable in the project and system Python environments used here; this report does not claim a Bandit scan. Broader shared native-catalog/restore/security verification is recorded by the parent integration report.

No independent evaluator, real holdout/corpus, externally approved cohort, operating key-retention ownership, real provider evaluation, native PostgreSQL operating migration, production load/DR/HA or public badge acceptance was available. Those remain external acceptance conditions. The default adapter remains unconfigured and therefore unassessed. Retention cleanup is an explicit bounded administrative operation; no new background timer is started by this module.
