- 질문: 새벽 01:42~07:47 점검은 실패 8~9건이었는데 10:44는 92건, 13:13은 85건이다. 07:47 뒤의 배포(08시·오전·낮 묶음)가 원인인가?

## 3. 배포별로 바뀐 것 (②③)
- 점검 기록은 통과한 페이지의 헤더를 남기지 않아, 07:47 당시의 헤더를 같은 URL로 직접 비교할 수는 없다. 대신 배포 내용으로 확인했다.
  - 08시 묶음(414782c6): HTML gzip 40~43KB → 31~37KB(작아짐), 카테고리·주간 원서버 헤더 public. 원서버 렌더 시간은 위와 같이 0.01~0.05초다.
  - 낮 묶음(08276c69): s-maxage를 넣어 Cloudflare swr이 꺼졌다. 공개 HTML·성장 페이지는 만료 뒤 EXPIRED·REVALIDATED가 됐다(13:13 점검의 REVALIDATED 32·EXPIRED 16 일부). 오후 묶음(93a0dc29·6408358b, 13:30)에서 고쳤다.
- REVALIDATED가 많았던 이유: 엣지 사본이 만료된 뒤 swr이 없으면, 엣지는 원서버에 조건부 요청(304)을 보내고 그 왕복을 방문자가 기다린다. 원서버는 0.01초에 답하지만 LAX↔이 맥 터널 왕복이 더해진다.

## 5. 남은 것 (PM 결정)
- 한국에서 새 연결로 재는 페이지 1초는 낮에 경로 바닥값(중앙값 0.8~1.7초)만으로도 넘는다. 무료 플랜에서는 LAX 경로를 바꿀 수 없다(11-10 PM 확인). 판정은 그대로 미달로 두고, 각 표본에 바닥값을 붙이는 기록은 이미 있다(`ref`).
- 이 맥은 운영 서버이면서 측정기다. 낮에 이 맥의 회선·CPU가 바쁜 것이 바닥값을 올리는지 가르려면, 다른 회선(예: 휴대폰 테더링이나 다른 장소)에서 같은 /cdn-cgi/trace를 재 볼 필요가 있다. 사용자 도움이 필요한 일이다.
