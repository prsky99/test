# 10차 보고서 및 추가 미확인 항목 개선 결과

2026-10-29. 현재 소스·운영 응답을 기준으로 재현 가능한 문제를 수정하고, 이미 해결된 항목과 실제 외부 검증이 남은 항목을 구분했다. 아래의 추가 개선 후보는 사용자 승인 후 **운영 적용 및 공개 API 확인 완료**다. 운영 마무리 확인일은 2026-10-30(KST)이다. 앞서 승인된 protocol-disclosures 프론트엔드·어드민 r1 배포는 완료했으며, 해당 운영 검증은 별도 보고서에 보존했다.

## 핵심 원인과 수정

1. **x402 수정이 공개 서비스에 보이지 않던 원인**: `/api/gateway/*`가 별도 Cloudflare Worker를 통과했다. 웹 서버의 첫 402·403 수정만으로 해당 경로는 바뀌지 않았다. 활성 Worker 원본을 소스맵으로 대조한 뒤 Worker도 수정했다. 최초 GET/POST 402에 검사 전용·결제 미처리/미전달/미정산 안내와 공개 제공자 정보 페이지 링크를 넣었다. 원래 v1/v2 조건은 보존하고 v2 PAYMENT-REQUIRED 헤더와 본문을 일치시켰다. 비공개 원본 연결 주소를 공개하지 않으므로 provider_url은 null이며 provider_details_url을 제공한다. 정책 거절은 안전한 원인 코드·설명·다음 행동을 담은 실제 403이다. 결제 증명 전달이나 정산 기능은 활성화하지 않는다.
2. **일반 날씨에 우주·항공 날씨가 섞임**: 명시적으로 우주·항공 기상을 요청하지 않는 일반 날씨에서는 해당 전용 서비스를 제외했다. 지상 날씨를 실제 제공하는 복합 서비스는 허용한다. 요청한 프로토콜 범위와 기존 검증·보안 기준은 유지한다.
3. **Chat 문맥과 다국어**: 운영 4턴 재현에서 `second` 다음 `it`이 같은 추천을 가리키는 것은 이미 동작했다. 추가로 조건 변경과 순번 선택이 함께 있는 요청을 처리하고, 직전 목록의 삭제·상태 변경된 항목을 되살리지 않도록 했다. 일본어·스페인어 기능 별칭을 보강하고, 알려진 기능 옆의 미번역 주제가 사라지지 않게 했다. 기존 wrapper에서 요청 조건·피드백 사유 인자를 빠뜨리던 원본도 복구했다.
4. **Explore**: 단어가 없는 기호·불용어 검색은 임의 최신 목록 대신 0건과 작업 입력 안내를 반환한다. 빈 검색의 최신 목록 탐색은 유지한다. `8004`는 기능명이 아닌 ERC-8004 등록 체계이므로 금융 에이전트가 있다는 사실만으로 오분류가 아니다. 검색 화면에 차이를 설명한다. 동일 질의의 동시 캐시 미스를 하나의 조회로 묶어 중복 부하를 줄인다. 재사용 시 현재 격리·삭제 상태를 다시 확인한다. 16개 동시 요청이 조회 1회로 합쳐지는 것과 실패 후 회복을 검증했다. 다른 검색까지 함께 막지 않는다.
5. **접근성과 배치**: 실제 Chat 입력창에 테마별 포커스 표시를 적용하고, 푸터·상태 링크와 등록 동의의 클릭 영역을 보완했다. 응답 후 전체 화면을 강제로 스크롤하던 동작을 없애고 입력창 위치를 유지한다. 이미 배포된 포커스·쿠키·작은 컨트롤 스타일을 빌드 원본에도 보존했다.
6. **페이지 생성 회귀**: 빌더가 마지막 script를 메인 런타임으로 잘못 고르는 문제를 수정했다. 운영 런타임·경험 개선 런타임을 각각 찾고 모두 포함한다. 비활성 페이지는 template에 넣고 런타임 초기화 전에 복구하여, JavaScript를 실행하지 않는 문서 읽기에서 모든 메뉴의 본문이 동일하게 섞이는 문제를 줄였다. 실제 화면 전환은 유지한다. 기존 Learn 검색도 원본에 동기화했다. 없는 해시는 안내와 복구 링크를 표시한다.
7. **API와 보안**: 공개 문서·익명 조회의 CORS/조건부 GET에 ETag·한도 헤더를 노출하고 If-None-Match를 허용했다. A2A-Version 요청 헤더를 허용된 Origin에서 사용할 수 있다. 세션·실행 API에는 허용된 Origin 정책을 유지하며 임의 Origin에 자격 증명 접근을 열지 않았다. 에이전트용 OpenAPI에 실제 entry·badge·자기 명세 경로를 추가했다. 공개 adapt_rest는 내부 작업용 private 옵션이 켜져 있어도 사설 주소를 거절한다. 없는 리소스·정책 거절을 제공자 실행 실패로 기록하지 않는다.
8. **보고서 오해 방지**: 과거 x402 등의 문자열 태그를 공개 응답의 제한된 문자열 배열로 정규화했다. 원본 DB 보고서는 변경하지 않는다. 현재 실행 증거가 없으면 명확한 과거 기록 안내를 표시하고 기존 평가 원문을 접어 둔다. 실제 실행 이력 없이 성공·현재 검증 완료 보고서로 바꾸지 않는다.

## 추가 보고서의 ‘미확인’ 항목 검증

- robots.txt: 공개 응답 200·text/plain·캐시 헤더와 게이트웨이 안내를 확인했다. status.json도 200이며 catalog_snapshot의 지표별 필드를 확인했다. 증거는 robots-and-status.json에 있다.
- A2A DataPart·contextId 후속 조회·다른 방문자 권한 충돌, 잘못된 버전·빈 parts: 격리 API 회귀 통과. JSON-RPC 오류가 HTTP 200인 경우에도 성공 result가 아닌 규격상 error인지 구분했다.
- MCP 조회 4개 주석, server.json, server/discover: 승인된 웹 배포 후 공개 응답에서 확인했다. 조회가 대화를 생성·갱신하지 않는지도 PostgreSQL에서 확인했다.
- 문의 관리 화면의 저장된 악성 마크업: 격리 실제 Chromium에서 실행되지 않음 확인. 문의 분류·상세·처리 상태·재조회 및 개인정보 요청도 검증했다.
- 문의·등록 한도: 기능별 제한으로 다른 문의/조회 기능을 전체 차단하지 않는 기존 회귀 확인. 인증 대기 구독의 24시간 삭제 회귀 통과.
- 등록 동의·프로토콜 미확인 거절·입력 오류: 기존 보안 경계를 유지하고 브라우저/API 회귀를 통과했다. 운영 카탈로그에 신규 시험 에이전트를 등록하지 않았다.
- 지원·워크스페이스: 격리 OAuth/세션·권한·지원 흐름은 검증했다. 개인 Chrome 로그인 세션의 실제 워크스페이스는 이번 탐색이 완료되지 않아 검증 완료로 세지 않았다.
- 보고서 표본: 운영 DB를 읽기 전용으로 A2A 15·MCP 15·x402 10건 확인했다. 40건 모두 현재 실행으로 인정되지 않는 과거 기록이며, 수정된 공개 투영의 태그는 모두 배열이다. 이것은 40개 제공자를 다시 실행했다는 뜻이 아니다. 상세는 read-only-report-sample.json에 있다.

## 재현에서 이미 해결되어 있던 항목

잘못된 MCP 버전은 400/JSON-RPC 오류, 잘못된 A2A 버전·빈 parts는 JSON-RPC 오류, 깨진 Chat JSON은 400 problem+json, 범위 밖 limit는 읽을 수 있는 422 problem+json이었다. robots.txt 캐시, 실제 오타 제안, 동일 대화 순번 참조도 확인했다. 없는 문서와 오류를 모두 새 문제로 집계하지 않았다. llms.txt와 Home은 같은 일별 통계 스냅샷을 사용하고 있다. 전체 수집량·활성 수·접속 확인 수는 서로 다른 지표이므로 같은 수치로 강제하지 않는다.

## 미적용 및 남은 한계

추가 웹 2개와 Worker는 승인 후 적용했다. 쿼리 문자열 없는 실제 공개 x402 경로의 GET/POST에서 최초 402 검사 전용 안내와 v2 헤더/본문 일치를 확인했다. 정책 403은 운영 차단을 억지로 유발하지 않고 앞선 통제된 Worker 시험 증거로 구분한다.

실제 금전 결제·정산 성공, 모든 외부 제공자의 가용성, 개인 로그인 세션의 운영 워크스페이스 전체, 재현되지 않은 credit 연결 끊김, 사람 5명 과업/실제 스크린리더 사용자 시험은 완료하지 않았다. 과거 40건을 현재 실행 보고서로 승격하려면 각 제공자에 대한 실제 허용된 실행과 그 시점의 계약·결과 근거가 필요하다. 임의 점수 상승이나 신규 종합 UI/UX 등급을 산정하지 않았다. 배포 후 실제 부하의 검색 꼬리 지연은 별도 재측정해야 한다.
