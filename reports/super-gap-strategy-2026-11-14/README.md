## 0. 한 줄 전략
**경쟁자는 한 단계씩만 잘합니다. 우리는 "검증 → 조합 → 끝까지 실행 → 실행 결과로 다시 검증"이라는 닫힌 고리를 먼저 돌려, 고리에서만 생기는 데이터와 신뢰를 쌓습니다.**

| 경쟁자 | 잘하는 단계 | 고리 밖이라 못 얻는 것 |
|---|---|---|
| SealKeeper | 확인(서명된 SEAL) | 조합 실행 결과. 자리별로 어떤 에이전트가 실제로 과제를 끝냈는지 |
| Agoragentic | 단일 능력의 대체 실행·정산 | 여러 자리를 잇는 조합의 Δ, 정답 세트 대비 품질 |
| HOL, Glama, Arcade | 수집·등급 | 실제 과제 성공 데이터 |

고리가 한 바퀴 돌 때마다 다음이 쌓입니다. 경쟁자가 따라오려면 그 사이 쌓인 기록을 처음부터 다시 쌓아야 합니다. 이것이 격차입니다.
- 진주 순위(역할별 실사용 성공률)
- 대체 사슬 품질
- 서명된 증거

## 1. 초격차 다섯 기둥
### 기둥 1. 속도: 첫 목걸이를 먼저 냅니다
- 일정: 실행기 11-17 → 첫 관문 신청 11-19 → 첫 공개 11-21 → 5개 11-28
- 당길 수 있는 것
  - 자체 대체가 이미 준비된 목걸이(cve-incident-brief, package-risk-audit)를 첫 관문에 먼저 올립니다.
  - 자체 대체 현황: nvd-cve 30/30, cisa-kev 30/30, package-registry 30/30, depsdev 30/30
- 측정: 공개 목걸이 수, 첫 외부 실행 성공 시각

### 기둥 2. 증거: 검증을 "주장"이 아니라 "누구나 다시 확인할 수 있는 기록"으로 만듭니다
- 보완 1(방법론 공개), 보완 3(서명)을 묶어 증거 체계로 만듭니다(2절).
- SealKeeper의 SEAL은 결과(등급)에 서명합니다. 우리는 **증거 자체**에 서명합니다. 증거는 다음과 같습니다.
  - 보낸 입력
  - 응답 해시
  - 대조한 정답 원천
  - 데이터 시각
  - 점수 항목별 값
  - 방법론 버전
- 목걸이 관문 결과(종단 성공률, Δ, 보류 세트 회차)에도 서명합니다. "검증된 조합"을 증명할 수 있는 곳은 우리뿐입니다.

### 기둥 3. 완주 보장: "끝까지 실행"을 측정 가능한 약속으로 만듭니다
- 목걸이 4단계(정상 → 외부 대체 → 자체 대체 → 정지·교체·공지)를 공개 지표로 보입니다.
  - 목걸이마다 7일 완주율, 자리별 대체 발생률, 자체 대체 사용률
- Agoragentic의 대체는 능력 하나 단위입니다. 우리는 여러 자리를 잇는 워크플로우에서 Δ>0을 증명하고 완주시킵니다.
- 공개 문구에는 측정값만 씁니다(표시광고법). "보장"이라는 낱말은 쓰지 않고 "7일 완주율 n/N"으로 씁니다.

### 기둥 4. 유통: "확인"하러 온 개발자를 "실행"으로 넘깁니다
- 보완 2(부르기 전 확인)를 SealKeeper식 확인 도구로 끝내지 않습니다. 확인 결과에 **같은 역할의 더 나은 검증 진주와, 그 일을 끝까지 해 주는 목걸이**를 함께 돌려줍니다(2절).
- 확인 호출 → 목걸이 실행 전환율을 지표로 둡니다. 북극성으로 가는 깔때기입니다.
- 지금은 우리 MCP 서버, A2A 카드, REST로 냅니다.
- LangChain·n8n 패키지는 외부 게시라 사용자 승인 뒤에 합니다. 성장세가 보일 때 사용자가 직접 정합니다(11-10 보류 결정).

### 기둥 5. 네트워크: 제공자가 우리 증거를 스스로 퍼뜨리게 합니다
- 진주가 된 에이전트의 제공자가 자기 README와 사이트에 붙일 수 있는 **서명 검증 배지**(`/badge/<id>.svg`, 클릭하면 서명된 보고서)를 제공합니다.
- 배지는 우리 사이트로 들어오는 링크입니다. AI 검색 인용에 크게 작용하는 제3자 언급(브랜드 조사 근거)도 늘립니다.
- 제공자에게 연락하는 것은 바깥으로 보내는 메시지라 사용자 승인 뒤에만 합니다. 그 전에는 진주 카드에 "Embed this badge" 안내만 둡니다.
- 소유자 확인(claim)은 2단계로 설계합니다. 워크스페이스 계정과 DNS나 well-known 파일 확인으로 하고, 확인된 제공자에게 재시험 요청 권한을 줍니다.

## 2. 보완 4건 적용 설계
### 보완 1. 점수 방법론 공개 → "AgentValCon Verification Method v1"
| 항목 | 설계 |
|---|---|
| 위치 | `/methodology`(영어, 디자인 시스템), 기계용 `/methodology.json`(버전·가중치·역할별 최신성 기준), 바뀔 때마다 `/methodology/changelog` |
| 내용 | 수집 원천과 범위, 등급 A 기준, 역할 과제 시험 방식, 점수 100점(데이터 품질 60 = 정확성 25·최신성 10·완전성 10·깨끗함 10·일관성 5, 증거 30, 글 10), 검증 진주(85점·서로 다른 날 2회)와 최종 진주(역할 1위), 목걸이 관문(보류 60건 두 회차, 95%, Δ>0), 상시 감시와 4단계, 한계 |
| 지킬 것 | **보류 정답 세트(관문용)는 공개하지 않습니다.** 공개하면 맞춤 응답으로 점수를 속일 수 있습니다. 공개하는 것은 방법과 예시 과제뿐입니다 |
| 맞추기 | 페이지 수치는 `report_v2.py`·`NECKLACE_GATE.md`와 같은 값을 읽어 만듭니다. 손으로 쓰지 않으므로 어긋나지 않습니다 |
| 담당 | 검색과 RAG(내용·json), 성장·유통(페이지·사이트맵·llms.txt) |
| 기한 | 11-18 |

### 보완 2. 부르기 전 확인 → "Check-and-Route" 도구
| 항목 | 설계 |
|---|---|
| 도구 | MCP `verify_agent`(에이전트 주소나 id → 상태), `best_for_role`(역할 → 검증 진주 순위와 그 역할을 쓰는 목걸이). A2A skill과 REST `/api/verify`, `/api/roles/<role>/best`에 같은 기능 |
| 돌려주는 것 | 등급, 최신 v2 판의 점수 항목, 검증·최종 진주 여부, 마지막 시험 시각, 데이터 시각, 도구 정의 지문, 서명된 보고서 주소, **더 나은 대안**(같은 역할의 상위 검증 진주), **이 일을 끝까지 하는 목걸이** |
| 속도 | 스냅샷 파일에서 답합니다(추천 2초 목표). 요청 경로에서 DB를 다시 확인하지 않습니다(속도 정책) |
| 지표 | 확인 호출 수, 대안·목걸이 안내 비율, 확인 → 목걸이 실행 전환 |
| 담당 | 성장·유통(MCP·A2A·REST 표면), 검색과 RAG(스냅샷 데이터) |
| 기한 | 11-19 |

### 보완 3. 서명된 증명 → 증거 서명(DSSE + Ed25519)
| 항목 | 설계 |
|---|---|
| 형식 | DSSE 봉투(Sigstore·in-toto가 쓰는 공개 표준)에 Ed25519 서명. 내용은 JCS로 정규화한 판 JSON: 입력, 응답 sha256, 점수 항목, 정답 원천, 데이터 시각, 방법론 버전, 시험 시각 |
| 대상 | 시험 보고서 v2 판 전부, 목걸이 관문 결과, 정지·교체 사건 |
| 공개 키 | `/.well-known/agentvalcon-keys.json`. 키 id와 유효 기간을 두고, 키를 바꿔도 옛 서명을 검증할 수 있게 합니다 |
| 개인 키 | 운영 맥 `gateway-data/signing/`(권한 600, git 제외)에 둡니다. 코드·로그·보고서에 값을 쓰지 않습니다. 맥미니 백업에 암호화 사본을 둡니다. 유출이 의심되면 키를 폐기 목록에 올리고 새 키로 다시 서명합니다. 이 키는 서명 전용이라 돈이나 지갑과는 관계없습니다 |
| 검증 | 공개 검증 방법을 방법론 페이지에 둡니다. 예제 코드 몇 줄과 `/api/verify-signature` |
| 담당 | 운영·SRE(키 생성·보관·교체·공개 키 문서), 검색과 RAG(판 서명), 워크플로우(관문·사건 서명) |
| 기한 | 설계 11-17, 적용 11-20(첫 목걸이 공개 전) |

## 3. 위험 대응
