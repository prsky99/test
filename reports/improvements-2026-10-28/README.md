## 이번 평가에서 새로 찾은 중요한 문제
1. **정상 사용자도 15분 차단될 수 있음(긴급)**
   - 읽기 요청은 IP당 분당 120회로 제한되는데, 정적 파일(JS·CSS·이미지)도 이 수에 포함된다.
   - 화면 하나가 약 15개 파일을 받으므로, 몇 화면을 빠르게 넘기면 한도를 넘는다.
   - 한도를 넘은 요청이 5번이면 그 IP가 15분 동안 자동 차단된다.
   - 오늘 이 작업 머신의 IP가 두 번 차단됐다. 차단 기록의 429는 모두 `/new/en/assets/*.css`·`.js`였다.
   - 사무실처럼 IP를 함께 쓰는 사용자는 더 쉽게 걸린다.
2. **차단을 엉뚱한 이유로 안내함**: 워크스페이스 AI 생성이 차단(403)됐을 때 "승인된 에이전트나 접근 권한이 없어졌다"고 안내했다.
3. **정적 파일 캐시 없음**
   - 원 서버가 정한 `no-cache`를 공통 보안 헤더가 `no-store`로 덮어써서, Cloudflare가 매번 원 서버에서 받았다.
   - 배포 직후 첫 화면 20~38초의 원인이다.

### 중복 요청 방지 키(C8)
- `/api/` 아래 모든 POST가 `Idempotency-Key`(8~128자)를 받는다(선택).
  - 같은 키·같은 본문: 첫 응답을 그대로 돌려준다(`Idempotent-Replayed: true`).
  - 같은 키·다른 본문: 422.
  - 첫 요청이 진행 중: 409.
- 범위: 로그인 세션, 방문 토큰, 실제 클라이언트 주소 순으로 정한다. 24시간 보관한다.
