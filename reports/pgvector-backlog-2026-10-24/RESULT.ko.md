# pgvector 대기열 증가 원인과 복구 준비

2026-10-24 KST. 운영 PostgreSQL을 읽기 전용으로 조사했습니다. 초기 점검은 읽기 전용으로 수행했고, 이후 사용자의 명시적 승인을 받아 jobs·프론트엔드·어드민을 교체했습니다. 운영 큐 삭제나 강제 전체 재색인은 수행하지 않았습니다.

## 결론

PostgreSQL 18 + pgvector 이전 자체는 적용되어 있습니다. 그러나 생성 모델을 맥미니의 OpenAI 호환 서버로 옮기고 로컬 Ollama를 끄는 과정에서, **동일한 스위치가 임베딩 생성도 중지**시켰습니다. 따라서 초기 조사 당시 신규·변경 데이터의 자동 벡터 적재가 멈춰 있었습니다. 승인 후 수정 적용으로 현재 적재가 재개되었습니다. 데이터베이스 저장 속도 저하나 단순 표시 지연이 주원인이 아닙니다.

사용자가 이후 Ollama를 다시 실행했고 기존 임베딩 모델도 설치되어 있음을 확인했습니다. 하지만 실행 중인 jobs의 `embeddings_enabled`는 시작 때 읽은 `LOCAL_OLLAMA_ENABLED=0`에 묶여 있으므로, Ollama 실행만으로는 처리 재개가 되지 않습니다.

## 실제 측정

초기 관측 22:24 무렵:

- PostgreSQL 18.6, pgvector 0.8.2, 768차원 cosine HNSW 구성 존재.
- pgvector 저장 행 134,110개. 이 숫자는 현재 유효한 검색 대상 수와 같지 않습니다.
- pgvector에 남았으나 현재 원본 공개 기록과 맞지 않는 행 46,789개. 기존 검색 검증 경계에서 현재 벡터로 인정하면 안 되는 기록입니다.
- 원본 벡터 87,327개, 원본 공개 근거 87,322개.
- 대기 56,170개. 계정/보고서 중복이 아니라 `resource_id` 기본키를 가진 에이전트별 작업 의도입니다.
- 대기 중 원본 벡터가 없는 대상 56,169개. 변경 시 이전 벡터를 무효화한 다음 새 임베딩을 기다리는 상태가 대부분입니다.
- 대기 중 현재 색인 대상 56,003개. 나머지는 비활성·은퇴·격리 등의 조건에 의해 제외될 수 있습니다.
- 현재 세대의 pending 작업 56,005개, 최대 시도 횟수 0. 최근 에러로 계속 재시도한 상태가 아니라 실제 실행 단계에 들어가지 않은 상태입니다.
- 최근 1시간·24시간 색인 완료 0개.
- 마지막 정상 색인 **2026-10-23 13:45:10 KST**.
- jobs의 수집·헬스·색인 스레드는 살아 있고 일시 정지도 아니었습니다. 스레드 생존은 색인 진행의 증거가 아닙니다.

후속 관측 22:33 무렵에는 대기가 **56,252개**로 증가했고 마지막 적재 시각은 그대로였습니다. 현재 세대·모델·원본·벡터 해시·활성/안전 조건을 모두 통과한 벡터와 pgvector 행은 **각각 87,256개**였습니다. 집계는 시각별 스냅샷이므로 수집·상태 변경 때문에 조금씩 달라집니다.

## 원인 경로

1. `gateway/server.py`가 `rag_engine.embeddings_enabled = config.local_ollama_enabled`로 생성 모델용 활성화 설정을 공유했습니다.
2. 현재 생성 설정은 맥미니 OpenAI 호환 모델이며 `LOCAL_OLLAMA_ENABLED=0`입니다.
3. `RagPipeline.step()`은 이 값이 꺼지면 큐를 claim하기 전에 `embedding_provider_disabled`를 반환합니다.
4. 수집·상태 변경은 계속 들어오므로 PostgreSQL 트리거는 기존 벡터를 무효화하고 새 작업을 등록합니다.
5. 작업자는 5초마다 호출하지만 매번 disabled로 종료합니다. 오류를 내지 않으므로 일반 오류 로그만으로는 놓치기 쉽습니다.
6. 기존 어드민은 대기 건수가 있으면 ‘검색에 반영하고 있습니다’라고 표시해, 중지 상태를 진행 중인 것처럼 안내했습니다.

기존 최신성·안전 검증을 해제해서 오래된 벡터를 검색에 다시 쓰게 하거나, 5만 건 큐를 삭제하는 방식으로 수치를 줄이지 않았습니다.

## 수정한 사항

- **생성과 임베딩 활성화를 분리:** `EMBEDDING_ENABLED`, `EMBEDDING_OLLAMA_URL`을 추가했습니다. 별도 `gateway-data/embedding.env`에서 임베딩만 켭니다. 생성 모델·맥미니 주소·폴백 설정과 `LOCAL_OLLAMA_ENABLED=0`은 유지합니다.
- **기존 임베딩 모델 유지:** `embeddinggemma-2:270m-mxfp8-text`, 768차원, 기존 모델 식별 해시를 유지합니다. 다른 모델의 768차원 출력을 혼합하지 않습니다. 유효한 기존 벡터 전체를 다시 만들 필요가 없습니다.
- **롤백 호환성:** 예전 릴리스가 엄격하게 읽는 생성 설정 파일에 새 키를 넣지 않았습니다. 새 서비스 코드만 별도 임베딩 설정 파일을 읽습니다.
- **실제 작업 상태 보고:** 마지막 시작·완료·실제 완료 건수·오류·활성화 상태를 jobs heartbeat에 포함합니다.
- **어드민 안내 수정:** 스레드 생존만으로 진행 중이라고 하지 않습니다. 비활성, 일시 정지, 오류, 진행 미확인, 실제 처리 중, 최근 완료를 구분합니다.

## 검증과 한계

- 실제 로컬 Ollama에서 기존 임베딩 모델 설치와 응답을 확인했습니다.
- 실제 모델 요청 2회와 격리 메모리 DB를 사용해 신규 색인과 설명 변경 후 재색인이 모두 성공했습니다. 대기 1→0, 현재 원문과 벡터 일치를 각각 확인했습니다. 최초 1.069초, 변경 후 0.019초였습니다. 이는 합성 대상 한 건의 측정으로, 운영 전체 처리량이나 예상 소요 시간을 보증하지 않습니다.
- 기존 운영 모델 식별 해시와 격리 검증의 식별 해시가 일치했습니다.
- 설정·생성 분리, 입력 검증, 큐 최신성, 파이프라인, 서비스 분리 129개와 어드민·브라우저 20개, 수집 회귀 38개가 통과했습니다. 서로 다른 사례 187개입니다.
- 별도 PostgreSQL 소유권·서명 테스트 1개는 임시 클러스터 `initdb` 환경 오류로 실행 준비가 실패했습니다. 운영 DB 쓰기로 대신 검증하지 않았습니다.
- 준비된 jobs/웹 릴리스에서도 임베딩 설정과 화면 상태를 별도 검증합니다. 이는 반복 검증이며 위 테스트 수에 다시 합산하지 않습니다.
- 초기 검증은 운영 데이터 쓰기·큐 삭제·프로세스 교체 없이 수행했습니다. 이후 사용자가 세 서비스 교체를 명시적으로 승인했고, 정상 작업자의 자동 적재가 재개되었습니다. 점검 스크립트는 운영 DB에 직접 쓰거나 큐를 삭제하지 않았습니다.

## 준비한 적용 대상

현재 운영 릴리스에서 필요한 파일만 교체한 불변 릴리스를 준비했습니다. 기존 워크플로·금융 화면·생성 모델·실행 워커를 되돌리지 않습니다. 매니페스트 검증을 수행했고 사용자 승인 후 세 릴리스를 활성화했고 아래 실측으로 적재 재개를 확인했습니다.

```sh
./agentcon worker-deploy jobs pgvector-embedding-20261024-r1
./agentcon deploy frontend pgvector-embedding-frontend-20261024-r1
./agentcon deploy admin pgvector-embedding-admin-20261024-r1
```

jobs는 신규·변경 벡터 적재 재개, frontend는 질의 임베딩 복구, admin은 정확한 처리 상태 표시를 위한 교체입니다. execution 워커는 이번 변경 대상이 아닙니다.

사용자 또는 명시적으로 승인받은 에이전트가 적용한 뒤, jobs heartbeat의 임베딩 활성화·최근 완료 건수, `legacy_vector_provenance.indexed_at` 증가, 유효한 pgvector 증가, 대기열 감소를 시간 차로 재확인합니다. 새 데이터가 계속 들어오므로 첫 관측 한 번만으로 ‘전체 완료’라고 판단하지 않습니다.

## 승인 후 운영 적용 결과

사용자가 “필요한 세 서비스 모두 적용해줘”라고 승인했습니다. 준비했던 jobs·frontend·admin 릴리스를 모두 적용했고 웹 준비 상태·정상 응답·어드민 상태 파일 일치·비로그인 접근 차단을 확인했습니다. 맥미니 생성 설정 파일 해시는 적용 전후 동일하고 execution 워커 릴리스는 변경하지 않았습니다. Ollama나 맥미니 서버 자체를 재시작하지 않았습니다.

20초 간격 3회, 총 40.1초 관측에서 대기열이 **56,265 → 56,185건**으로 순감소했습니다. 같은 구간 최신 공개 색인 기록은 **87,290 → 87,377건**으로 순증가했습니다. 마지막 색인 시각은 **2026-10-24 22:52:58 KST**까지 갱신됐습니다. jobs의 임베딩 활성화 true, 관측된 최근 배치 완료 **50건·실패 0건**을 확인했습니다.

누적 대기는 아직 남아 있고 백그라운드로 처리 중입니다. 신규·변경 데이터가 동시에 유입되므로 대기 감소량과 실제 처리 건수는 다릅니다. 물리 pgvector 행 수에는 무효화된 옛 행이 포함되어 있었으며, 재개된 파이프라인이 제한된 단위로 이를 정리하므로 물리 행 수가 일시 감소할 수 있습니다. 이를 최신 유효 벡터 손실로 판단하지 않습니다. 전체 5만여 건 처리가 완료됐다고 주장하지 않습니다.

원본 증거: `activation.json`, `post-activation-progress.json`, 역할별 배포 로그. 배포 실패 0건. 추가 사용자 재시작은 필요하지 않습니다.
