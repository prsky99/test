# 워크스페이스 공개 메뉴

요청 범위: 공개 프론트엔드에서 Workspace 메뉴를 통해 기존 고객 로그인·워크스페이스에 접근할 수 있게 합니다.

`CUSTOMER_WORKSPACE_LINK_ENABLED`를 켰고, 홈 기본 경로와 공개 Pearl 페이지 9개 모두 기존 `workspace_shell` 공개 설정을 적용하도록 연결했습니다. 사용자 인증·워크스페이스 권한은 그대로 유지됩니다. 비로그인 방문자는 구글·깃허브 로그인 화면으로 이동합니다. 상단 메뉴 링크에 기존 Lucide 아이콘과 테마 스타일을 적용했습니다.

960px 검증 중 기존 980px 헤더 전환과 950px 메뉴 전환 사이의 레이아웃 충돌을 발견해 접이식 메뉴 기준을 980px로 맞췄습니다. 최초 실패 증적은 `launch-initial-failure.xml`, 수정 후 최종 57개 통과는 `final-regressions.xml`입니다. 공개 콘텐츠 검사 237개 파일·위반 0건, 변경된 Pearl 응답 모듈 Bandit 발견 0건입니다. 기존 보안 경계 및 공개 경로·자산 회귀를 포함합니다.

390·960·1024·1440px에서 메뉴 노출·가로 넘침·헤더 높이·키보드 이동·로그인 화면 연결을 검증했습니다. 증적은 `public-menu-*.png`, `signin-from-menu-*.png`입니다. 이 화면들은 격리 테스트의 예시 데이터입니다.

현재 상태: 사용자 재시작 후 공개 반영 검증 완료. 서버 PID가 88435에서 98141로 교체됐고 검증된 소스 해시가 일치합니다. 실행 서버의 홈·공개 페이지 9개에 메뉴가 각각 하나씩 있으며 공개 설정 API도 활성입니다. 실제 공개 Chrome 홈에서 Workspace 메뉴를 확인하고 클릭해 `/customer/workspaces`와 로그인 상태를 확인했습니다. 공개 주소에 대한 원시 urllib 요청은 403으로 거절되어 전체 경로 응답 검증은 로컬 실행 서버에서, 공개 접속과 클릭 검증은 실제 Chrome에서 수행했습니다. 비로그인 및 모바일 검증은 앞선 격리 테스트 범위입니다. 운영 증적은 `live-home-workspace-public.png`, `live-workspace-menu-destination.png`입니다. 서버 재시작과 계정 변경·크레딧 사용·워크플로우 실행은 수행하지 않았습니다.
