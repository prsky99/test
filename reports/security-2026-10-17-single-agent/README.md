# 단일 에이전트 추천 보안 점검

2026-10-17 KST · 로컬 소스와 격리 실행 검사. **코드 보완 4건 완료, 로컬 운영 조치 2항목 남음.** 운영 사이트 배포·재시작·공격성 DAST는 수행하지 않았다.

최종 전체 회귀 **795개 통과**, 실패·오류·건너뜀 0개(192.20초). 이후 인증 문자열 제거 패턴을 확장하고 전용 공격 검사 **63개를 다시 통과**했다. 설치 패키지 **53개에서 점검 시점에 알려진 취약점 0개**였다. 이 결과는 모든 취약점의 부재나 운영 환경의 안전을 인증하지 않는다.

## 범위와 방법

직전 변경의 선정기·대화 엔진·공개 응답·브라우저 렌더링·도구 스키마를 상세 검토하고, Python 애플리케이션 전체 **61개 파일**에 Bandit를 실행했다. REST `/chat`, A2A, MCP 및 공개 에이전트 상세 API에 실제 FastAPI 요청을 전송했다. 임시 SQLite에 합성 에이전트와 가짜 인증값을 넣어 공격을 재현했다. Chromium은 실제 CSP 헤더를 적용하고 모든 외부 요청을 차단했다.

기존 프론트·어드민의 XSS·CSP, 권한·계정 경계, SSRF·DNS 재바인딩, TLS·프록시, 본문·응답·동시 요청 제한, 토큰 저장과 관리자 메뉴 검사도 회귀 실행했다. 외부 에이전트·온체인 결제·알림 전달은 실제 실행하지 않았다. 로컬 운영 DB 4개는 읽기 전용으로 조사했고 자격 증명 값은 보고서에 기록하지 않았다.

## 발견과 수정

1. **S1 / 중간: 저장 인증값의 공개 응답 노출 가능성.** 도구 스키마의 기본값·예제·민감 파라미터 enum/const와 인증 안내에 넣은 합성 비밀값이 추천 JSON에 포함됐다. 공개 상세 응답도 같은 경계로 확인했다. 공통 제거 처리를 적용해 파라미터 이름·타입·필수 여부와 일반 enum은 유지하고 저장된 인증값을 제거한다. 일반 JSON 메타데이터의 민감 키와 Bearer·Basic·API key 문자열도 처리한다. 임의의 식별 불가능한 비밀 문자열까지 자동 판별한다고 보장하는 기능은 아니다.
2. **S2 / 낮음: 내부 주소 변형과 미검증 출처를 호출 주소로 안내.** 기존 추천 필터가 `localhost.`, `2130706433`, `0x7f000001`, `127.1`과 잘못된 포트를 허용했다. DNS 없는 IDNA·호스트·공인 IP·포트 검사, userinfo·민감 쿼리·fragment 차단을 적용했다. 가이드의 호출 주소가 검증된 출처와 다르거나 유효하지 않으면 원래 검증 주소를 안내한다. 이 항목은 추천 안내의 문제이며 서버 접속 시점의 기존 SSRF 방어를 실제 우회했다는 의미는 아니다. DNS 재바인딩 방어는 외부 호출 클라이언트가 계속 담당한다.
3. **S3 / 낮음: 실행 결과 자료형 혼동.** `bool("false")`가 참이고 bool이 int의 하위형인 특성 때문에 잘못된 성공 기록을 허용할 수 있는 코드를 확인했다. 성공 여부는 실제 bool, 리소스 ID는 양의 실제 int만 허용한다. 존재하지 않는 리소스와 잘못된 입력은 피드백 DB에 기록하기 전에 거부한다.
4. **S4 / 낮음: 비정상 원격 스키마의 응답 500 오류.** 합성 스키마의 `maximum: NaN`이 엄격한 JSON 직렬화에서 500 오류를 유발했다. 비유한 수 제약은 제외하고 목록의 비정상 숫자는 표준 JSON 값으로 정규화한다. 공개 스키마의 재귀 처리 깊이도 제한한다. 원래 오류 응답은 내부 예외를 클라이언트에 노출하지 않았으나 가용성 보완은 필요했다.

우선순위는 수동 검토 분류이며 CVSS 점수가 아니다. 상세 근거·소스 위치는 [findings.json](findings.json), 인터랙티브 요약은 [security-review.canvas.tsx](security-review.canvas.tsx)에 있다.

## 동적 검증 결과

- 기존 보안·브라우저 검사 **229개 통과**: 변경 전 기준선.
- 신규 공격 및 관련 기능 검사 **182개 통과**: 최초 보완 후 REST/A2A/MCP, SQL 문자열, 인증값과 주소 변형 검증.
- 실제 브라우저를 포함한 보안 검사 **78개 통과**: 새 카드의 모든 텍스트·속성 필드 XSS, 화면 및 원본 JSON 인증값 노출, CSP와 공개 메뉴 확인.
- 최종 전체 회귀 **795개 통과**: 공개 상세 응답의 공통 제거 처리까지 포함.
- 마지막 인증 패턴 확장 후 전용 검사 **63개 통과**.

건수는 서로 중복되므로 합산하지 않는다. 초기 `shared-redaction.xml`의 로컬 소켓 검사 1건은 샌드박스 권한 때문에 실패했으며, 필요한 권한으로 실행한 최종 전체 결과에서는 통과했다. 기존 OpenAPI GET/HEAD의 중복 Operation ID 경고 1건은 남아 있으며 보안 검사 실패는 아니다.

## 정적 분석과 의존성

Bandit 원시 결과는 **High 0 / Medium 78 / Low 75**다. 경고를 삭제하거나 숨기지 않았다. Medium에는 문자열 SQL 구조 경고 76개와 와일드카드 바인딩 문자열 2개가 포함된다. 이전 점검과 같은 구문을 추적하고 새 선정기 SQL 1건을 수동 검토했다. 신규 f-string은 고정 SQL 시간 변환식을 삽입하며 사용자 검색어·시간 값은 별도 파라미터로 바인딩한다. 실제 SQL/FTS 공격 문자열로 테이블과 조회 경계가 유지되는지 확인했다.

Low에는 예외 처리·스케줄 난수·개발 설정·OpenSSL 호출 등이 포함된다. 이전 점검의 분류를 참고해 변경된 경로를 검토했으며, 기본 관리자 계정은 도구 경고 유무와 별개로 아래 미해결 항목에 기록했다. **정적 High 0은 미해결 운영 위험이 0이라는 뜻이 아니다.**

`pip-audit`는 설치된 Python 환경의 패키지 53개를 취약점 데이터와 대조했다. 알려진 취약점 0개는 해당 환경·점검 시점에 한정된다. 운영 서버의 설치 버전은 확인하지 않았다.

## 남은 운영 조치

읽기 전용 조사에서 다음을 확인했다.

- **O1 / 높음: 기본 관리자 자격 증명을 유지한 활성 계정 3개.** 로컬 DB 세 곳에서 각각 1개씩 확인했다. 운영에 사용하는 DB의 비밀번호 변경 또는 계정 비활성화가 필요하다. 기존 production 시작 방어는 이 상태의 시작을 거부한다.
- **O2 / 중간: 유효한 레거시 관리자 세션 4개.** 로컬 collector DB에 새 해시 형식이 아닌 세션이 남아 있다. 운영 전 기존 세션 폐기와 재로그인이 필요하다.

DB 파일 4개의 권한은 모두 0600이었다. 알려진 저장 필드의 평문 방문 토큰 잔여 값과 비어 있지 않은 플랫폼 자격 증명 값은 0건이었다. 계정·비밀번호·관리자 세션을 일괄 변경하지 않았다. 이 수량은 로컬 DB 현황이며 운영 호스트의 현황으로 단정할 수 없다. 배포 후 운영 환경 검증도 별도로 필요하다.
