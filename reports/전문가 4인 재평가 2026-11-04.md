### 3.1. UI/UX 기획 (3.7/5)

**좋아진 점**
- 사이트 전체가 "에이전트와 그 운영자"라는 같은 대상을 말한다. 사람 운영자가 떠날 이유가 없어졌다.
- 모바일 홈에서 과업 입력이 첫 화면 안(727px)에 들어왔다. Explore는 검색 뒤 결과가 첫 화면에 보인다.
- 모호한 요청에 추천을 억지로 내지 않고 되묻는다.

**지적**
- **B5(새). 첫 방문자의 첫 동작을 쿠키 배너가 가린다.**
  - 375×812에서 배너가 화면 아래 255px를 차지해 과업 입력(727px)을 덮는다.
  - 데스크톱 Chat에서는 "Find matches" 버튼을 덮는다.
  - 배너는 선택을 강요하지 않는 게 맞다. 다만 첫 화면 정책("고정 내용 즉시 보임")의 취지와 부딪힌다.
  - 개선: 모바일에서는 한두 줄의 하단 띠(약 72~96px)로 줄이고 "Reject non-essential"을 같은 무게로 둔다. 세부 설명은 "How we use cookies"로 접는다.
- **B6(새). 되묻기에 선택지가 없다.** "What should the agent do?" 한 줄뿐이고 `suggested_replies`는 빈 배열이다.
  - 사람은 무엇을 쓸지 모르고, 에이전트는 고를 것이 없다.
  - 개선: 데이터 관련 대표 과업 3개(예: "clean a CSV", "chart a spreadsheet", "query a database")를 칩과 `suggested_replies`로 함께 준다.
- **B3(남음). 추천 이유가 여전히 단어 일치다.** 항공편 요청의 1위 이유는 "the listing covers status, number"다. "Conditions" 줄이 생긴 것은 좋지만, 조건이 없는 일반 과업에서는 이 줄이 안 나온다.

### 3.2. 웹 디자인 (4.1/5)

**좋아진 점**
- 홈 제목 바로 아래에 서비스가 하는 일을 한 줄로 말한다.
- 모바일 Explore가 필터를 접어 결과 중심이 됐다. 가로 넘침은 여전히 0이다.

**지적**
- **W4(새). 배너가 나타나는 동안 반투명 상태로 본문과 겹친다.**
  - 배너는 `backdrop-filter: blur(16px)`에 서서히 나타나는 효과를 쓴다. 그동안 홈 제목·본문과 배너 글자가 겹쳐 읽히지 않는다.
  - 개선: 나타나는 효과를 위치 이동만으로 하고(불투명도 0→1 생략), 배경을 처음부터 불투명하게 둔다. 사용자가 동작 줄이기를 켰으면 효과를 없앤다.
- **W3(남음). 숫자 카드 위계.** "236,530 Cataloged"와 "231,730 Reachable"이 같은 크기로 첫 화면 위쪽을 차지한다. 사람에게 의미 있는 "지금 연결 가능" 하나를 크게 두고 나머지는 작게 두는 편이 낫다.
- 이름 없는 보이는 버튼 3개는 디자인 시스템의 아이콘 버튼 규칙(`aria-label` 필수)으로 막는다.

### 3.3. AI 개발 (3.2/5)

**좋아진 점**
- 과업 해석이 기계가 읽는 형태(`task_spec`)로 나온다. 필수 조건(`no_api_key`), 언어쌍(`en→ko`), 지역, 예보 기간까지 뽑는다.
- 추천마다 `task_fit` 구조와 `quality_policy: task_constraints_verified_recency_v1`가 붙는다. 정책 이름이 응답에 드러나는 것은 2026년 기준으로 좋은 투명성이다.
- 모호한 요청은 `intent: "clarify"`로 구분된다.

**지적**
- **A-4(새). `task_fit`이 조건을 판정하지 않는다.**
  - 환율 요청은 `required: ["no_api_key"]`이고, 추천 3개 모두 `auth_required: false`다. 그런데도 `matched`가 비어 있다. 조건을 지켰다는 근거가 구조에 없다.
  - 번역 요청은 문장에 "Not confirmed: requested language pair"라고 쓰면서 `unknown`은 비어 있다. 사람용 문장과 기계용 필드가 서로 다르다.
  - 에이전트는 기계용 필드만 읽는다. 지금은 모든 후보가 "status: match, 근거 없음"으로 보인다.
  - 개선: `task_spec.required`와 `conditions`의 각 항목을 후보마다 matched / unknown / violated 중 하나로 반드시 넣는다. 문장의 "Conditions" 줄은 이 필드에서 만든다(한 곳에서 만들어 둘이 어긋나지 않게).
- **A-1(남음). 과업 핵심과 어긋난 1위가 6건 중 2건이다.**
  - 항공편: 쇼핑몰 "주문 상태"가 1위이고, FlightAware가 3위다. "status", "number" 같은 흔한 단어가 점수를 만든다. 등급 A가 B보다 앞서는 효과도 겹친 것으로 보인다(재평가 진행 중이라 확정하지 않음).
  - PDF 요약: "검색해서 요약"하는 에이전트가 "가진 PDF를 요약"하는 과업 1위다.
  - 개선 ① 과업의 대상 명사(flight, pdf)를 후보의 기능 설명에서 반드시 찾는 조건으로 둔다. 흔한 단어(status, number, data)는 가중치를 낮춘다.
  - 개선 ② 동작 동사(summarize vs search)를 비교한다.
  - 개선 ③ 등급은 같은 적합도 안에서만 순위를 가른다.
- **A-3(남음). 평가 세트가 없다.** 이번 6건도 사람이 골랐다. 위 6건과 본 보고서의 표본을 기대 답과 함께 고정 세트로 만들고, `selection.py`가 바뀔 때마다 재는 것이 다음 단계다.
- **응답 시간.** 번역 5.26초로 Chat 5초 목표를 넘었다. 언어쌍 조건 확인 단계에서 시간이 더 드는 것으로 보인다. 처음 보는 질의 20건으로 다시 재서 분포를 봐야 한다.

### 3.4. 웹 개발 (4.3/5)

**좋아진 점**
- `security.txt`(RFC 9116), MCP 버전 협상(`2025-11-25`), 공개 문서 edge 캐시가 하루 만에 들어갔다.
- 배포 전 사본 시험이 배포 명령에 묶였다. 11-03 야간 전체 시험은 10,347건 통과에 재현되는 실패 0건이다.
- 보안 헤더(CSP nonce, HSTS, `X-Frame-Options`, `nosniff`)와 problem+json, `RateLimit`, `Idempotency-Key`는 그대로 강하다.

**지적**
- **D5(새). edge 캐시의 보관 시간이 30초다.**
  - Cloudflare 규칙은 원 서버 `Cache-Control`을 따른다. 원 서버가 `max-age=30`이라 edge도 30초만 보관한다. 24회 중 `HIT`는 4회였다.
  - 반대로 브라우저 쪽은 Cloudflare 영역 설정 때문에 4시간이다.
  - 개선: 원 서버가 공개 문서에 `s-maxage=600, stale-while-revalidate=3600`처럼 edge용 값을 따로 보낸다. 또는 규칙의 Edge TTL을 10분으로 둔다. 브라우저 TTL은 "Respect origin"으로 바꿔 30초~5분에 맞춘다.
  - 문서가 바뀌면 Cloudflare 캐시를 지우는 단계(`purge`)를 배포 절차에 넣는다.
- **D2(남음). 페이지마다 숨은 화면이 많다.** Chat 페이지에 버튼 163개, 숨은 구역 60개가 있다. 첫 응답 크기(41~49KB)는 괜찮지만, DOM과 메모리, INP에 불리하다.
- **D6(새). 시험 설정.** 저장소에 pytest 설정(`testpaths = tests`)이 없어서, 경로 없이 돌리면 내장 Python 표준 라이브러리 시험까지 모아 1,371건 오류가 난다(11-03 야간 첫 실행). 흔들리는 시험 3건(CSP와 `wait_for_function` 문자열 식, 로거 상태 순서 의존, 늦은 응답 타이밍)도 고쳐 둔다.
- **D4(남음). 비동기 작업과 Web Bot Auth.** 버전 협상은 됐지만, 워크플로 실행을 MCP 비동기 작업(작업 ID, 상태, 취소)으로 노출하는 일과 수집기 요청 서명은 아직이다.
