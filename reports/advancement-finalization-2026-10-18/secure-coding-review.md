# Secure-coding review scope

The review covers purpose-specific authority, token/session confusion, tenant object access, duplicate admission/dispatch, unknown outcomes, restore revocation, private signatures and encryption, bounded model guidance, safe DOM rendering, callback access-log handling and the public launch hold. It is a source and isolated regression review, not a whole-platform penetration certificate.

Two independently reproduced root integration defects were corrected: automatic model-response decompression before its size check, and authentication codes/state retained in Uvicorn response-start scopes when customer callbacks were closed or rejected before routing. New tests reject compressed/invalid-length model responses and exercise held, early-rejected, malformed and successful Google/GitHub callbacks through the actual frontend middleware. The native browser uses synthetic private APIs and mocked model/provider responses.

The root static scan retains its raw findings rather than suppressing them. `B608` frontend queries assemble fixed server-owned SQL clauses and bound placeholders; request values remain parameters. The `B108` location checks a temporary-path substring only for a cache namespace and creates no temporary file. The product-composer `B105` value is a false boolean output marker, not a password. Low exception-handling findings occur in guarded compatibility/cache/projection cleanup paths; they are not evidence that every ignored failure is harmless in every future caller. These classifications apply to the inspected current paths and are not a waiver for new SQL or silent security failures.

The PostgreSQL application profile is independently reviewed and tested in disposable Unix-socket clusters. Its native schema trigger/function attestation, rollback poisoning and inherited libpq environment isolation are separate findings and verification, recorded in the application report. Unsupported legacy Store paths remain source work and cannot be relabeled as external operating acceptance.

Limits remain: actual identity-provider setup, operating ingress/provider/browser logs, operating model quality, key custody/rotation/retention policies, lost-IdP recovery and physical backup erasure, real provider control/independent expert assessment, representative workload/DR/HA and full PostgreSQL cutover, legal provider assent, payments and payouts. No operating server restart, DB migration, key rotation, advertising delivery or real commerce was performed.
