## 하드링크 사용 시 주의

하드링크로 통합된 경로는 동일한 실제 파일입니다. 어느 경로에서든 파일 내용을 제자리에서 변경하면 다른 연결 경로에도 반영됩니다. 특정 제안서나 이미지만 별도로 수정할 때는 먼저 독립 사본을 만들고 그 경로의 파일을 교체해야 합니다. 정확한 연결 관계는 `cleanup-plan.json`과 `cleanup-result.json`의 canonical 항목에서 확인할 수 있습니다. 파일 내용과 기존 경로는 이번 정리로 바뀌지 않았습니다.

`.git/`의 기존 스냅샷이 가진 사본은 그대로 남아 있습니다. 이번 확보량에 Git 정리 예상치를 더하지 않았습니다. 파일 경로별 크기를 단순 합산하면 하드링크가 중복 계산될 수 있으므로, 실제 사용량은 `du` 또는 inode를 한 번씩 세는 방식으로 확인해야 합니다.

## 상세 내역

- `cleanup-plan.json`: 그룹별 보존 파일, 삭제/통합 계획, 캐시 범위
- `cleanup-result.json`: 실제 완료 작업과 정리 전후 할당 공간
- `cleanup-verification.json`: 전체 해시·inode·디자인 manifest 검증
- `cleanup-live-verification.json`: 서비스 경로 응답 검증
- `cleanup-summary.json`: 최종 수치 요약

정리 전 조사인 `README.md`, `inventory.json`, `duplicates.json`은 비교 자료로 보존했습니다. 중간 파일 삭제와 경로를 유지한 중복 데이터 통합을 구분하여 기록했습니다.
