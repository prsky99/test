# 검색 미충족 원인 수정 및 로그인·외부 실행 점검

작성: 2026-10-26. 현재 단계는 **소스 수정·격리 검증 완료, 프론트엔드 반영 및 실제 계정 로그인 대기**다. 운영 복구가 완료됐다고 판정하지 않는다.

## 확인한 원인과 수정

1. compact 검색이 추천기의 기본값인 후보 1개만 조회했다. 그 후보의 현재 버전 실행 증거가 만료되면 뒤의 적격 후보를 확인하지 않고 `no_match`로 종료할 수 있었다. 프로토콜별 최대 32개 후보를 검증하고 최대 3개를 반환하도록 수정했다. 자동/Any는 적격 A2A 우선, MCP 보충을 유지하며 x402를 자동 포함하지 않는다. 전체 카탈로그 무제한 탐색은 하지 않는다.
2. 실제 문서 검색은 성공했지만, Worker 경로가 기존 Origin MCP 프록시를 우회하여 검증 이력을 쓰지 않았다. DB에서 동일 연결 버전의 최신 Edge 성공과 만료된 기존 `capability_evidence`를 대조해 확인했다. 공개 ManagedGateway의 확정된 Worker MCP 완료도 기존 Registry에 기록하도록 수정했다. Origin MCP는 원래 프록시가 기록하므로 중복으로 기록하지 않는다.

실행 성공을 임의로 DB에 입력하거나 만료 시간을 연장하지 않았다. 연결 버전이 달라지거나 결과가 불확실한 실행은 현재 연결의 성공 검증으로 인정하지 않는다. 후보의 오래된 표시 시각 대신 현재 증거 스냅샷의 시각을 반환한다.

변경 소스:

- `agent_market/agent_access/catalog.py`
- `agent_market/concierge/managed_gateway.py`

## 실제 외부 작업

공개 서비스에서 ByJG Open Source Docs의 `search_docs`를 `micro-orm`, 최대 2개 결과로 1회 실행했다. HTTP 200, 실제 실행 성공, 전송·프로토콜 검증 정상, 약 2.54초, 시뮬레이션 아님을 확인했다. 공개 문서 출처 링크가 포함됐다. 계정 키·개인 데이터·크레딧·금액을 제공하지 않았다.

- [실제 실행 결과 요약](live-docs-execution.json)
- [현재 버전과 Worker 성공/검증 증거 대조](evidence-gap.json)
- [공개 제공자 계약 검토](provider-review.json)

이 호출 뒤에도 **현재 운영 중인 이전 코드**의 동일 compact 문서 검색은 MCP·자동 모드 모두 `no_match`였다. 이는 수정본 반영 전 실패 증거로 [보존](recovered-live-discovery.json)했다. 파일명과 달리 내용의 `passed=false`가 실제 결과이며 복구 성공 증거가 아니다. 배포 후 같은 요청을 다시 확인해야 한다.

## 검증

최신 결과를 테스트 식별자로 중복 제거하면 **313개 통과, 미해결 실패 0개**다. 실제 계정 인증 또는 운영 업무 전체 통과 수치가 아니다.

- 검색·실행·Edge 경계: [134개](execution-search-regressions.xml) 통과.
- ManagedGateway API·입력/권한/타임아웃·브라우저: [119개](managed-gateway-security.xml) 통과.
- 합성 Google/GitHub 로그인·재로그인·compact 브라우저: 최초 60개 중 58개 통과. 모바일 로그아웃이 메뉴 안으로 이동한 현재 UI에 맞춰 테스트 동선을 수정한 뒤 [로그인 브라우저 5개](auth-browser-refreshed.xml)가 모두 통과했다. 동일 테스트의 이전 실패를 최신 결과로 대체했으며 최초 로그는 보존했다. 로그인 제품 소스를 수정한 것은 아니다.
- 정적 시큐어코딩 F/E9/S 검사 통과. 공개 콘텐츠 290개, 위반 0개. Python 문법 검사 정상.
- Worker 완료 후 compact 발견 가능, 만료/최신 실패/연결 버전 불일치 제외, 불확실 결과 미승격, Origin 이력 중복 방지, 실행 중 계약 변경 시 새 버전 미승격을 확인했다. 격리 회귀의 제공자는 합성이다.

## 실제 로그인 상태

기존 Chrome 프로필·쿠키를 읽지 않고 새 Chrome 창을 열었다. 사용자가 Google 또는 GitHub 계정으로 직접 로그인해야 실제 워크스페이스 접근과 기존 QA 워크플로우를 확인할 수 있다. 마지막 확인은 인증 전 HTTP 401이었다. 비밀번호·MFA·인증 코드를 요청하거나 세션을 위조하지 않았다. 쿠키·토큰·브라우저 저장 상태를 산출물에 내보내지 않는다.

로그인 완료 전에는 운영 계정의 메뉴·워크플로우·실행 권한·외부 실행을 검증했다고 주장하지 않는다. 합성 Google/GitHub 테스트 결과와 실제 로그인 완료는 구분한다.

## 적용 대기

`compact-discovery-proof-20261026-r1`을 1,268개 파일의 불변 릴리스로 준비했다. 전체 manifest, 영향 소스 2개 일치, 패키지 인터프리터 import를 확인했다. 새 DB 테이블·마이그레이션·모델 변경은 없다.

```sh
./agentcon deploy frontend compact-discovery-proof-20261026-r1
```

이번 공개 검색·테스트 경로의 수정은 프론트엔드 교체로 반영한다. jobs·어드민·execution 교체는 이 수정의 적용 조건이 아니다. 저장소의 명시적 서버 교체 지시 규칙에 따라 적용 승인을 요청한 상태이며, 아직 운영 프로세스를 교체하지 않았다. [패키지 검증](package-verification.json), [체크포인트](checkpoint.json)를 참조한다.

남은 순서: 프론트엔드 적용 → 실제 문서 조회 재실행 → 현재 버전의 성공 이력과 동일 compact 검색 확인 → 실제 로그인 세션의 워크스페이스 메뉴·기존 검증용 워크플로우 실행 확인. 새 저장·크레딧 사용·추가 실행 권한 발급은 필요성과 기존 승인 범위를 확인한다.
