사용자 기준: "품질등급 A가 진주(후보)여야 하고, 테스트 결과 보고서 최고 품질이 최종 진주가 되어야 함."

- 운영 DB 구조는 바꾸지 않습니다. 1단계는 파일로 하고, 2단계(DB)는 리허설·복구 SQL·승인 순서를 거칩니다.

## 1. 시험 보고서 v2 = 역할 과제 시험 (배정 2번)
### 시험 방법
- `scripts/role_tool_test.py` 방식을 표준으로 씁니다.
  - 역할 도구를 실제 인자로 1회 호출합니다.
  - 중계 허용 읽기 전용 도구만 부르고, 제공자 규칙(하루 3회, 60초 간격, 429면 그날 중지)과 개인정보 금지를 지킵니다.
- 인자 우선순위:
  1. 워크플로우 팀의 역할별 고정 과제 입력(정답 세트 형식)
  2. 도구 스키마의 예시나 기본값
  3. 역할별 공개 일반값

### 내용 판정 (새로 추가)
- 역할마다 기대 조건을 둡니다.
  - 워크플로우 팀 정답 세트가 오면 그것으로 바꿉니다.
  - 그 전에는 아래 기본 판정을 씁니다.

| 역할 | 기본 판정(모두 만족해야 통과) |
|---|---|
| papers.search | 논문 제목 같은 줄 1개 이상, 그리고 연도(19xx/20xx)나 DOI/arXiv id |
| encyclopedia.summary | 입력 주제어가 응답에 나옴 + 80자 이상 서술 |
| news.search | 날짜 1개 이상 + 제목 같은 줄 |
| package.advisories | 입력 패키지 이름 + 취약점 id(GHSA-/CVE-) 또는 "no known vulnerabilities" 명시 |
| package.metadata | 입력 패키지 이름 + 버전 번호 형식 |
| country.indicator | 국가 코드나 이름 + 숫자 값 + 연도 |
| fx.rate | 두 통화 코드 + 0이 아닌 숫자 |
| weather.forecast | 기온 수치나 단위(°, C, F) + 날짜나 요일 |
| events.search | 행사 이름 같은 줄 + 날짜. 입력 지역 밖이라는 답은 실패 |
| cve.kev | 입력 CVE id + 심각도나 CVSS나 KEV 여부 |
| company.lookup | 입력 회사 이름 + 등기·LEI·주소 같은 식별 정보 1개 |

- 거절 응답("not covered", `{"error": …}`, "API key required")은 실패입니다.
- 보고서에는 결과 발췌(최대 1,000자), 판정 항목별 통과·실패, 판정 규칙 버전을 남깁니다.

### 실패도 보고서
- 결과는 succeeded, failed, refused, stopped(추가 입력 요구), skipped(안전 규칙) 가운데 하나로 남깁니다.
- 결과와 상관없이 보고서 파일을 씁니다.
- 공개 문구 검수는 운영·SRE가 맡습니다(점검 보고서 7절).

### 새 판 추가
- 지금 에이전트당 보고서 1개 제한은 DB에서 걸립니다.
  - 고유 색인: `idx_report_creation_subject ON agent_test_reports(creation_subject_key)`
  - 주장 표: `test_report_subject_claims`
- 그래서 "새 판 추가"는 DB 변경입니다.
- **1단계(지금, 파일):** 판이 쌓입니다. 경로는 `exports/pearls/reports/<resource_id>/<role>/<YYYYMMDD-HHMM>.json`이고, 판 번호는 같은 (자원, 역할) 안에서 1, 2, 3…입니다. 최신 판 색인은 `exports/pearls/latest.json`입니다.
- **2단계(DB, 승인 뒤):** `agentcon_search.test_report_versions` 표를 새로 만듭니다.
  - 열: 자원, 역할, 판 번호, 결과, 점수, 발췌, 판정, 시각
  - public 스키마도 트리거도 아닙니다.
  - 공개 보고서 화면은 이 표의 최신 판을 보여 줍니다. 이 화면 변경은 앱 배포입니다.
  - 기존 `agent_test_reports`와 고유 색인은 그대로 둡니다. 연결 보고서는 "이전 기록"으로 남습니다.
  - 순서: 리허설(네 역할 버전 연결) → 복구 SQL → 사용자 승인 → 실행

## 3. 최종 진주 (배정 4번)
- 같은 역할 키 안에서 그날 최신 판의 품질 점수로 순위를 매깁니다.
  - 1위이고 85점 이상: **최종 진주**
  - 2·3위(점수 제한 없이 성공 판): **외부 대체**
- 같은 등록 도메인은 한 역할에서 한 자리만 셉니다(장애 영역 규칙).
- 매일 다시 매기고, 결과를 `exports/pearls/final-YYYY-MM-DD.json`과 `role_groups.json`(워크플로우 팀 입력)에 씁니다.
- 조건 7(도구 정의 변경)은 운영·SRE 지문으로 판정합니다.
  - 진주 근거 도구의 정의가 바뀌면 재시험 전까지 순위에서 뺍니다.
  - 다른 도구가 추가된 것만으로는 빼지 않습니다.
- 지금 진주 25개는 "1차 진주"로 남기고, v2 순위가 나오면 대체합니다.
  - 38634와 47538은 역할 시험이 실패해 이미 순위에서 빠집니다.

## 6. 진주 분야 (배정 6번)
- 진주의 분야는 카탈로그 category가 아니라 역할 키로 정합니다.
  - 예: papers.search → research, cve.kev·package.advisories → security, fx.rate → finance
- 대응 표는 `role_groups.json`에 `domain` 칸으로 넣습니다.
- 점검에서 나온 오분류(popdot 도메인 검색, ceadigital CISA KEV가 finance_crypto)는 역할 키로 다시 매기면 바로 고쳐집니다.
- 카탈로그 category 자체는 바꾸지 않습니다. 그것은 classify.py VERSION 일이라 이번 범위가 아닙니다.
