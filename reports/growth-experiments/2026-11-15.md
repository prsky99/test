# 성장·매출 실험 목록 1차 (2026-11-15, PM)

사용자 지시(11-15): "더 적극적으로 방법을 찾아서 진행. 문제가 있을 때 논문과 SNS 검색으로 해결하고 새로운 아이디어를 발굴."
조사는 논문·회사 문서·HN·보안 보고서를 읽어 모았다. Reddit과 X는 원문을 직접 열지 못해 인용 글을 거쳤다. "(자체)"는 회사가 스스로 밝힌 수치다. 매주 갱신한다.

## 1. 근거가 가리키는 것

1. **에이전트가 도구를 계속 쓰는 이유는 "적은 컨텍스트로, 설정 없이, 바로 호출되는 것"이다.**
   - 도구 정의를 미리 싣지 않고 검색으로 불러오면 컨텍스트가 약 77K에서 8.7K 토큰으로 줄고 정확도가 오른다(자체). https://www.anthropic.com/engineering/advanced-tool-use (2025-11-24)
   - LiveMCPBench: 실패의 50%가 도구 검색 오류, 18.3%가 도구 자체 오류. 대다수 서버가 API 키를 요구한다. https://arxiv.org/html/2508.01780v2
   - 도구 설명 품질이 선택을 좌우한다: 표준을 지킨 설명의 경쟁 상황 선택 확률 72%(기준 20%). https://arxiv.org/abs/2602.18914 . 다만 보강하면 실행 단계가 67% 늘고 16.7%는 나빠진다. https://arxiv.org/abs/2602.14878
   - "연결만 하고 호출하지 않음"은 흔하다. https://claude.com/docs/connectors/building/managing-your-listing.md
2. **레지스트리에 없는 신호가 우리가 이미 재는 것이다.**
   - 9,695개 서버 조사: 검증 표시가 있는 서버도 문제 수가 같고 별 수와도 무관. https://www.trendaisecurity.com/en/resources-insights/research/stars-dont-save-you-popularity-is-not-security-in-the-mcp-ecosystem (2026-06-24)
   - 레지스트리에 없는 신호: 운영자 신원, 실행 서버와 소스의 일치, 서명된 출처, 유사 이름, 폐기·도메인 만료. 권고는 고정 버전 허용 목록. https://labs.cloudsecurityalliance.org/research/csa-research-note-mcp-marketplace-governance-ox-20261007-csa/ (2026-10-07)
   - 도구 추가·설명 변경 때 경고하라는 권고와 무료 구현. https://blog.trailofbits.com/2025/07/28/we-built-the-security-layer-mcp-always-needed/
   - 기업의 최대 장애물은 보안·컴플라이언스 49%(업체 설문). https://forkast.news/mcp-locked-in-its-architecture-today-now-the-hard-part-enterprise-adoption-at-scale/
3. **조직은 레지스트리 주소를 지정해 그 밖의 서버를 막을 수 있다.** GitHub Copilot·VS Code가 v0.1 MCP registry 규격의 자체 레지스트리와 "Registry only"를 지원한다. https://github.blog/changelog/2025-11-18-internal-mcp-registry-and-allowlist-controls-for-vs-code-stable-in-public-preview/ . 공식 Registry는 보안 검사를 하위 집계자에 맡긴다. https://modelcontextprotocol.io/registry/about.md
   → **시험을 통과한 서버만 담은 규격 레지스트리**는 우리만 낼 수 있는 것이고, 기업이 주소 하나로 쓸 수 있다.
4. **집중된 작은 묶음이 큰 묶음보다 낫다.** 모듈 3개 이하의 스킬이 통과율을 33.9%→50.5%로 올렸다. https://arxiv.org/abs/2602.12670 . 설치가 가장 많은 스킬 분류는 웹 검색. https://arxiv.org/html/2602.08004v1
5. **건당 과금은 지금 돈이 되지 않는다.** x402 판매자 30일 중앙값 $0.04, 상위 10개가 79%. https://x402stats.io/reports/2026-09 . 사용자 결정(목걸이 무료 이벤트)과 같은 방향이다.
6. **llms.txt는 인용을 늘리지 않는다.** 파일이 있는 도메인의 97%가 한 달 요청 0건. https://ahrefs.com/blog/llmstxt-study/

근거가 약한 통념(따르지 않음): 검증 배지·별이 안전을 뜻한다 / 디렉터리 등재나 설치 버튼이 설치를 늘린다 / 건당 과금을 붙이면 에이전트가 결제한다 / 묶음 워크플로우가 재사용이 많다(성공률 근거만 있음).

## 2. 실행하는 실험

| # | 실험 | 근거 | 담당 | 측정 | 목표일 |
|---|---|---|---|---|---|
| E1 | 연결→목록→호출→재방문 깔때기 계측(MCP·A2A·REST) | 1 | 운영·SRE | 단계별 전환율, 호출 없는 세션 비율 | 11-18 |
| E2 | MCP 도구 설명 다시 쓰기: 목적·언제 쓰나·무엇을 돌려주나, 짧게. 클라이언트 묶음으로 A/B | 1 | 성장·유통(문구) + 검색과 RAG(배분) | 세션당 호출 비율 | 11-19 |
| E3 | 기본 노출 도구를 2~3개(찾기·확인·실행)로 줄이기. 먼저 지금 tools/list의 토큰 수 측정 | 1 | 검색과 RAG | tools/list 토큰, 호출 비율 | 측정 11-17 |
| E4 | 추천 기본값을 "키 없이 지금 호출 성공"으로, 마지막 성공 시각 표시 | 1 | 검색과 RAG | 연결 성공률, real_task_score | 밤 창 11-18~19 |
| E5 | 도구 정의 변경 피드(해시·바뀐 곳, JSON). 의미 있는 변경만 | 2 | 에이전트 팀 + 운영·SRE(지문) | 되풀이해 받아 가는 클라이언트 수 | 11-20 |
| E6 | 수명 신호 파일: 죽은 호스트, 만료가 가까운 도메인, 유사 이름 | 2 | 에이전트 팀 | 요청 수, 외부 인용 | 11-21 |
| E7 | **검증 레지스트리**: 시험 통과 서버만 담은 v0.1 규격 엔드포인트(CORS). 조직이 주소 하나로 허용 목록을 씀 | 2, 3 | 에이전트 팀(운영·SRE 검토) | 주기적으로 받아 가는 고유 클라이언트 | 설계 11-18, 공개 11-24 |
| E8 | 목걸이는 3단계 이하, SKILL.md로도 내려받게 | 4 | 워크플로우 | 다시 실행한 클라이언트 수 | 첫 공개 때 |
| E9 | 목걸이 주제 우선순위에 웹 검색·정보 수집 반영 | 4 | 워크플로우(100개 계획) | 목걸이별 실행 수 | 11-17 |
| E10 | 방법론·보고서에 "배지·별은 안전이 아니다"의 근거와 우리가 실제로 재는 항목 | 2 | 성장·유통 | 보고서 조회→API 호출 | 11-19 |
| E11 | llms.txt 요청 로그 점검(누가 읽나) 뒤 맨 위 문구 조정 | 6 | 성장·유통 | 요청 주체별 건수 | 11-18 |
| E12 | Claude Connectors Directory 요건 맞추기(도구 title, readOnlyHint·destructiveHint, 문서·개인정보 주소, 아이콘). 제출과 약관 동의는 사용자 | 유통 2-2 | 성장·유통 + 검색과 RAG | 요건 점검표 | 11-20 |

하지 않는 것: 목걸이 건당 과금(사용자 결정: 무료 이벤트), 커뮤니티 게시(목걸이 100개 뒤), 설치 버튼(효과 자료 없음, E1 뒤 재검토).

## 3. 방향

E5·E6·E7을 한 묶음으로 본다. "실제 호출로 확인한 서버만, 바뀌면 알려 주는 레지스트리"는 조사한 보안 보고서들이 없다고 지목한 것이고, 조직이 주소 하나로 쓸 수 있으며, 개발자용·제공자용 이용권의 혜택(대량 접근·알림)과 이어진다. 유료 순위나 배지 판매 없이 신뢰를 파는 길이다.
