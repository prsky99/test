Latest development update: **The requested basic Google/GitHub account creation, sign-in and service sign-out checks are complete. After the user's corrective restart, GitHub sign-in, sign-out and returning sign-in passed in Chrome. The public Workspace link and Home promotion were verified hidden, while direct customer sign-in remains available.** The source retains its 305 passing scoped regression cases. The link has not been re-enabled; it remains hidden until the user confirms release.

2026-10-19 · User-authorized opening of the customer Workspace surface.

## Implemented

- `CUSTOMER_WORKSPACE_ACCESS_ENABLED=1` enables direct customer route testing. The independent `CUSTOMER_WORKSPACE_LINK_ENABLED=0` hides public navigation and Home advertising. Both code defaults stay closed. Their running-server reflection was verified in Chrome after the user's corrective restart.
- Google and GitHub use the already registered clients. Their existing private credentials were connected to the owner-only, Git-ignored runtime settings file. No credentials were printed or added to public source.
- First verified sign-in creates a provider-linked customer account. Returning sign-in reuses it. Email is not an account-linking key; two providers are not silently merged. Customer identity grants no staff privileges or access to another customer's workspace.
- Sign-out revokes the customer session and its BFF capabilities. Authenticated sign-in navigation returns to Workspace; guest Workspace navigation opens sign-in. Failure and cancellation offer a fixed retry route without exposing provider diagnostics. Initiation failure restores the provider buttons.
- The English account views use local Lucide icons, responsive light/dark styling, accessible status/focus and nonce CSP. Opaque account IDs, credentials and raw diagnostic responses are not rendered. Public HTML remains synchronized with its embedded source.
- Google ID tokens accept its two documented issuer spellings only after signature and claim verification, then normalize before account lookup. See [Google's issuer requirements](https://developers.google.com/identity/openid-connect/openid-connect). Existing code/PKCE S256 and provider restrictions remain; see [GitHub's OAuth flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps).

## Actual account test status

- After the user's restart, `/customer/sign-in` rendered and both providers became available. Google selected the requested account in its provider UI; the verified callback opened Workspace and the session displayed signed in. Service sign-out returned to sign-in; sanitized access records confirmed logout 200 and the subsequent session check 401. See [live signed-in](live/google-signed-in.jpg) and [live signed-out](live/google-signed-out.jpg) screenshots.
- GitHub confirmed the `prsky99` account with **Public data only**. Two fresh attempts returned to the safe failure view. A read-only aggregate query showed only the Google flow consumed, narrowing rejection to before token exchange. A single deliberately invalid-code diagnostic returned GitHub `bad_verification_code`; no real authorization code or token was reused or saved.
- GitHub's [published metadata](https://github.com/.well-known/oauth-authorization-server/login/oauth) advertises `authorization_response_iss_parameter_supported=true` and issuer `https://github.com/login/oauth`. The old guard rejected every GitHub `iss`. The fix accepts only that exact authorization issuer while retaining `https://github.com` as the existing account namespace, plus state/browser/PKCE checks. Wrong, cross-provider and lookalike issuers remain rejected.
- After the user reloaded the fix, GitHub callback opened Workspace and the authenticated session rendered successfully. Sign-out returned to sign-in, and another GitHub sign-in returned to the existing account. Both test sessions were then signed out. See [GitHub signed-in](live/github-signed-in.jpg), [returning sign-in](live/github-returning-signed-in.jpg), [signed-out](live/github-signed-out.jpg) and [final signed-out](live/final-signed-out.jpg).
- A [read-only aggregate](live/provider-account-aggregate.json) confirmed one customer identity per tested provider, two GitHub sessions from the original/returning sign-ins, and no unexpired unrevoked test sessions. Account creation times matched the first successful callbacks; identities were not duplicated by returning sign-in. No identity IDs, emails, subjects or private profile fields were retained in this evidence.
- Chrome verified **zero Workspace navigation links and zero Workspace Home promotion elements**, with the remaining navigation intact. See [hidden public link](live/public-workspace-link-hidden.jpg). Direct `/customer/sign-in` remained functional. No source or server configuration changed in this final confirmation, and no further restart is requested.
- A supplementary generic non-browser GET check returned HTTP 403. It is not used as passing deployment-header evidence; the live link visibility and sign-in flows above were verified through the actual Chrome UI. No ingress/security protection was weakened to run the check.

No provider code, token, credential, raw callback query or private profile response is copied into the evidence. Actual account results are recorded separately from synthetic regression results. All server restarts were performed by the user; only normal application sign-in/sign-out wrote customer records, and no production data was modified directly.
