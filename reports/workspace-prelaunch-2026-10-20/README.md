# Workspace prelaunch usability remediation

Source implementation and isolated acceptance: 2026-10-20. Public Workspace navigation remains closed. The operator's existing server is never started, stopped or replaced by this task. Restarted operating-service acceptance is recorded separately below when available.

## Changes

- The studio now has four keyboard-accessible stages: Design, Review & save, Test, and Download. Only the selected stage is shown. AI proposals advance to a structured review; a confirmed save advances to testing. Exact proposal/input data remains available in disclosures. The AI objective is a multiline field with public-input guidance.
- Saved workflows appear on entry, ordered by signed update time. The current workflow, revision and unsaved state are explicit. A separate New workflow action and discard dialog protect drafts. Changes to the objective, name or steps invalidate the previous test/release state. Unsaved edits cannot execute a previously saved graph. Sign-out also checks for unsaved edits before sending logout.
- Pearl nodes show the declared source references. Connector strokes appear only for an actual adjacent dependency. The preview retains focus when consent or other unrelated state changes. Result links are restricted to HTTPS without URL credentials; result text remains escaped.
- Valid existing deployments and download controls are restored from the scoped release history. The new read-only deployment-list route uses current customer session, workspace authority and exact release scope. ZIP download errors stay in the studio rather than navigating to an API error document. Export still requires an owner, a successful tested version, separate origin authorization, an active release and current enrollment.
- Initial independent lookups run concurrently, redundant reads were removed, and requests have bounded waiting. Failed access has retry/sign-in actions. Known validation/access failures are distinguished from ambiguous mutations; no mutation is automatically repeated. Optional feedback and A2A panels load on demand and cannot masquerade as a failed login. A2A history cannot clear a graph's uncertain execution state.
- Overview selects a sole organization, makes AI workflow creation the first organization action and keeps selected-organization links coherent. Team controls, advanced individual tasks and destructive settings use disclosures. Member removal requires a confirmation dialog. Organization writes also report credit/enrollment failures correctly. Read-only actions no longer claim to have saved changes.
- Sign-out is available in the common header, including studio and plan views. Recovery and downloaded-app authorization now share the Pearl shell, local Lucide SVGs, light/dark appearance and responsive layout. Recovery completion is disabled until the retained request's review period has elapsed. Enrollment keeps its separate unchecked legal choices and gains a clear continuation action and empty credit-history state.
- Native customer pages retain English copy, private metadata, no-store/noindex headers, nonce-based CSP, visible keyboard focus and reduced-motion support. Generated account pages are synchronized with the native sign-in logic. No public login/workspace switch was enabled. No private workflow or objective is persisted in browser storage; only the theme preference uses browser storage. The header uses the same Pearl pill switch and session preference as the public frontend, with a legacy local preference fallback, keyboard operation and an expanded pointer target. Dark-theme selected-stage text has a measured contrast regression.

### Defects fixed during acceptance

- Download transport failures preserve the release and show an explicit history/manual retry path without rerunning a workflow. Download fetches have a 20-second bound. A failed read or download cannot clear an existing uncertain mutation.
- ZIP handlers reuse one transport actor per request. Revision lookup contention is normalized to a safe conflict response through the existing exception boundary. An injected-contention regression proves a later explicit retry works without extra debit or execution; it does not establish the cause of the observed live download response failure.
- AI availability now requires a currently eligible approved agent, rather than merely a configured model and historical connection metadata. Reading current history refreshes availability without discarding the current objective. A stale-access advisory failure does not blame the objective or conceal an expired sign-in.
- Credit enrollment controls remain hidden and disabled while account state and the exact current terms are loading; an already-enrolled customer no longer briefly sees a join form. This last slow-response refinement passed 15 relevant Chromium cases. After the operator's final restart, CUA also observed hidden/disabled enrollment controls during the initial read, then the active-account view with no join form, a balance of 99,988 and the two retained debit events. The theme preference persisted across navigation. Evidence: `live-credit-enrollment-final.png` and `completion-state.json`.
- Workspace theme appearance and preference behavior match the published frontend. Keyboard, invalid preference fallback, navigation persistence, small headers and selected-tab text contrast are covered.
