# 전체 Provider·장기 부하 검증 현황

전체 등록 149,052건의 정적 분류를 완료했다. 실제 개별 호출은 완료 미확정으로 보호 대기 중이다. 기존 격리 부하는 메모리 안전 기준으로 중단됐으며, 별도 디렉터리에서 24시간 목표 재검증을 시작했다. 확대된 운영 검증에서 CPU 최대 23.6ms를 관측하여 Free 기준10ms의 상시 충족을 확인하지 못했다. 운영 순회는 CPU 초과와 완료 미확정 감지 시 보호 대기하도록 구성했다. 이 문서는 모든 Provider가 성공했다는 인증 자료가 아니다.

## 전체 등록 분류

동일한 읽기 전용 PostgreSQL 스냅샷으로 등록 ID 160175까지 149,052건, 고유 호스트 26,896개를 분류했다. 운영 DB 쓰기와 Provider 호출은 각각0건이다.

- 정책상 실행 제외: 123,745건. 인증·결제·비활성·상태·안전 정책 등의 제한을 그대로 적용했다.
- 정적 호출 후보: 18,080건. 현재 DNS와 실제 프로토콜 계약은 실호출 단계에서 검증한다.
- Schema 확보 필요: 3,135건.
- 안전한 입력 준비 필요: 3,249건.
- 메타데이터 검토 필요: 843건. 대용량 메타데이터 등 기존 Edge 프로필 범위를 구분했다.

동일 연결·입력·Schema 중복 13건을 정리한 개별 순회 입력은 18,067개다. Schema가 제공한 기본값/예제에 포함될 수 있는 인증정보·개인정보·외부URL·복합 값은 그대로 전송하지 않는다. 상세 ID별 분류는 census.jsonl, 후보 입력은 소유자만 읽을 수 있는 recipes.jsonl에 저장했다.

## 실제 운영 순회

기록 시점 219건을 분류했다. 최초 관측 분류는 Worker 실행 성공 120건, 결과 미확정 28건, 완료 확인 대기 4건, 실행 실패 55건, 검증·정책 제한 12건이다. 이 숫자는 개별 응답을 기록한 시점 기준이며, 이후 영수증 상태가 바뀔 수 있다. 현재 대기 사유는 `receipt_unsettled`, 대상 등록 ID는 55450이다. 불확실한 작업을 재실행하거나 완료 처리하지 않았다.

전체 최소 10초, 호스트별 최소 30초 간격과 동시 1건을 유지한다. 사용자 선택에 따라 운영 검증 시한은 최초 시작부터 24시간으로 적용했다. UTC 시한은 2026-10-24T14:04:29.556689+00:00이다. 72시간 승인은 로컬 상태 추적에만 적용한다. 이 속도에서는 후보 18,067개 전체의 개별 실행을 24시간 안에 완료하기 어려우므로, 시한 종료 시 실제 검증한 범위와 잔여 대상을 구분한다.

Provider별 소개·조회 요청 또는 x402 미결제 GET probe만 사용한다. 인증·결제·외부 쓰기 작업, 보안/무료 한도 우회, 불확실하거나 이미 실행한 요청의 자동 재실행은 하지 않는다. 호출 의도를 먼저 기록하여 프로세스 중단 후에도 같은 Provider 작업을 무조건 반복하지 않는다. 응답 본문은 저장하지 않고 상태·해시·바이트·영수증을 저장한다.

확대 표본에서 일부 완료 기록이 늦거나 누락되는 현상을 확인했다. 기존 결과 미확정 상태를 강제로 성공 처리하지 않았다. Worker에 일시적인 완료 callback 오류만 최대3회 재시도하도록 보강했다. 실행·attempt·결과 메타데이터는 동일하게 유지하고 매번 새로운 HMAC nonce를 사용한다. Provider 실행은 반복하지 않는다. 확정할 수 없는 callback은 비공개 이벤트로 남긴다. 원인 전체가 확정됐거나 모든 누락을 해결했다는 주장은 하지 않는다.

보강 버전 `30b03bd3-c801-446d-a157-3cf70063d803`가100% 배포됐고,5개 fail-open Route·암호화 Secret·Free를 유지했다. Frontend·Admin·Jobs·Execution의 실행 상태는 바꾸지 않았다. 기존 공개 응답과 Provider 주소 보호를 유지했다.

## 24시간 격리 부하

실제 배포 Worker 소스 스냅샷의 첫 격리 시험은 활성 8.2시간, 115,404건 후 `Worker heap safety threshold`로 실패 종료했다. 시나리오별 예상 밖 응답 오류는 0건이었으나, 메모리 기준 실패 때문에 24시간 통과로 판정하지 않는다. 마지막 Worker JS heap+backing store는 약 102.1 MiB였고, 자체 중단 기준 100 MiB를 넘었다. Node 프로세스 RSS와 Worker heap은 별도 지표이다. 원본 `soak-current-24h` 기록을 보존했다.

후속 시험은 `soak-memory-diagnostic-24h`에서 24 활성 시간, 4요청/초, 최대 동시 4건으로 시작했다. 동일 배포 소스 SHA를 사용하고 모든 Provider·제어 요청을 모의 처리한다. 실제 외부 Provider 호출은 0건이며 기존 100 MiB 안전 중단 기준을 유지한다. A2A JSON/1.0/SSE, MCP JSON/SSE/Schema, x402, 의도한 오류·잘못된 UTF-8·과대 응답·Origin 전환을 혼합한다. 초기 실패 시간과 후속 시험 시간을 합쳐 연속 24시간 통과로 계산하지 않는다.

추가 진단은 시험 완료 또는 실패 후에만 GC 전후 heap 측정을 시도한다. 로컬 inspector가 GC 명령에 응답하지 않아 `diagnostic_gc_unavailable`로 기록되며, 이 선택 진단의 미지원은 기능 테스트 실패와 구분한다. 1,200건 사전 실행에서 응답 오류 0건 후 진단 timeout이 발생했고, 이 처리 보완 후 120건 사전 검증은 통과했다. 이 결과로 메모리 증가 원인이 해결됐다고 판단하지 않는다. 후속 시험이 동일 기준으로 실패하면 반복 가능한 메모리 문제로 보고한다.

10초 이상의 관찰 공백은 활성 시간에서 제외해 별도 기록한다. 로컬 지연·heap은 실제 Cloudflare 운영 CPU·전체 isolate 메모리 안정성의 대체 지표로 사용하지 않는다. 공식 한도와 참고: https://developers.cloudflare.com/workers/platform/limits/ .

## 검증 근거와 추적

Worker 회귀37개와 검증 도구 안전 테스트15개가 통과했다. 임시 PostgreSQL의 두 연결 간 단일 실행권·할당량·동시 실행 제한·완료 기록 검증도 통과했다. 해당 PostgreSQL 검증은 운영 DB를 사용하지 않았다. 검증 도구 Bandit0건, 공개 콘텐츠249개/위반0건, Canvas TSX 구문 검사0경고를 확인했다.

주요 파일은 campaign-summary.json, campaign-control.json, campaign-process.json, cloudflare-observations.jsonl, runtime-results.jsonl, soak-current-24h/summary.json, soak-current-24h/process.json이다. 모두 현재 대화에서 시작한 유한한 검증 작업이다.

사용자가 24시간 검증과 72시간 읽기 전용 추적을 명시적으로 승인했다. `Agent Concierge 검증 상태 확인` 자동화(ID: agent-concierge)를 생성하고 ACTIVE 상태와 유한한 시간당 일정을 확인했다. 추적 종료는 2026년 10월 27일 08:25 Asia/Seoul이다. 로컬 결과 파일과 검증 프로세스 상태만 읽고, 새로운 실패·완료·조치 필요 변화에만 알린다. Provider 호출, 네트워크·DB 조회, 재시작, 코드·설정·결과 변경은 추적 범위에서 제외한다. 운영 서버는 그대로 유지했다.
