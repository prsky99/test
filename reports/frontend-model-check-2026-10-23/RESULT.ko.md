# 모델 변경 후 프론트엔드 점검 — 2026-10-23

## 결과와 범위

로컬 Ollama 종료 후 실제 운영 프론트엔드의 검색·목록·보고서 필터·추가 조회·뉴스 테스트·기본 워크플로우·채팅·모바일 메뉴와 로그인 화면을 점검했다. 로그인한 워크스페이스는 격리 세션/DB에서 실제 Mac mini 모델을 연결해 생성→검토→동의 후 저장→별도 동의 후 테스트까지 검증했다.

확인한 범위에서 모델 변경으로 인한 기능 오류는 발견하지 못했다. 운영 서비스 소스 수정과 서버 재기동은 수행하지 않았다. 재사용 가능한 실모델 브라우저 시험 `tests/test_frontend_macmini_live.py`를 추가했다. 이 시험은 `LIVE_MACMINI_FRONTEND_CHECK=1`일 때만 실제 모델을 호출한다.

## 실제 공개 서비스

- 홈·탐색·테스트·워크플로우·채팅·로그인 화면: 초기 진입 브라우저 오류 없음, 데스크톱 가로 넘침 없음.
- 탐색: documentation 검색 45개 결과 표시, List 전환 후 텍스트가 결과 영역을 넘지 않음.
- 보고서 필터: 응답 45개 모두 report_count > 0 확인. 응답과 첫 카드 ID를 대조하고 중앙 로딩 해제 확인.
- 추가 조회: 보고서 결과 45→90개 확장, HTTP 200.
- Technology News: 실제 공개 읽기 예제를 실행해 Completed 및 소스 링크가 있는 3개 결과 확인.
- 기본 워크플로우: Run Workflow 활성화 확인. 실제 실행 결과 succeeded, 3개 단계(수동 시작·Technology News·Research Papers) 완료. 원격 읽기 결과와 출처 링크 표시.
- 채팅: MCP 문서 검색 추천 정상. 모바일에서 서로 다른 2개 질문 모두 HTTP 200, 각 1개 추천. 모델명과 내부 맥미니 주소가 화면에 나타나지 않음.
- 모바일 390px: 실제 모바일 메뉴를 열고 Explore/Test/Workflows/Chat 이동. 4개 메뉴 가로 넘침 없음.
- 로그인: Google/GitHub 버튼 활성 상태 확인. 실제 개인 계정 OAuth 로그인은 이번 점검에서 수행하지 않음.

공개 채팅은 기존 정책대로 기록된 검증·검색 결과를 사용하는 빠른 추천 경로다. 모델을 억지로 호출하도록 기능을 변경하지 않았다. 일반 공개 뉴스 실행과 기본 워크플로우 실행은 실제 서비스에 테스트 기록을 남긴다. 사용자 워크스페이스·크레딧·유료 제공자를 사용한 시험은 아니다.

## 실제 맥미니 모델 + 격리 워크스페이스

2단계/데스크톱 1440px, 3단계/모바일 390px 두 경우를 검증했다.

1. 모델 사용 동의 전 생성 버튼 비활성, 모델 호출 없음.
2. 실제 `gemma4-e4b-mlx`에 요청당 `enable_thinking=false`로 1회 호출.
3. 요청한 2개/3개 단계와 앞 단계 제목을 다음 단계 query에 연결한 구조 확인.
4. 생성 자체로 에이전트가 실행되거나 새 워크플로우가 저장되지 않음.
5. 검토 후 별도 저장 동의와 격리 크레딧 확인을 거쳐 저장.
6. 저장 카드의 진주와 단계 개수가 실제 구성 개수와 일치.
7. 테스트 준비만으로 실행하지 않음. 별도 실행 동의 후 합성 MCP 에이전트를 2회/3회 호출하여 Workflow succeeded 표시.
8. 브라우저 오류·API 오류·가로 넘침 없음.

이 시험에서 모델은 실제 원격 서버이고, 워크스페이스 계정/DB/크레딧과 에이전트 응답은 격리된 합성 데이터다. 실제 개인 워크스페이스를 변경하거나 제공자 실행 권한을 발급하지 않았다. 점검한 워크스페이스 화면/라우트/모델 어댑터 소스는 현재 활성 프론트엔드 배포본과 일치하는 것도 확인했다.

- 별도 실제 모델 브라우저 여정: **2개 통과**.

기존 모델이 합성 테스트에서 출력하던 특정 단어에 의존하지 않고 실제 단계 구조를 검사하도록 새 점검 코드를 작성했다. 생성 완료 대기와 격리 fixture의 기존 에이전트 호출 기준값도 반영했다. 최초 공개 모바일 점검은 숨겨진 데스크톱 메뉴를 클릭하려 했고, 추가 조회는 누적 응답을 증분 응답으로 잘못 계산했다. 이 두 점검 도구의 조건을 수정한 뒤 실제 메뉴/누적 응답 계약에 맞춰 재확인했다. 이를 제품 결함 수정으로 보고하지 않으며 최초 원본 점검 기록도 보존한다.

## 별도 개선 후보

기본 워크플로우 Research Papers 결과에는 1987년 자료처럼 오래된 서지 항목도 포함됐다. 실행·표시 오류나 모델 전환 실패는 아니지만, 최신 연구를 기대하는 방문자에게는 최신성 필터 또는 결과 안내를 개선할 여지가 있다. 이번 모델 변경 회귀 범위를 넘어 검색 정책은 변경하지 않았다.

벡터 검색/신규 임베딩 비활성은 앞서 합의한 Ollama 종료 정책이다. 이번 탐색 성공은 키워드 검색 경로를 검증한 결과이며, 벡터 검색이 복구됐다는 의미가 아니다.
