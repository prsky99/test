## 3. 시간이 어디서 갔나
### 탐색 > 3초 (121표본, 서버 시간 있는 100개 기준: 총 p50 4.09초, 서버 p50 1.41초, TLS p50 0.88초, 서버 밖 p50 2.26초)
- 서버 > 3초: 20표본 → 서버 혼자 미달이다(검색과 RAG).
- 서버 1.5~3초: 28표본 → 서버를 1.5초 안으로 줄이면 경로 몫이 있어도 대부분 3초 안에 든다.
- 서버 ≤ 1.5초: 52표본 → 경로가 원인이다(한국↔LAX/SEA TLS, 엣지→원서버).
  - 그 분의 엣지 바닥값이 높았던 표본이 47개다.
- 서버 시간 기록 없음: 21표본(11-11 초기 기록, 단계 시간 기록 전)
### 추천 > 5초 (23표본, 19개 기준: 총 p50 6.73초, 서버 p50 4.22초, 서버 밖 p50 2.0초)

### 페이지 > 3초 (42표본)
- 화면별: chat.html 15, / 15, explore.html 12
- 캐시 상태: EXPIRED 11, UPDATING 10, HIT 6, 기록 없음 15

## 4. 가장 짧은 길(제안)
1. **탐색 서버 시간 p90을 1.5초 안으로**(검색과 RAG): 서버 > 1.5초 48표본을 줄인다. 탐색만 고쳐도 통과 회차가 12회에서 최대 29회가 된다.
