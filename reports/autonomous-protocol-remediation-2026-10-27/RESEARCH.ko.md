# 자율형 에이전트 호환성 개선 근거 — 2026-10-27

## 논문을 적용한 판단

[ToolRet, ACL 2025](https://arxiv.org/abs/2503.01763)는 일반 검색에서 좋은 검색기가 도구 검색에서도 좋은 결과를 내는 것은 아니며, 도구 검색 실패가 실제 작업 성공률을 떨어뜨린다고 보고한다. 따라서 문자열 일치나 결과 개수만 성공으로 판정하지 않았다. 서울 날씨 요청의 실제 도구 계약, 세 프로토콜의 추천 일치, 후속 상세 조회, 현재 실행 증거와 실행 권한을 각각 검증했다. 기존 시험이 현재 날씨 계약과 예보 계약을 혼용한 부분도 수정했다. 보고된 운영 오류가 현재 버전에서 계속 발생한다고 가정하지 않았다.

[Tool-DE](https://arxiv.org/abs/2510.22670)는 구조화된 도구 설명의 보완이 도구 검색에 도움이 됨을 제시한다. 이번에는 서버가 소유한 입력·출력 계약과 행동 표시를 보강하고, 구조화 결과만 읽는 클라이언트도 사용자 안내를 이해하도록 `text`를 포함했다. 제공자 설명을 LLM으로 임의 확장하거나 검증되지 않은 실행 능력을 만들어 넣지는 않았다. 논문의 검색 성능 수치를 이 서비스의 개선율로 인용하지 않는다. 별도 학습 모델 도입은 이번 변경 범위가 아니다.

## 공식 규격과 실제 수정

[MCP 2025-11-25 도구 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)은 outputSchema와 annotations를 선택 사항으로 정의한다. 누락 자체를 규격 위반이라고 부르지는 않지만, 기계 클라이언트의 상호운용성을 위해 전 도구에 추가했다. 스키마는 공통 결과 필드와 작업별 추가 필드를 수용하며, 제공자 출력 전체를 엄격하게 검증하는 완전한 도메인 스키마라고 주장하지 않는다. annotations는 허가를 대신하지 않는다. 방문 대화 기록을 수정하는 검색은 읽기 전용으로 잘못 표시하지 않았다.

[MCP 전송 보안 규칙](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)에 맞춰 Origin을 검사하고, 명시적인 HTTPS 허용 출처만 CORS로 연결했다. `/mcp`의 GET 405는 SSE를 제공하지 않는 서버에서 허용되는 동작이므로 유지했다. 반대로 실제 공개 문서의 HEAD 405는 수정했다. 쿠키 자격 증명 공유나 관리자·워크스페이스 API의 일괄 개방은 하지 않았다.

현재 소스는 [MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)의 버전 번호를 알리면서 새로운 필수 요청 메타데이터와 resultType 체계를 구현하지 않고 있었다. 일부 메서드만 흉내 내는 대신, 실제 구현된 2025-11-25 계열로 협상하도록 수정했다. 최신 버전이라고 표시하는 것보다 사실에 맞는 협상과 클라이언트의 표준 폴백이 안전하다.

[A2A의 contextId 의미](https://github.com/a2aproject/A2A/blob/main/docs/specification.md)에 따라 수락할 수 없는 기존 대화 문맥은 오류로 거절한다. 토큰 소유자와 문맥 소유자가 충돌하거나 다른 클라이언트가 추측한 문맥을 제시할 때, 새 방문자를 만들어 같은 문맥에 연결된 것처럼 응답하지 않는다. 기존 텍스트·data part 병행 응답과 정상 문맥의 후속 대화는 유지했다. 지원하지 않는 지속 Task/스트리밍 기능을 새로 지원한다고 표시하지 않았다.

## SNS·커뮤니티 조사와 적용 한계

[Reddit MCP 보안 점검 논의](https://www.reddit.com/r/mcp/comments/1uk3tw2/most_mcp_servers_ive_tested_ship_with_zero/)에서는 도구 설명을 신뢰하지 말고 인증·실행 시 정책·Origin 검증을 분리해야 한다는 경험이 공유된다. 이는 공식 규격의 보조 자료로만 사용했다. 모든 외부 Origin을 허용하거나 annotations를 권한으로 해석하지 않는 설계에 반영했다.

[MCP 유지보수자 GitHub 논의 #1624](https://github.com/modelcontextprotocol/modelcontextprotocol/issues/1624)는 클라이언트마다 content와 structuredContent 중 어느 쪽을 우선하는지 다르다는 호환성 문제를 다룬다. 사람이 읽는 안내를 구조화 결과에도 포함하고 두 경로를 함께 검증했다. 해당 논의의 제안 전체를 확정 규격으로 취급하지 않는다.

## 성능 판단

보고된 ‘25회 129초’는 전체 합계이며, 요청당 약 5.16초다. 이번 운영 기준 측정은 REST 7.232초, MCP 5.659초, A2A 3.798초였다. 같은 실험 조건이 아니므로 속도가 몇 배 개선됐다고 주장하지 않는다. 카테고리 렌더링은 범용 탐색의 전체 범주 검색을 피하고, 최대 96개씩 8회로 제한한 게시 후보를 현재 증거로 재검증한다. 정상 후보가 앞의 여섯 항목 뒤에 있어도 찾도록 시험했다. 요청 시 외부 제공자 생존 확인이나 LLM 재순위화를 추가하지 않았다. 전체 운영 부하의 지연 목표 충족은 배포 후 별도 측정이 필요하다.
