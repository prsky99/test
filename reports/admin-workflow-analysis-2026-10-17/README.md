# 어드민 워크플로우 분석

2026-10-17 현재 소스와 격리된 임시 DB·앱을 분석했습니다. 운영 DB, 실제 키,
방문자 정보는 조회하지 않았고 실행 중인 서버나 제품 소스는 변경하지 않았습니다.

## 판단

**비주얼 편집·저장·템플릿 관리 기능과 시뮬레이션 실행 화면은 구현되어 있습니다.
현재 어드민 워크플로우 실행 경로를 실제 에이전트 자동화 실행·예약·발송 엔진으로
사용하기에는 핵심 연결이 빠져 있습니다.**

이는 전체 서비스에 외부 호출 기능이 없다는 뜻은 아닙니다. 별도의 보호된 도구 실행
코드는 존재하지만 워크플로우 실행 루프와 연결되어 있지 않습니다. 현재 실행 화면의
성공 표시, 발송 완료, 품질 검증 및 실행 시간은 실제 외부 작업 성공의 증거가 아닙니다.

## 화면과 데이터 구조

- **노드 캔버스:** Trigger, MCP, A2A, x402, Router 노드를 배치하고 연결합니다.
  인스펙터에서 입력·동작을 수정하고 자동 정렬·확대/축소·저장·실행을 제공합니다.
- **템플릿 허브:** 검색·분류·정렬·복제·리뷰·템플릿 공개 기능이 있습니다.
  공개 전환은 `is_template=1` 플래그 변경 방식입니다.
- **마이 워크플로우:** 현재 조회 조건은 `is_template=0&active_only=true`입니다.
  로그인 사용자별 작성자 조건이 없는, 어드민의 활성 비템플릿 공용 목록입니다.
- **LLM 연동:** 키 저장·마스킹 조회 기능은 별도 구현되어 있습니다. AI 구성 버튼이
  해당 키나 모델을 사용해 파이프라인을 생성하는 연결은 확인되지 않았습니다.
- **저장:** `agent_workflows`의 `steps` JSON에 nodes/edges/derived steps를 함께
  포장하고, 리뷰는 `workflow_reviews`에 저장합니다. 생성·수정·복제·공개는 실제
  DB 변경입니다. 프론트엔드와 어드민은 같은 저장소의 템플릿을 사용합니다.
- **실행:** 어드민은 `/admin/api/workflows/{id}/run`, 공개 프론트는
  `/api/workflows/run`, 다운로드 HTML은 자체 자바스크립트 루프를 사용합니다.
  세 경로 모두 현재는 실제 도구 실행이 아닌 생성/샘플 출력 방식입니다.

## 우선순위가 높은 발견 사항

여기서 P1/P2는 수정 순서이며 외부 표준의 보안 점수가 아닙니다.

**1. P1 — 실제 실행·발송 없이 성공으로 표시합니다.**

어드민 실행 루프는 짧게 대기하고 입력 키에 맞춘 항공편·환율·뉴스 등의 문구를
생성합니다. 실측 지연 시간에 40ms를 더합니다. 최종 결과에는 고정된 이메일/Slack
발송 성공과 `DELIVERED`를 넣지만 이 경로에는 실제 발송 호출이 없습니다.
존재하지 않는 `resource_id=987654321`도 `COMPLETED`와 `DELIVERED`를 반환했습니다.
서버의 proof hash는 작업명과 시각으로 만들며, 외부 실행 결과나 수신 영수증의
무결성을 검증하는 증거가 아닙니다.

근거: [실행 루프](<저장소>/agent_market/gateway/dashboard.py:3211),
[결과 생성](<저장소>/agent_market/gateway/dashboard.py:3307),

**2. P1 — DAG와 조건 분기 검증이 실제 실행 의미를 보장하지 않습니다.**

노드 수·중복 ID·알 수 없는 연결 대상 검사는 있으나 순환을 거부하지 않습니다.
진입점이 없으면 모든 노드를 큐에 넣고, 실행되지 못한 노드도 secondary branch
완료 결과로 보충합니다. Router는 조건을 평가하지 않고 PASS를 반환합니다.
순환 그래프, 도달 불가능한 순환 분기, false 조건 및 비활성 노드에서 완료 처리를
재현했습니다. 입력 참조는 실행된 노드 출력의 문자열 치환이며 타입·스키마와
연결된 부모만의 데이터 흐름을 보장하는 매핑 엔진이 아닙니다.

근거: [기초 그래프 검사](<저장소>/agent_market/gateway/admin_security.py:56),
[진입점 보정](<저장소>/agent_market/gateway/dashboard.py:3249),
[미실행 노드 완료 처리](<저장소>/agent_market/gateway/dashboard.py:3428).

**3. P1 — 공개 템플릿에 비활성 상태와 민감 입력 필터가 빠져 있습니다.**

공개 API는 `is_template=1`과 테스트 이름/태그 필터를 적용하지만 활성 상태를
필수로 제한하지 않고 전체 워크플로우 객체를 반환합니다. 격리 DB에 만든
`is_active=0` 템플릿도 공개 조회됐고, 노드 입력의 합성 `api_key` 값도 그대로
반환됐습니다. 실제 키 유출을 확인했다는 뜻은 아닙니다. 관리자가 키를 노드 입력에
넣은 채 템플릿으로 공개하면 노출될 수 있는 경로를 확인한 것입니다.
비공개 워크플로우를 모두 익명 공개한다는 뜻도 아닙니다.

근거: [공개 템플릿 조회](<저장소>/agent_market/concierge/front.py:646),
[공개 전환](<저장소>/agent_market/gateway/dashboard.py:2720).

**4. P1 — 스케줄·발송 대상 설정이 실제 작업으로 이어지지 않습니다.**

화면에는 매시간/매주/6시간 주기와 발송 대상 입력이 있지만 저장 핸들러가 읽는
것은 trigger type뿐입니다. preset과 대상 입력은 저장에 사용되지 않습니다.
테스트로 요청한 cron/timezone도 저장되지 않았고 실행 응답은 고정 Daily 09:00을
표시했습니다. 확인한 서버 Scheduler는 수집·재평가·작업 알림을 처리하며 이
워크플로우 테이블의 예약이나 이벤트 웹훅을 실행하는 연결은 없습니다.

**5. P1 — 기본 템플릿 편집 내용과 카운터가 재초기화될 수 있습니다.**

Store 초기화 시 기본 템플릿과 이름이 같으면 그래프·설명·작성자·트리거·평점·사용
카운터를 시드 값으로 다시 UPDATE합니다. 임시 DB의 기본 템플릿 설명과 실행 수를
변경하고 Store를 다시 열었을 때 둘 다 원복되는 것을 재현했습니다. 모든 사용자
워크플로우가 대상인 것은 아니며 기본 시드 이름과 일치하는 항목의 문제입니다.

**6. P2 — AI 생성은 현재 키워드 기반 구성입니다.**

프롬프트 앞부분 단어를 검색하고 최대 3개 에이전트를 선형 연결합니다. 후보가
없으면 이름과 ID를 가진 기본 항목을 생성합니다. 모델을 설정해 둔 격리 객체에서도
이 경로의 LLM 호출은 0회였고, 빈 카탈로그에서 ID 1·2를 포함한 결과를 받았습니다.
‘AI 자동 구성’을 실제 모델 추론·스키마 검증 완료로 해석하면 안 됩니다.

**7. P2 — 웹앱 내보내기는 현재 독립형 시연 HTML입니다.**

관리자 export API는 설정 JSON을 만들고, 실제 HTML은 브라우저가 생성합니다.
다운로드 HTML도 임의 지연·샘플 결과·발송 완료 문구를 생성합니다. ‘SHA256’ 접두사의
브라우저 proof 값은 Math.random으로 만든 문자열입니다. 구글 로그인은 credential
존재 여부로 브라우저 상태를 바꾸며 서버 측 신원 검증·접근 통제를 대체하지 않습니다.
이 내보내기 경로에는 한국어 UI와 `lang=ko`가 있어 공개 프론트의 영어 기준과도
다릅니다. 외부에 배포하려면 실제 실행·인증·언어 정책을 먼저 통일해야 합니다.

근거: [내보내기 설정](<저장소>/agent_market/gateway/dashboard.py:2897),

**8. P2 — 실행 이력·버전·운영 지표가 부족합니다.**

현재 확인한 워크플로우 관련 테이블은 정의와 리뷰 두 개입니다. 실행 응답의 노드별
결과·발송 결과를 영구 저장하는 별도 run/node-run/delivery 모델은 없습니다.
실행 수는 읽고 더해 UPDATE하므로 동시 실행 시 갱신 유실 가능성도 있습니다.
새 DB의 기본 시드는 26개 템플릿과 총 6,637회 실행 카운터를 이미 포함하므로
이 값이나 기본 평점을 실제 서비스 사용·검증 실적으로 볼 수 없습니다.
26개는 새 DB의 시드 수이며 운영 DB의 현재 개수가 아닙니다.

## 유지할 기반과 구현 순서 제안

현재 관리자 인증·역할별 쓰기 제한, 파라미터화된 저장 쿼리, 기본 그래프 크기/ID
검사, CSP와 출력 이스케이프는 유지할 기반입니다. 익명 관리자 목록 조회 차단과
없는 연결 대상 거부도 재현했습니다. 별도 플랫폼 키 목록은 마스킹되고, 기존
내보내기 테스트는 플랫폼 LLM 키 제외를 검사합니다. 이것이 노드 입력의 공개
템플릿 노출 문제까지 막아 주는 것은 아닙니다.

1. 시뮬레이션/실행/발송 상태를 구분하고, 생성 문구를 실제 성공·검증·발송으로
   표시하지 않도록 먼저 정리합니다. 공개 템플릿의 활성 필터·전용 projection·키
   참조 방식을 함께 보완합니다.
2. 하나의 서버 실행 엔진과 run/node-run 상태 모델을 만들고 admin/front/export가
   이를 사용하도록 연결합니다. 기존 보호된 MCP/REST/x402 실행 코드는 검토 후
   재사용하고 A2A 실제 실행 경로는 별도 연결합니다. 순환 거부·조건 분기·상위 노드
   출력 매핑·실패 전파·시간 제한·취소·재시도를 실제 동작으로 정의해야 합니다.
3. 워크플로우 버전과 시드 식별자를 분리하고 초기화는 기존 사용자 수정과 통계를
   덮어쓰지 않게 바꿉니다. 실제 실행 영수증으로 통계를 집계합니다.
4. 실제 schedule/timezone/target 모델, 예약 워커, 검증된 이벤트 수신, 동의된 목적지
   발송과 수신 결과 기록을 구현합니다. 예약 저장과 활성화 성공도 별도로 표시합니다.
5. 마지막으로 AI 구성의 모델 사용 여부와 검증 단계를 명확히 하고, 다운로드 앱의
   인증·언어·실행 경로를 통합합니다. 키는 템플릿/HTML의 값이 아닌 서버의 참조로
   다룹니다. 플랫폼 키의 DB 평문 저장도 파일 권한 보호와 별개로 암호화 검토 대상입니다.
