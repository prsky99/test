작업 기간: 2026-10-26~27 KST. 최종 준비 릴리스: `chat-remediation-20261027-r4`.
> 2026-10-27 운영 반영 확인: 사용자가 적용한 프론트엔드·어드민에서 r4 정상 기동과 공개 기능을 확인했습니다. 간헐 다국어 안내 및 관리자 로그인 검증 범위는 [운영 확인 기록](post-deploy/REPORT.ko.md)에 남겼습니다.


코드 수정과 검증을 마쳤으며 운영 적용을 위한 고정 배포본을 준비했다. 이 작업에서 운영 프로세스 교체는 실행하지 않았다.

## 확인한 원인과 수정

추천의 문제는 검색어 확장만으로 해결되지 않았다. 도구 이름·설명의 일부 단어가 맞으면 통과하거나, 검사를 통과한 도구가 없어도 상위 에이전트의 도구 목록을 다시 표시하는 경로가 있었다. 요청의 행동과 대상, 입력 스키마를 함께 검사하고, 적합한 도구가 남지 않은 후보는 제외했다.

- 일반 번역에 경전 구절 조회, 이미지 생성에 작업 마켓·3D 모델 생성, 현재 시세에 채용 신호·과거 캔들·가격 예측을 추천하던 경로를 보완했다.
- SQL 실행과 SQL 생성·변환·분석을 구분했다. DNS 검사는 레코드 추가·수정 도구로 대체하지 않는다. 저장소 검색에 GitHub 토론·다이어그램 조회만 하는 도구가 끼어들지 않게 했다.
- 회의록 요약은 사용자 텍스트·회의록·전사문을 입력받는 도구인지 확인하고, 요청한 실행 항목 추출 조건도 유지한다. 결제 안내·계정 생성·도구 디렉터리는 실제 작업 수행 도구로 취급하지 않는다.
- `translate`와 `translation`처럼 이미 검증된 같은 기능이 기존 어휘 점수 때문에 다시 탈락하는 경우를 수정했다. 관련성·스키마·안전 검사를 모두 통과한 단일 도구의 근거가 있어야 적용된다.

프로토콜과 정렬 정책은 유지했다. 명시 선택자가 우선이고, 자동·Any는 적격 A2A부터 MCP 순서로 채운다. x402는 명시 요청일 때만 검색한다. 적격 후보 안에서는 최근 성공 검증, 활동, 품질 순서를 적용한다. 날씨 예보 요청을 현재 날씨만 제공하는 도구로 충족시키는 완화는 적용하지 않았다.

한국어 별칭을 검색과 최종 용도 검사에 동일하게 적용했다. 일본어·스페인어는 검증된 영어 정규화를 검색 앞부분에 사용하면서 원문의 조건을 유지한다. `Necesito`, `Busca` 같은 스페인어 요청 동사를 고유명사로 오인해 정상 번역을 거절하던 문제도 수정했다. 정규화가 실패하면 구체적인 재입력 안내를 제공한다.

## 대화와 화면

사용자의 요청을 해당 응답과 함께 표시하고, 최신 대화부터 보여준다. “두 번째 것”, “second one” 같은 후속 선택과 기존 요청에 조건을 추가하는 흐름을 유지한다. 카드번호·접근 키는 전송 및 기록 전에 차단·마스킹하며, 화면에 인용하는 이메일 주소도 가린다.

Enter 전송, Shift+Enter 줄바꿈, IME 조합 중 중복 전송 방지, 실행 중 재클릭 방지를 적용했다. 시작 예제는 바로 전송하고, 프로토콜 변경 시 기존 결과가 이전 조건의 결과임을 표시한다. 모호한 요청·서로 다른 여러 작업·보장할 수 없는 로또 결과·자격증명 탈취 요청은 각각 구분해 안내한다. 메일 전송·예약 요청에는 실행 사실을 꾸미지 않고 별도 검토·권한 부여가 필요함을 알린다.

탐색의 진행 상태는 결과 영역에서 표시하고, 자동 조회가 중앙 로딩을 띄우지 않도록 정리했다. 단순 메뉴 재방문과 명시적인 검색 주소 복원을 구분해 미전송 입력을 보존한다. 홈 일일 통계는 접힌 설명 안에 숨지 않도록 했다. 새 링크형 메뉴에서도 채팅 자동 초점과 이동을 확인했다.

관리자 실행에서도 실제 결함을 발견했다. 변경하지 않은 공개 템플릿을 실행할 때 매번 다시 저장해 게시 승인 절차에 걸렸다. 저장된 그래프와 같으면 바로 실행하고, 수정한 그래프는 기존 저장·승인을 거치도록 했다. 공개 템플릿을 수정한 경우 승인 전에 실행되지 않고 원본이 유지되는 보안 회귀도 추가했다.

## Claude Code가 남긴 항목

- PostgreSQL/SQLite 추천 지문에서 저장소마다 무작위로 달라지는 증거 ID를 제외했다. 결과·시각·계약 버전에 따른 변경 감지는 유지하며, 실제 PostgreSQL 18 비교 검사를 통과했다.
- Any 프로토콜의 오래된 기대값을 현재 A2A→MCP 정책에 맞췄다. 명시적 x402 검사는 유지했다.
- `WorkflowRuntime.products` 오류는 격리 저장소 픽스처가 운영 생성자를 우회하면서 `Products`와 `IOProfiles` 초기화를 빠뜨린 것이었다. 백그라운드 작업·운영 초기화를 호출하지 않는 격리 방식으로 두 구성 요소를 연결했다. 연쇄적으로 가려졌던 저장소 불변조건 검사도 실제 실행했다.
- 저장소 왕복 검사의 고정 숫자 32 대신 현재 33개 정식 테이블의 집합을 대조한다. 기존 보존·복구·권한·동시 실행 검사는 유지했다.
- 공유 다운로드 SDK를 원본과 동기화해 워크플로우 정의 확인값을 전달한다. 단일 추천을 기대하던 점검 스크립트도 최대 세 개 정책에 맞췄고, 점검이 가짜 제공자 실패 이력을 남기지 않게 했다.
- 공유 로그인 픽스처를 다른 모듈에서 가져오면 비밀번호 교체 준비 조건이 누락되는 문제와, SDK 비동기 로딩 전 요청이 도착했다고 가정하던 검사를 수정했다. 강제 비밀번호 교체·개인 세션·게시 승인 정책은 유지했다.

## 검증 증적

192개 계획 모듈을 모두 확인했다. 단계별 실행 및 수정 후 재검증을 시험 시작 시각 기준으로 대조한 최종 결과는 **중복 제외 4,293개 통과, 미해결 실패 0개**다. 한 번의 중단 없는 실행 결과로 표현하지 않는다. 중간 실패와 중단 로그도 보존했다.

- 실제 카탈로그와 설정된 모델을 읽기 전용으로 사용한 리뷰 기반 요청 33개: 상호작용 33개 통과, 22개에서 추천, 나머지는 안내·무결과·입력 차단. 영어·한국어·일본어·스페인어, 오타, 민감정보, 상세 보기와 실행 안내를 확인했다.
- 원래 리뷰의 전체 33개 질의 목록은 제공되지 않아 재구성한 사례다. 기존 Claude 평가 29개와 최종 수정에 해당하는 5개도 재평가했다. 이를 전체 정확도나 원본 리뷰 대비 정확도 향상률로 일반화하지 않는다.
- 추천이 나온 요청의 내부 검증 응답 중간값은 4.12초, 평균 4.25초였다. 운영망 왕복 시간은 포함하지 않으며 동시 회귀 검사 중 측정했다.
- 기계형 클라이언트 점검 32/32, 관리자 65개, 채팅 핵심 165개, 추가 API·보안 168개, 탐색 ANN·배치·하이브리드 42개 등을 포함한다.
- 고정 배포 파일 자체의 화면 회귀는 133개를 확인했다. 링크 변경으로 낡아진 선택자 1개는 수정 후 같은 고정 배포본에서 다시 통과했다.
- 최종 배포본의 소스 1,296개 파일 해시를 검증했다. 공개 런타임 콘텐츠 300개 파일에서 위반 0개이며, 저장소 전용 가이드까지 포함한 소스 콘텐츠 검사도 통과했다. 정적 E9/F/S 검사와 관련 브라우저/API 보안 회귀를 통과했다.

검증은 격리 앱·데이터와 읽기 전용 운영 카탈로그를 사용했다. 추천된 모든 외부 제공자의 유료 실행이나 업무 수행 성공을 주장하지 않는다. 적격 도구가 없는 YouTube 요청이나 엄격한 A2A 범위의 논문 검색은 무결과를 유지할 수 있다.

PostgreSQL 격리 검사 중 macOS 공유 메모리 한도도 확인했다. 작업 시작 때 기록한 객체 중 본인 소유·56바이트·접속 0·사용 PID 0·생성 프로세스 종료를 재확인한 고아 메타데이터만 정리했다. 실행 중인 PostgreSQL 공유 메모리는 보존했다.

작업 중 운영 프론트엔드의 탐색 릴리스와 일부 프로세스 ID가 달라진 것이 관측됐다. 따라서 모든 운영 PID가 동일했다고 보고하지 않는다. 이 작업은 운영 프로세스를 교체하지 않았으며 공개 홈페이지의 HTTP 200 응답을 확인했다. 동시에 작업 중인 소스를 덮어쓰지 않도록 검증한 소스를 고정했고, 그 안에서 SQL 사전의 소스 지문을 재생성했다. 실행 SQL 3,801개와 스키마는 검증본과 동일하다.

증적: `verification-summary.json`, 각 JUnit XML 및 로그, `actual-catalog-browser/results.json`과 33개 화면 캡처, `final-release-catalog-smoke/`의 최종 배포본 실제 조회, `sealed-release.json`, `release-integrity.json`, `process-final.json`.

## 운영 적용

프로젝트 폴더에서 다음 두 명령을 실행한다.

```bash
./agentcon deploy frontend chat-remediation-20261027-r4
./agentcon deploy admin chat-remediation-20261027-r4
```

이번 반영에 jobs·execution·PostgreSQL·모델 서버 재시작은 필요하지 않다. 운영 반영 이후 공개 채팅과 관리자 저장본 실행을 다시 확인하면 된다. 앞선 준비용 r1~r3보다 이 r4가 최종 검증본이다.
