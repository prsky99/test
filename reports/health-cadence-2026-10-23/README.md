# 헬스체크 기본 주기 6시간 변경 (2026-10-23)

6시간 실행 주기와 기존 개요의 6시간 집계·표시 후속 수정 모두 운영 반영을 확인했다. 점검 과정에서 프로젝트 서버·운영 DB를 재시작/수정하지 않았다.

## 변경

- 기본 주기 120분 → 360분(21,600초). GatewayConfig, 기본 Schedule, 단독 collector 진입점이 같은 기본값을 사용한다. 기존 HEALTH_INTERVAL_MINUTES 재정의 기능은 유지한다. 현재 비공개 agentcon.env에는 이 항목의 별도 재정의가 없다.
- 자체 에이전트 데이터 소스 확인 성공 후 다음 점검도 같은 설정값을 사용한다. 실패 시 짧은 확인 예약은 유지한다.
- 공개 등록·Learn·기능 요약·엔진 설명·알림 안내를 영어 6시간 기준으로 맞추고, embedded HTML과 extracted HTML 및 게시용 new/en 출력을 동기화했다. 페이지 제목·메타데이터/스크립트도 기존 게시 생성기를 통해 재생성했다.
- 어드민 overview.health.interval이 실제 구성된 checker 주기를 반환한다. 기존 화면의 주기·필요 처리량 계산은 이 값을 사용한다. 기존 고정 2시간 분모를 제거했다.
- 최근 2시간 점검 수와 예정 시각보다 2시간 지연된 건수는 통계/경보 창이며 주기가 아니다. API 필드·기준을 유지하고 안내를 명확히 했다.
- 사용 중/실패 직후 15분 재확인, ±10% 분산, 동일 호스트 보호, 신규 즉시 점검, 수동 점검, 퇴역 정책과 10분 품질 보고서 정책은 변경하지 않았다.
- 기존 저장 next_check_at을 대량 갱신하지 않는다. 기존 예약이 한 번 실행된 뒤 정상/down 다음 예약부터 6시간 기준이 적용된다. 운영 데이터 변경이나 동시 대량 호출을 유발하지 않는다.

## 검증

- 관련 격리 API·Chromium·수집·상태 보호·자체 에이전트·프론트/어드민·메타데이터·동적 보안 회귀 **198건 통과**, 실패/skip 0. 모의 데이터/대상을 사용했다.
- 공개 콘텐츠 **248개 파일 위반 0건**, 실행 JS 6개 및 JSON-LD 검사 통과. appBootstrapData의 {bootstrap_json}는 응답 시 채워지는 기존 템플릿이며 실행 JS/완성 JSON으로 오인하지 않는다.
- 전문/직원 생성물 동기화 확인, SQL 카탈로그 재생성/일치 확인(229테이블/3,668구문), 스키마 변경 없음. 카탈로그는 현재 소스의 위치/추출 내용을 반영하며 무관한 기존 변경도 보존했다.
- Ruff에는 변경하지 않은 줄의 기존 경고 15건이 남는다. 새 변경 줄의 경고는 없다. 원문은 lint.txt에 보존한다. git diff --check도 기존 대시보드/테스트의 변경하지 않은 줄의 공백·EOF 항목을 보고했으며 이번 주기 변경과 무관해 보존했다. 관련 콘텐츠 변경은 인증·CSP·출력 이스케이프·SSRF·동의 경계를 바꾸지 않았고 관련 동적 회귀가 통과했다. 운영 전체 침투 시험이나 장기간 가용성 검증은 아니다.
- [검증 요약](validation.json), [회귀 원문](regressions.txt), [소스 지문](source-sha256.json).

## 운영 적용

관리형 서비스에서 agentcon restart는 웹만 교체하며 jobs 워커를 재시작하지 않는다. 아래처럼 동일한 새 릴리스를 웹과 jobs에 배포한다. 실행 워커는 이번 변경에 교체할 필요가 없다. 프로젝트 AGENTS.md의 사용자 직접 서버 실행 지침에 따라 사용자가 실행한다.

```bash
agentcon package health6h-20261023-v1
agentcon deploy frontend health6h-20261023-v1
agentcon deploy admin health6h-20261023-v1
agentcon worker-deploy jobs health6h-20261023-v1
```

이미 새 코드로 agentcon restart를 했다면 그 결과의 새 릴리스 ID로 jobs worker-deploy만 추가하면 된다. 기존 운영 릴리스를 워커에 다시 배포하면 새 소스가 적용되지 않는다. 별도의 HEALTH_INTERVAL_MINUTES 환경 재정의가 있는 실행 경로에서는 360인지 확인한다.

## 사용자 배포 후 확인 완료

- 사용자가 health6h-20261023-v1을 프론트엔드·어드민·jobs에 배포했다. 이후 웹은 추가 릴리스 web-20261023-161236-3dbf로 교체됐고 jobs는 health6h-20261023-v1(PID 38080)이다. 현재 서비스 상태는 정상 롤백 보유 단계 retained다. execution은 기존 services-20261022-r1을 유지한다.
- 활성 웹 2개와 jobs의 검증 대상 배포 파일은 각각 **173/173 일치**. 핵심 설정/수집기/자체 에이전트 코드도 모두 동일하다. 환경의 HEALTH_INTERVAL_MINUTES 재정의가 없어 배포본의 기본 **21,600초(6시간)**가 적용되는 구성임을 확인했다. 실행 중 Python 메모리를 직접 조사한 것은 아니다.
- 읽기 점검 **7/7 통과**: 공개 홈/게시 런타임/어드민 셸·모듈, 비인증 관리자 접근 차단, 공개 포트의 관리자 경로 차단. 응답 자산은 실제 활성 릴리스와 일치하고 6시간 안내를 확인했다.
- PostgreSQL 서비스 하트비트를 SELECT로 확인했다. jobs는 available=true, paused=false이고 A2A/MCP/x402 헬스체크 스레드가 모두 alive=true다. 검사한 현재 서비스 콘솔 로그 범위의 ERROR/CRITICAL은 0건이다. 장기간 오류 부재를 의미하지 않는다.
- 사용자 출력과 읽기 연결의 `/dev/null` password-file 경고는 기존 PostgreSQL 설정 경고이며, 이 점검에서 서비스 시작·하트비트 실패를 유발하지 않았다. 해당 설정은 변경하지 않았다.
- 소스 지문 변경이 없어 동일한 198개 격리 회귀를 반복하지 않았다. 비인증 GET·파일/프로세스 상태·하트비트 SELECT만 사용했고 운영 고객 데이터/예약/설정/프로세스를 변경하지 않았다. [운영 확인 원문](post-rollout.json).

추가 재시작은 필요하지 않다. 기존 예약은 한 번 실행된 뒤 정상/down 다음 예약부터 6시간 기준으로 전환된다. 15분 우선 재확인 정책은 그대로다.

## 기존 개요 화면 누락 보완 — 재시작 후 반영 확인 완료

사용자가 `/admin/ui#overview`에서 미변경을 지적했다. 초기 작업은 실제 예약을 6시간으로 바꿨지만 대표 카드의 2시간 집계를 별도 통계로 유지했기 때문에, 요청한 화면의 시각적 수용 기준을 충분히 확인하지 못했다. 앞선 “양쪽 반영 완료”는 이 화면의 집계 변경 완료를 뜻하지 않았으며 이번에 바로잡는다.

- 첫 카드에 **기본 헬스체크 주기 / 6시간**을 명시하고 우선 대상 15분과 분산 정책을 설명한다.
- 최근 6시간 점검 수/성공률 및 예정 시각보다 6시간 지연된 수를 실제 DB에서 집계한다. 프로토콜별 지연/큐/필요 처리량과 새 어드민 홈/경보도 맞춘다. 2시간 데이터를 6시간으로 이름만 바꾸지 않는다. 이전 API의 1h/2h 값은 기존 클라이언트 호환을 위해 별도로 유지한다.
- 영향 범위 격리 API/실제 Chromium/접근제어/CSP/캐시 회귀 **77건 통과**, 실패/skip 0. 과거 198건과 합산하지 않는다. 3·5시간 전 기록의 포함/7시간 전 기록 제외와 2시간/6시간 지연 값 차이를 검증했다.
- 임시 PostgreSQL의 새 집계와 관리자 옵션/권한 검증 통과, 클러스터 제거. 운영 DB 변경 0건. 신규 SQL은 카탈로그와 동기화했다(229테이블/3,668구문). 실행 JS 구문과 생성물 동기화도 통과했다.
- [검증 요약](overview-validation.json), [77건 결과](overview-regressions.txt), [임시 PostgreSQL](overview-postgres.json), [화면 캡처](overview-six-hour.png). 캡처의 숫자는 운영 데이터가 아닌 격리 테스트 데이터다. 최초 PG 실행에서 모듈 경로 없이 파일을 직접 호출한 오류는 `python -m`으로 바로잡았으며 이후 검증을 통과했다.

이번 후속 수정은 **`agentcon restart admin` 후 관리자 탭 전체 새로고침**이 필요하다. 공개 프론트엔드와 jobs 워커의 6시간 스케줄은 이미 반영돼 있어 재배포하지 않는다. 사용자 직접 서버 실행 지침에 따라 운영 서버를 재시작하거나 배포 파일을 직접 덮어쓰지 않았다.
