# 워크스페이스 기능 테스트 (agentconcierge.biz) — 로그인 전 범위

- **일시:** 2026-10-27
- **방법:** 소스 코드를 보지 않고 시험했습니다.
  - **API:** 공개 OpenAPI에 있는 워크스페이스 관련 경로 138개(GET 66, POST 72)를 로그인하지 않은 상태로 한 번씩 불렀습니다. 3초 간격으로 보냈습니다.
  - **화면:** Chromium으로 고객 화면 6개를 열었습니다.
- **대상 범위:**
  - 고객 조직(`/api/customer-organizations/*`)
  - 워크스페이스 앱(`/api/workspace-apps-v2`, `/api/workspace-flow-apps-v2`)
  - 워크플로 앱·연결(`/api/workflow-apps*`, `/api/workflow-connection*`)
  - 고객 지원, 고객 화면(`/customer/*`)
- **주의:** 워크스페이스 ID는 사용자 것(`ws_df76…f39`)과 없는 ID를 썼습니다. 다른 경로 인자(app·run·release 등)는 모두 가짜 값이라 실제로 실행되거나 바뀐 것은 없습니다.
- **한계:** 로그인 뒤의 기능은 시험하지 못했습니다. 워크스페이스는 Google/GitHub 로그인(OAuth)이 필요합니다. 이 클라우드 세션에서는 로그인할 수 없고, 자격 증명을 받아 쓰지 않는다는 원칙도 있습니다. 로그인 뒤의 기능 시험 방법은 끝 절에 적었습니다.

## 요약
- **잘 된 점:**
  - 로그인 없이 부른 138개 경로 중 개인 데이터를 돌려준 경로는 하나도 없었습니다. 2xx는 8개였고, 모두 원래 공개인 것입니다(로그인 화면, 로그인 시작, 공개 연결 목록 등).
  - 사용자 워크스페이스 ID와 없는 ID에 같은 응답을 줍니다. 워크스페이스가 있는지 밖에서 알아낼 수 없습니다.
  - 로그인 흐름 쿠키가 `__Host-` 접두어, `HttpOnly`, `Secure`, `SameSite=Lax`, 5분 만료로 안전하게 설정돼 있습니다.
- **고칠 점:** 서버가 응답 없이 연결을 끊은 경로 2곳, 일관되지 않은 401·403, 로그인한 적 없는 사람에게 나오는 "세션 만료" 문구, 로그인 뒤 원래 주소로 돌아오지 못할 가능성, 로그인 없이 보이는 지원 폼.

## 결과

| 401 | 81 | "The customer session is unavailable." 등 |

| 연결 끊김 | 2 | 아래 1번 |

- **200을 준 경로:**
  - `/customer/sign-in`, `/customer/support`, `/customer/workflows`, `/customer/provider-connections`, `/customer/plan`(HTML 화면)
  - `/api/customer-auth/options`, `/api/customer-auth/begin`
  - `/api/workflow-connections`(공개 연결 목록, 빈 배열)
- **CORS `*`:** 11개 경로에 있습니다. 모두 내려받은 웹 앱이 호출하는 공개 실행 경로(`/api/workflow-apps*`, `/api/workflow-connection-apps-v13/*`)입니다. 쿠키 없이 쓰는 경로라 의도된 설정으로 보입니다.

## 개선 필요 (우선순위 순)

### 높음
1. **서버가 응답 없이 연결을 끊는 경우가 있습니다.**
   - 다음 2곳에서 "Server disconnected without sending a response"가 났습니다.
     - `GET /api/customer-organizations/{ws}/members`(사용자 워크스페이스)
     - `POST /api/workspace-apps-v2/{app}/prepare`
   - 두 번씩 다시 부르니 401로 정상이었습니다.
   - 결제 테스트의 `credit add`에서도 같은 일이 한 번 있었습니다. 지금까지 3번 모두 재현되지 않았습니다.
   - 워커 재시작이나 처리하지 않은 예외로 보입니다. 아래 시각 무렵의 서버 로그에서 예외와 워커 종료를 확인하세요.
     - 2026-10-27 00:08 UTC(credit)
     - 이번 시험 시간대(members, prepare)
   - 개선: 예외 처리 미들웨어로 모든 예외를 JSON 500으로 바꿉니다. 워커 메모리·시간 제한도 확인합니다.

### 중간
2. **로그인하지 않았을 때 401과 403이 섞여 있습니다.**
   - 같은 "로그인 안 됨" 상황에 81곳은 401, 47곳은 403입니다.
   - 문구도 둘로 나뉩니다: "The customer session is unavailable." / "Review the current customer session."
   - 개선: 세션이 없으면 401, 세션은 있지만 권한이 없으면 403으로 통일합니다. 401에는 `WWW-Authenticate`와 로그인 주소를 넣습니다.
3. **로그인한 적 없는 사람에게 "세션이 만료됐다"고 합니다.** `/customer/plan`과 `/customer/organizations/{ws}/flows`는 `/customer/sign-in?result=expired`로 보내 "Your session expired. Sign in again to continue."를 보여 줍니다. 처음 온 사람에게는 "로그인해 주세요"가 맞습니다.
4. **로그인 뒤 원래 주소로 돌아오지 못할 수 있습니다.**
   - `/customer/organizations?workspace=ws_…`로 들어가면 `/customer/sign-in`으로 이동합니다. 이때 원래 주소나 워크스페이스 ID를 담는 값(`next` 등)이 붙지 않습니다.
   - 초대 링크나 공유 링크로 온 사람은 로그인 뒤 기본 화면에 떨어질 가능성이 큽니다. 로그인 뒤 동작은 확인하지 못했습니다.
   - 개선: 같은 사이트 경로만 허용하는 `next`를 서버 세션에 저장해 두고, 로그인 뒤 그 주소로 보냅니다. 외부 주소는 거절합니다.
5. **로그인 없이 지원 폼이 보입니다.**
   - `/customer/support`는 로그인 없이 지원 요청 폼("Ask about sign-in, workflows or credits.")을 보여 줍니다.
   - 하지만 요청을 만드는 API(`POST /api/customer-support/cases`)는 로그인 없이는 403입니다. 작성하고 보내면 실패합니다.
   - 개선: 로그인하지 않았으면 폼 대신 로그인 안내를 보여 주거나, 로그인 문제 문의는 공개 문의 폼(Contact)으로 안내합니다.
6. **로그인 전에 입력 검사를 먼저 하는 경로가 있습니다.**
   - `provider-connections` 계열 9곳은 로그인 여부보다 입력 형식을 먼저 검사해 422를 줍니다.
   - `workspace-apps-v2/{app}/exchange`, `status-capability` 등은 400을 줍니다.
   - 정보가 새지는 않지만, 경로마다 응답이 달라 공격자에게 구조를 알려 줍니다. 인증 검사를 가장 먼저 합니다.

### 낮음
7. **화면 콘솔에 401 오류가 찍힙니다.** 고객 화면 6곳 모두 세션 확인 요청의 401이 브라우저 콘솔에 "Failed to load resource"로 남습니다. 로그인 전에는 정상 흐름이므로, 세션 확인 API가 로그인 전에는 200 `{"authenticated": false}`를 주게 바꿉니다.
8. **고객 API 138개가 공개 OpenAPI에 모두 있습니다.** 인증으로 막혀 있지만 공격 표면이 드러납니다. 고객 문서는 로그인한 사람에게만 보이게 하거나, 공개 스키마에서 뺍니다.

## 문제없었던 항목
- **개인 데이터:** 로그인 없이 개인 데이터(조직, 멤버, 앱, 실행 기록, 제공자 연결, 크레딧)를 돌려준 경로는 0개입니다.
- **워크스페이스 존재 여부:** 사용자 워크스페이스와 없는 워크스페이스의 응답이 같습니다.
- **5xx 없음**
- **가짜 실행 경로:** 가짜 app·run·release ID로 실행·취소·준비 경로를 부르면 404 또는 403이고, 아무것도 실행되지 않았습니다.
- **OAuth:** state, PKCE S256, 고정 redirect_uri가 있고, 로그인 콜백에 가짜 응답을 보내면 400입니다(등록 기능 테스트에서도 확인).
- **쿠키:** `__Host-ac_oidc_flow`에 `HttpOnly; Secure; SameSite=lax; Max-Age=300`이 설정돼 있습니다.
- **화면 이동:** 로그인이 필요한 화면은 모두 로그인 화면으로 이동합니다(`/customer/support` 제외).

## 확인하지 못한 것 — 로그인 뒤 기능
다음은 로그인한 브라우저가 있어야 시험할 수 있습니다.
- **조직·멤버:** 워크스페이스 생성, 이름 변경, 멤버 초대·수락·거절·내보내기, 역할 변경
- **권한:** 다른 워크스페이스 ID로 바꿔 넣었을 때 막히는지. 계정 2개가 필요합니다.
- **워크플로:** 자연어 생성, 편집, 실행, 실행 기록, 취소. 계획은 `docs/qa/workflow-test-plan.md`(시나리오 40개)에 있습니다.
- **제공자 연결:** API 키·OAuth 연결, 확인, 해제
- **앱:** 웹 앱 내려받기와 내려받은 앱 실행
- **크레딧:** 충전 견적, 등록, 차감, 해지
- **지원 요청:** 생성, 메시지, 공개 동의, 철회
- **로그아웃·세션 만료** 뒤의 동작, 로그인 뒤 원래 주소로 돌아오는지(4번)
