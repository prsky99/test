# PostgreSQL 18 격리 검증 보완 결과

검증일: 2026-10-26. 기존에 OS 자원 제한으로 제외했던 네이티브 서비스 검증을 PostgreSQL **18.6**에서 완료했다. 추가 스키마 권한은 필요하지 않다.

## 확인한 원인과 수정

1. 운영 DB는 PostgreSQL 18.6이며, 현재 애플리케이션 역할에는 이미 스키마 생성 권한이 있었다. 권한 부족이 실패 원인은 아니었다. 운영 DB에 테스트 스키마를 만들지 않았다.
2. macOS 공유 메모리 슬롯 32개 중 31개가 연결되지 않은 상태였다. 소유자·크기·연결 수·생성 프로세스 종료 여부를 재확인하고, 연결 이력이 없는 56바이트 잔여 세그먼트 **1개만** 해제했다. 운영 PostgreSQL의 공유 메모리와 프로세스는 보존했다. 커널 제한은 변경하지 않았다.
3. 기존 테스트 도구 경로는 Homebrew의 PostgreSQL 14.22 기본 별칭을 선택할 수 있었다. 버전별 PostgreSQL 18 도구를 우선하고, 같은 디렉터리의 `initdb`·`pg_ctl` 쌍만 선택하도록 수정했다. 이번 실제 선택은 둘 다 18.6이다.
4. 다시 실행하면서 드러난 일일 통계 테스트 연결의 `autocommit` 누락을 수정했다. 운영 연결에는 이미 `autocommit=True`가 적용되어 있었다. 테스트 연결은 임시 Unix 소켓과 짧은 연결 제한을 명시한다.

## 검증 결과

- 실제 네이티브 서비스·영구 저장·롤백 검증: 통과.
- 일일 통계 PostgreSQL 집계·재연결 후 보존·동시 발행 검증: 통과. JUnit에 실제 서버 버전 `180006` 기록.
- 위 네이티브 검증 **2건 통과, 실패 0건, 건너뜀 0건** (`native18-final.xml`, `native18-final.log`).
- 테스트 도구 선택·환경 격리 등 안전성 회귀 **21건 통과** (`harness-safety.xml`, `harness-safety.log`). 이 실행에서 제외한 실제 DB 검증 1건은 위 네이티브 실행에 별도로 포함했다.
- 변경 파일의 Ruff F/E9 검사 통과. PostgreSQL SQL 카탈로그 일치 검사 통과: 3,802개 문장·232개 테이블.
- 초기 재실행 실패·건너뜀 기록도 보존했으며 최종 통과 결과와 구분한다.

## 운영 영향과 정리

운영 서비스 재시작 0건, 운영 DB 스키마·데이터 쓰기 0건, DB 권한 변경 0건이다. 검증은 별도 임시 PostgreSQL 클러스터에서 수행했다. 종료 후 임시 DB 프로세스 잔존 0건, 운영 PostgreSQL PID와 공유 메모리 보존, 공개 홈 HTTP 200을 확인했다 (`cleanup-and-operation-check.json`).

수정 대상은 테스트 하네스와 테스트 코드이므로 이번 보완을 위해 운영 배포나 재시작이 필요하지 않다. 기존 608개 검사 실적과 이번 추가 검사 실적은 별도로 기록한다.
