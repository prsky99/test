## Implemented security and behavior

- Strict supported IntentSpec fields/types/limits; reject URL/contact/secret/template/markup patterns and unsupported protocols/contracts. This is not a universal personal-data detector.
- Current safe stateless MCP, exact schemas/annotations, approval and successful execution/contract evidence for every selected candidate; no popular-agent fallback.
- Fifteen-minute owner-bound signed proposal; per-node integrity proof binds current connection/version/approval and literal input. Recheck at invocation and actual dispatch; validate actual result before recording contract success.
- Strict model selection JSON, no arbitrary tool/URL/graph/input/authority, one configured-model request, redirects disabled, bounded response/plan size and client/cooperative time limits. No automatic model repair/fallback or agent execution.
- Fixture status explicitly says no live verification and creates no evidence. Separate unchecked save/live-test/publication controls. Native centered dialog, text-node rendering, no proposal/consent browser persistence, session/close/logout clearing and stale-response guards.
- Publication requires unchanged tested definition/current pins/routing policy and signed retained checkpoints, with writer lock around publication. Compiled definitions cannot use the old untested template-publication shortcut. Public publication discloses that fixed inputs and agent choices become public.
- Public projection excludes private composition proofs/version/approval data. Published generated templates execute through the existing gateway and download through the existing ZIP builder. Public frontend and seven frontend/SDK/package implementation files retain their input hashes.
- No new database table/schema; a generated signed snapshot/checkpoint passes the existing 27-table PostgreSQL state rehearsal. Full application PostgreSQL conversion is not implemented.
