## 3. 패턴과 시사점

1. **회사 이름은 추상·은유, 기능은 서술어.** 오래 가는 회사명은 뜻이 넓은 단어(Anthropic, Glean, Sierra, Arcade, Perplexity)나 조어(n8n, Gumloop, Glama, Composio)이고, 하위 제품은 "브랜드 + 일반명사"(Zapier MCP/Agents, Glean Protect, Glama MCP Gateway, Composio Platform)로 붙인다. 역할어(gateway, registry, router, store)는 **제품·기능 칸**에 있지 회사명에 있는 경우는 적다(예외: OpenRouter, Agent Store, MCP Registry).
2. **"agent"나 프로토콜 이름을 회사명에 넣으면 수명이 짧다.** AgentHub는 "Agent"가 오해를 부른다며 Gumloop로 바꿨고, Agent.ai는 HubSpot 본 제품에 흡수되며 도메인이 다른 제품으로 넘어갔다. "MCP" 이름 디렉터리(MCP.so, PulseMCP)는 서술력은 높지만 프로토콜에 운명이 묶이고 서로 구별이 어렵다(Glama는 "superset of the official MCP Registry"로, Smithery는 인수됨). → 우리 이름에 "Agent"·"MCP"·"A2A"를 넣는다면 설명 문구나 하위 제품명에 두는 편이 안전하다.
3. **남의 상표에 기댄 이름은 결국 바꾼다.** GPT Engineer→Lovable, OpenDevin→OpenHands, Roo Cline→Roo Code, Clawdbot→OpenClaw(Anthropic 상표 요청). 이름 후보는 모델 회사·주요 도구 이름(Claude, GPT, Devin, Copilot, Gemini 등)과 소리·철자가 비슷하지 않은지 먼저 본다. Imbue처럼 **발표 전에 상표 출원**하는 순서가 참고가 된다.
4. **제품명이 이기면 회사명을 바꾼다.** Codeium→Windsurf, Fixie→Ultravox, Grammarly→Superhuman, Bard→Gemini. 처음부터 회사명과 대표 제품명을 같게 하거나(Perplexity, n8n, Gumloop), 분리할 거면 Anthropic/Claude처럼 역할을 분명히(회사=연구·신뢰, 제품=사용자 접점) 나눈다.
5. **인수·흡수 때 작은 브랜드는 사라진다.** Windsurf→Devin Desktop(인수 11개월 뒤), Smithery→Arcade 운영, Agent.ai→HubSpot 흡수. 레지스트리·디렉터리 분야는 2026년에 실행(execution)·게이트웨이 회사가 발견(discovery) 회사를 사는 흐름이 보인다(Arcade의 Smithery 인수 근거: 발견과 실행·권한을 합침). → "찾기 + 연결 + 실행"을 이미 묶은 우리 위치는 이 흐름과 같은 방향이다.
6. **도메인 경향.** 개발자 인프라는 .dev(arcade.dev, composio.dev, lovable.dev), AI 제품은 .ai(sierra.ai, smithery.ai, glama.ai, openrouter.ai, perplexity.ai, toolhouse.ai), 오래된·대형 회사는 .com(glean.com, zapier.com, crewai.com, gumloop.com, pulsemcp.com), 짧은 TLD 해킹(mcp.so, n8n.io). Gumloop는 ".dev가 비개발자에게 맞지 않는다"를 개명 이유로 들었다 → **대상이 사람(비개발자)도 포함이면 .com/.ai, 개발자·에이전트 전용이면 .dev**가 근거 있는 선택이다.
7. **역할어의 2025–2026 유행.** 포지셔닝 문장에 "gateway"(Arcade "Enterprise MCP Gateway", Glama "MCP Gateway", AgentCore "Gateway", LangChain "LLM Gateway", OpenRouter의 비교군 전체가 "AI Gateway"), "registry"(공식 MCP Registry, Glama, Arcade Registry), "runtime"(Arcade "actions runtime", CrewAI "Build & Runtime"), "studio"(Sierra Agent Studio, Copilot Studio), "store"(Microsoft Agent Store), "hub"(HubSpot Agent Hub)가 반복된다. 이 단어들은 이미 흔해서 **구별력이 낮다** → 회사명보다 범주 설명어로 쓰는 게 맞다.
8. **사람·노동 은유가 늘었다.** "AI teammates"(Zapier Agents), "AI workers"(Toolhouse), "AI Workforce"(Relevance AI), "AI solutions engineer"(Relevance Invent), "Fleet"(LangChain), "Intern"(OpenRouter Ori Intern), "Ghostwriter"(Sierra), 그리고 "LinkedIn for agents"(Agent.ai). 사람 이름 자체를 쓰는 경우(Devin, Claude)는 회사가 아니라 **에이전트·모델 제품**에 붙는다.
9. **하위 브랜드 가족을 만들 거면 접두사 하나로.** LangChain의 Lang-, OpenRouter의 Ori-, Glama의 MCP-, Zapier의 "Zapier + 명사". 반대로 LangChain도 2025–2026 신제품(Deep Agents, Fleet, Engine)은 접두사를 버리고 서술어로 갔다 → 가족 이름은 2~3개까지, 그 뒤는 서술어가 관리하기 쉽다.
10. **개명은 비용이 크고, 개명 순간이 공격면이다.** Windsurf는 실행 파일 이름이 바뀌어 기업 허용 목록을 고쳐야 했고(2차), OpenClaw는 핸들 이전 틈에 사칭이 생겼으며, Roo·Claude SDK는 옛 ID·패키지명이 남았다. 에이전트가 읽는 서비스라면 **도메인·MCP 레지스트리 이름(biz.agentconcierge/...)·패키지 이름·A2A 카드 URL**이 다 바뀌어야 하므로, 사람용 브랜드를 바꾸더라도 기계용 식별자는 그대로 두는 설계(옛 이름 리디렉트, 별칭 유지)가 필요하다.
