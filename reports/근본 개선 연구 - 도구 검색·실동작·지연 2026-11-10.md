# 근본 개선 연구: 도구 검색, 실제 동작, 지연 (2026-11-10, PM)

사용자 지시: "근본적인 문제에 대해 최신 논문과 SNS 검색으로 확실하게 개선될 정보를 조사하고 연구해서 적용해줘."

## 1. 우리 문제 (사용자 기준 실측, 11-10 17~18시)

- 공개 주소로 처음 보는 질의를 검색하면 3~6초 걸린다. 서버 안만 재도 1.1~3.3초다.
- "crypto price json output"처럼 단어가 하나 더 붙으면 결과가 0건이 된다. 모든 단어가 맞아야 결과가 나오는 방식이라 그렇다.
- 에이전트용 추천(find_agents)은 6~17초 걸린다.
- 추천한 서버의 도구가 0개인 경우가 있다(Clearcrawl).
- 카탈로그는 30만 건이지만, 실제로 시험해 동작이 확인된 것은 소수다.

## 2. 연구에서 확인한 것

| 근거 | 내용 | 우리에게 주는 뜻 |
| --- | --- | --- |
| ToolRet, arXiv 2503.01763 | 일반 검색 모델은 도구 검색에 약하다. 가장 좋은 모델도 nDCG@10 33.8이다. 질의에 "무엇을 하려는지" 지시를 붙이고 도구 검색용으로 학습하면 크게 오른다 | 키워드나 일반 임베딩만으로는 부족하다. 질의를 의도로 바꾸고, 도구 단위 문서로 검색해야 한다 |
| RAG-MCP, arXiv 2505.03275 | 도구를 미리 검색해 후보만 넘기면 선택 정확도가 3배 넘게 오르고 토큰이 절반 넘게 준다. 후보가 약 100개를 넘으면 성능이 급히 떨어진다 | 순위를 매길 후보를 작게, 정확하게 줄여야 한다 |
| MCP-Zero, arXiv 2506.01056 (NeurIPS 2025) | 먼저 서버를 고르고, 그다음 도구를 고르는 계층 검색. 도구 약 3,000개에서 높은 정확도를 낸다. 한 번 검색으로 실패하면 끝나는 구조를 비판한다 | 서버 → 도구 2단계로 검색한다. 결과가 0건이면 질의를 넓혀 다시 찾는다 |
| MCP 레지스트리 무작위 400개 실측, arXiv 2609.10962(2차 출처로 확인) | initialize 핸드셰이크에 성공한 서버는 48.8%다 | 등록된 서버의 절반은 동작하지 않는다. 동작이 확인된 것만 추천해야 한다 |
| MCPZoo, MCP 측정 연구(arXiv 2509.25292) | 수집한 15.7만 건 가운데 실제로 띄울 수 있는 서버는 3.7만 건이다. 마켓 기록의 검증 통과율은 26% 수준이다 | 같은 결론이다 |
| Cloudflare 커뮤니티 다수 스레드 | 무료 플랜에서는 한국 방문자가 서울(ICN) 대신 LAX·SJC·SEA로 가는 일이 흔하다. 무료 플랜에서 고치는 공식 방법은 없다. 우회책은 DNS-only(직접 연결)나 사용자 쪽 WARP뿐이다 | 한국에서 재면 약 1초가 더해진다. 우리 서버는 공인 IP가 없는 터널 뒤에 있어 DNS-only는 쓸 수 없다. 해외 클라우드에 있는 에이전트는 이 손해가 작다 |

## 3. 적용 설계 (바탕부터)

1. **동작 확인된 도구 색인을 기본으로 한다.**
   - 추천과 탐색의 기본 후보는 최근 7일 안에 initialize와 tools/list가 성공하고 도구가 1개 이상인 서버, 그리고 Agent Card가 응답한 A2A다.
   - 나머지는 "미확인"으로 따로 둔다. 기본 결과에는 넣지 않는다.
2. **도구 단위 문서로 검색한다.** 문서 하나에 서버 이름, 도구 이름, 도구 설명, 입력 인자 이름을 담는다. 검색 결과는 서버로 묶어 보여 준다(MCP-Zero 방식).
3. **질의를 의도로 바꾼다.** 수식어(json, bulk, for my team, 숫자 등)를 떼고 동사와 대상(예: translate + pdf)을 뽑는다. 한국어는 다국어 임베딩이나 미리 만든 사전으로 영어 의도어로 바꾼다. 요청 경로에서 LLM을 부르지 않는다.
4. **하이브리드 검색으로 0건을 없앤다.** BM25는 OR로 찾고 일치하는 단어 수로 점수를 매긴다. 여기에 임베딩 근접도를 더한다. 그래도 0건이면 단어를 하나씩 빼며 다시 찾는다.
5. **2단계 순위.** 상위 50개만 다시 순위를 매긴다(도구 설명과 의도어의 일치, 실측 성공률, 지연). 최종 3개는 근거 문장(도구 설명)과 함께 낸다.
6. **시간 예산.**
   - 탐색: 서버 안 0.8초 이하. 임베딩은 미리 계산하고, 요청 중에는 질의 임베딩 1번만 만든다.
   - find_agents와 Chat: LLM은 설명 문장에만 쓰고, 2초를 넘기면 근거 문장으로 대신한다.
7. **채점.**
   - 실제 과제 30개 정답 세트로 Recall@3을 잰다.
   - 1순위 추천에 실제로 연결해 성공하는 비율을 잰다(ToolRet과 같은 방식).
   - 공개 주소의 시간은 scripts/user_slo.py로 잰다.
   - 매 변경마다 전후를 비교한다.

## 4. 바꿀 수 없는 것 (정직하게)

- 한국 방문자의 LAX 우회는 무료 플랜에서는 고칠 수 없다(공식 해법 없음). 서버 시간을 줄이는 것이 우리가 할 수 있는 몫이다.
- 측정에는 "한국에서 잰 값"이라고 표시해서 보고한다.
