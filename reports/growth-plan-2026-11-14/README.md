# 2주 성장 계획 — 진주 목걸이 중심 (11-14 ~ 11-27, 성장·유통)

PM 11-14 04:3x 지시로 다시 썼다. 서비스 정체성이 **Agentcon — 에이전트 밸류 게이트웨이**로 바뀌었다(`reports/agentcon-strategy-2026-11-14/README.md`).
- 사용자 지시: 홍보는 기존 에이전트가 아니라 **우리가 만든 워크플로우(진주 목걸이)** 를 한다.
- 사용자 원칙(PM 11-14 05:1x)
  - "홍보도 에이전트 진주를 홍보하는 것이 아니라 워크플로우로 생성된 진주 목걸이 에이전트를 홍보하는 것임."
  - 목걸이가 끝까지 실행되도록 진주 자리마다 대체 에이전트를 둔다. 외부 대체를 여럿 두고, 마지막에 Agentcon 대체를 최대 2개 둔다.
- 개별 에이전트 단위로 짰던 옛 계획은 `directory-era-plan.md`에 남긴다. 그 계획에서 이미 끝났거나 배포 대기인 일(브랜드 신호 A, noindex B, 표면별 끊김 집계, A2A run, 실패 고칠 방법, Run here 첫 줄, Glama 정리)은 목걸이 공급의 바탕으로 그대로 쓴다.
- 지켜야 할 것은 같다: 지출 0, GitHub 홍보 금지, 외부 게시·등록·계정·약관은 사용자 승인 뒤, 차선 목표(탐색 3초·추천 5초·페이지 3초·품질 90%), 목걸이 실행은 "복잡한 답변 5초".

## 0. 용어

| 말 | 뜻 | 정하는 곳 |

| 진주 | 등급·헬스·시험·공개 보고서·도구 정의 지문을 모두 통과한 외부 에이전트 | 검색과 RAG(판정), 운영·SRE(지문·재검증) — 전략 6절 1번 |

지금(11-14) 목걸이는 **0개**다. 공개 워크플로우 28개는 대부분 우리 자체 에이전트를 쓰고, 외부 에이전트는 1개뿐이다. 그래서 2주 계획은 "표면을 먼저 만들고, 검색과 RAG가 목걸이를 통과시키는 대로 하나씩 연다"로 짠다. **기준을 통과하지 않은 워크플로우는 목걸이로 홍보하지 않는다.**

### 홍보 단위 원칙 (사용자 05:1x)

- 홍보·SEO·등록·llms·SNS 초안에서 이름과 링크의 주인공은 언제나 **목걸이 에이전트**다.
- 개별 진주는 목걸이 페이지 안 "쓰인 진주(Pearls used)" 칸에서만 근거로 연결한다. 진주 단독 홍보 문구, 진주 단독 등록, 진주 페이지를 앞세우는 사이트맵 순서는 만들지 않는다.
- 진주 카드(에이전트 상세)는 목걸이에서 들어오는 근거 페이지다. 색인 기준은 noindex B를 유지한다.

## 3. 목걸이 = 새 에이전트 공개 표면 (전략 6절 4번, 2주)

목걸이 하나는 세 표면으로 나간다. 실행은 모두 이미 있는 경로를 쓴다.
- 워크플로우 실행: `run_workflow` / 공개 실행 API
- 대화 안 실행: A2A run, 실패 때 고칠 방법(70f9c1fa)
- 중계 정책: 읽기 전용 도구만, 결제·자격 증명 없음

| 표면 | 내용 | 재사용 |
|---|---|---|
| 웹 실행 페이지 `/necklaces/<slug>` | 지표 칸 + **완주 보증 칸** + 입력 양식 + 실행 결과 영역(클릭할 때만 불러옴, 화면 정책) + 쓰인 진주(근거) | Pearl Connection 디자인 시스템, 워크스페이스 틀, 공용 assets. 진주 목걸이 그림은 홈·About의 목걸이와 같은 그림(`necklace.css`) |
| MCP | 우리 `/mcp`의 목걸이별 도구 + `/necklaces/<slug>/mcp` | `mcp_tasks`(긴 실행은 MCP task), 도구 설명 형식(Glama 정리 뒤 형식) |
| A2A | 우리 카드의 목걸이별 기술 + 목걸이 전용 카드 | A2A run, `a2a_wording` |

- 공개 조건은 목걸이 판정(검색과 RAG)을 통과한 것만이다: 외부 진주 2개 이상, Δ > 0, 최근 재시험 통과.
- 조건이 깨지면(진주 고장·정의 변경) 세 표면에서 같이 "보류"로 바뀐다. 페이지는 200으로 남기고 실행만 막는다.
- 페이지에 보이는 숫자는 모두 시험 기록에서 온 값이다. 직접 쓴 홍보 문구로 숫자를 만들지 않는다.

### 완주 보증 칸 (사용자 05:1x)

| 보이는 것 | 값의 출처 | 값이 없으면 |
|---|---|---|
| 자리별 대체 수(외부 n, Agentcon m ≤ 2) | 목걸이 표의 자리별 대체 목록 | 그 자리 줄을 숨긴다 |
| 최근 완주율(대체 포함 마지막 단계까지 결과를 낸 비율, 시험 횟수와 기간을 함께) | 재시험 기록 | 칸 전체를 숨긴다 |
| 마지막 재시험 시각(UTC) | 재시험 기록 | 칸 전체를 숨긴다 |

- 문구는 사실만 쓴다. "100% 보장", "항상 완료" 같은 약속 문구는 쓰지 않는다. 보이는 것은 "최근 N회 시험 중 M회 완주(기간)"처럼 측정값뿐이다.
- 대체로 완주한 실행은 결과 영역에 어느 자리가 어느 대체로 바뀌었는지 표시한다(원래 진주가 실패한 사실을 숨기지 않는다).
- Agentcon 대체는 "Agentcon fallback"으로 따로 표시한다. 외부 진주로만 완주한 비율과 섞지 않는다.

### 단계
1. **1주 차(11-14~20)**
   - 목걸이 판정 결과를 읽는 공개 목록(`/api/necklaces`)을 만든다. 검색과 RAG가 내는 판정 표를 읽기만 한다.
   - 웹 페이지·MCP 도구·A2A 기술을 시험 데이터 목걸이로 완성한다. 공개 목록이 비어 있으면 아무것도 노출하지 않는다.
   - 게이트 시험: 판정 없는 워크플로우는 어디에도 노출되지 않음, 보류 목걸이는 실행 불가, 화면 정책(로딩은 영역에만).
2. **2주 차(11-21~27)**
   - 검색과 RAG의 첫 목걸이가 통과하는 대로 하나씩 연다.
   - 목걸이 페이지 방문·실행 시작·외부 성공을 북극성 줄에 붙인다.
   - 주간 목걸이 시험 보고서 1호를 낸다.
