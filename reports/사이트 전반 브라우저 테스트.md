# 사이트 전반 브라우저 사용자 테스트 (agentconcierge.biz)

- **일시:** 2026-10-26
- **방법:** 실제 Chromium 브라우저(Playwright)로 일반 사용자처럼 이동·클릭·입력했습니다. 소스 코드는 보지 않았습니다.
- **환경:** 데스크톱 1366×900, 모바일 390×844, 라이트·다크 모드
- **범위:**
  - 주요 화면: 홈, Explore, Chat, Test, Workflows, Learn, Status, Register, Contact, 로그인
  - 상단 메뉴, 푸터, 법률 문서 링크, 404
  - 폼 검증, 성능, 접근성, 모바일 메뉴
- Explore와 Chat의 세부 결과는 별도 보고서에 있습니다: `Explore 검색 브라우저 테스트.md`(17건), `Chat 자연어 요청 브라우저 테스트.md`(14건).

## 요약
- **가장 큰 문제는 화면 전환입니다.** 주소의 `#` 뒤만 바뀔 때(직접 입력, 링크, 뒤로 가기) 화면이 바뀌지 않는 경우가 많습니다.
  - 그 결과 법률 문서·푸터 링크가 동작하지 않고, 문의 폼이 등록 폼으로 막히는 일이 생깁니다.
- **링크가 링크가 아닙니다.** 메뉴와 푸터 항목은 버튼입니다. 그래서 새 탭으로 열 수 없고, 주소를 복사할 수 없고, 검색엔진도 따라가지 못합니다.
- **무겁습니다.**
  - 모든 페이지가 1MB짜리 이미지(`pearl.png`)를 받습니다.
  - 페이지마다 3~6초가 걸립니다.
- **잘 되는 것:**
  - Status 화면
  - 다크 모드
  - 모바일 메뉴
  - 쿠키 배너
  - 키보드 건너뛰기 링크

## 개선 필요 (우선순위 순)

### 높음
1. **`#` 주소만 바뀌면 화면이 그대로입니다.**
   - 재현:
     1. `/#register`를 연 다음 주소창에 `/#contact`를 입력합니다.
     2. 주소는 `#contact`로 바뀌지만, 제목은 "Give your agent a place in the connection."(등록) 그대로이고 등록 폼도 그대로 보입니다.
   - 같은 현상이 나온 곳:
     - `#contact` → `#test`로 이동했을 때 Test 화면이 나오지 않았습니다.
     - 없는 주소(`/#nonexistent`)는 아무 안내 없이 홈을 보여 줍니다.
   - 처음부터 그 주소로 열면(새로고침) 화면이 맞게 나옵니다.
   - 개선: `hashchange`와 `popstate` 이벤트에서 화면을 다시 그립니다. 없는 주소에는 "페이지를 찾을 수 없습니다" 화면을 보여 줍니다.
2. **법률 문서·푸터 링크가 동작하지 않습니다.**
   - Test 화면에서 Terms, Privacy, AI, CCPA, Accessibility, Contact를 누르면 주소의 `#`만 바뀌고 Test 화면이 그대로입니다(1번과 같은 원인).
   - Terms를 누르자 엉뚱한 창("Live Workflow Execution Results")이 열린 적이 있습니다.
   - Cookie Preferences와 `contact@` 메일 링크는 `#test`로 가서 아무 일도 일어나지 않습니다.
   - 법률 문서는 가입·결제 전에 반드시 열려야 하므로 법적 위험이 있습니다.
   - 개선:
     - 푸터를 실제 `<a href>` 링크로 바꿉니다. 법률 문서는 별도 페이지(`/terms` 등)로 둡니다.
     - Cookie Preferences는 쿠키 설정 창을 엽니다.
     - 메일은 `mailto:`로 엽니다.
3. **문의를 보낼 수 없는 경우가 있습니다.**
   - 재현:
     1. Register 화면을 봅니다.
     2. 메뉴나 주소로 Contact로 갑니다.
     3. 문의 내용을 채우고 보냅니다.
   - 결과:
     - 1번 문제로 등록 폼이 남아 있습니다. 화면의 첫 제출 버튼은 등록용 "Submit for review"입니다.
     - 누르면 등록 필수 항목(`regUrl`, `regName`, `regDesc`, 권한 확인 체크)에 막힙니다.
     - 콘솔에는 "An invalid form control … is not focusable"이 5번 찍힙니다.
   - Contact를 처음부터 열면 문의 폼 하나만 보이고 검증도 통과합니다.
   - 개선: 1번을 고치고, 문의 폼과 등록 폼을 서로 다른 화면·`<form>`으로 확실히 나눕니다.
4. **등록 폼이 잘못된 입력에 아무 말도 하지 않습니다.**
   - 아래 주소를 넣으면 요청도 보내지 않고 화면에도 아무 안내가 없습니다.
     - 잘못된 형식의 URL
     - 사설 주소(`http://127.0.0.1…`)
     - `javascript:` 주소
   - 반대로 빈 상태로 제출하자 API 요청이 2건 나갔습니다.
   - 개선: 입력란 옆에 이유를 보여 줍니다(예: "공개 https 주소만 등록할 수 있습니다"). 빈 제출은 브라우저 단계에서 막습니다.

### 중간
5. **오류 화면이 날것의 JSON입니다.**
   - 없는 페이지: `{"detail":"Not Found"}` 또는 `{"detail":"Page not found."}`
   - API 입력 오류: pydantic 422 내용이 그대로 보입니다.
   - 개선:
     - 사이트 디자인을 따른 404 페이지에 홈·검색 링크를 둡니다.
     - API 오류는 짧은 문장으로 바꿉니다.
6. **페이지가 무겁고 느립니다.**
   - 홈: 요청 12건, 1.2MB, DOMContentLoaded 약 2.3초. 다른 페이지도 networkidle까지 3~6초입니다.
   - `pearl.png` 1,058KB를 모든 페이지에서 받습니다.
   - 로고를 누르면 전체 페이지를 다시 불러옵니다(4.6초).
   - 개선:
     - 이미지를 WebP/AVIF로 줄이고(목표 100KB 이하) `loading="lazy"`를 붙입니다.
     - 로고는 화면 전환으로 처리합니다.
7. **주소 체계가 두 가지입니다.**
   - 같은 화면이 `/#status`, `/new/en/agent-status.html`, `/new/en/index.html#tos`처럼 여러 주소로 열립니다.
   - 공유·북마크·검색 노출이 흩어집니다.
   - 개선: 주소를 하나로 정하고 나머지는 그 주소로 보냅니다(301).
8. **메뉴가 버튼입니다.**
   - 상단 메뉴와 푸터 항목은 `href`가 없는 버튼입니다.
   - 가운데 클릭, Ctrl+클릭, 오른쪽 클릭 "새 탭에서 열기"가 되지 않습니다.
   - 개선: `<a href>`로 바꿉니다(1·2번과 함께 고치면 됩니다).
9. **Test 화면의 예제 실행이 끝나지 않는 것처럼 보입니다.**
   - "Country Profile" 예제를 고르고 15초 뒤에도 "Checking availability…"였습니다.
   - 진행률, 남은 시간, 취소 버튼이 없습니다.
   - 개선: 단계별 상태를 보여 주고, 일정 시간이 지나면 "시간 초과, 다시 시도"를 띄웁니다.
10. **접근성: 이름 없는 버튼과 라벨 없는 입력란이 많습니다.**
    - 텍스트나 `aria-label`이 없는 버튼: Explore 16개, Test 10개, 홈 4개(아이콘 버튼)
    - 라벨이 없는 입력란: Test 2개, Contact 5개
    - 화면낭독기 사용자는 무슨 버튼인지 알 수 없습니다.
    - 개선: 아이콘 버튼에 `aria-label`을 달고, 입력란을 `<label for>`로 연결합니다.

### 낮음
11. **Workflows 화면의 첫 로딩이 깁니다.**
    - "Loading available workflows…", "Loading template…"이 몇 초 보이다가 사라집니다(30초 안에 모두 로드됨).
    - 개선: 빈 틀(스켈레톤)을 먼저 보여 줍니다.
12. **로그인 화면 콘솔에 401 오류가 찍힙니다.** 로그인 전 세션 확인 요청입니다. 정상 흐름이므로 오류로 남지 않게 처리합니다.
13. **Learn 화면에 검색이 없습니다.** 글이 늘어나면 찾기 어렵습니다.
14. **홈 검색 뒤 화면 제목이 그대로입니다.**
    - 홈 검색창에서 Enter를 누르면 `#chat`으로 가고 요청(`POST /chat`)도 나갑니다.
    - 하지만 화면 제목은 홈 제목("Individual strengths. Shared possibilities.")으로 남습니다. 1번과 같은 원인일 수 있습니다.

## 문제없었던 항목
- **Status:** 수집 185,754개, 24시간 +17,615개, 응답률 92.4%, 갱신 시각이 맞게 나옵니다.
- **다크 모드:** 전환이 되고 새로고침 후에도 유지됩니다.
- **모바일:** 메뉴가 열리고 닫힙니다. 주요 화면에서 가로 넘침이 없습니다.
- **쿠키 배너:** 첫 방문에 나오고, 동의하면 사라집니다.
- **키보드:** "본문으로 건너뛰기" 링크와 Tab 순서가 자연스럽습니다.
- **문의 폼:** 처음부터 열면 필수 항목 검사와 이메일 형식 검사("@ 누락")가 동작합니다.
- **Workflows:** 템플릿 목록과 기본 워크플로우가 결국 로드됩니다.

- **로그인 후 화면(워크스페이스·결제):** 계정이 필요해 이번 범위에서 뺐습니다. `docs/qa/workflow-test-plan.md` 참고.
