# 등록된 테스트 결과 보고서 품질 분석 (agentconcierge.biz)

- **일시:** 2026-10-26
- **대상:** 사이트에 공개된 에이전트별 테스트 결과 보고서. Explore의 `has_report` 필터와 `/api/agents/{id}`의 `test_reports`에서 읽었습니다.
- **범위:**
  - 보고서가 있는 항목은 3,998개입니다. 목록 API가 한 조건에 600건까지만 넘겨줘서 그중 2,855개(71%)의 보고서 2,855건을 읽었습니다.
  - 빠진 쪽은 주로 A2A `docs_knowledge`와 MCP `finance_crypto`입니다.
- **제외:** 등록 주기(30분 단위 등록)는 요청에 따라 분석하지 않았습니다.
- **x402 판단 기준:** 결제 직전까지만 시험한 보고서로 보고 판단했습니다. 결제 요구 응답(402)을 정상 결과로 봅니다.

## 요약

| 종류 | 보고서 | 자동 시험 보고서(`transport`) | 복원된 과거 보고서(`legacy`) | 실패 판정 |
|---|---|---|---|---|
| A2A | 1,001 | 881 | 120 | 0 |
| MCP | 1,554 | 1,363 | 191 | 0 |
| x402 | 300 | 29 | 271 | 0 |
| 합계 | 2,855 | 2,273 | 582 | 0 |

- **보고서가 두 가지 방식으로 만들어졌습니다.**
  - **자동 시험 보고서:** 짧고(700~900자) 측정값 위주라 정확한 편입니다. 다만 거의 같은 문장이 반복됩니다.
  - **복원된 과거 보고서:** 길고(5,800~7,400자) 홍보성 문장과 확인할 수 없는 주장이 많습니다.
- **판정이 품질 정보 역할을 하지 못합니다.**
  - 2,855건 모두 "성공"이고 실패가 한 건도 없습니다.
  - 모두 `execution_measured=false`, `execution_verified=false`, `verification_state=historical_record`입니다. 즉 "실제 실행을 확인하지 않은 과거 기록"입니다.
  - 그래서 보고서가 있다는 사실이 에이전트 사이의 차이를 거의 보여 주지 못합니다.
- **x402는 결제 전 정보가 잘 담겨 있습니다.** 다만 대부분이 과거 보고서라, 결제 전에는 알 수 없는 내용을 단정한 문장이 섞여 있습니다.

## 문제점 (우선순위 순)

### 높음
1. **실패 판정이 하나도 없고, 오류 응답도 "성공"으로 기록됩니다.**
   - A2A의 AgentMesh는 HTTP 401, ADIN Tutor Clone은 HTTP 402입니다. MCP에도 HTTP 402가 1건 있습니다. 모두 `is_success=1`입니다.
   - 현재 상태가 down 16개, retired 6개인 항목도 보고서는 성공입니다.
   - 개선:
     - 판정을 성공·실패 둘로 나누지 말고 세 가지로 둡니다.
       - **통과**
       - **인증·결제 필요(정상 차단)**
       - **실패**
     - 현재 상태와 다르면 "현재 down, 보고서는 과거 기록"을 맨 위에 표시합니다.
2. **MCP 보고서가 설명이 있는데도 "설명 없음"이라고 씁니다.**
   - MCP 자동 시험 보고서 1,363건이 모두 "The provider published no description."이라고 씁니다.
   - 그런데 그중 1,347건(99%)은 카탈로그에 20자가 넘는 설명이 있습니다.
   - 핸드셰이크(`serverInfo`)에 설명이 없다는 뜻으로 보이지만, 읽는 사람은 제공자가 설명을 안 냈다고 받아들입니다.
   - 개선: "핸드셰이크에 설명 없음"으로 고치거나, 카탈로그 설명을 함께 보여 줍니다.
3. **A2A 보고서가 같은 보고서 안에서 서로 다른 말을 합니다.**
   - 111건이 단점에 "카드에 프로토콜 버전이 없다"고 쓰면서, 같은 보고서의 측정표에는 "Protocol | A2A v0.3.0"을 적었습니다.
   - 버전을 선언하지 않은 카드에 기본값을 넣어 표를 채운 것으로 보입니다.
   - 개선: 선언되지 않은 값은 표에 "선언 없음"으로 적습니다. 추정한 값이면 "(추정)"을 붙입니다.
4. **복원된 과거 보고서(582건)에 확인할 수 없는 주장이 많습니다.**
   - 홍보성 단어(production-grade, robust, seamless, ensures 등)가 120건에서 나왔습니다.
     - 자동 시험 보고서에서는 한 건도 없었습니다.
   - 예:
     - "Reduces duplicated agent compute by maintaining a verified reusable knowledge graph"
     - "Includes production-grade health probes"
   - 251건의 본문에 "[Retired gateway reference]"가 남아 있습니다. 문장이 깨진 채 공개되고 있습니다.
   - 개선:
     - 과거 보고서는 측정값(상태 코드, 응답 시간, 선언 내용)만 남기고 평가 문장은 숨깁니다.
     - 아니면 "과거 기록, 다시 확인되지 않음" 배너를 붙이고, 추천 순위의 근거에서 뺍니다.

### 중간
5. **x402 과거 보고서가 결제 전에는 알 수 없는 내용을 단정합니다.**
   - 결제 전에는 402 요구 조건만 볼 수 있습니다. 그런데 응답 품질을 단정한 장점이 있습니다(정규식으로 찾은 것만 최소 18건).
   - 예:
     - "Accurately factors in prompt caching discounts"
     - "Sub-450ms query latency delivers real-time orderbook updates"
     - "Returns comprehensive trader entity records"
   - 반대로 자동 시험 보고서 29건은 "Paid response content was not exercised"라고 범위를 정확히 밝힙니다.
   - 개선: 결제 전 보고서의 장점은 402에서 확인한 사실로 한정합니다.
     - 가격, 네트워크, 자산, 받는 주소, 제한 시간, 설명 유무
6. **x402 보고서에 결제 정보가 빠진 경우가 있습니다.**
   - 300건 모두 가격·네트워크·자산·x402 버전은 들어 있습니다.
   - 하지만 53건(18%)은 받는 주소(payTo)가 없고, 22건은 제한 시간(maxTimeoutSeconds)이 없습니다.
   - 결제 에이전트가 결제 전에 꼭 확인해야 하는 값입니다.
7. **x402 보고서 3건은 402가 아니라 200입니다(api.wsystem.dev의 eori·company·sanctions/screen).**
   - 무료 체험 한도 안이었던 것으로 보입니다. 그런데 보고서는 x402 결제 시험처럼 쓰여 있습니다.
   - 개선: "결제 없이 응답함(무료 한도)"으로 따로 표시합니다.
8. **형식이 제각각입니다.**
   - **시험 방식 이름(test_method):** A2A 36종, MCP 60종, x402 26종입니다. `POST`, `GET`, `a2a_agent_card_inspection` 같은 이름이 있고, x402 111건은 "x402 V2 Micro-payment ($0.005 USDC Base)"처럼 가격이 이름에 들어가 있습니다.
   - **등급:** 비어 있음 2,273건, `Grade A` 288건, `A` 251건, `Grade B` 40건, `B` 3건이 섞여 있습니다.
   - **태그:** 자동 시험 보고서는 쉼표 문자열, 과거 보고서는 JSON 배열 문자열입니다.
   - **입력 기록(input_wire):** x402 80건은 비어 있습니다.
   - 개선: 시험 방식은 정해진 목록(예: `A2A_CARD`, `A2A_MESSAGE_SEND`, `MCP_TOOLS_LIST`, `MCP_TOOLS_CALL`, `X402_CHALLENGE`)으로 고정합니다. 등급은 `A`~`D`, 태그는 배열로 통일합니다.
9. **실제 동작을 시험한 보고서가 거의 없습니다.**
   - A2A 892건(89%)은 카드 GET뿐이고, `message/send`는 8건입니다.
   - MCP 1,369건(88%)은 `initialize`와 `tools/list`뿐이고, 도구를 실제로 호출한 것은 약 55건입니다.
   - 자동 시험 보고서는 이 한계를 단점에 정직하게 적습니다. 하지만 881건, 1,363건이 똑같은 단점 문장 하나라, 에이전트를 비교하는 정보가 되지 못합니다.
   - 개선: 읽기 전용 도구 하나, 또는 `message/send` 한 번을 시험 호출해서 응답 형식이 맞는지 기록합니다. 수집기의 `capabilities.py` 시험 호출 결과를 쓰면 됩니다.

### 낮음
10. **자동 시험 보고서가 사실상 같은 문서입니다.**
    - 숫자를 빼고 보면 서로 다른 장단점 문장은 MCP 1,363건에서 4개, x402 29건에서 7개뿐입니다.
    - A2A는 499개지만, 대부분 스킬 이름만 다른 "Card declares N skill(s): …"입니다.
    - 사람과 검색엔진에게는 중복 문서로 보입니다.
    - 개선: 장단점 대신 측정표(응답 시간, 도구 수, 스키마가 있는 비율, 선언 필드)를 중심으로 보여 줍니다. 다른 항목과 비교한 수치를 넣습니다(예: "응답 시간 상위 20%").
11. **A2A 보고서 303건은 설명이 이름과 같습니다.** 예: "Provider description: Jedero". 설명으로서 정보가 없으므로 "설명 없음"으로 처리합니다.
12. **제목이 겹치는 보고서가 65건 있습니다.**
    - 이름이 같은 항목이 87개입니다(wikipedia-intel, spacex-data 등).
    - 같은 서비스가 여러 번 등록된 것이면 하나로 묶고, 다른 서비스면 제목에 도메인을 넣습니다.
13. **MCP 협상 버전이 대부분 2025-03-26입니다.**
    - 1,249건(92%)이 2025-03-26이고, 최신(2025-11-25, 2026-07-28)은 17건입니다.
    - 서버들이 시험 클라이언트가 요청한 버전에 맞춘 결과로 보입니다.
    - 시험 클라이언트가 최신 버전을 먼저 요청해야 최신 규격 지원 여부가 기록됩니다.

## 잘 된 점
- **판정 근거:** 자동 시험 보고서는 측정값(상태 코드, 응답 시간, 협상 버전, 도구 수와 스키마 비율)을 표로 보여 주고, 시험 범위를 단점으로 정직하게 밝힙니다.
- **보안:** 인증 정보는 `[REDACTED]`로 가려져 있고, 결제·자격 증명을 쓰지 않았다는 범위 문구가 모든 자동 시험 보고서에 있습니다.
- **x402:** 300건 모두 가격·네트워크·자산·x402 버전을 담고 있고, 402를 정상 결과로 처리했습니다.
- **응답 시간 기록:** 2,855건 모두 응답 시간이 있습니다.

  | 종류 | 중앙값 | 상위 10% | 최대 |
  |---|---|---|---|
  | A2A | 471ms | 1.3초 | 9.2초 |
  | MCP | 1.1초 | 2.3초 | 19.9초 |
  | x402 | 420ms | 1.0초 | 3.1초 |
- **MCP 도구 집계:** 도구 수와 "설명 있음·스키마 있음" 수가 1,363건 모두에서 일관됐습니다. 설명이 빠진 도구가 있는 서버는 1건뿐이었습니다.

## 권장 수정 순서
1. 판정을 통과·정상 차단·실패로 나누고, 현재 상태와 다르면 표시합니다(1번).
2. MCP "설명 없음" 문구와 A2A 프로토콜 버전 모순을 고칩니다(2, 3번). 템플릿 수정으로 2,700건이 한 번에 바로잡힙니다.
3. 과거 보고서의 평가 문장을 숨기거나 배너를 붙이고, "[Retired gateway reference]"를 정리합니다(4, 5번).
4. x402 결제 정보 누락을 채우고 무료 응답을 따로 표시합니다(6, 7번).
5. 시험 방식·등급·태그 형식을 통일하고, 읽기 전용 시험 호출을 추가합니다(8, 9번).
