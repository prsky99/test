## Warning review

- **B608, 85 warnings:** reviewed SQL construction sites use fixed identifier
  sets, finite schema/catalog columns, enumerated predicates/orderings, and bound
  values or generated placeholder counts. The inventory is migration 7, native
  store 17, collector 3, SQLite store 24, backup 3, maintenance 2, catalog builder
  24, rehearsal 3, and HTML view strings 2. The two HTML cases are JavaScript/HTML
  strings rather than database execution. SQL generated by the catalog builder
  comes from repository AST/literal contracts, not a request-supplied table or
  query. Runtime translation still rejects unregistered SQL. Native sequence names
  come from the fixed-schema PostgreSQL sequence lookup. This review does not
  authorize arbitrary identifiers, request SQL or changes to the generated
  catalog during concurrent development.
- **B104, 2 warnings:** both flagged sites compare host/domain strings containing
  `0.0.0.0`; these expressions do not themselves open a listener. Listener and
  ingress deployment acceptance remains separate.
- **B311, 4 warnings:** random values provide health-check scheduling jitter,
  not identity tokens, signatures or authorization entropy.
- **B404/B603, 3 warnings:** the private PostgreSQL tools import subprocess and
  use a fixed Python executable/argument vector. They do not interpolate an
  arbitrary shell command. Their temporary-cluster evidence does not establish
  hosted deployment safety.
- **B110, 7 warnings:** retained cleanup/optional JSON/vector compatibility
  handlers were reviewed in context. Worker startup/shutdown and authority
  failures are not ignored: startup refusal raises after rollback, remaining
  workers are drained after one close error, and the host receives failed drain
  status. Scanner suppression was not added to conceal these warnings.

No additional confirmed blocking vulnerability was found in these reviewed
contexts. This is not a certification that every possible path, dependency or
deployment is secure. Warnings and trust assumptions remain available to the
peer reviewer; final whole-version checks are intentionally pending.

## Confirmed defects corrected in the fixed requirements

- **FINAL-03.02:** signed active/unknown A2A, evaluation, machine-update and
  finance states now block writer handoff; forged terminal proof/locators also
  block it. Optional supported tables are materialized and fenced before SQLite
  retirement, preventing a stale raw schema constructor from creating an
  unfenced writer domain.
- **FINAL-06.01 / FINAL-06.05:** customer SDK policy ownership includes current
  customer/link/organization/workspace revisions. Null pins are rejected and
  policy updates require the expected revision.
- **FINAL-06.02:** recovery request status is checked against its signed body;
  unsigned challenge throttling is separate from valid pending proofs. Proof
  submission has a signed one-hour window and consumed/stale enrollment is not
  reported as current authority.
- **FINAL-06.01 / FINAL-09.02:** partial private worker startup rolls back and
  raises to all hosts. Other workers still drain after one close error. A closed
  private runtime cannot reopen permanently closed workers.
- **FINAL-05.02:** the concrete configured Ollama transport rechecks current
  authority, adapter generation and candidate pins before send and after reply;
  output must pass bounded strict JSON and the existing typed compiler. No
  redirect, automatic retry, ambient proxy or automatic publication is added.
- **FINAL-08.02:** provider responses must match the pinned original command ID;
  duplicate/non-finite JSON is rejected. Lost responses remain unknown and are
  reconciled by the original transaction rather than a new payment.
