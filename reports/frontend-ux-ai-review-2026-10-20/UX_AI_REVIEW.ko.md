# Agent Concierge 프론트엔드 UX·AI 검토

검토일: 2026-10-20 KST. 보고서 생성: 2026-10-20T18:34:53+09:00. 대상: 홈, 에이전트 현황, 탐색, 테스트, 워크플로우, 채팅, 등록, 배우기, 소개, 푸터, 로그인/가입, 고객 워크스페이스.

## 먼저 판단할 사항

진주 목걸이의 브랜드 방향은 유지할 가치가 있다. 현재 가장 큰 문제는 색상이나 장식의 부족보다 **첫 유용한 결과까지의 연결, 실제 연쇄 실행의 신뢰성, AI 판단의 근거와 사용자의 통제**다. 에이전트 수집량·상태 점검·실행 증거는 서비스가 가장 먼저 내세울 자산이다. 수치를 없애거나 챗봇 하나로 모든 메뉴를 대체하는 방향은 권하지 않는다.

실제 서비스에서 공개 정보 예제 4개를 각 1회 호출해 모두 완료 응답을 받았다. 반면 게시 워크플로우 3개는 각 1회 실행에서 모두 실패했고, 하나는 외부 결과가 미확정이었다. **단일 도구 사용 성공과 연결된 작업 성공은 현재 다른 문제다.** 투자자에게 연결의 가치를 보여주려면 이 차이를 먼저 해결해야 한다.

이 보고서는 71개 개선 항목을 메뉴·화면·요소·근거·완료 기준으로 구분했다. P0는 공개 검증·신뢰를 막는 문제 또는 출시 전 필수 검증 조건, P1은 핵심 여정 개선, P2는 재방문과 확장에 관한 항목이다. 개선 제안을 모두 현재 버그로 분류하지 않았다. 우선순위는 전문가의 판단이며 정량 사용자 연구의 결과가 아니다.

## 검토 방법과 확인 범위

- 공개 배포 주소를 실제 Chromium으로 열어 데스크톱 1440×1000 및 모바일 390×844 화면을 확인했다. 공개 검토에서는 34개 화면 상태를 기록했으나 그중 HTTP 200 화면은 14개다. 나머지는 연속 탐색 중 발생한 제한·차단 상태다. 전체 화면이 정상 응답했다고 주장하지 않는다.
- 정적 자산까지 제한되는 현상을 확인한 뒤 공개 반복 탐색을 중단했다. 제한을 해제하거나 다른 IP로 우회하지 않았다. 공개 주소의 HTML·JS·이미지 제한과 로컬 서비스 렌더링 확인은 다른 증적으로 구분했다.
- 나머지는 실제 서비스의 렌더러·API 핸들러를 격리된 합성 데이터로 열었다. 메뉴·푸터·45건 목록/추가 조회·필터·상세·두 번의 채팅·등록 검증 등 72개 공개 UI 상태와 고객 워크스페이스 20개 상태를 캡처했다. 격리된 캡처용 TestClient만 읽기 제한 대상에서 제외했으며 운영 보안 설정은 변경하지 않았다.
- 실제 단일 예제 4개 및 실제 게시 워크플로우 3개는 운영 서비스 API로 호출했다. 입력은 기존 공개 정보용 예제 그대로이며 새 계정·권한·전달 목적지·유료 호출을 만들지 않았다. 결과 미확정 건은 재전송하지 않았다. 테스트가 만든 실행 이력은 정상 이력으로 보존했다.
- 실제 Chat 추천 API를 새 익명 테스트 대화에서 2회 호출하고 별도 실제 브라우저에서 1회 제출했다. 브라우저는 기존 로컬 운영 서비스에 비동기 same-origin 중계로 연결했으므로 화면 타이머와 실제 backend 응답은 사용하지만 외부 배포 프록시까지 검증한 것은 아니다. 방문자 토큰은 전송 헤더/브라우저 세션에만 사용했고 증적 파일에 저장하지 않았다.
- 브라우저·실행·AI 제안 계약·수신기 전달·알림 권한·TLS 검증 회귀 183개가 통과했다. 합성 AI·제공자·수신기를 사용한 검증은 실제 모델 품질이나 실제 이메일/네이티브 푸시 수신 확인과 다르다.
- 운영의 실제 응답 7개를 별도 격리 UI에서 재생해 성공/실패/미확정 렌더링도 확인했다. 이 캡처는 **실제 응답 재생**이며 추가 운영 실행 또는 당시의 실시간 클릭 장면으로 표현하지 않는다.
- 사용자 제공 주소 `/customer/organizations`는 확인 대상 진입점이다. 지정 메일의 OAuth 세션에 접속하거나 신원을 위조하지 않았다. 운영 집계상 고객 소유 워크스페이스 1개, 활성 흐름 26개, 과거 성공 기록 24개·미확정 1개를 읽기 전용으로 확인했으나 지정 이메일과의 연결을 확정하지 못했다. 지정 계정의 실 로그인 후 자료별 검토 완료를 주장하지 않는다.
- 검토 중 생성된 인증 파일이 18:19 KST에 갱신됐다. 초기 전체 캡처의 status 중복 선언 오류는 후속 새 브라우저에서는 재현되지 않았다. 초기 관찰·후속 결과를 함께 기록하며 다른 시점의 산출물을 같은 버전의 결과로 섞지 않는다. 종료 시 파일 해시를 별도 보관했다.

## 제품 경험의 중심 구조

### 홈: 규모를 증명하고 바로 한 가지 일을 시작하게 한다

브랜드/핵심 메뉴 → 작고 분명한 대표 현황 4개 → 무엇을 할지 입력/대표 예제 → 실제 결과와 근거 → 변화/최근 발견 → 연결의 의미 → 푸터 순서로 검토한다. 현황은 계속 대표 강점으로 유지하되 모바일에서는 장식과 여백 때문에 주 행동이 1,000px 아래로 밀리지 않게 조정한다. 현재 모바일의 목표 실행 버튼 y≈1,087은 실측이고, 개선 후 1화면 안에 진입을 제공하자는 것은 설계 목표다.

핵심 문구 후보: `Find the right agent. See the evidence. Build your next workflow.` 목표 입력 예: `Find recent battery recycling research with source links.` 주 CTA는 `Find an agent`, 첫 경험 보조 CTA는 `Try a live example`이다. 실제 가용성과 결과가 검증된 예제에만 live를 사용한다. 하나의 페이지에 비슷한 Explore CTA를 반복하기보다 각 구간의 다음 행동을 명확히 한다.

### 탐색·채팅·테스트: 같은 작업 문맥을 이어 간다

탐색은 여러 후보를 비교하는 도구, Chat은 한 번에 한 관련 후보를 추천하는 도구, Test는 실제 입출력을 확인하는 도구로 역할을 정리한다. 서로를 없애지 않는다. 명시적 프로토콜 선택은 유지한다. 탐색의 45개 기본 결과와 더 보기 기능도 유지하며 모바일 compact view와 적용 필터 요약으로 다루기 쉽게 만든다.

추천 카드의 순서는 용도 → 내 작업에 맞는 이유 → 최근 성공 증거/시점 → 제한사항 → 다음 행동이다. 토큰·원시 JSON·개인 프로필·지갑/과금/플랜 정보를 Chat에 가져오지 않는다. 다른 후보를 요청해도 한 번에 한 추천을 제공하는 정책을 유지한다.

### 워크스페이스: 관리 화면에서 실제 작업 공간으로

첫 화면은 현재 작업 공간 → 최근 작업 재개 → 새 목표 → 최근 결과/검토 대기로 구성한다. 현재 조직 선택·초대·계정 설정에 집중된 레이아웃에서, 실제 산출물을 만들고 다시 쓰는 경험으로 중심을 옮긴다. 작업이 26개로 늘어난 상황에는 단순 select보다 검색 가능한 라이브러리와 최근 작업 목록이 유리하다는 것이 본 검토의 판단이다.

데스크톱에서는 작업 목록, 목표/진주 연결, 선택 단계 inspector가 같은 상태를 공유하도록 한다. 모바일에서는 현재 목표와 다음 행동을 먼저, 라이브러리와 기술 상세를 뒤에 둔다. Design, Review, Test, Download를 거쳐도 선택된 버전과 연결 계획이 눈앞에서 사라지지 않아야 한다. 현재 검토 화면의 first/followup, 기본으로 펼쳐지는 긴 JSON, 모호한 완료 메시지는 우선 정리한다.

### 진주 목걸이를 기능 언어로 사용한다

진주 하나는 검토된 capability, 연결선은 실제 전달 필드, 잠금/버클은 실행 승인 범위, 완성된 목걸이는 사용자가 얻을 결과를 뜻하게 한다. 같은 진주 이미지의 반복만으로는 연결의 가치가 전달되지 않는다. 선택·실행 중·성공·실패·생략·미확정 상태를 아이콘과 텍스트로 보여주고, 진주를 누르면 해당 단계의 입출력과 출처가 열린다. 장식 애니메이션보다 데이터 흐름의 이해를 우선한다.

## AI 기능은 이 순서로 강화한다

1. **목표 이해와 조건 정리**: 자연어를 task brief와 수정 가능한 검색 조건으로 변환한다. 불필요한 질문은 줄이되 모호한 범위는 확인한다.
2. **근거 있는 후보 선정**: 의미 검색을 기록된 검증·프로토콜·활성/보안 조건과 결합한다. AI가 근거 없이 점수나 가용성을 만들지 않는다.
3. **계획 생성과 검토**: 허용된 도구·typed 입출력으로 진주 연결 계획을 제안한다. 공유 데이터·가정·출력 형식·왜 이 단계인지 설명한다.
4. **입력 보조**: schema에서 사용자용 폼·샘플을 만들고 검증된 값과 AI 제안을 구분한다. 적용 전에 사용자가 확인한다.
5. **실행의 해석**: 정형 실행 상태를 기준으로 진행·부분 성공·미확정을 설명한다. AI 문장이 backend의 실패를 성공으로 바꿀 수 없다.
6. **최종 결과와 출처**: 실제 응답만 요약하고 최신성·문헌 유형·중복·부족한 근거를 설명한다. 원문에서 나온 명령은 작업 지시로 실행하지 않는다.
7. **복구와 재사용**: 확정된 무실행과 미확정 실행을 구분해 검토 가능한 수정안을 만든다. 성공한 작업은 저장·재개하되 예약·전송 권한은 따로 확인한다.

모든 메뉴에 범용 챗봇을 새로 넣는 것, 검증 없는 자동 에이전트 교체, 실제 실행처럼 보이는 예시 출력, 기본 체크된 입력 공유/마케팅 동의는 권하지 않는다. 독립적인 권한 경계는 유지하고 사용자가 이해하기 쉬운 표현과 배치로 바꾼다. 현재 지원하지 않는 민감 자료 업로드나 외부 전송 기능을 준비된 기능처럼 소개하지 않는다.

## 실행·전송·AI 테스트에서 아직 확인하지 못한 것

- 지정 이메일의 실제 OAuth 완료 및 해당 세션에서의 모든 저장 자료 확인.
- 현재 운영 모델의 다양한 목표 이해·계획 관련성·출처 정확도. 격리 AI adapter 통과는 그 모델 품질 평가가 아니다.
- 실제 사용자의 네이티브 PushSubscription과 테스트 알림 클릭 확인, 실제 지정 수신자의 이메일 수신. 이번에는 합성 수신기/TLS/동의·철회 동작을 검증했다. 계정 이메일을 알림 수신 동의로 간주하지 않았다.
- 다수 실제 사용자 연구, 전환율·재방문율 개선, WCAG 전체 적합성, 정상 운영 부하의 p95와 오류율.
- 결과 미확정인 실행의 외부 최종 상태. 이력을 지우거나 성공/실패로 바꿔 검증 완료처럼 만들지 않았다.

## 적용 순서와 완료 기준

**첫 번째 묶음 — 공개 검증의 신뢰**: W00 실제 워크플로우 시간 예산·내부 대기, C00 Chat API/화면 예산과 표시 실패, G01 정적 자산/일반 읽기 제한, F01 운영 정책/시안 경로를 먼저 정리한다. I01 인증 문서는 현재 미재현 상태이므로 빌드 회귀와 실제 OAuth 확인을 추가한다. AI06은 독립적인 출시 평가 조건이다. 화면을 더 꾸미는 작업으로 이 항목들을 덮지 않는다.

**두 번째 묶음 — 첫 성공과 연속 작업**: 홈 첫 화면, 탐색 compact/필터/상세, 단일 테스트의 결과 표시, 공개 workflow의 입력·상태·복구, Chat의 선정 이유를 같은 작업 문맥으로 연결한다. 정상·빈 결과·권한 필요·실패·취소·시간 초과·중복 클릭을 함께 검증한다.

**세 번째 묶음 — AI 작업 공간**: 라이브러리/목표 입력 중심 개요, 진주 계획 편집·검토, 단계별 정확한 동의, 버전/테스트 결과/다운로드를 재구성한다. 공개 흐름과 고객 흐름의 서로 다른 예산·권한·재개 규칙을 UI에서 혼동시키지 않는다.

**네 번째 묶음 — 재방문과 확장**: 저장된 작업 재개, 최신 근거의 변화, 비교, 문맥형 도움말, 검증된 알림을 강화한다. 개인화·자동 실행·외부 전달·마케팅을 같은 동의로 합치지 않는다.

검증 목표는 먼저 기준선을 측정한 뒤 합의한다. 예를 들어 첫 유용한 결과까지 걸린 시간, 목표에 맞는 후보를 찾은 비율, 계획 검토 이해도, 실제 최종 산출물 완료율, 실패 후 복구율을 분리한다. 클릭 응답을 빠르게 보여주고 첫 행동을 모바일 첫 화면에 배치하는 것은 설계 목표다. 제시한 목표를 이미 달성한 측정값으로 표시하지 않는다.

완료 기준: 방문자는 예제 선택→실행→출처가 있는 결과→저장/다음 연결까지 갈 수 있다. 기록 재생을 새 실행으로 집계하지 않는다.

#### H04 · P2 · 재방문 동기

완료 기준: 각 동작 후 상태 문구·활성 버튼·실제 저장/실행 상태가 일치한다. 동의 전 release 비활성 자체는 정상 경계로 유지한다.

[증적·관련 소스](<저장소>/reports/frontend-ux-ai-review-2026-10-20/evidence/isolated-workspace-download-desktop.png)

#### X06 · P1 · 테스트 전 입력 검토

근거 구분: 격리 재현+소스. AI 관련: 예.

Prepare 동작은 긴 exact JSON을 기본으로 펼친다. 기술적으로 정확하지만 비개발자는 공유 범위를 해석하기 어렵다.

개선: 각 단계에 보낼 필드·출처·민감 여부·최대 호출·외부 전달 유무를 읽기 쉬운 표와 연결선으로 요약한다. exact JSON도 고급 상세로 보존한다.

완료 기준: 요약이 실제 승인 payload와 일치하고 AI 요약이 필드를 누락해도 승인 범위가 넓어지지 않는다.

[증적·관련 소스](<저장소>/reports/frontend-ux-ai-review-2026-10-20/evidence/isolated-workspace-test-review-desktop.png)

#### X07 · P1 · 결과·성공의 의미

근거 구분: 격리 검토+개선 제안. AI 관련: 예.

현재 step results는 first/followup과 각 응답을 보여준다. 두 호출이 성공했다고 사용자의 목표가 달성됐다고 단정할 수는 없다.

개선: 최종 산출물·원문 근거·단계별 기록·부분 실패를 함께 보여준다. 실행 완료와 사용자의 목표 달성 평가는 분리한다.

완료 기준: 실제 소스 링크를 열 수 있고 요약의 근거가 추적된다. 선택적 task feedback은 별도 동의·철회 계약을 유지한다.

#### X08 · P1 · 다운로드·실행 환경

근거 구분: 격리 검토+개선 제안. AI 관련: 아니오.

최종 단계는 immutable release, exact origin, authorize 등의 구현 개념이 주 행동이어서 일반 사용자의 완료 경험이 무겁다.

개선: 사용 목적에 따라 Hosted app 준비 상태, Download package, Developer setup을 구분하고 실제 가능한 경로만 안내한다. 원본·허용 origin·유효기간은 쉬운 말로 설명한다.

완료 기준: 검토한 버전의 실제 패키지를 실행하고 만료·철회·잘못된 origin에서 차단되는지 격리 환경에서 검증한다.

#### X09 · P1 · 멤버·계정·선택 상태

근거 구분: 격리 재현+개선 제안. AI 관련: 아니오.

초대에 cu_ 형태의 참조가 노출되고 Account는 같은 개요 안의 앵커다. 모바일 개요에서는 Overview와 Workflows가 함께 강조되는 상태도 보였다.

개선: 이름/표시명과 역할 중심의 멤버 목록, 복사 가능한 초대 참조, 전용 계정 페이지를 제공한다. 한 메뉴만 현재 위치로 표시한다.

완료 기준: 초대 참조만으로 권한을 주지 않고 제공자 계정을 자동 결합하지 않는다. 조직 전환 후 링크와 aria-current가 모두 같은 조직을 가리킨다.

#### X10 · P2 · 동의·크레딧·전문 용어

근거 구분: 격리 검토+개선 제안. AI 관련: 아니오.

여러 목적의 승인이 분리된 것은 유지해야 한다. 다만 긴 설명과 크레딧 바가 목표 입력보다 먼저 반복돼 AI 창작 흐름을 끊는다.

개선: 권한별 동의는 유지하되 해당 행동 바로 앞에서 간결하게 설명한다. 저장 시점에 적용량·잔여량을 보여주고 크레딧 상세는 보조 패널로 둔다.

완료 기준: 저장 전 명확한 확인이 있고 중복 클릭·실패·재다운로드에서 잘못 차감하지 않는다. Chat에는 플랜·과금 정보를 가져오지 않는다.

### AI 전략

#### AI01 · P1 · 목표→검색 조건

근거 구분: 개선 제안. AI 관련: 예.

현재 사이트의 큰 자산은 수집·상태·실행 증거다. AI는 그 근거를 사용자가 원하는 일과 연결할 때 가치가 크다.

개선: 자연어 목표를 작업·프로토콜·범위·출력 조건으로 바꾸고 수정 가능한 task brief로 유지한다. 꼭 필요한 경우만 추가 질문한다.

완료 기준: 사용자가 지정한 제약을 지키고 추천 근거와 누락 조건을 보여준다. 단순 필터가 더 빠른 곳에 불필요한 생성 호출을 추가하지 않는다.

[증적·관련 소스](<저장소>/agent_market/concierge/engine.py)

#### AI02 · P1 · 에이전트 선정·계획 생성

근거 구분: 개선 제안. AI 관련: 예.

AI가 이름만 멋있게 붙인 워크플로우보다 실제 연결 가능한 입출력과 검증된 후보가 중요하다.

개선: 검색·품질·실행 증거는 결정적 필터로 적용하고 AI는 역할 배분·대안 설명·typed 계획을 제안한다. 자동 실행은 별도 승인을 요구한다.

완료 기준: 없는 도구·리소스·권한을 만들어내는 제안은 거절되고 읽기/쓰기/외부 전송 범위가 실행 전 확정된다.

[증적·관련 소스](<저장소>/agent_market/workspace_app_factory.py)

#### AI03 · P1 · 결과 요약·출처 검증

근거 구분: 개선 제안. AI 관련: 예.

요약이 유창해도 원문·범위·시점이 없으면 신뢰를 잃는다. 외부 에이전트 출력은 신뢰할 수 없는 입력이다.

개선: 최종 요약은 실제 반환 자료에만 근거하고 주장별 출처를 연결한다. 원문의 명령문은 데이터로 다루며 내부 행동 지시로 실행하지 않는다.

완료 기준: 출처 없는 주장·날짜 변조·prompt injection·부분 결과 사례에서 허위 성공과 권한 상승이 없다.

[증적·관련 소스](<저장소>/reports/frontend-ux-ai-review-2026-10-20/execution-delivery-regressions.xml)

#### AI04 · P1 · 오류 설명·대안·복구

근거 구분: 개선 제안. AI 관련: 예.

네트워크 실패, 공급자 권한 요구, 입력 불일치, 결과 미확정은 다른 문제다. 모두 failed로만 표현하면 사용자가 고칠 수 없다.

개선: 정형 오류 코드를 먼저 분류하고 AI는 사용자용 설명과 검토 가능한 수정안을 제시한다. 확정된 무실행과 미확정 실행을 구분한다.

완료 기준: 수정안이 자동 재전송·자동 과금·권한 확대를 만들지 않고 사용자가 입력·대상·공유 범위를 다시 확인한다.

[증적·관련 소스](<저장소>/agent_market/workflow_persistence.py)

#### AI05 · P2 · 반복 작업·재방문

근거 구분: 개선 제안. AI 관련: 예.

현재 기능은 발견·추천·실행·보존 요소를 갖지만 반복 작업의 재개 경험은 약하다.

개선: 검증된 작업을 reusable workflow로 저장하고 변경점·최근 결과·실패 검토를 한 화면에 모은다. 일정 실행은 목적별 권한과 검증된 전달 수단을 전제로 한다.

완료 기준: 방문·콜백·기존 notify 플래그만으로 예약 실행이나 마케팅 허가를 추론하지 않는다. 중지·철회·만료 상태를 검증한다.

[증적·관련 소스](<저장소>/AGENTS.md)

#### AI06 · P0 · AI 품질·출시 평가

근거 구분: 출시 조건 제안. AI 관련: 예.

격리 AI 제안 테스트는 UI와 계약을 검증하지만 실제 모델의 목표 이해·관련성·인용 품질을 입증하지 않는다.

개선: 분야·프로토콜·난이도가 다른 대표 과제 집합으로 목표 해석·후보 관련성·계획 유효성·실제 완료·출처·복구를 분리 평가한다. 투자자 대표 시나리오는 별도 게이트로 둔다.

완료 기준: 합성 테스트·실제 제공자 실행·실제 AI 생성·지정 계정 OAuth·실제 알림 수신의 검증 범위를 각각 표시한다. 검증하지 않은 것을 완료로 표시하지 않는다.

[증적·관련 소스](<저장소>/reports/frontend-ux-ai-review-2026-10-20/execution-delivery-regressions.xml)
