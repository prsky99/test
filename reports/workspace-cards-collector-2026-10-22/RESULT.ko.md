# 워크플로우 카드와 수집 오류 수정

## 변경

- Your workflows 카드의 고정 진주 3개를 저장된 최신 워크플로우 정의의 단계 수로 교체했습니다. 진주 하나는 구성된 에이전트 단계 하나를 의미하며, 같은 에이전트를 여러 단계에서 사용하면 각 단계를 표시합니다.
- 진주 아래에 에이전트·단계 수를 텍스트로 표시합니다. 기존 진주 질감, 연결선, 선택 상태, 밝은/어두운 테마를 유지합니다.
- 목록 API는 서명된 현재 버전을 한 번에 조회해 `step_count`만 추가합니다. 카드별 추가 요청이나 DB 조회를 만들지 않으며, 과거 버전과 비활성 워크플로우도 현재 저장 정의를 기준으로 표시합니다. 단계 내용이나 인증정보는 목록에 추가하지 않습니다.

## 수집 경고 원인과 수정

운영 로그의 반복 경고는 한 제공자 호스트에 집중되어 있었습니다. 해당 제공자의 공개 도구 목록 40개를 실제 실행 없이 조회해 재현한 결과, 도구 설명에 포함된 NUL 제어문자가 검색 텍스트에 들어가 PostgreSQL 매개변수 검사에서 거부됐습니다. `INSERT INTO resources_fts` 단계의 실패로 전체 수집 결과가 롤백되어 다음 조사에서도 반복됐습니다.

원본 도구 JSON은 그대로 보존하고, 검색용 텍스트를 추출할 때 NUL만 공백으로 바꾸도록 수정했습니다. DB 매개변수 검증과 트랜잭션 롤백 정책은 유지합니다. 실제 제공자 메타데이터를 수정 코드로 다시 재생했을 때 `accepted=1`, `ok=1`, 저장 오류 없음으로 확인했습니다. 이 재생은 메모리 테스트 DB에서 수행했습니다.

## 검증 및 증적

- 백엔드·보안 경계 회귀 74개 통과. 같은 실행의 임시 PostgreSQL 테스트 1개는 샌드박스 기동 제한으로 실패하여 별도 권한으로 재실행했고 통과했습니다.
- 고객 API·브라우저 회귀 18개 통과. 2·5·10개 진주, 검색, 카드 선택, 편집기 단계 수, 가로 넘침 및 불필요한 실행 방지를 확인했습니다.
- 실제 임시 PostgreSQL 수집 계약 24개 통과: NUL 포함 메타데이터의 전체 저장, 원본 보존, SQLite 동등 동작 포함. 임시 DB는 제거됐습니다.
- 공개 콘텐츠 243개 파일 검사: 위반 없음. SQL 카탈로그 최신성 검사 통과.
- 변경 부분의 파라미터 바인딩, 작업 공간 범위, 버전 서명 검증, DOM 텍스트 삽입을 검토했습니다. 전체 파일 Bandit 결과 31개는 기존 코드/임베디드 HTML 진단으로 기록했으며, 이번 변경 외 전체 코드의 무취약성을 의미하지 않습니다.

운영 DB 변경, 실제 도구 실행, 결제, 인증정보 전송, 서버 재시작은 하지 않았습니다. **서버 재시작 후 새 목록 API와 수집 정규화 코드가 운영에 반영됩니다.** 이후 운영 자동 수집의 경고 해소 여부는 재시작 후 확인이 필요합니다.
