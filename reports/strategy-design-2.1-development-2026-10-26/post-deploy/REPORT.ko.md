# 2.1 릴리스 운영 반영 점검 — 2026-10-26

사용자가 실행한 배포의 실제 상태를 확인했다. 프론트엔드·어드민·jobs·execution 모두 `strategy-design21-20261026-r1`로 실행 중이다. 배포 상태는 stable이며, 이번 점검에서 프로세스를 중지·재시작·교체하지 않았다.

## 서비스와 보안 경계

[서비스 결과](service-results.json)의 **40개 점검이 통과**했다.

- 프론트엔드와 어드민의 릴리스·준비 상태, jobs와 execution의 최근 하트비트 정상.
- 불변 릴리스 전체 manifest 검증 정상. 공개 CSS·JS가 해당 릴리스 파일과 일치.
- 로컬·공개 홈, 로그인 진입, 제공자 연결 선택 화면 정상. 선택 화면은 HTTP 200인 공개 셸이며, 브라우저에서 인증 확인 후 로그인 화면으로 이동한다.
- 비로그인 세션·워크스페이스 API는 401. 외부에서 내부 readiness 경로는 404. compact 실행 상태 요청은 인증 없이 401.
- OpenAPI의 공개 경로 5개, 조건부 조회 304, compact 도구 5개, 검증 피드 정상. 홈 CSP 확인.
- DB는 읽기 전용 트랜잭션으로 하트비트만 조회했다. 어드민 진입 응답은 확인했으나 실제 관리자 로그인과 전체 관리 작업은 이번 범위에 포함하지 않았다.

## 실제 검색 결과와 남은 수용 조건

[검색 결과](search-results.json)는 **8개 기대 조건 중 7개 충족, 1개 미충족**이다. 미충족 항목을 통과로 변경하지 않았다.

- `ai news`: 탐색 10개, 채팅 3개, compact API 일치 결과 반환.
- 공식 소프트웨어 문서 검색: MCP 탐색 7개, 채팅 3개 반환. 프로토콜 필터 유지.
- `Find agent named Technology News`: 정확 이름 검색 결과 1개 반환.
- 공개 워크플로우 템플릿 25개 조회 정상. 템플릿 실행·저장은 하지 않았다.
- **남은 조건:** 문서 검색 compact API는 HTTP 200 / `no_match` / 빈 목록 / `execution_authorized=false`. 위 채팅 후보 3개 모두 `verified_within_24h=false`임을 [추가 진단](document-contract-review.json)으로 확인했다. `agent_market/agent_access/catalog.py`는 현재 버전의 실행 검증 증거가 없는 후보를 공개 실행 후보에서 제외한다. 이번 결과는 최근 실행 검증을 충족한 후보 확보가 필요함을 보여주며, 탐색 오류나 HTTP 장애로 판정하지 않는다. 전체 카탈로그에 적격 후보가 전혀 없다는 결론은 내리지 않는다.

최종 소수 표본에서 탐색·채팅·compact 응답은 약 **0.9~2.4초**였다. 부하 시험·장기 가용성·정확도 인증 수치가 아니다. 별도 진단 요청 1회는 JSON 파싱에 실패했고 당시 상태 코드를 보존하지 못했다. 후속 동일 요청은 HTTP 200 JSON으로 확인했다. 이 한 건의 원인은 확정하지 않았다.

## 실제 공개 브라우저

[브라우저 결과](browser-results.json)의 **데스크톱·모바일 2개 흐름이 통과**했다. 새 브라우저 저장소로 접속했으며 기존 로그인 쿠키는 사용하지 않았다.

채팅에서 `ai news` 입력 → 현재 첫 추천의 `Review task in Test` 클릭 → 테스트 준비 화면에서 원문과 실제 `topic` 입력 보존, 실행 버튼 활성, 외부 요청 전송 없음 안내를 확인했다. 실행 버튼은 누르지 않았다. JavaScript 오류와 테스트 준비 화면의 가로 넘침이 없었다. 제공자 연결 진입 후 로그인 이동과 Google·GitHub 버튼도 확인했다.

- 데스크톱: [채팅 전환 전](desktop-chat-before.png), [테스트 준비 후](desktop-test-after.png), [로그인 이동](desktop-signin-guard.png).
- 모바일: [채팅 전환 전](mobile-chat-before.png), [테스트 준비 후](mobile-test-after.png), [로그인 이동](mobile-signin-guard.png).

초기 점검 도구는 제공자 연결 셸을 HTTP 리디렉션으로 예상하고, 모든 에이전트의 입력 필드를 `query`로 가정했다. 실제 서버·계약을 확인하여 공개 셸과 보호 API를 분리하고 현재 에이전트의 `topic` 필드를 검증하도록 수정했다. 이를 서비스 소스 수정으로 기록하지 않는다.

## 범위

실제 고객 로그인, 만료 자격 증명의 운영 계정 재연결, 제공자 업무 실행, 크레딧 사용, 워크플로우 저장·실행, 16개 동시 부하 시험은 이번에 수행하지 않았다. 공개 검색으로 정상 방문·검색 관측 정보가 기록될 수 있다. 고객 업무 데이터·자격 증명·권한을 변경하지 않았다.

이전의 392개 API/unit/security 및 6개 격리 브라우저 검증은 이전 개발 증거로 유지한다. 이번 운영 점검과 합산해 운영 기능 전체 통과라고 주장하지 않는다. 기존 설계의 제공자별 dispatch/refresh, 전체 카탈로그 품질·독립 평가·장기 부하 수용 조건은 그대로 남는다.
