# 7차 확인 지적사항 수정·검증 결과

> **운영 배포 완료 업데이트:** 2026-10-29 사용자 승인으로 네 서비스를 r4에 적용했다. 실제 공개 서비스 확인 결과는 [배포 후 검증 결과](DEPLOYMENT.ko.md)를 참고한다. 아래 본문은 배포 전 수정·격리 검증 기록이다.

작성일: 2026-10-29. 소스 수정과 서비스별 배포 패키지 준비를 완료했다. **운영 서비스에는 아직 적용하지 않았다.** 이 문서의 격리 시험 결과와 운영 확인 결과는 구분해야 한다.

## 수정한 문제

### 1. 모바일 폭과 클릭을 방해하던 배치

`#chatProtocol`의 고정 폭·최소 폭을 컨테이너에 제한했다. 실제 브라우저 클릭 시험에서는 표시용 프로토콜 버튼이 두 줄로 바뀌어도 그룹 높이가 고정되어, 아래 설명이 MCP 버튼을 가리는 문제도 발견했다. 그룹 높이를 자동으로 바꾸고 줄바꿈을 허용했다. 강제 클릭으로 시험을 통과시키지 않았다.

Explore의 작은 필터 컨트롤에는 최소 24px 클릭 영역을 적용했다. Workflows 동작 영역은 최소 높이를 확보했다. 기존/새 화면을 320·390·768px에서 확인했고 Home·Chat·Workflows·Test·Explore의 문서 폭은 화면 폭 안에 들어왔다. Enter 제출, 프로토콜 선택, Calling details 열기와 Learn 이동도 확인했다.

제공된 176~246px의 화면 전체 넘침은 이번 운영 화면 측정에서 그대로 재현되지 않았다. 다만 533px인 내부 선택 요소와 실제 버튼 가림을 확인해 수정했다. 수정 후 격리 측정의 320px Workflows layout-shift 합계는 약 0.024였다. 이는 짧은 실험실 측정이며 실사용자 p75 CLS나 전체 사이트 접근성 인증을 의미하지 않는다. 숨겨진 select, 키보드 포커스 전용 링크, 문장 안 링크를 모두 작은 터치 버튼으로 세는 방식도 구분했다.

증적: `before-mobile-*.png`, `after-published-{320,390,768}.png`, `after-legacy-{320,390,768}.png`, `layout-*.json`.

### 2. Test 예제 실행 차단과 잘못된 대체 응답

현재 운영 상태에서는 예제 5개가 모두 사용 불가였다. 4개는 `SCHEMA_CHANGED`, GitHub 예제는 저장된 404 상태였다. 한편 실제 원본 데이터 조회와 공개 뉴스·GitHub MCP 도구 목록 조회는 성공했다. 따라서 이번에 확인한 주원인은 단순한 제공자 502가 아니었다.

웹 릴리스에서 출력 스키마를 넓혔으나 등록된 계약과 다른 worker의 선언은 이전 스키마여서 해시가 맞지 않았다. 기존 스키마 안전 검사는 올바르게 실행을 차단하고 있었다.

수정 내용:

- 실제 출력과 일치하는 정확한 스키마로 복원하고 운영자 에이전트 선언을 서비스별로 일치시켰다.
- 검토된 자체 에이전트에만 계약 개정 식별자를 적용했다. 과거 실패 이력은 보존하며 성공 증거를 새 버전에 복사하지 않는다.
- 같은 스키마·같은 엔드포인트였던 기존 승인만 유지한다. 미승인 도구나 외부 스키마 변경을 자동 허용하지 않는다.
- 실제 원본 조회 후에만 오래된 자체 에이전트의 연결 실패 상태를 복구하고, 실제 도구 실행이 성공해야 실행 검증이 성립한다.
- 재설치가 반복되어도 같은 버전에서 발생한 새로운 스키마 실패를 지우지 않는다.
- GitHub 오류 시 다른 검색어의 과거 성공 결과를 반환하던 fallback을 제거했다. 같은 검색어의 허용된 캐시 범위만 사용하고, 사용할 결과가 없으면 실제 실패를 알린다. 구현되지 않은 자동 갱신 안내도 제거했다.

격리 환경의 실제 외부 원본을 이용한 검증에서 7개 에이전트·3개 워크플로우·입력 변형 6개를 완료했다. 운영 DB의 검증 이력을 조작하거나 예제를 가짜 성공으로 바꾸지 않았다. 운영 예제 활성화와 공개 실행 최종 확인은 배포 후 필요하다.

### 3. Chat·MCP 추천 정확도와 카드 이름

기존 집중도 판정은 핵심 단어의 일부만 맞아도 통과했다. GitHub 네임스페이스나 광범위한 도구 목록의 translation 언급만으로 전문 서비스보다 앞설 수 있었다. 도구가 적다는 이유만으로 관련 없는 작은 서버도 전문 서비스로 취급했다.

서비스의 실제 주목적과 요청 핵심 조건이 맞아야 전문 후보로 판단하도록 수정했다. 기능 적격성 확인 후, 전문 후보를 우선하고 각 계층에서 검증·활동·품질 순위를 적용한다. 프로토콜 제한과 기존 안전 검사는 유지한다.

- 번역 실행과 기존 번역 자료 검색을 구분한다. `search_translations`가 일반 번역 실행 요청에 들어오지 않게 했다.
- 전체 GitHub 이슈 검색과 특정 저장소의 이슈 목록 조회를 구분한다. GitHub 이슈에서 수집한 지식 문서를 찾는 도구도 실제 이슈 검색으로 취급하지 않는다.
- 날씨 제공자 목록을 찾는 도구와 실제 날씨 예보를 구분한다.
- 금융 카테고리라는 이유만으로 관련 있는 도구를 일괄 배제하던 예외를 제거하고 실제 기능으로 판단한다.
- 원래 서비스 이름을 보존하고 화면용 이름을 별도로 제공한다. 이름이 없을 때도 `Recommended agent` 대신 프로토콜·식별자가 있는 이름을 쓴다.

격리 회귀에서 전문 번역·이슈 검색이 번들보다 앞서고 부적격 후보는 제외됐다. 운영 카탈로그를 읽기 전용으로 사용한 비교에서도 Faceabot Translate가 번역 1위가 됐다. 다만 그 비교는 RAG를 끈 경로였으므로 운영 성능 비교로 사용할 수 없다. 이 경로의 1.8~19.5초 지연을 운영 응답 속도가 개선됐다는 근거로 사용하지 않았다. 운영 설정의 검색·Chat 지연과 실제 GitHub 전문 에이전트 순위는 배포 후 다시 측정해야 한다.

서울 날씨는 수정 전 운영 확인에서도 Faceabot Weather가 1위였으며, 한국어 ‘그 두 번째 것’ 후속 질문도 동작했다. 이 두 현상을 이번 수정으로 새로 해결했다고 계산하지 않았다.

### 4. 실행 없는 성공 보고서

메타데이터만 있는 보고서를 생성할 때 성공으로 기본 설정하지 않도록 바꿨다. 관리자 API·일괄 등록 도구에서 성공 보고서를 공개하려면 실행 또는 계약 검증 범위가 필요하다. 저장소의 기존 검사로 대상 버전·시간·실행 증거 일치를 확인한다.

기존 연결 검사 문서를 실행 성공 보고서와 구분하는 표시를 추가했다. 과거 보고서를 일괄 삭제하거나 과거 실행을 만들어내지 않았다. DB에 직접 쓰는 임의 SQL까지 모든 위조를 막는 변경은 아니며, 이번 범위는 제품의 생성·공개 경로와 표시다.

### 5. API·문서·Learn

- 공개 API 404와 등록 검증 오류를 RFC 9457 형식으로 정리했다. MCP·A2A의 JSON-RPC 오류는 해당 프로토콜을 유지한다.
- 공통 오류 처리에서 모든 경로에 붙이던 wildcard CORS를 제거했다. 공개 카탈로그 읽기와 허용한 브라우저 에이전트 전송 경로만 각 정책으로 노출한다. 비공개 워크스페이스·관리자 경로를 개방하지 않는다.
- MCP 도구 annotation은 실제 동작에 맞췄다. 대화 기록을 저장하는 search/find_agents/whats_new/search_workflows는 읽기 전용으로 주장하지 않는다. 단순 잔액·공개 정의 조회와 외부 실행 위험 표시를 구분한다. QA 시나리오도 이 기준으로 수정했다.
- 자체 MCP 에이전트의 버전 협상·메타데이터 처리를 현재 클라이언트와 맞췄다.
- 명시적 `Accept: text/markdown` 요청에 Home/Chat의 Markdown 응답을 제공한다. 기본 HTML/JSON, 토큰 헤더와 접근 경계는 유지한다.
- Learn에 가이드·프로토콜 검색과 실제 이동을 추가했다. 이는 Learn의 로컬 가이드 색인이며 전체 사이트 검색은 아니다.
- `skill.md`에서 클라이언트의 지시 파일·시스템 프롬프트에 규칙을 복사하라는 문구를 제거했다. 선택적 연동 참고 문서로 바꾸고, 힌트는 실행 권한이 아님을 명확히 했다.
- 정상 단어 analysis 등이 오타 교정으로 다른 검색어가 되는 사례를 막았다.

x402 최초 402의 검사 전용 표시는 현재 코드에 이미 있었고, HEAD·카테고리 sitemap·방문 토큰 초기화·A2A 문맥 등 기존 수정도 관련 회귀에서 확인했다. 크롤러용 본문은 기존 공개 페이지·메타데이터·llms 문서를 활용하며 모든 페이지의 SEO를 재작성한 작업은 아니다.

## 검증 결과와 한계

서로 겹치는 시험 묶음이므로 아래 숫자를 합쳐 고유 시험 수로 제시하지 않는다.

- 핵심 보안·품질 회귀: 308개 통과.
- 최종 추천·API·추가 변경 회귀: 177개 통과.
- 실제 Chromium 격리 브라우저: 30개 통과, 구형 Learn 화면에 해당하지 않는 1개 제외.
- PostgreSQL 18 격리 시험: 통과. TCP 외부 연결을 금지한 DB 계약 시험과 실제 원본을 사용하는 별도 시험을 구분했다.
- 최종 서비스별 동결 패키지 4개의 파일 해시·PostgreSQL 계약 시험: `frozen-candidate-verification.json` 확인.
- 공개 프론트엔드 파일 313개: 콘텐츠 정책 위반 0, embedded HTML 동기화 확인.
- Ruff F/B 정적 검사: 운영 기준본의 기존 지적 39개가 남아 있고 이번 수정에서 새로 추가한 지적은 0개다. 전체 저장소 정적 검사 무결함을 주장하지 않는다.
- 이번에 만든 QA 방문자 5명, 관심사 5건, 메시지 12건, 전용 QA 방문 집계 1건은 비공개 백업 후 정리했다. 실제 고객·평가·결제 기록은 삭제하지 않았다.

실사용자 p75 지표, 7차와 동일한 90분 전체 UX 재평가, 모든 외부 제공자의 지속 가용성, 실제 결제는 이번 시험으로 보장하지 않는다. UI/UX 종합 점수를 임의로 올려 산정하지 않았다. 테스트 도구에서 Starlette/httpx의 향후 호환성 경고 1개가 발생했고 현재 시험 실패는 아니다.

## 논문·커뮤니티 검토의 반영

[ToolRet](https://arxiv.org/abs/2503.01763)는 일반 정보 검색 성능이 도구 검색 성공을 보장하지 않음을 보여준다. 이번에는 단어 일치에 더해 **실제로 요청한 동작을 수행하는 도구인지** 확인하는 조건을 강화했다.

[ToolRerank](https://aclanthology.org/2024.lrec-main.1413/)의 계층적 재정렬 관점을 참고해 서비스 주목적과 개별 도구 적합성을 분리했다. 논문의 학습 모델을 도입하거나 그 논문의 성능 향상을 이 서비스에서 달성했다고 주장하지 않는다.

SNS·개발자 커뮤니티 논의인 [MCP Discussion #2550](https://github.com/modelcontextprotocol/modelcontextprotocol/discussions/2550)도 확인했다. 서비스 중심 기능과 부수 기능을 구분하는 문제의식을 참고했지만, 제안 단계의 priorityHint를 공식 표준이나 신뢰 가능한 권한으로 사용하지 않았다.

터치 영역은 [WCAG 2.2의 최소 타깃 크기와 예외](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), CLS 판단은 [web.dev의 CLS 가이드](https://web.dev/articles/optimize-cls)를 기준으로 했다.

## 운영 반영

운영 슬롯을 변경하지 않았다. 패키지는 공유 작업 트리 전체가 아니라 각 역할의 실제 활성 릴리스 위에 이번 검토 파일만 얹어 만들었다.

- frontend/admin 기준: `qa7-web-20261029-r3`
- jobs 기준: `ux7-jobs-20261028-r1`
- execution 기준: `ux7-execution-20261028-r1`

프로젝트 터미널에서 적용할 명령:

```sh
./agentcon deploy frontend qa7-repair-frontend-20261029-r4
./agentcon deploy admin qa7-repair-admin-20261029-r4
./agentcon worker-deploy jobs qa7-repair-jobs-20261029-r4
./agentcon worker-deploy execution qa7-repair-execution-20261029-r4
./agentcon status
```

배포 직전 기준 활성 릴리스가 위와 달라졌다면 이 패키지를 그대로 적용하지 말고 새 기준으로 변경분을 합쳐야 한다. PostgreSQL·Ollama·맥미니 모델 서버 재시작은 필요 없다. jobs/execution 교체 때 신규 작업 처리가 잠시 멈출 수 있다.

배포 후에는 Test 5개, Chat 번역·날씨·GitHub 이슈, MCP 동일 요청, 모바일 화면·버튼을 다시 확인해야 한다. 운영자가 원본을 사용하는 실제 재검증을 마친 뒤에 예제와 검증 배지가 활성화되는지 확인하며, 검증 전 상태를 임의로 성공 처리하지 않는다.
